## 一、总体架构

```
┌─ exploreUrl (@js) ─────────────────────────────┐
│ 域名下拉框(select) + 搜索框 + 搜索按钮          │
│ ┌─ if (域名含 boluomao) ─┐  ┌─ else ─────────┐ │
│ │ BM专属分类(gender/...) │  │ rrssk分类(list-N)│ │
│ └────────────────────────┘  └────────────────┘ │
└─────────────────────────────────────────────────┘
        │ source.putVariable 持久化当前域名
        ▼
┌─ jsLib ────────────────────────────────────────┐
│ TEMPLATES: 11套发现页列表规则模板               │

        ▼
ruleExplore / ruleBookInfo / ruleToc / ruleContent
  全部用 @js: if (GET('server').indexOf('boluomao')>=0) {...} else {...}
```

## 二、域名切换机制

### 2.1 持久化变量

```javascript
// jsLib 里封装（注意 Java String 空串陷阱，见 07 文档）
function GET(k) {
  const { java, source } = this;
  var d = {};
  try { d = JSON.parse(source.getVariable() || "{}"); } catch (e) { d = {}; }
  return d[k] || '';
}
function SET(k, v) {
  const { java, source } = this;
  var d = {};
  try { d = JSON.parse(source.getVariable() || "{}"); } catch (e) { d = {}; }
  d[k] = v;
  source.putVariable(JSON.stringify(d, null, '\t'));
}
```

### 2.2 发现页下拉框（select 控件）

```javascript
push('域名', '', 1, 1, {
  "type": "select",
  "chars": hosts,            // jsLib 里由 HOST_TEMPLATE_MAP 生成
  "default": hosts[0],
  "action": "java.refreshExplore()"   // 切换后刷新发现页
});
SET('server', infoMap['域名']);       // infoMap 读取 select 当前值
```

> ⚠️ **260923 v8 已改造**（原文如上，保留演进痕迹）：
> - `SET('server', infoMap['域名'])` **移进 select 的 action**：`"action": "SET('server', infoMap['域名']); java.refreshExplore()"` —— kinds 求值期拿的是 **live InfoMap 进程级缓存**（`exploreInfoMapList`），过期值会覆盖登录面板选站；且 check_source 校验器无 UI 态 infoMap 缺「域名」键会 `SET(undefined)` 把变量洗成 `{}` → 生成 `/list-` 相对 URL 直接炸校验（evalButtonClick 源码带 infoMap+java 绑定，点击时先 `infoMap[title]=char` 再执行 action，链路闭环）
> - `default` 改 `GET('server') || hosts[0]`（重建后显示当前真值）
> - 下拉正下方新增**状态栏行**（`type:button` + `viewName` 动态 `🌐 当前网址: GET(server)`，读真值不依赖下拉显示），并在 kinds 求值时 `infoMap['域名'] = GET('server')` 同步下拉显示

`hosts` 数组直接由 HOST_TEMPLATE_MAP 的 key 生成——**加新站只需在映射表加一行**，下拉框自动出现。

## 三、发现页模板系统

11 套模板对应 11 种列表 DOM 结构，每套 8 个字段：

```javascript
const TEMPLATES = {
  fanqxsw: {
    bookList: '//div[@class="list"]/ul/li',   // XPath
    name: 'a.1@text',                          // 默认规则（@分隔）
    author: '.time@span.0@text',
    kind: '.about@span.1@text&&.time@span.1@text',
    wordCount: '.about@span.2@text',
    lastChapter: '',
    intro: '.intro@text',
    coverUrl: 'img@src',
    bookUrl: 'a.1@href'
  },
  // ... xinghuowxw / shoudaxsw / kelexs / shuwuwan / shuxiangdzs
  //     cbtxt / dadawx / x630 / imglist369 / nmxswz / boluomao
};
```

ruleExplore 侧按当前域名取模板规则执行：

```javascript
"bookList": "@js:\nlet bookListRL = rules[GET('server')].bookList;\njava.getStringList(bookListRL);"
```

**新站接入流程**（以 xiakezww.com 为例，5分钟完成）：
1. GET `/list-1-1/` 识别列表容器 class → 匹配已有模板（div.list → fanqxsw）
2. 抽查一个 `<li>` 逐字段核对选择器
3. HOST_TEMPLATE_MAP 加一行 `'https://www.xiakezww.com': 'fanqxsw'`
4. debug_source 全链路验证

## 四、规则级域名分支（关键难点）

发现页可以靠模板系统分流，但 **详情/目录/正文是全局唯一规则**，两套体系（rrssk家族 vs 菠萝猫）差异巨大，只能在每个规则内部用 @js 分支：

```javascript
// ruleContent.content
@js:
if (GET('server').indexOf('boluomao') >= 0) {
  // BM: 正文是 data-obf 加密段落，逐段解码
  let arr = java.getStringList('.content@p@data-obf');
  ...
} else {
  // rrssk家族: 图标字体反爬解码 + 三容器兜底
  ...
  java.setContent(解码后HTML);
  java.getString('.content@html||article@html||#ad@html');
}
```

**实测踩坑**：BM 分支最初写 `JSON.stringify(res);` 想提前结束发现页脚本——结果脚本继续执行把 rrssk 分类也追加了（发现页 72 条 = 34 BM + 31 原分类 + 控件）。改用顶层 `return` 又报"返回的值无效"。**最终方案：if/else 完全隔离**，两分支互不穿透：

```javascript
if (sourceUrl.indexOf('boluomao') >= 0) {
  ...BM分类...
  JSON.stringify(res);
} else {
  ...rrssk分类...
}
JSON.stringify(res);
```

验证数据：boluomao1 → 34 BM分类/0 原分类；kelexs → 0 BM/31 原分类。

## 五、域名级缓存

密钥、bookId 等按域名隔离存储：

```javascript
cache.put(GET('server'), JSON.stringify({secretKey, ivKey}));  // 存
let keys = cache.get(GET('server'));                            // 取
```

> 260923 起：**init 写入**仍按 og:url 对齐域存（上式视角）；**目录读取**改为 `dataEncrypt(body, serverUrl)` 显式传键（`serverUrl = SRV(book.url)` 推导），并带 http/https 互换兜底——避免全局 server 漂移后读不到键。

切域名后自动使用对应密钥，互不污染。
