# 方法：登录·注册·验证码·限频破解

> **主干方法论**。蓝本：ppxsw.cc（皮皮小说）全要素实测源——登录 + 注册 + 图形验证码 + MD5 密码 + search_time 限频 + base64 反爬 + UA 双模板 + 目录乱序，一站集齐。
> App 环境：Legado 阅读 3.0 lyc 修改版（与官方版 API 存在差异，文中已标注）。
> 站点级完整实录（含推导过程、对照实验数据）见补充篇 → [登录注册验证码与限频破解实战-ppxsw篇](./登录注册验证码与限频破解实战-ppxsw篇.md)

---

## 适用场景

遇到以下任一任务，直接按本文档流程执行：

- 书源需要**账号登录**才能搜索/阅读（302 到登录页、返回推荐书列表等）
- 站点有**图形验证码**（`/code.jpg` 类端点）
- 需要**注册功能**（书源内完成开户）
- 搜索被**限频**（提示"请稍后再试"、倒计时、返回占位数据）
- "手动抓包验证 OK 但 App 里失效"类诡异问题

## 0. 三十秒速查表

| 问题 | 一句话结论 |
|---|---|
| 验证码怎么弹？ | loginUi 加 text 框 + 刷新按钮；函数内 `java.startBrowser(图片URL,'验证码')` 内置浏览器看图，用户回来手填 |
| `java.getVerificationCode` 能用吗 | lyc 版仅独立 eval_js 环境**可弹窗**；loginUi 对话框上下文调用**不弹窗静默返 null** |
| `java.getVerification` | 官方 API，lyc 版**不存在** |
| 改单个 Cookie 键 | `cookie.setCookie(url,str)` 是**整体替换**！必须"取全文→正则改→回写全文" |
| 限频怎么破 | 先四组对照实验定位服务端校验依据；若只查 Cookie 存在性→searchUrl 前置 JS **删键即破** |
| tocUrl 写在哪 | **ruleBookInfo 内**（放 ruleToc 被静默丢弃）；且不支持 `\|\|` 兜底 |
| 手动 OK 但 App 失效 | 头号嫌疑 **UA 双模板**，用 `get_http_log` 看 App 实际收到的响应再定规则 |
| 目录乱序 | 阅读**只按出现顺序去重、不排序**；用 li 的 class 特征过滤掉"最新章节倒序区" |
| 密码加密 | 抠站点 JS 到 eval_js 实跑比对，多数是标准 MD5 hex 小写→直接 `java.md5Encode` |
| 延迟等待 | 此 App **没有 java.sleep**！只能 `Packages.java.lang.Thread.sleep(ms)` |
| 注册接口参数 | 与登录**不同名**（name/pass/pass2/mobile/code），别照抄登录的 user_* |

## 1. 五步标准工作流

### 第一步：登录接口分析三步法

1. **抓登录页 HTML**：找 `<form>` 和按钮 onclick 绑定的 JS 函数名
2. **下载对应 common*.js**：提取该函数，拿到真实端点、参数名、成功判定标记
   ```js
   // 典型形态
   jq.post('/qs_login_go.php', {user_name, user_pass, user_code}, function(data){
       data.split("|")[0] == "1"   // ← '1|xxx' = 成功, '0|文案' = 失败原因
   })
   ```
3. **逆向加密函数**：把站点的加密 JS 整体抠进 eval_js 实跑，与 Python 标准算法比对：
   ```js
   qsskel("a7894563") === "fd26f013d2c05c33c6ab53e654b8bf97"  // true → 标准 MD5 hex 小写
   ```
   一致就直接用 `java.md5Encode(pwd)`，无需内联。
   > 识别特征：`function xxx(o){... return (G(T)+G(S)+G(R)+G(Q)).toLowerCase()}` 结构 = Paul Johnston 风 JS-MD5。

探测技巧："故意填错验证码"逐项触发服务端校验，记录各错误文案，即可摸清校验环节先后顺序。

### 第二步：loginUrl / loginUi 黄金范式

```json
"loginUrl": "function getHost(){return 'https://www.example.com';}\n\nfunction refreshCaptcha(){\n  java.startBrowser(getHost()+'/code.jpg?'+Math.random(),'验证码');\n}\n\nfunction login(b){\n  if(b==undefined) return true;          // ★ App打开UI时会无参预执行一次,必须守卫\n  var info=result;                        // ★ result 就是 UI 键值 map\n  var u=info['账号'],p=info['密码'],c=info['验证码'];\n  if(!u||!p||!c){java.toast('请完整填写');return;}\n  var body='user_name='+encodeURIComponent(u)+'&user_pass='+java.md5Encode(p)+'&user_code='+encodeURIComponent(c);\n  var resp=String(java.ajax(getHost()+'/qs_login_go.php,'+JSON.stringify({\n    method:'POST', body:body,\n    headers:{'Content-Type':'application/x-www-form-urlencoded',\n             'Referer':getHost()+'/login.html','X-Requested-With':'XMLHttpRequest'}})));\n  if(resp.indexOf('1|')>=0){\n    var ck=java.getCookie(getHost());\n    if(ck) source.putLoginHeader(ck);     // ★ 第二重保险,CookieJar丢失仍可兜底\n    java.toast('登录成功');\n  }else{java.toast('登录失败:'+resp);refreshCaptcha();}\n}\n\nfunction logout(){\n  source.removeLoginHeader();\n  cookie.removeCookie(getHost());\n  result['账号']='';result['密码']='';result['验证码']='';\n  source.putLoginInfo(JSON.stringify(result));\n}",
"loginUi": "[{\"name\":\"账号\",\"type\":\"text\"},{\"name\":\"密码\",\"type\":\"password\"},{\"name\":\"验证码\",\"type\":\"text\"},{\"name\":\"刷新验证码\",\"type\":\"button\",\"action\":\"refreshCaptcha()\"},{\"name\":\"登 录\",\"type\":\"button\",\"action\":\"login(true)\",\"style\":{\"layout_flexGrow\":1,\"layout_flexBasisPercent\":0.5}},{\"name\":\"登 出\",\"type\":\"button\",\"action\":\"logout()\",\"style\":{\"layout_flexGrow\":1,\"layout_flexBasisPercent\":0.5}}]"
```

五条铁律：
1. loginUrl 是**顶层具名函数集合**，不加 `@js:` 前缀；按钮 action 只写函数调用名
2. `login(b)` 内 `result` 就是 UI 输入 map；也可用 `source.getLoginInfoMap()`（Java Map，`.get(key)` 取值）——二选一，**同函数内勿混用**
3. `if(b==undefined) return true;` 守卫必须有
4. AJAX 头带齐 `X-Requested-With` / `Referer` / `Content-Type`（部分站强校验）
5. 成功后 `source.putLoginHeader(java.getCookie(host))` 持久化

### 第三步：验证码接入选型树

```
需要验证码？
├─ 官方版 Legado
│   └─ java.getVerification(imgUrl)        // 弹图+输入框一体
├─ lyc 版 + 独立 eval_js 调试环境
│   └─ java.getVerificationCode(imgUrl)    // 存在且可弹窗
└─ lyc 版 + loginUrl/loginUi 对话框上下文   ← 绝大多数实际场景
    └── ★ 黄金方案: java.startBrowser(imgUrl,'验证码')
        内置浏览器看图 + loginUi 验证码 text 框手填
        (getVerificationCode 在此上下文不弹窗、静默返 null)
```

**为什么 startBrowser 方案能通过会话校验**：`GET /code.jpg?rand` 响应同时下发图片和 `Set-Cookie` 会话；startBrowser 的 WebView Cookie 已与 CookieJar 打通，看图与提交同一会话。用户拿手机浏览器开图地址则对应浏览器的会话，App 提交必错码。
验证法：请求图片后立刻 `java.log(cookie.getCookie(host))`，确认新 session 键出现。

### 第四步：登出三清

登出必须同时清：①`source.removeLoginHeader()`（登录头）②`cookie.removeCookie(host)`（会话 Cookie）③UI 缓存输入并 `source.putLoginInfo()` 回写。漏任何一项都会造成"登出了但还是登录态"或"界面还记着旧密码"。

### 第五步：loginCheckJs 登录态自检契约

每个请求完成后执行，`result` 是 **StrResponse 对象**：

```json
"loginCheckJs": "(function(){try{var b=String(result.body());if(b.indexOf('<title>用户登录')>=0){throw new Error('xx源·登录已失效，请到书源界面重新登录');}}catch(e){if(String(e).indexOf('重新登录')>0){throw e;}}return result;})()"
```

- **必须 `return result`**——返回 Boolean 会 `ClassCastException`
- 自身逻辑 try-catch 包裹，只放行"掉线提示"，其余异常吞掉透传，避免污染正常请求
- `.body()` 是方法调用（lyc 版），不是属性

## 2. 注册流程接入

注册与登录是**两套参数名体系**，复用同一个 loginUi（加手机号 text 框 + 注册按钮）即可承载：

| 字段 | 登录 `/qs_login_go.php` | 注册 `/qs_register_go.php` |
|---|---|---|
| 账号 | `user_name` | `name` |
| 密码 | `user_pass`（MD5） | `pass` **和** `pass2`（两次均 MD5） |
| 验证码 | `user_code` | `code` |
| 手机号 | 无 | `mobile` |
| 成功判定 | `1\|` 前缀 | 文案不定 → toast 原文 |

```js
function zc() {                                   // 注册按钮 action 写 zc()
    cookie.removeCookie(source.key);              // ① 重置会话再取码,保证图码同源
    res = source.getLoginInfoMap();               // ② Java Map 取 UI 值风格
    use=res.get("帐号"); pwd=res.get("密码"); sj=res.get("手机");
    code = java.startBrowser(getHost()+'/code.jpg?'+Math.random(),'验证码') 后手填;
    body=`name=${use}&mobile=${sj}&pass=${java.md5Encode(pwd)}&pass2=${java.md5Encode(pwd)}&code=${code}`;
    html=String(java.ajax(getHost()+'/qs_register_go.php,'+JSON.stringify({
        method:'POST', body:body,
        headers:{'Content-Type':'application/x-www-form-urlencoded',
                 'X-Requested-With':'XMLHttpRequest','Referer':getHost()+'/'}})));
    java.longToast(html);                         // ③ 结果文案各异,原文展示最稳
    Packages.java.lang.Thread.sleep(3000);        // 给toast留时间;无java.sleep!
}
```

注意：
- 注册成功**不必** putLoginHeader（站点一般不自动登录），提示用户走一次登录
- `pass2` 漏传/不一致时部分站只回"非法访问"；先浏览器手动注册一遍记录各分支正常文案做基准
- 完整双函数实现样本：examples/`皮皮小说网ppxsw_注册版参考.json`

## 3. Cookie 三大铁律

### 铁律一：setCookie 是整体替换，不是合并

```js
// ✗ 这一句会把该域名全部 Cookie 清空只剩一个 → 登录态被抹、全体302
cookie.setCookie(u, "search_time=123");

// ✓ 取全文 → 正则删/改键 → 回写全文
var c = String(cookie.getCookie(u)).replace(/search_time=\d+/, "");
cookie.setCookie(u, c);
```

### 铁律二：验证码绑定会话

看图的会话 = 提交的会话才有效（见第三步）。失败自动 `refreshCaptcha()` 换一张。

### 铁律三：限频先做对照实验，可能"删键即破"

ppxsw 实测：服务端**只检查请求是否携带 search_time Cookie**——带就拒（回12条推荐书+倒计时），不带就当首次放行；且**每次失败的尝试都会重置倒计时**（干等无效，实测 P1=122s→等26s→P2=122s）。

四组对照实验定位机制：
1. 立即连发两次 → 观察提示变化（是否重置计时）
2. 静默等待后单发 → 排除纯时间因素
3. 改 Cookie 值再发 → 判断是否看值
4. 删键再发 → 判断是否只查存在性

确认为"只查存在性"后，把删键放进 **searchUrl 前置 JS**（每次搜索前自动执行）：

```xml
<js>
var U="https://www.ppxsw.cc/";
var c=String(cookie.getCookie(U)).replace(/search_time=\d+/,"");
cookie.setCookie(U,c);
"/search.html,{\"method\":\"POST\",\"body\":\"s=\"+encodeURIComponent(key)+\"\"}"
</js>
```

## 4. 高频陷阱速查

| 陷阱 | 症状 | 解法 |
|---|---|---|
| **UA 双模板** | 工具里规则命中N条，App里0条 | 分类页/目录页按UA返回两套DOM。开HTTP日志→`get_http_log(id)`看App实际收到的体→按它写规则。eval_js取移动版页面须显式带移动UA（裸java.ajax走桌面UA） |
| **tocUrl 位置** | 日志"获取目录链接"永远是详情页本身 | tocUrl 属于 **ruleBookInfo**；放 ruleToc 被反序列化静默丢弃。且**不支持`\|\|`兜底**（整串被当URL发出） |
| **目录乱序** | 前14章是最新章节、后面才从第1章开始 | 移动版目录=最新14章倒序区(li无class)+正序区(li.br-b-1)+推荐区(第二个ul)。修复：`class.ph_list.0@class.br-b-1@tag.a`。跨分页各页同样滤掉最新区→天然有序 |
| **base64 动态对象名** | 正文空白或乱码 | 加密对象名每书随机(rgr.owes/vypflhij.atyffy…)。恒定特征`var (\w+)=\{_keyStr`，动态提名字再匹配`obj.method('Base64串')`全局解码。纯@js:规则的result才是完整源码 |
| **分页变量随机名** | 只拿到第1页 | 匹配**赋值形态**而非变量名：`/'(\/[a-z]+\/[a-z]+_[0-9]+\.html)'/`。末页变量指向下一章不含_N.html→自动不匹配 |
| **延迟函数** | 报"找不到函数sleep"，整个规则炸 | 无java.sleep！用`Packages.java.lang.Thread.sleep(ms)` |
| **respondTime 过小** | 校验器误报失效 | 慢站设大（如180000），否则批量校验时超时连坐 |
| **文字匹配省略号** | `text.查看更多章节` 匹配失败 | 页面实际是"查看更多章节..."；用 `text.查看更多章节@href` 或模糊匹配 |

## 5. 可复用片段速拷

**封面从书籍 URL 推导**（页面无 img 时）：
```json
"coverUrl": "href##.*\\/([A-Za-z0-9]+)\\/$##/img/$1.jpg"
```

**og:url 正则重组 tocUrl**（og 标签全书籍恒存在时通用）：
```json
"tocUrl": "[property=og:url]@content##/([a-z]+)/$##/index/$1/1/"
```

**搜索前置去限频通式**（替换 LIMIT_KEY 为实际键名）：
```xml
<js>
var U="https://www.site.com/";
var c=String(cookie.getCookie(U)).replace(/LIMIT_KEY=\d+/,"");
cookie.setCookie(U,c);
"/path,{\"method\":\"POST\",\"body\":\"k=\"+encodeURIComponent(key)+\"\"}"
</js>
```

## 6. MCP 调试速查

| 场景 | 手法 |
|---|---|
| 规则手动OK但App失效 | `set_http_log_recording(true)` → 触发请求 → `get_http_log(id)` 看**App实际收到的响应体**（双模板/CDN缓存一锤定音） |
| debug_source 超时 | 含 sleep/重试的长链路改用 `eval_js` 分段模拟；MCP客户端约120s上限 |
| 校验误报失效 | 连续快速请求触发限频所致；先破限频再校验，或以手动单请求为准 |
| 确认API存在性 | eval_js 里 `typeof java.xxx` 先探，再 try-catch 实调 |
| 探测登录校验环节 | 固定session+故意错码，按返回文案区分校验先后 |
| 验证限频是否重置计时 | probe→sleep→probe 对比倒计时读数：递减≈间隔则不重置；不变则每次尝试都重置 |

## 7. 交付检查清单

- [ ] loginUrl 为具名函数集；按钮 action 仅函数调用名
- [ ] `login(b)` 有 undefined 守卫；UI 取值风格统一
- [ ] 成功路径 `source.putLoginHeader(java.getCookie(host))`
- [ ] logout 三清（登录头/Cookie/UI缓存）
- [ ] 验证码方案匹配上下文（对话框内一律 startBrowser+手填）
- [ ] AJAX 头齐全；密码加密已实跑比对
- [ ] 所有 Cookie 写操作均为"取全文→改→回写"
- [ ] tocUrl 在 ruleBookInfo 且无 `||`
- [ ] chapterList 已滤最新倒序区/推荐区
- [ ] content/nextContentUrl 已在**移动 UA 页面**验证
- [ ] respondTime ≥ 实测最长耗时
