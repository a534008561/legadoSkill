# 方法-限速器与测速提速（Legado 书源测速通道设计）

> 蓝本：黄果短剧 v10.1（261031）。用户报障「登录界面测试路线太久」。
> 关联：方法-登录面板E兼容动态线路板-V1数组与reLoginView.md（面板配方）、方法-DNS污染间歇性线路与Web服务字节级直传.md（自愈FIX）

## 1. ConcurrentRateLimiter 机制（LT 源码实锤）

`concurrentRate="1/1500"` = 任意 1500ms 窗口只放行 1 个请求（非并发模式）。`ConcurrentRateLimiter.withLimit` 里：
- 非并发模式（无 `/`）：每个请求等 `concurrentRate.toInt()` ms；
- 并发模式：窗口内第 N 个请求等 `(time+1500)-now` ms。

**后果**：绑定书源环境的 `java.ajaxAll`（内部每条请求都过限速器）被**串行化**，N 条候选纯限速等待 ≈ N×1.5s。60 候选 ≈ 90 秒排队。

**对照实验**（eval_js 绑定本源，concurrentRate=1/1500 生效环境）：
- `ajaxAll(5条,单参)` = **6269ms**（≈5×1.5s 限速排队，理论吻合）
- `ajaxAll(8条,双参skip)` = **500ms**（并发完成）

**注意**：eval_js **不绑定书源**时 source==null ⇒ 限速器直接放行（baidu 4 条 418ms）⇒ **沙盒测速数字完全失真，测限速相关必须绑定书源实测**（eval_js 带 url 参数）。

## 2. 两版 ajaxAll 签名与可用通道

| API | LT 手机 APK（实测） | LT master 源码 | E 版源码 |
|---|---|---|---|
| `ajaxAll(urls)` | ✅ | ✅ | ✅ |
| `ajaxAll(urls, skipRateLimit)` | ✅（老构建保留） | ❌（重构删了） | ✅（JsExtensions.kt:127） |
| `ajaxTestAll(urls,timeout)` | 存在但不可用 | ❌ | 存在但不可用 |

- **`java.ajaxAll(urls, true)`（skipRateLimit）= 两版通吃的跳限速并发通道**（LT 手机构建实测可用）；
- **`ajaxTestAll` 的 isTest=true 硬编码不真发请求**（实测 body 恒 7 字节）⇒ 永远不可用于测速。

## 3. java.ajax 失败行为与判据（本番踩坑）

`java.ajax` 内部 `runCatching{...}.getOrElse{ it.stackTraceStr }` ⇒ **网络失败不抛异常，返回 ~1618B 异常堆栈串当 body**。

⇒ 凡 `length>500` 的探活判据**恒真**（v9.6.1 自愈 FIX 因此失效）。

**判活三判据**（缺一不可）：
1. `code = r.raw().code()`，要求 200-399；
2. `body().length > 20000`（站点首页 ~135KB，favicon 探活端点已废弃——favicon/首页都只回 1618B 堆栈串的教训）；
3. 排除「含 `Exception` 且 <3000B」的堆栈串。

## 4. StrResponse 属性全是方法（raw 也是！）

- `r.raw().code()`、`r.callTime()`、`r.body()` —— **`raw` 也是方法**：`r.raw.code()` 属性访问拿 undefined（判据全错，曾致批量测速 alive=0）；
- 302 终态 URL：`r.raw().toString()` 抠 `url=(\S+?)\}`。

## 5. URL 选项 timeout 的真实语义

`{"timeout":N}`（LT）只映射 **read timeout**（option.getTimeout→readTimeoutMs）；**连接超时独立 ~15s 不可压短**（DNS 假 IP 连接挂 15s）。死线批量探测靠 ajaxAll 并发自然吞掉耗时。

## 6. 测速通道设计定式

```
候选池（健康根域优先 + 老根域殿后）
  → 分批 10 条
  → java.ajaxAll(batch, true)
  → 三判据筛活 + raw().toString() 抠 302 终态 URL
  → 断路器：攒够 N=12 条即停
  → 排序 → hg_sites 存储 → 自动选最快
```

实测：jxqg 19 条全活时 2 批完成，**全活测速 <2s vs 旧版最坏 10 分钟**。

★★**候选池禁止放裸根域**（本次 100s 超时真凶）：`https://jxqgmx5ga.cc/`（无子域）DNS 不解析（gaierror）→ ajaxAll 整批抛异常 → 该批 0 条 → 断路器失效继续跑全部死线批。只放 `https://xxx.根域/` 子域形态。

## 10. v10.5 追加教训（DNS 污染窗口与 IIFE return）

**站点 DNS 污染窗口期三形态**（同 URL 随机返回，10 连抓实测 10/10 normal 说明窗口性）：
1. **正常页** ~200KB（有 `<source>`/`data-track-total-episode`）；
2. **中间形态** ~75KB（有 data-track-title 推荐卡但无 total-episode/无 hg-list-page/无 source）——目录判据若含 data-track-title 会误判可用；
3. **DNS 错误堆栈串** 3236B/2765B（UnknownHostException）——**各分类页拿到的是同一堆栈串 ⇒「各目录返回一样的东西」的真因**。

**ruleContent/ruleToc 重试配方**（最多 3 次）：
- 正文判据 = `<source` 标签命中（覆盖中间形态+错误页两种形态）；
- 目录判据 = `data-track-total-episode` 或 `hg-list-page`（**不能用 data-track-title**——中间形态也有它）；
- 失败时批量探活 8 条健康子域换线 + `hg_line_chk` 置 0；
- **host 替换必须 `.replace(/\/$/,'')`**——line 带尾斜杠 + baseUrl 以 / 开头 ⇒ 双斜杠 `//video/`（部分服务器 404）。

**IIFE 末尾 `got;` ≠ return**：手术替换 `return m?...` → `got;` 时丢了 return 语义 ⇒ AnalyzeRule 拿到 undefined ⇒ ContentEmptyException。**手术式 patch 后必须 App 内 eval 完整规则文本验证返回值**（分段验证每步对 ≠ 整体对——IIFE 返回值只有整体 eval 才暴露）。

**交付记录**：v10.5（md5 fe9d1ee9990a5ab879a46b9801296c1b，dpaste 9GF4WQMA6）debug 全链路 4.6s 全绿 + check_source 1/1。
