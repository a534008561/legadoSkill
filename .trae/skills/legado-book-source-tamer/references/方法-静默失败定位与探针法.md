## 一、什么是"静默失败"

**定义了"报错优先"的排查观**：

Legado 里大部分规则写错**不会报错**，只会**返回空**。所以：

```
"获取成功"     ≠ 规则生效    （可能返回了空字符串）
"书籍总数: 1"  ≠ 站点只有一本 （可能是 bookUrl 取空后全被去重）
"目录获取失败"  ≠ 目录规则错  （可能是上游 bookUrl 错位，压根没打开对的书）
字段显示错位    ≠ 选择器写错  （可能是状态污染）
```

**排查的第一动作永远是：把"我以为产出的值"和"实际产出的值"打出来看。** 四种探针就是为这个服务的。

## 二、13 类静默失效总表

| # | 写法/情形 | 静默表现 | 根因 | 正解 |
|---|---|---|---|---|
| 1 | `(function(){…; 表达式;})()` | 字段空 / "发现规则为空" / 搜索无结果 / 正文"内容为空" | **IIFE 没有 `return`** | 一律写 `return` |
| 2 | `searchUrl` 用整条 `@js:` | "获取成功"日志消失，URL 变 `https://api/...` | 被当相对路径解析 | `{{}}` 模板或 `<js>…</js>` |
| 3 | `ruleExplore.kind` 用 JS 拼接值 | debug 里 kind 空，离线模拟又正常 | `kind` 是唯一走 `getStringList`，尾部 `as? List<String>` 强转 | `kind` 只放纯 `.text()`，文案并入 `intro` |
| 4 | `loginCheckJs` 写 `result.body` | 0 结果 / 诡异 NPE | Rhino 里 Kotlin 属性是**方法引用** | `gv()` 双通道 |
| 5 | `source.get('未设置的键')` 参与 `\|\|` 兜底 | 兜底不生效、拼出空串 | Rhino 的 **JsNull 是 truthy** | `String(v)` 归一化后判三态 |
| 6 | `ruleToc.tocUrl` 写在 `ruleToc` 内 | 永远用"当前页"当目录 | 字段被**反序列化丢弃** | 放进 `ruleBookInfo` |
| 7 | 顶层 `checkKeyWord` | 校验器抓不到关键词 | GSON 丢弃；只读 `ruleSearch.checkKeyWord` | 放 `ruleSearch` 内 |
| 8 | 组合规则 `选择器@html@js:` 里找 `<script>` | `match` 返回 null | 组合通道给的是**净化后**内容 | 改纯 `@js:` |
| 9 | `ruleToc.chapterUrl` 写"选择器@js:" | 规则不执行 | 组合形式不跑（纯 `@js:` 前缀可跑） | 用 `{{}}` 插值 |
| 10 | `jsLib` 里发网络请求 | 该字段静默为空 | 本 App jsLib 作用域 `java.ajax` 非函数、`source` 未定义 | 内联进规则 `@js:`，或参数注入法 |
| 11 | 规则里用 `prevContentUrl`/`:contains()`/`:first-child` | 解析异常或行为异常 | Legado 不支持（技能强约束） | 索引写法 `[0]`/`[-1]`、`##` 正则 |
| 12 | `tag.meta[property=x]@content` | og 标签全空 | `tag.` 前缀走 `getElementsByTag(整串)` | `meta[property=x]@content` |
| 13 | jsoup `absUrl('href')` | 书籍总数 1 | `Jsoup.parse` 无 `baseUri` | `attr('href')` 交给 `isUrl` 拼 |
| 14 | URL 选项写成两个 JSON | `NPE getClass on null` | GSON 解析失败 | 合并成单对象 |
| 15 | 规则字符串里含真实换行 | 规则被截断/解析断裂 | 多层转义 | `fromCharCode(10)` |

## 三、★IIFE 漏 return：一个源同时犯三次

lwenxsw（2026-09-06）在同一次开发里，**同一处错误同时出现在正文、发现、目录三个字段**：

```javascript
// ✗ 静默返回 undefined
@js:(function(){
  var doc = Packages.org.jsoup.Jsoup.parse(String(result));
  var out = [];
  ...
  JSON.stringify(out);        // ← 表达式语句，没有 return
})()

// ✓
@js:(function(){
  ...
  return JSON.stringify(out);
})()
```

**为什么容易犯**：Rhino **脚本顶层**的"最后语句值"确实就是求值结果（`@js:` 直接写表达式能用），于是误以为函数里也一样。**但 `(function(){…})()` 的返回值只由 `return` 决定。**

**三个位置的三种症状**（同一次事故）：

| 字段 | 症状 |
|---|---|
| `ruleContent.content` | `ContentEmptyException: 内容为空` |
| `exploreUrl` | `发现规则为空`（`check_source` 自动在 `bookSourceGroup` 追加 `,发现规则为空`） |
| `ruleSearch.bookList` | **完全静默**：0 结果、无任何报错 ← 最隐蔽 |

**防御**：

1. 构建脚本内置检查——每个 `@js:(function(){` 块，末尾断言存在 `return`；
2. `node --check` 查不出这个（合法语法）→ 用**语义仿真**：`new Function(...,'return eval(code)')` 跑一遍看返回是不是 `undefined`；
3. 写法规约：**能不包 IIFE 就不包**（`@js:` 本身就是表达式位置，直接写语句序列 + 末表达式也能返回值；只有需要 `var` 声明且不污染时才包 IIFE）。

## 四、探针一：微书源 + 废域名看最终 URL

**用途**：一切"URL 到底被求值成什么"的问题（模板被吞、大小写、选项是否生效、`@js:` 是否退化成相对路径）。

```
① 新建微书源，bookSourceUrl = http://probe.invalid      （.invalid 是保留 TLD，必解析失败）
② 把待验的 searchUrl 原样贴进去
③ App 里点搜索
④ MCP get_http_logs → 看那条请求的【最终请求 URL】
```

- DNS 报错本身没有信息量，**error 里回显的 URL 就是"模板求值 + 选项剥离"后的真实产物**；
- mdcmai 的 `{{}}` 域名段被吞、`@js:` 退化成 `https://api/...` 都是这一招一次定位；
- 用完 `delete_sources` 清掉。

**成本**：一个废域名 + 一次搜索。**这是 URL 类问题的首选探针。**

## 五、探针二：eval_js 真机离线复现（最省力）

**这是全套方法论里效率最高的一招**：在真实 Rhino + jsoup 环境里，喂真实 HTML，直接跑规则文本，**一次跑多页多样本**，比"改规则→save_source→debug_source"快一个数量级，且**不消耗站点配额**。

```javascript
// 通用夹具（zhaoshu 定型）
function ev(rule, res, burl) {
  var result = res, baseUrl = burl;
  return (rule.indexOf('@js:') === 0)
    ? eval(rule.substring(4))
    : eval(rule);                       // 非 @js 规则交给真实 AnalyzeRule 更准（见下）
}

// 1) 取 App 里真实的规则文本
var r = source.getContentRule();
var rule = (typeof r.content === 'function') ? r.content() : r.content;

// 2) 取真实页面（手机侧网络，判定被墙问题的唯一可信来源）
var html = String(java.ajax('https://site/read/1.html'));

// 3) 跑
java.log(String(ev(rule, html, 'https://site/read/1.html')).substring(0, 400));
```

**真 AnalyzeRule 模拟**（测 CSS/XPath，可复现污染）：

```javascript
var AR = Packages.io.legado.app.model.analyzeRule.AnalyzeRule;
var ar = new AR(); ar.setContent(html);
ar.getString('规则');                       // 注意：@js: 前缀在其中不走 @js 通道
// 列表级：getElements + 逐条 getString，完整复现 BookList.getSearchItem
```

**规则 API 名（本 App）**：`source.getTocRule()`（**不是** `getRuleToc()`）、`getBookInfoRule()`、`getContentRule()`、`getSearchRule()`、`getExploreRule()`。

**⚠️ 两个必知的失真**：

1. `eval_js` 独立环境的 `java`/`source` 能力**与规则上下文不同**（`typeof` 探测为 undefined ≠ 规则里不能用）；
2. **改了规则必须先 `save_source` 再 `eval_js` 测**，否则测的是 App 里的旧版规则（novelServices 那次专门翻在这里）；
3. `eval(js)` 在函数作用域内声明的 `function` **不外泄** → 把 `js + '\n' + 测试代码` 合成一段一起 eval；
4. 重新声明同名函数**不能覆盖** SharedJsScope 里已加载的 jsLib 旧绑定（hanime1 实测）→ 改 jsLib 后必须先导入再测。

## 六、探针三：最小对照源（改前/改后同跑）

**用途**：验证"某个写法到底行不行"，且不污染正式源。

```
① 复制正式源 → 改名 __diag_xxx（bookSourceUrl 加后缀区分，避免 REPLACE 覆盖正本）
② 只改一个字段（如给疑似漏 return 的 IIFE 补上 return）
③ debug_source 跑同一 key
④ 两版结果对比 → 一步确认根因
⑤ delete_sources 清掉 __diag
```

lwenxsw 的 IIFE 诊断就是这么做的（memory 里明确写了这条方法论）。

**变体：微型测试源验站点行为**（rrssk 7shuw 用 `__s7test` 验 `::list-8/`）——比翻整个聚合源快得多。**⚠️ 别忘了带移动 UA header，否则吃 GoEdge WAF；验完删。**

## 七、探针四：破坏性单变量矩阵

**用途**：定位"到底哪个变量在起作用"——鉴权参数、必需 header、必需字段、编码。

```
固定其他项，每次只破坏一项，观察响应是否变化。
每项至少两个反例（改了变 / 改了不变），才构成证据。
```

两个实战范例：

| 站 | 疑点 | 实验 | 结论 |
|---|---|---|---|
| wendulou | `sign`/`pt`/`time`/`package`/UA 哪个要算 | `sign=deadbeef` | **照常返回数据 → 签名完全不校验**；删 UA 尾部 `_{package}` → `books=0` ⇒ 真鉴权在 UA |
| mdcmai | `POST` 变量矩阵 | `fromLang` × `origin` × `IID` 全组合（400/200 表） | 定位到"`fromLang` 必须显式 ja/en，auto 与空都 400" |

pixiv 翻译篇的同类经验："先单测 `bingCred` 再矩阵测 POST 变量定位 400 根因"。

**⚠️ 注意副作用**：实验本身会改变环境状态（米游社清域删掉配对必需键；限频站越试越久）。**先想清楚可逆性，并留回退备份。**

## 八、Rhino/jsoup 语法类静默坑合集

| 写法 | 症状 | 正解 |
|---|---|---|
| `elements.remove().end()` 链式 | `找不到函数 end`（HtmlUnit Rhino） | 显式循环 `for(i) bs.get(i).remove()` |
| `.text().replace(/a/g,'b')` | `选择不明确 char,char / CharSequence,CharSequence` | 先 `String(...)` 包一层（`trim()`、`indexOf(String)` 不受影响） |
| 规则里 `'\n'`（多层转义） | 变成真实换行 → 规则断裂 | `String.fromCharCode(10)` + split/join |
| 反引号模板串 | QuickJS 不支持；某些版本报语法错 | 统一单引号拼接 |
| `java.sleep(1000)` | 找不到方法 | `Packages.java.lang.Thread.sleep(1000)` |
| HTML 属性无引号值带空格 | 属性值提前结束（`padding:9px 26px`） | 改单值 / `style=width:100%` 合法 |
| 正则 `^(https?:[^/]+)` 取 origin | **恒 null**（`https:` 后紧跟 `//`） | `url.split('/')` 取 `ps[0..2]` |
| `<img src=xxx>` 无引号 | 图片不显示 | 官方 `imgPattern` 要双引号 → `fromCharCode(34)` |
| `@css:` 写在 `\|\|` 段内 | 整条规则失效 | 拆开写 |
| 顶层 `return`（`loginCheckJs`/定时任务 script） | "返回的值无效" / 不执行 | IIFE 包裹 / 去掉顶层 return |

## 十、定位流程（症状 → 探针）

```
症状：某字段为空
 ├─ 是列表字段（name/bookUrl/…）？
 │    ├─ 单条测对、连调错 ─────────► ★状态污染 → 探针二(真 AnalyzeRule 同实例连调) → 换通道
 │    └─ 单条测就错 ───────────────► 规则写错 → 探针二(@js 夹具)逐步打印中间值
 ├─ 是 @js 块？ ──────────────────► ★先查 IIFE 有没有 return → 探针三(最小对照源)
 ├─ 是 URL/参数不对？ ─────────────► 探针一(微书源+废域名看 HTTP 日志)
 ├─ 整源"能保存但不能用"？ ────────► 探针：字段 md5 回读（交付闭环第八节）
 ├─ 鉴权/参数不知道哪个必填？ ─────► 探针四(破坏性矩阵)
 ├─ 报"内容为空/规则为空" ─────────► 依次：save 是否覆盖、规则 API 名、IIFE return、上游 URL 错位
 └─ 只在别人手机上坏 ─────────────► 版本差异篇（列表返回值协议 / 属性 vs 方法）
```

**贯穿原则**：

> **不要推理，要打印。** 每一次"我觉得这里应该是 X"，都用一次 `java.log` 或一条探针变成"我看到这里是 Y"。

## 十一、避坑清单

| # | 坑 | 对策 |
|---|---|---|
| 1 | 用"有没有报错"判断规则是否生效 | Legado 大部分错是静默返回空 |
| 2 | IIFE 末表达式当返回值 | 一律 `return`；构建脚本断言 |
| 3 | 拿 `eval_js` 的探测结论定义规则上下文能力 | API 存在性必须在真实上下文实测（ppxsw 误判案） |
| 4 | 改规则不 `save_source` 就 eval_js | 测的是旧规则 |
| 5 | 在函数作用域 eval 后调用其中声明的函数 | 拼成一段一起 eval |
| 6 | 重声明同名函数覆盖 jsLib | SharedJsScope 旧绑定还在，先导入再测 |
| 7 | `getRuleToc()` | 本 App 是 `getTocRule()` |
| 8 | 探针实验不可逆（清域/改 Cookie/高频撞） | 留备份、意识到自己也是变量 |
| 9 | 微型源不带站点必需 header | 吃 WAF 误判成"写法不行" |
| 10 | 诊断源/测试源忘记删 | 交付前 `list_sources` 扫一遍 `__`/`probe` |
| 11 | 用 `check_source` 结论覆盖 debug | 聚合源/CF 站误报 |
| 12 | 用官方源码结论覆盖实测 | 版本行为差异大；跨版本要双测 |
| 13 | 比字符串长度判一致 | 编码维度不同，只比 UTF-8 md5 |
| 14 | 一次 debug 连打多页 | 触发频控/挑战，把自己打进冷却 |
