# 方法-小说漫画视频三合一书源详解

> 蓝本：🎨🔞禁漫天堂Pro（bookSourceUrl=https://jmcomicui.net，2026-09-24 v1~v14 迭代全记录）
> 一句话：**一个书源同时承载 小说/漫画/视频 三种内容形态**——站点有现成多内容类型、且列表/详情/正文结构可归纳为少量分支时，用「模式变量 + 字段整体分发 + 统一解析器 + 按类型分支」四招做成三合一书源。
> 姊妹篇：想要"同一本书换数据来源"看《方法-APP接口聚合书源拆解》；想要"同站换接入线路"看《方法-发布页线路轮换与登录界面测速选线》；想要"更激进的内容形态切换（6形态+内联播放页）"看《方法-单源多模式切换书源制作》。

## 0. 适用场景识别

先问三个问题再决定做不做三合一：

1. **站点是否真的多形态**：有 /albums（漫画）+ /novels（小说）+ /videos（视频）三类列表、三类详情、三类正文内容结构。
2. **三类之间是否有大量公共代码**：列表拖卡容器 class 基本一致（`.list-col/.list-item`）、详情 meta 结构同构（og/title/img）、搜索接口同形（`/search/{photos|novels|videos}`）。
3. **一次登录是否覆盖三类**：同域同 Cookie（禁漫一个账号管漫画收藏夹+小说书架）。

满足 1+2 则三合一收益 > 三个独立源的维护成本；只满足 1 则老实拆三个源。

**禁漫三形态速查**：

| 形态 | 列表页 | 详情 | 目录 | 正文 | book.type |
|---|---|---|---|---|---|
| 漫画 | `/albums`、分类、榜单、周更 | `/album/{id}/` | 详情页=1章「开始阅读」 | 图片集 `<img>`（仅正文图 `/media/photos/{id}/`） | `64`(image) |
| 小说 | `/novels?o={sort}`（仅74本，服务端不分页） | `/novel/{id}/` | 详情页内 `a[href*=novelchapters]` 多章 | `div.novel-content[id^=ncc]` 多段文本拼接 | `8`(text) |
| 视频 | `/videos`、`/videos_cosav`(COS片) | `/video/{id}/`、`/video_cosav/{id}/` | 1章=视频本身 | m3u8 直链文本 | `4`(video) |

## 1. 全局架构：四招总纲

```
                ┌────────────────── 书源入口 ──────────────────┐
  发现页 jmode下拉 ──► 模式变量 mode ∈{漫画,小说,视频}（infoMap+source变量双写）
                │                                              │
  exploreUrl  = @js: jmExplore()     按 mode 生成整套按钮列表
  searchUrl   = @js: jmSearchUrl()   #前缀=小说 !前缀=视频  其余=漫画
  ruleBookInfo.init = @js: jmDetailInit()  按 URL 特征三分支 → 统一 JSON
  ruleToc.chapterList = @js: jmChapters()  按 URL 特征三分支 + 动态 book.type
  ruleContent = @js: jmContent()    视频=m3u8 / 小说=文本 / 漫画=<img>串
  ruleSearch/ruleExplore.bookList = @js: jmParseList()  (同一解析器吃全部列表页)
```

**四招**：

1. **模式变量**驱动发现页入口集合（`jmode` select，写变量 + 刷新发现）。
2. **字段整体分发**：exploreUrl/searchUrl/init/toc/content 五个字段全是 `@js:` 函数，函数内部按模式分支——不是写三套规则互相打架，而是一套代码一个 switch。
3. **统一解析器 jmParseList()**：无论搜索/发现/收藏夹/周榜，都输出 `[{name,author,kind,coverUrl,bookUrl,wordCount,intro,id}]` 的 JSON 字符串数组，字段规则全用 `$.xx` 纯键 JSONPath（LegadoTeam 与 legado-E **双版本通用**，避开 E 版 getString 无 Mode.Js 分支的坑，见《方法-legado各版本行为差异对照》）。
4. **按类型分支**：目录/正文只按 **URL 路径特征**（`/novel//photo/、/video/`）判断，不依赖任何全局状态——书架老书换线路后照样正确取分支。

要点：

- 下拉控件放在 `infoMap`（`title/type/chars/action` 由发现页顶栏原生渲染）；`jmExploreAction()` 里 `infoMap.save()`（发现页 select 的当前值回写）+ `java.refreshExplore()`。
- `jmExplore()` 按 `MODE()` 三分支各 `push(title,url,size)` 一组按钮：标题占整行用 `layout_flexBasisPercent:1` + `wrapBefore`，标签按钮 0.14~0.2 多列。url 里 `{{page}}` 留给 AnalyzeUrl 二次求值。
- 模式变量读写走**双通道**：`try{getVariable()}catch{e}{get()}` + 读后 `String(x)` 判 `null/undefined/''` 三态（HtmlUnit Rhino 的 Java 空串是 truthy，不归一化必翻车；详见《方法-聚合源状态漂移修复与选站面板-rrssk》四铁律）。
- 切换模式后**发现页缓存不会自动换**：靠 select 的 action 里 `java.refreshExplore()`（或 `source.refreshExplore()`）清两级缓存重求 exploreUrl。

> 与"单源多形态（X夜社）"的区别：X夜社用登录界面按钮 set_laiyuan() 切换且一个源扛**六**形态；禁漫只三形态、用发现页下拉。选型：形态≤3 且都是站内常用入口 → 发现页下拉体验最好；形态多或用户按书切换 → 登录界面按钮 + 书源全局变量。

## 4. 统一列表解析器 jmParseList()

```js
function jmParseList(html){
  var host=BASEH();
  var doc=Packages.org.jsoup.Jsoup.parse(String(result===undefined?html:result)); // result Element/字符串双兼容
  var cells=doc.select('.list-col');
  if(cells.size()===0){cells=doc.select('.list-item');}  // 周更/收藏夹等页换容器
  var out=[];
  for(var i=0;i<cells.size();i++){
    var c=cells.get(i);
    var a=c.selectFirst('a[href^="/album/"],a[href^="/novel/"],a[href^="/video/"],a[href^="/video_cosav/"]');
    if(!a)continue;
    var href=String(a.attr('href')).split('?')[0].split('#')[0];
    var m=href.match(/\/(album|novel|video|video_cosav)\/(\d+)/);
    if(!m)continue;
    // name: .video-title > img[title/alt] > a[title]
    // cover: jmAttr(img,['data-original','src'])   ← 懒加载, ★必须显式判空
    // author: 特征行提取(见 §4.2)
    // kind: .label-category 兜底 .video-keywords
    // wordCount: [id*=likes]
    out.push(String(JSON.stringify({name,author,kind,coverUrl,bookUrl:'https://'+host+href,wordCount,intro,id})));
  }
  return out;  // ★必须 return JS 数组(不是 JSON 字符串)——LT 版 getElements 只吃 List/Array
}
```

铁律：

- **列表输出协议**：LegadoTeam 版 `getElements` 只接受 List/Array/NativeArray——`return out;`（JS 数组）。若为兼容 legado-E（其 getString 对 NativeObject 无 Mode.Js 分支），则**逐条目** `String(JSON.stringify(item))` 转 JSON 字符串再 push。二选一按分发对象定；字段规则统一 `$.name/$.author/...` 纯键 JSONPath 两版都走 Mode.Json 直取。
- **bookUrlPattern 绝不能匹配搜索/发现 url**：`BookList.kt:62` 若 baseUrl 命中 pattern 会当详情页解析，列表直接废。本站 pattern=`https?://[^/]+/(album|photo|novel|novelchapters|video|video_cosav)/\d+[^,]*`（`[^/]` 替代 `\.` 实现零反斜杠，防 JSON 转义层事故）。
- 新类型入口（COS片）要**四处同接**：parser 白名单、详情 init 分支、目录分支、bookUrlPattern——漏一处就是"入口能进、列表空/详情错"。

### 4.2 ★作者等附属字段：宁缺毋滥 + 特征行定位

多模板站（分类页/周榜/连载/收藏夹/搜索页各一套 DOM）的 author 提取：

```js
// 作者行特征: 行内含作者搜索链接 main_tag=2, 或行文本以"作者:"开头
var auRows=c.select('div.title-truncate, p.title-truncate');
for(var ai=0;ai<auRows.size();ai++){
  var elA=auRows.get(ai); var ling=elA.select('a'); var hits=0;
  for(var a2=0;a2<ling.size();a2++){var h2=String(ling.get(a2).attr('href')||'');if(h2.indexOf('main_tag=2')>=0)hits++;}
  var tA=String(elA.text()).replace(/[\s\u00a0]+/g,' ').trim();
  if(hits>0||/^作者[:：]/.test(tA)){
    var names=[];
    for(var a3=0;a3<ling.size();a3++){var nn=String(ling.get(a3).text()).trim();if(nn&&names.indexOf(nn)<0)names.push(nn);}
```

**无误则空，绝不用书名/其它行凑数**（周更/收藏夹页根本没有作者行，fallback 到书名就是著名的"作者显示错误"）。本项目实测五模板：分类页=多作者 join、每周必看=带"作者:"前缀行、连载/收藏夹=空、搜索页=main_tag=2 行。

## 6. 目录 + 正文：按类型分支

### 6.1 目录 jmChapters()

- `/video/` → `book.type=4;` 返回单章{text:视频名,url:baseUrl}（本体即媒体）。
- `/novel/` → `book.type=8;` 从详情页抓 `a[href^="/novelchapters/"]` 多章（站内小说全量内联，无分页）。
- 其它相册 → `book.type=64;` 系列书用 `a[data-index][href*=/album/]`（带真实序号），单行本兜底 `a.reading` → `a[href*=photo]` → `/photo/{albumId}`。

**★book.type 必须在 ruleToc.chapterList 里动态设置**：`WebBook.getChapterListAwait` 每次刷目录都会 `removeAllBookType()+addType(bookSource.getBookType())` 把 detail init 里设的 type 冲掉；type 位掩码 video=4/text=8/audio=32/image=64（BookType.kt 源码，0/1/2 无效旧值）。

## 7. 收藏体系（登录态业务完整闭环）

### 7.1 数据流

```
登录界面(loginUrl 函数集 + loginUi V1按钮组)
  ├─ 🔐登录(账号/密码 POST /auth/login)      → jmuser 变量 + Cookie(putLoginHeader)
  ├─ ❄️解冻账号(站点冻结风控, 输入验证码 POST)   → X-Requested-With+Referer 必带
  ├─ 📂选择收藏夹(GET /user/{u}/folders)      → jmFoldersRaw + source.put('jmfid')
  ├─ 🚀测速选线(发布页→线路池→逐域测速→存 url 变量)
  └─ 🖼 CDN切换(cdn-msp/2/3 + 测速)
详情页 useweb 面板(内联页面<script>, 走官方注入桥)
  ├─ 首屏: jmfav_缓存→fas判定 → ❤️已收藏/🤍未收藏/🔒未登录 三态
  ├─ 点击: java.post(/ajax/favorite_album) → 状态行+按钮切换+longToast
  └─ 取消: java.post(/ajax/remove_album_playlist) video_id={aid}&list=favorites
```

### 7.2 ★收藏态判定与自我修复

- 服务端详情页 `#album_favorite_{id}` 内层 `<i class="fas/far fa-bookmark">`：实心=已收藏、空心=未收藏（`btn-primary` 是恒定类名**不可当判据**，经典反例）。
- **本地缓存兜底**：收藏成功 `source.put('jmfav_'+aid,'1')`、取消写 `'0'`；init 判据**缓存优先**（`'1'→true / '0'→false / 无缓存→fas`）。根治"收藏后关详情再开又显示未收藏"（站点只给默认夹亮星，收藏到其它夹时重开误判）。
- **重复收藏=站点返回 HTML alert 非 JSON**：加清洗函数 + 关键词判定「重复/重複/已收藏/收藏過」→ **当成已收藏处理**：状态行"❤️ 已收藏: 本书已在收藏夹中(无需重复收藏)"+按钮切取消+toast。错误讯息本身即真相——重复收藏报错是"该书已收藏"的最强证据，顺势修正 UI 而非显示错误。
- 收藏夹列表为空时明确提示"未获取到收藏夹列表, 请检查登录状态"。

### 7.3 useweb 面板按钮的正确通道（页面里调 Rhino 函数=静默死路）

按钮 onclick 只能执行**页面内联脚本**；书源 jsLib（Rhino 函数）不会进页面，直接 `onclick="jmfs(...)"` 是 `ReferenceError` 零反应（用户体感"点了不知状态"的最大元凶）。正确姿势（源码级）：

- 官网 onPageStarted 自动注入 `try{var java=<随机名>,source=<随机名>,cache=<随机名>}catch(e){}` → 页面里全局 `java/source` 可用。
- 同步桥（@JavascriptInterface）签名：`java.post(url, body, headerJson, timeout)→String body`、`java.get→body`、`java.head→GSON`、`java.toast/longToast`；`source.put/get(k,v)`。
- `JS_INJECTION`（postAwait 等 Promise 桥）只注入 RSS 订阅源正文，**useweb 没有**；`java.request('run')` activity=null 静默失败；页面 fetch 没有 Legado Cookie（必须走 java.post）。
- 完整机制见《方法-简介useweb内嵌页面与浏览器调起》§增补1（含双层转义铁律：页面 V8 双引号串内嵌引号 `\"` → loginUrl 单引号串要 `\\"` → python 三引号要 `\\\\"`；排查只看 hex 字节，工具输出带 JSON 转义显示层肉眼数反斜杠必误导）。

## 8. 发现页扩充的老实人方法论：数据化标签，不编造

需求"扩充热门标签"的诚实做法：

1. **拉一个搜索结果页**（`/search/photos?search_query=巨乳`，单页含 200+ 作品卡片）。
2. **汇总频次**：解析页面所有 `a[href*="search_query="]`，按 text 计数——高频者即站点真实热门标签（不依赖动态"热门关键字"热词、不凭记忆编）。
3. **过滤**：剔除女性向（女性向/百合/BL/純愛/女性支配）与敏感词、超长用户梗；保留筒体站点标签。
4. 新类型入口加之前**先验证列表解析器兼容**（拉入口页看容器 class 与卡片 href 前缀，如 COS片 `/video_cosav/{id}/` 要补进白名单）。

## 9. 避坑清单（按踩坑顺序）

- K1 **challenge 词误报**：站点页面恒定包含 `challenge-platform` 等词，loginCheckJs 判 CF 挑战只能用 `Just a moment / verify.php / Attention Required / cf-chl` 白名单词。
- K2 **解冻接口必带 X-Requested-With: XMLHttpRequest + Referer**，否则"非法访问"；验证码 POST 是站点风控解冻通道（个位成功率是常态）。
- K3 **列表容器双模板**：`.list-col` 为主、`.list-item` 兜底；两者并存页先取前者（防重复条目）。
- K4 **详情 faved 判据**：内层 `<i>` fas 实心=已收藏 / far 空心=未收藏；`btn-primary` 恒定类不可当判据。
- K5 **作者字段宁缺毋滥**（§4.2）：无作者行=空，绝不回退书名。
- K6 **attr||attr 短路失效**：Java 空串 truthy → 必须 `jmAttr(el,[keys])` 显式判空（收藏夹封面恒空、懒加载图取不到 src 全是它）。
- K7 **book.type 在 chapterList 里设**：详情 init 设的会被刷目录 removeAllBookType 冲掉。
- K8 **kind 芯片头部=作者**：唯一零成本的"点作者本源搜索"通道；面板内无其它通道。
- K9 **重复收藏报错=已收藏**：识别关键词顺势修 UI，别当错误透传（HTML alert 先清洗再判定）。
- K10 **作者芯片与标签混列**：kind 逗号分隔=芯片分隔，多作者会自动变成多芯片（点击搜单个作者，可接受）。
- K11 **双层转义铁律**（§7.3）：`\"`在多语言字符串层各自为政，只信 hex。
- K12 **搜索前缀丑但有效**：`#小说 !视频` 零 UI 成本，写进 bookSourceComment。
- K13 **发现页新入口先验 DOM 再上**：入口 URL 有效≠解析器能吃（博客区 `.list-col` 为 0 的不上）。
- K14 **零双引号零反斜杠纪律**：JS 全用 `String.fromCharCode(34)` 生成引号、`[.]`/`[0-9]` 替代 `\.`/`\d`，杜绝 MCP/dpaste 多层传输转义事故。

## 10. 验证方法论（本项目的验收习惯）

1. **node 离线仿真**（jsLib/loginUrl 抽出来 stub source/java/infoMap 跑通各函数）：五页卡 fixture 断言 author/name/cover；三态面板断言状态行/按钮/提示词；六场景收藏流（重复HTML/重复JSON/成功/取消/普通失败/未登录）。
2. **App 内 eval_js（真 Rhino+真 jsoup）**复跑上一步 fixture（node 与 App 的 Rhino 行为确有差异，如 Java 空串 truthy）。
3. **check_source 1/1**（每次 save 后必跑）；checkKeyWord 选"第一本详情就能解析"的词。
4. **debug_source 全链路**：关键词=搜索流；`::URL`=发现页；绝对 URL=详情；多入口逐个 `::` 打。
5. **真机人工验收清单**：useweb 按钮点击（WebView 渲染层只能肉眼看）/ 分类②收藏→退出→重开→再点（缓存闭环）/ 点作者芯片跳搜索 / 视频页 m3u8 起播 / 书店老书兑换线路后正文仍可用。
6. 40KB+ 源一律 **dpaste+深链导入**（save_source 内联上限 ~19KB），硬证据=get_http_logs 出现 `GET <raw> -> 200`，导入版本靠回读特征串（如新函数名）确认。
