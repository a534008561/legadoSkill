## 五轮报障与修复

1. **加载正文失败**：站点 261107 改版，`document.write(strencode2('…'))` → HTML 注释内
   `var vbF0=strencode2("…")` + `POST /vlk.php` 指纹换链。旧内层正则失配输出空；
   旧规则 `replace(/&f=[^&]*/,'')` 还会误删防盗链签名（带 → 200 video/mp4 7MB，去掉 → 302 html）。
   ⇒ 只重编码三层 Base64 的**内层第 2 段**，三级兜底 + 保留 `&f=`。
2. **换路线有些地方没跟着换**：`ruleLink=a@href` 抓到页面写死的绝对 URL；
   ★★★ `jsLib` 共享 scope 绑定隔离（`SharedJsScope.getScope(jsLib)` 密封 scope，
   `AnalyzeUrl.evalJS` 的 source/cache/java/baseUrl 对 jsLib 函数体不可见）⇒ 面板
   `source.put('pnLine')` 的值 `PN_base()` 读不到。唯一可靠通道 =
   **`this.source.getVariable()/setVariable()`**（`sourceVariable_<sourceUrl>` 两环境同 key）。
   ⇒ 面板双写 + `PN_base()` 四级兜底 + `ruleLink @js` 同源重写 + 「📍 当前线路」动态 label。
3. **E 版正文链接还是 418**：E 版 LAN 1125 / WS 1126 有 3 个同名 91PORN；
   诊断桩证明 `variable.pnLine=a.26702.app`、文章链接跟随、`418.sol148.com` 是活线路。
4. **内容页 `≡获取成功:418` 质疑**：WS「实际响应水印」正反两组对照
   （站点正文页自带 `var baseurl='当前域/'`），A 组 app 线路水印 `https://a.26702.app/`、
   B 组强制 418 水印 `https://418.sol148.com/`，两组列表域/文章链接域/直链都跟随，
   唯内容页日志恒定。用户选 **A 保持现状**（不换 sourceUrl，避免 `RssArticle` 主键
   `(origin,link,sort)` 漂移）。
5. **★★ 版本差异纠正**：用户实测「team 里内容页日志变了、E 版没变」是对的。
   **仅 legado-E** 的 `Rss.getContentAwait` 正文日志写死打印 `rssSource.sourceUrl`；
   LT team 官版当前 master 已重构为 `getResponse(url,printLog)` 委托并打印
   `analyzeUrl.ruleUrl` 真实 URL。此前拿本地缓存源码误判「两版共有」，已全部改正。
