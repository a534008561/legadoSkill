## 二、三条硬规则（照抄即错）

### 1. `bookUrl` 必须自拼绝对 URL

源码 `BookList.getSearchItem` 里 `getString(ruleBookUrl, isUrl=true)` 会用 **`baseUrl`（当前列表页）** 解析相对路径。

`/ranks/hot/` 页的 `/video/323/` 会被拼成 `/ranks/hot/video/323/` → **404**。

```js
var root = String(source.get('hg_line')||'');
if(!root||root.indexOf('http')!==0){ root = String(source.getBookSourceUrl()); }
root = root.split(String.fromCharCode(35,35))[0];   // ★ 见下条
root = root.replace(/\/$/,'');
var mv = h.match(/href="(\/video\/\d+\/)"/);
if(mv) return root + mv[1];
```

### 2. 传输层会吃掉 `##`

书源 JSON 里写 `split('##')` → 传到 App 后变成 `split('#')` → 报「字符串文字没有限制」。

⇒ 必须用 `String.fromCharCode(35,35)` 构造双井号。

### 3. 多选 `bookList` 后字段级选择器不按索引对应

```css
bookList = .a, .b, .c
name = .a__title, .b__title      /* ← 返回空字符串 / 书籍总数 0 */
```

实测多选后 `name` 返回空。**根因**：多选择器的元素集合与字段选择器不按索引对应。

⇒ **所有字段必须统一 `@js:` 自解析**，按结构用各自锚点：

```js
// video: data-track-title / data-track-id / data-track-type-name / data-src
// rank:  .hg-rank-item__title / __tags / __desc
// topic: .hg-topic-card__title / __meta span，bookUrl → /topics/xxx/
```

## 四、封面修复（★★★ 三个叠加坑）

### 坑 1：`coverDecodeJs` 返回值必须是 Java `byte[]`

源码 `RhinoScriptEngine.kt:235` `unwrapReturnValue` **只 unwrap `Wrapper`**：

| JS 写法 | Rhino 类型 | `as ByteArray` | 结果 |
| --- | --- | --- | --- |
| `Packages.java.util.Arrays.copyOf(bytes, n)` | `NativeJavaArray`（**是 Wrapper**） | ✅ | 成功 |
| JS 数组字面量 `[b0,b1,...]` | `NativeArray`（**非 Wrapper**） | ❌ 强转失败 | `runCatching` **静默吞掉** → `onStreamReady(null)` |

⇒ 静默失败 → Glide `failUrl` 拉黑该 URL → 「封面二次解密失败」。

```js
// ✓ 正确
var out = Packages.java.util.Arrays.copyOf(bytes, bytes.length);
// ✗ 错误：JS 数组字面量
```

### 坑 2：Glide 丢弃 `dnsIp`

封面走 Glide `OkHttpStreamFetcher` → `AnalyzeUrl.getGlideUrl()`，**只保留 `url` + `headerMap`，丢弃 `dnsIp`**；
正文走 `getByteArrayAwait()`，`dnsIp` 完整生效。

⇒ 「正文能显示但封面全灰」的通用根因。

**解法**：`http://<CF-IP><path>` + `{"headers":{"Host":"域名"}}`
（Host 头在 OkHttp `BridgeInterceptor` 只在缺失时补 ⇒ 保留）。

**通用结论：只要图片可能走 Glide（封面/漫画浏览/预览），URL 就必须自带 IP+Host 头，不能依赖 `dnsIp` 选项。**

⚠️ **禁止在 `<img src>` 外层再套 `dnsIp`**（双层选项 ⇒ UrlOption 解析失败 ⇒ 回退裸 URL ⇒ 又超时）。

### 坑 3：三层缓存

1. **Glide 密文缓存**（磁盘）→ 改 URL 加 `&hgimgv=2` 换 cache key
2. **Glide `failUrl` 黑名单**（**进程级**）→ 改完必须**重启 App**
3. **正文缓存** → 正文图 URL 含选项串 ⇒ `MD5(src)` 变化 ⇒ **旧书须删书重加或清正文缓存**

### 判据：沙盒直连 ≠ 真机 Glide

用 LAN `/cover` 端点或 `eval_js + java.ajax` 实测。
`/cover` 返回 **PNG**（不能用 JPEG 魔数判）。
正确做法 = 先取必然失败 URL 作「占位图基准」比 md5。

## 八、E 版（legado-E）兼容改造（v9.4）

用户报「E 版目录加载失败」⇒ 源码级定位到**头号杀手**：

```kotlin
// LT 版 AnalyzeRule.getElements 末尾 —— 有显式分支
is NativeArray -> { val values = ArrayList<Any>(...); return values }

// E 版 AnalyzeRule.getElements 末尾 —— 直接强转
result?.let { return it as List<Any> }
```

Rhino `NativeArray` 不是 `java.util.List` ⇒ E 版 ClassCastException。
**症状指纹**：搜索/详情/发现全正常，**唯独目录失败**（只有目录走 `getElements`）。

### 修法

```js
// ❌ JS 数组 → E 版 CCE
var list=[]; list.push(x); return list;

// ✅ java.util.List → 两版都通
var list=new Packages.java.util.ArrayList();
list.add(x);   // ★ Java List 用 add 不是 push
return list;
```
