## 三、典型案例

### 案例1：图标字体反爬（漏字）
- URL: https://www.kelexs.com/book/H0G0FK-1393.html
- 症状: 正文 48 处 `<i class="icon icon-uniEXXX"></i>`，抓取后缺字
- 验证: 解码后 48/48 还原，与网页逐字一致
- 方案: 见《02-图标字体反爬破解》

### 案例2：密钥 JS 不在首位
- URL: https://www.x630xsw.com/book/5B6BB.html
- 页面 JS 顺序: addons.js(无密钥) → ... → P2eLpItHT9sN7DemGZtMHuxrKWTjl5xA.js(有密钥)
- 固定取首个 → 密钥提取失败 → 目录接口 404/报错
- 方案: 遍历所有 /templates/js/*.js 直到 /AESCrypt\('/ 命中

### 案例3：POST 被 GOEDGE WAF 拦截
- URL: https://www.x630xsw.com/index.php?action=loadChapterPage
- 症状: GET 一切正常，POST 返回 `Verify Yourself` 页
- 请求头对比: 失败=无Referer；成功=Referer+Origin+X-Requested-With
- 方案: 见《04-GOEDGE-WAF应对策略》

### 案例4：SEO URL 与真实 id 不一致
- URL: https://www.dadawx.com/book/eftdep.html（搜索结果给的地址）
- 章节地址: /book/eft-1.html；目录接口 id: eft
- og:url 提取: `content=".../book/eft.html"` → bookId=eft ✓
- 教训: bookId 必须取 og:url，不能从地址栏正则

### 案例5：WAF 触发 UA 指纹
- https://www.boluomao1.com 首页
- Windows UA → 302 `/WAF/VERIFY/CAPTCHA?info=...`（172字节跳转页）
- 移动端 UA → 200 正常首页（89909字节）
- 教训: 书源 header 与 JS 内 java.get 的 headers 都要用移动端 UA

### 案例6：发现页分支泄漏
- 症状: 选菠萝猫域名，发现页 72 条（34 BM + 31 rrssk原分类 + 控件）
- 原因: BM 分支只 `JSON.stringify(res)` 未中断，脚本继续执行原分类段
- 修复失败方案: 顶层 `return` → `返回的值无效`
- 修复成功方案: if/else 完全隔离
- 修复后: boluomao1=39条(34分类+5控件)，kelexs=36条(31分类+5控件)
