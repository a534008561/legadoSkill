## 一、字体反爬的三种形态与判别

拿到正文/标题"是中文但读不通"，先分类型：

| 形态 | 特征 | 判别 | 对策 |
|---|---|---|---|
| **A. 图标字体 PUA** | 正文正常，只在**少量位置**插入 `<i class="icon icon-uniE600">` 之类，码点落在 U+E000–U+F8FF 私有区 | 正则扫 `[⺀-鿿]` 之外的非常规区段；看有没有 `@font-face` + `editor.css`/`fonteditor` 字样 | 建 PUA→数字 的固定映射（同族站共用一张表） |
| **B. 会话置换全文混淆** | 整篇汉字都是"读不通的常用汉字"；每会话/每章下发 `woff2`；站点 JS 里有 `reader_guard_id`、`font-g2` 之类 | 同一本书换 Cookie 后乱码字集变化；把 `woff2` 用 fontTools 打开看 `cmap` 是否把常用汉字映到怪字形 | **本篇主角**：固定 Cookie → 离线建全量置换表 |
| **C. 加密而非混淆** | 正文是 base64/LZString/AES 密文 | 长度、字符集（`A-Za-z0-9+/=`）、JS 里有 `_keyStr`/`LZString`/`AESCrypt` | 见[加密解密篇](方法-加密解密.md)，别拿字体方案硬凑 |

**B 的识别铁证**：拿一段"乱码"和真实语义比对——若乱码字符全是**高频常用汉字**且**同一乱码字在全文中总代表同一真字**，就是置换表型（字体只是显示层还原）。aaawz 的样本：`第→彼 一→锝 章→戋 陨→闵 落→殍 的→乃 天→氤 才→凫 斗→褛 之→越 气→戗 三→捉 段→蓦`。

## 二、第一代：图标字体 PUA 还原（章节序号）

rrssk 家族（kelexs / lwenxsw / 7shuw）在目录里插 `<i class="icon icon-uniEXXX">` 冒充数字，字体名 `Forbityph`（`fonteditor` 导出），**全家族统一 257 个码点**。

做法：

```
① 下载字体 css 指向的 woff/woff2
② fontTools: TTFont(f).getBestCmap() → {0xE600: 'glyph_uniE600', ...}
③ 字形名里通常直接带目标字符（uniE600 的 glyph name 可能就是 'one'/'uni4E00'）
   或渲染成位图与人眼比对，一次性人工确认 10 个数字 + 少量标点
④ 产出 PUA→明文 映射，硬编码进 jsLib（CHARS 表），规则里逐字符替换
```

要点：**这种站的表是同族通用的**——rrssk 聚合里一张 `CHARS` 映射覆盖多域名，新站接入直接复用。字体文件带 `fonteditor` 标记 = 大概率在线工具生成，字形名未被混淆，可自动还原。

## 三、第二代：会话置换表 + 每章 woff2（全文混淆）

aaawz 的完整链路（2026-08 实测）：

```
旧接口 /api-chapterlist-{tid}-{sid}  →  返回"请刷新页面"占位
新接口 必须带 ?format=g2
正文 API → LZString 压缩 → 解压得"字体混淆乱码"
        + 每章下发一个 woff2（浏览器端靠它还原显示）
★ 关键发现：字符置换表由 Cookie `reader_guard_id` 决定
   固定该 Cookie 值 ⇒ 置换表固定 ⇒ 可离线预计算全表
```

**破解三步**：

1. **锁定会话**：把 `reader_guard_id=f4680a0fbbdb01ae7c218f012fa745ab` **写死进书源 `header` 的 Cookie**。自此该源所有请求看到的都是同一张置换表。
2. **离线建表**：见第四节。
3. **运行时查表**：见第五节（表托管在外部 URL，规则里加载 + 缓存）。

> 为什么不直接把 6763 字的表塞进书源？表文本约 20KB+，会撑爆 MCP 传输、也让源文件难维护。**外置托管 + 首解析加载** 是正解。

## 四、离线字形位图匹配建表（核心算法）

思路：**混淆字体里的字形，画出来的形状 = 某个真字的形状。** 把混淆字体每个码点渲染成归一化位图，与参考字体（正规开源中文字体）逐字比对，取最相似者。

### 4.1 算法（生产脚本 buildmap3.py 精要）

```python
SIZE=60; CANVAS=92; OUT=36
def norm_img(img):
    a = np.asarray(img, dtype=np.float32)
    ys, xs = np.nonzero(a > 40)
    if len(xs) == 0: return None                     # 空白字形丢弃
    a = a[ys.min():ys.max()+1, xs.min():xs.max()+1]   # ★裁到内容包围盒（消除字形大小差异）
    im = Image.fromarray(a.astype(np.uint8)).resize((OUT, OUT)) \
           .filter(ImageFilter.GaussianBlur(1))       # ★高斯模糊容忍笔画抖动
    v = np.asarray(im, dtype=np.float32) / 255.0
    n = np.linalg.norm(v)
    return (v / n).flatten() if n > 0 else None       # ★L2 归一化 → 点积即余弦相似度
```

**三个设计点决定了精度**：包围盒裁剪、缩放到统一 36×36、高斯模糊 + L2 归一化。少任何一个准确率都会掉。

### 4.2 双参考字体（★这是 97% 而非 80% 的原因）

```python
REFS = ['.../wqy-microhei.ttc',   # 文泉驿微米黑（无衬线，覆盖常用字全）
        '.../notosc.otf']          # Noto Sans SC（第二候选，补 wqy 缺字/形近歧义）
ref = {}
for rp in REFS:
    for ch in chars:
        v = render(rp, ch)
        if v is not None:
            ref[ch] = v if ch not in ref else np.maximum(ref[ch], v)   # 逐像素取 max 融合
```

- 混淆字体是**衬线还是黑体**要先看：黑体用 wqy-microhei / NotoSansSC；宋体要换 NotoSerifSC / 思源宋体。**参考字体族选错，形近字大面积翻错**。
- 更稳的做法是"逐字体分别匹配取最高分"，`np.maximum` 融合是简版（够用）。

### 4.3 批量匹配 + 置信度筛

```python
A = np.stack([fake[c] for c in fc])     # 混淆字形矩阵  (N, 1296)
B = np.stack([ref[c]  for c in rc])     # 参考字形矩阵  (M, 1296)
sim = A @ B.T                           # ★一次矩阵乘 = 全表 N×M 余弦相似度
best = np.argsort(-sim, axis=1)[:, :2]
mapping, weak = {}, []
for i, c in enumerate(fc):
    mapping[c] = rc[best[i][0]]
    m = float(sim[i, best[i][0]] - sim[i, best[i][1]])   # ★第一第二名的差 = margin
    if m < 0.25: weak.append(c)                          # 低置信度入待复核清单
```

`weak` 清单是**精度的诚实度量**：这些字（通常 3%~5%）要用别的证据修正——比如用真实正文的词频、双字组合、或直接多下几章人工核对。

### 4.4 用已知样本验收

```python
known = {"第":"彼","一":"锝","章":"戋","陨":"闵","落":"殍","的":"乃","天":"氤",
         "才":"凫","斗":"褛","之":"越","气":"戗","三":"捉","段":"蓦"}
bad = [(r, f, mapping.get(f)) for r, f in known.items() if mapping.get(f) != r]
print("acc:", len(known) - len(bad), "/", len(known), "wrong:", bad)
```

**没有已知样本就建表 = 自欺。** 建表前先从站点的"未混淆页面"（如书籍简介、评论、目录书名）拿到若干真字↔乱码字配对。

### 4.5 产出：位置对齐的双串（比 JSON 省一半体积）

```python
k = ''.join(sorted(mapping.keys()))            # G2K.txt 乱码字符序列（字典序）
v = ''.join(mapping[c] for c in sorted(mapping.keys()))   # G2V2.txt 真值序列（同位置）
# 运行时：真字 = v[K.indexOf(乱码字)]
```

合并成 JSON `{"k":"…","v":"…"}` 上传托管。**用 md5 记录 K/V 指纹**，便于日后确认"表是否变了"。

## 五、映射表的存储与运行时加载（生产代码）

来自 aaawz 目录规则（已上线实测版，`bookSourceUrl=https://www.aaawz.cc`）：

```javascript
@js:
(function(){
  var d = (typeof result === 'string') ? JSON.parse(result) : result;
  var arr = d.chapters || d;                       // ★双兼容：字段可能是对象或数组
  var kv = null;
  /* 1) 先读物化缓存（书籍级变量） */
  try {
    var cv = source.getVariable();
    if (cv && cv.indexOf('"k"') > -1 && cv.length > 5000) kv = JSON.parse(cv);
  } catch(e) {}
  /* 2) ★哨兵校验：不信任缓存的形状 */
  var ok = false;
  if (kv && kv.k && kv.v) {
    try {
      ok = (kv.k.charAt(0) === '一'
        && kv.k.indexOf('戗') > -1 && kv.v.charAt(kv.k.indexOf('戗')) === '气'
        && kv.k.indexOf('褛') > -1 && kv.v.charAt(kv.k.indexOf('褛')) === '斗');
    } catch(e) { ok = false; }
  }
  /* 3) 缓存不可用 → 外置加载并写回 */
  if (!ok) {
    try {
      kv = JSON.parse(String(java.ajax('https://dpaste.com/HZCRR8UDC.txt')));
      try { source.setVariable(JSON.stringify(kv)); } catch(e2) {}
    } catch(e) {}
  }
  /* 4) 逐字符还原（未知字符原样保留，绝不吞字） */
  if (kv) {
    var K = kv.k, V = kv.v, o = {};
    for (var i = 0; i < K.length; i++) { o[K.charAt(i)] = V.charAt(i); }
    for (var j = 0; j < arr.length; j++) {
      var t = String(arr[j].title), s = '';
      for (var q = 0; q < t.length; q++) {
        var r = o[t.charAt(q)];
        s += (r === undefined ? t.charAt(q) : r);
      }
      arr[j].title = s;
    }
  }
  return arr;
})()
```

**这段代码里有四个值得抄的防御式设计**：

1. **加载必须内联在规则里**：`jsLib` 作用域 `java.ajax` 不可用（本 App），且 `source` 未定义 → 网络加载放 `@js:` 里；
2. **`typeof result === 'string'` 双兼容**：`chapterList` 的 `result` 可能是字符串或对象；
3. **哨兵校验**（`戗→气`、`褛→斗`）：比长度判据强得多——表被截断、被 CDN 返回 HTML 错误页、被别的源污染，都过不了这两对；
4. **未知字符原样保留**：还原失败最多是"还带着乱码"，不会变成"少字"。**绝对不要 `s += o[ch]`（未定义会变 `undefined` 字符串）**。

正文规则同理，把还原逻辑套在 LZString 解压之后。

## 六、变量 API 澄清：书籍级 vs 源级

上面的 `source.getVariable()` / `setVariable(str)` 能工作，但**语义容易搞错**，实测澄清：

| 上下文 | `source` 是谁 | `getVariable()` | `put/get(k,v)` | 生命周期 |
|---|---|---|---|---|
| 规则 `@js:` | `JsExtensions` | ✅ **无参**，读写**当前书籍**的 `book.variable` 字段 | 部分可用 | 随书持久（存库） |
| `loginUrl` / `loginUi.action` | `BaseSource` 系 | ❌ 不存在 | ✅ `source.put(k,v)` / `source.get(k)` | `CacheManager` 键 `v_{sourceKey}_{key}`，**进程内存级**，重启失效 |
| `eval_js`（绑定书源） | `BookSource` 对象 | ❌ 实测抛"找不到方法" | ✅ | 同上 |
| `jsLib` | `source` 未定义 | ❌ | ❌ | — |

**结论**：

- 想**随书缓存**（如字体表、密钥、总章数）→ 规则里 `source.setVariable(JSON.stringify(x))`，下次自动带上；
- 想**跨书全局**（如当前线路、图床主机、翻译引擎开关）→ 登录 UI `source.put`，规则里 `source.get` 双通道读，并接受"重启失效"；
- `eval_js` 里探测不到 `getVariable` **不代表规则里不能用**（老规矩：API 存在性要在真实调用上下文实测）。

## 七、精度评估与兜底策略

**实测 ~97% 意味着**：每 100 字错 3 字。可读，但不完美。要如实告诉用户。

分层兜底：

| 层级 | 手段 |
|---|---|
| 表加载失败 | 原样返回（不还原）→ 用户至少能看到章节结构与字数，可换源 |
| 低置信度字符（`weak` 清单） | 用双字词库二次修正；或保守替换（拿不准就不换） |
| 高频字校验 | 建表后用整本真实语料回测，统计"替换后文本的 2-gram 命中率" |
| 用户提示 | 正文首行加一行说明（"本站全文字体混淆，本表还原率约 97%，偶有错字"）——比让用户怀疑源坏了强 |
| 表过期 | 站点轮换 guard 策略后整表失效 → 哨兵校验会拒绝缓存并重新拉取；若远端表也换了，需要人工重建（在源备注里留建表脚本路径） |

**过期监控**：把 K/V 的 md5 写进 `bookSourceComment`，每次建表比对，一眼看出"是不是同一张表"。

## 八、完整流程清单（照做即可）

```
1. 判别类型（A 图标 PUA / B 会话置换 / C 加密）
2. B 类：在 JS 里找"表由什么决定"（aaawz = Cookie reader_guard_id）
   → 把该 Cookie 固定写进书源 header
3. 抓一本未混淆页面 + 一本混淆页面 → 得到 ≥10 组真字↔乱码字样本
4. 下载混淆字体 → fontTools 取 cmap 全字符集
5. 选参考字体（族要对：黑体/宋体）→ 渲染归一化位图
6. 矩阵乘匹配 → mapping + weak 清单
7. 用第 3 步样本验收 → 不达标就换参考字体/加融合
8. 产 G2K/G2V 双串 → 合并 JSON → 上传托管（dpaste api/v2 + 尾斜杠，365 天）
9. 记录 K/V md5 进源备注
10. 写内联加载规则（含哨兵校验 + 未知字原样保留 + setVariable 缓存）
11. debug_source 验目录标题 → 再验正文
12. check_source + 字段 md5 回读（见交付质量闭环篇）
```

## 九、避坑清单

| # | 坑 | 对策 |
|---|---|---|
| 1 | 把置换混淆当加密去逆向 | 先看字符集是不是常用汉字 + 一对一稳定映射 |
| 2 | 不固定会话 Cookie 就建表 | 表随会话变，全白做 |
| 3 | 参考字体族选错（黑体配宋体） | 形近字大面积翻错；先看混淆字体族 |
| 4 | 不做包围盒裁剪/归一化 | 大小笔画差异淹没相似度 |
| 5 | 没有已知样本就建表 | 无法验收，等于蒙眼 |
| 6 | 只存 top1 不看 margin | 歧义字全进正文；`weak` 清单必须出 |
| 7 | `s += o[ch]` 不判 undefined | 未知字变 "undefined" 字符串 |
| 8 | 长度判据代替哨兵校验 | CDN 错误页 20KB 也能过；用具体字符对 |
| 9 | 表放书源内联 | 撑爆 MCP 传输/难维护；外置托管 |
| 10 | 在 jsLib 里加载表 | 本 App `java.ajax` 不可用 → 内联在 `@js:` |
| 11 | 以为 `getVariable` 不存在就不能缓存 | 规则上下文可用，是**书籍级** |
| 12 | 表换了没更新 md5 基线 | 哨兵拒绝缓存后拉的是新表，旧 md5 会误导排查 |
| 13 | 混淆 + 分页 + 广告混杂时只处理一层 | 顺序：解压 → 还原 → 清广告（先还原才能按词过滤广告） |
