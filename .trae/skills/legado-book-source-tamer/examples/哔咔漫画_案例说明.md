# 案例：哔咔漫画 自包含书源（picaapi.picacomic.com）— v76

> 成品：`哔咔漫画_picaapi.picacomic.com.json`
> 书源名：`🎨哔咔漫画💞〔自包含〕`　bookSourceUrl：`https://picaapi.picacomic.com`
> 类型：漫画（bookSourceType=2）　实测：2026-10-24 App 内 MCP + LAN Web 服务全链路通过
> 方法沉淀：[[方法-图片CDN间歇阻断与Legado重试语义]]、[[方法-LAN-Web服务保存书源与全端点手册]]

---

## 1. 站点性质

- 官方 App JSON API（`picaapi.picacomic.com`），**无远程代码依赖，自包含**；
- **服务端强制登录**：未登录连 `categories` 都返回 `401 error 1005`；
- 全请求 **HMAC-SHA256 签名**：`raw = path + time + nonce + METHOD + apiKey`（全小写），`signature = hex(HMAC-SHA256(raw, secret))`；
- 缺 time/nonce/signature 时服务端**伪装成 400「必須更新」且 message 为 `--`**（极易误判为版本问题）。

## 2. v76 修复的两个真问题

### 2.1 正文图片部分失败（用户报障）

**实测根因链**：

| 层次 | 事实 |
|---|---|
| 书源规则 | 产出的 `src` **确实带 dnsIp**，`imgPattern` 提取 40/40，参数正常 |
| Legado 语义 | `retry` **只重试非 2xx，不重试 IOException** → 写 retry 无效 |
| CDN 行为 | 同批 IP 被**间歇性阻断**；所有图共用一个池 → 全压在同一首选节点 → 整章批量失败 |
| 日志形态 | 0ms = Glide failUrl 黑名单秒拒；10s/15s = 连接层超时 |

**对照实验（含反向验证组）**：

- 组A 裸 URL（无 dnsIp）→ `UnknownHostException` 1.3s / `SocketTimeoutException` 15.3s —— **必败**
- 组B 同 URL + dnsIp → **1.7s 成功**（512336 hex 字符 / 256168 字节）
- 同图 × 10 IP × 3 次 → **30/30 全通** → 节点可用，问题在并发洪峰 + 首选节点集中

**v76 处置**：

1. 移除对 IOException 无效的 `"retry":3`；
2. IP 池从 5 扩到 **10 个**（全部实测可连通）；
3. **按图序号轮换首选 IP 顺序**（`idx % 10`），40 张图首选节点分布成 10 组 × 4 张 → 单节点阻断只影响 4 张；
4. `concurrentRate` 由 `1/800` 降到 `1/1200`，降低并发洪峰。

### 2.2 章节内分页只出第 1 页（隐藏 bug）

章节接口 `comics/{id}/order/{order}/pages?page=N` 返回 `pages.total=6`（6 页 × 40 图 = 240 张图）。

旧版 `nextContentUrl` 用 `book.tocUrl` 匹配 `order/(\d+)` —— 但 `book.tocUrl` 是**目录页 URL**（`/eps?page=1`），不含 `order/` → 永不命中 → 只出第 1 页 40 张。

**正解**：从章节自身的 `baseUrl`（`comics/{id}/order/{order}/pages?page=N`）取 order。

修正后 App 自动翻完 6 页：**40+40+40+40+40+32 = 232 张**。

> 排障抓手：debug 日志 `◇本章总页数:1` 就是信号（真实应为 6）。

## 3. 结构要点（可作模板）

| 字段 | 要点 |
|---|---|
| `header` | 9 个静态头（不含 time/nonce/signature/authorization） |
| `jsLib` | `picab_opt/picab_get/picab_post/picab_img/picab_bookid/picab_item/picab_list` + 登录面板 6 个 `PICAB_*` 函数；**全部 (SRC, JV) 参数注入**（jsLib 作用域无 source/java） |
| `searchUrl` | POST `comics/advanced-search?page=N`，body `{keyword, sort}` |
| `ruleSearch.bookList` | 必须返回 **JS 数组对象**（返回 JSON 字符串会被 getElements 吞成空列表） |
| `ruleBookInfo.init` | 重拉详情并生成带选项 tocUrl |
| `ruleToc.chapterList` | 章 URL 带签名选项 |
| `ruleContent.content` | `<img src="URL,{options}">`，dnsIp 池 + 按图轮换 |
| `ruleContent.nextContentUrl` | 从 `baseUrl` 取 order；末尾表达式（不写 return） |
| `exploreUrl` | 43 分类 + 3 榜单 + 随机/收藏/馆藏/骑士榜 |
| `ruleExplore.bookList` | 全部逻辑**内联**（逃离 SharedJsScope 编译缓存陷阱） |

### 3.1 jsLib 作用域铁律（复盘）

- jsLib 在独立 ScriptBindings，**只有函数定义被 chainTo 共享**；`source/java/baseUrl/result` 一律不存在 → 全部走 `(SRC, JV)` 参数注入；
- jsLib 内 `java.*` 密码学/随机方法全灭（报"不是函数"）→ 改 `Packages.javax.crypto.Mac`；
- `secret` 含 `` ` `` `:` `<` `>` → 必须 `String.fromCharCode(96,58,60,62)` 拼接，否则触发 Rhino E4X 语法错误且报错行号完全错位；
- `source.getVariable()` 是无参方法返回整串 → 多值场景必须 `source.put/get(key,value)`；
- `loginUi` 的 action 环境**没有 `result` 绑定**（只有 `loginUrl` 的 `login()` 才有）→ 登录必须写在 `loginUrl` 的 `function login()`。

## 5. 用户侧必读

1. **旧书修复**：正文按书+章节缓存，改书源后**旧章节不重跑规则** → 必须**删除书籍后重新搜索加入**；
2. **净化规则**：`哔咔图片IP修复(自动)` 保持禁用；
3. **封面**：走 Glide，不支持 dnsIp，依赖手机 DNS；可给手机配私人 DNS（dns.alidns.com）改善，不影响正文；
4. 登录面板含「🔑登录 / ①检查登录 / ②每日签到 / ③退出 / ④刷新发现页 / 🔍一键诊断」等。
