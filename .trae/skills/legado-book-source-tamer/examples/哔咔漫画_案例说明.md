## 1. 站点性质

- 官方 App JSON API（`picaapi.picacomic.com`），**无远程代码依赖，自包含**；
- **服务端强制登录**：未登录连 `categories` 都返回 `401 error 1005`；
- 全请求 **HMAC-SHA256 签名**：`raw = path + time + nonce + METHOD + apiKey`（全小写），`signature = hex(HMAC-SHA256(raw, secret))`；
- **签名会过期**（time 过期 → `400 error 1029 time is not synchronize`）⇒ 必须每次请求现签。

### 1.1 服务端响应的判据速查

| 形态 | 含义 |
|---|---|
| `400 必須更新` | 缺 time/nonce/signature 头 |
| `400 1029 time is not synchronize` | 签名过期 |
| `400 1022 invalid id` | 请求的 id 错了（书源取 id 的逻辑有 bug） |
| `200 success` 但 **data 为空** | 签名对但 **path 算错**（最易误判） |
| `200 success` + data | 全部正确 |

## 2. v83 修复的四个真问题

### 2.1 正文图片部分失败（用户首报障）

**根因链**：

| 层次 | 事实 |
|---|---|
| 书源规则 | 产出的 `src` **确实带 dnsIp**，`imgPattern` 提取 40/40 |
| Legado 语义 | `retry` **只重试非 2xx，不重试 IOException** ⇒ 写 retry 无效 |
| CDN 行为 | 同批 IP 被**间歇性阻断**；所有图共用一个池 → 全压在同一首选节点 → 整章批量失败 |
| 日志形态 | 0ms = Glide failUrl 黑名单秒拒；10s/15s = 连接层超时 |

**对照实验（含反向验证组）**：裸 URL（无 dnsIp）→ `UnknownHostException` 1.3s / `SocketTimeoutException` 15.3s **必败**；同 URL + dnsIp → **1.7s 成功**（512336 hex 字符）。

**处置**：移除无效 retry；IP 池扩到 **10 个**（全部实测可连通）；**按图序号轮换首选 IP 顺序**（`idx % 10`）→ 40 张图首选节点分布 10 组 × 4 张，单节点阻断只影响 4 张；`concurrentRate` 降到 `1/1200`。

### 2.2 章节内分页只出第 1 页

旧版 `nextContentUrl` 用 `book.tocUrl`（**目录页 URL** `/eps?page=1`）匹配 `order/(\d+)` → 永不命中。
正解：从**章节自身 `baseUrl`**（`comics/{id}/order/{order}/pages?page=N`）取 order。

### 2.3 翻页循环重复请求（末尾报"正文获取失败"）

`AnalyzeRule.getStringList(isUrl=true)` → `NetworkUtils.getAbsoluteURL(redirectUrl, str)`：
**空串会被 `URL(baseURL, "")` 解析成 baseURL 本身** ⇒ `nextContentUrl` 返回 `""` 被当成"还有下一页" ⇒ 重复请求已消费的签名 ⇒ 400。
**必须返回 `"javascript:void(0)"`**（`getAbsoluteURL` 对 `javascript` 前缀明确返回空串）。

### 2.4 check_source 失败（invalid id / invalid baseUrl）

**根因**：`picab_bookid` 用贪婪正则，对**不含 `comics/`** 的 URL（发现页骑士榜条目 `comics?page=1&ca=xxx`）会返回 **`https:`** → 请求 `comics/https:` → `400 1022 invalid id`。
**修复**：改用精确正则 `comics/([0-9a-fA-F]{24})`，取不到返回空串。

## 3. v83 架构：签名走 `@js:` 现签

```
章节URL / 续页URL / kind.url
   = "https://host/<path>" + fromCharCode(64,106,115,58) + 内联签名IIFE(字符串字面量)
        ↓ AnalyzeUrl.analyzeJs() 每次请求重新求值
   = "https://host/<path>,{method,timeout,dnsIp,headers:{time,nonce,signature,authorization}}"
        ↓ 服务端验签通过
   code 200 + data
```

**三个必守约束**（详见方法文档）：

1. 规则文本里**禁止出现字面 `@js:`**（会被 `splitSourceRule` 误判并立即求值）→ 用 `String.fromCharCode(64,106,115,58)` 拼；
2. 签名 IIFE 必须是**字符串字面量**（不能立即执行，否则在目录规则阶段就跑了一次）；
3. `@js:` 表达式**全部内联**（该环境无外部变量、`java` 是 AnalyzeUrl 无 `getLoginHeader`/`ajax`），密钥里的反斜杠用 `String.fromCharCode(92)` 拼。

## 4. 结构要点（可作模板）

| 字段 | 要点 |
|---|---|
| `header` | 9 个静态头（不含 time/nonce/signature/authorization） |
| `jsLib` | `picab_opt/picab_get/picab_post/picab_img/picab_bookid/picab_item/picab_list` + 登录面板 6 个 `PICAB_*`；**全部 (SRC, JV) 参数注入** |
| `searchUrl` | POST `comics/advanced-search?page=N`，body `{keyword, sort}` |
| `ruleSearch.bookList` | 必须返回 **JS 数组对象**（JSON 字符串会被 getElements 吞成空列表） |
| `ruleBookInfo.init` | `picab_bookid(baseUrl)` 取 id → 重拉详情 → 生成带选项 tocUrl |
| `ruleToc.chapterList` | 章 URL 用 `@js:` 现签（fromCharCode 拼） |
| `ruleContent.content` | `<img src="URL,{options}">`，dnsIp 池 + 按图轮换；`imageStyle: FULL` |
| `ruleContent.nextContentUrl` | 从 `baseUrl` 取 order；终止值 `"javascript:void(0)"` |
| `exploreUrl` | 43 分类 + 3 榜单 + 随机/收藏/馆藏/骑士榜；kind.url **完全内联现签** |
| `ruleExplore.bookList` | 全部逻辑**内联**（逃离 SharedJsScope 编译缓存陷阱） |

### 4.1 jsLib 作用域铁律（复盘）

- jsLib 在独立 ScriptBindings，**只有函数定义被 chainTo 共享**；`source/java/baseUrl/result` 一律不存在 → 全部走 `(SRC, JV)` 参数注入；
- jsLib 内 `java.*` 密码学/随机方法全灭 → 改 `Packages.javax.crypto.Mac`；
- `secret` 含 `` ` `` `:` `<` `>` → 必须 `String.fromCharCode(96,58,60,62)` 拼接；
- `source.getVariable()` 是无参方法返回整串 → 多值场景必须 `source.put/get(key,value)`；
- `loginUi` 的 action 环境**没有 `result` 绑定** → 登录必须写在 `loginUrl` 的 `function login()`。

## 6. 用户侧必读

1. **旧书修复**：正文按书+章节缓存，改书源后**旧章节不重跑规则** → 必须**删除书籍后重新搜索加入**；
2. **净化规则**：`哔咔图片IP修复(自动)` 保持禁用（会二次包装带选项 URL 导致全挂）；
3. **封面**：走 Glide，不支持 dnsIp，依赖手机 DNS；可给手机配私人 DNS（dns.alidns.com）改善，不影响正文；
4. 登录面板含「🔑登录 / ①检查登录 / ②每日签到 / ③退出 / ④刷新发现页 / 🔍一键诊断」等。
