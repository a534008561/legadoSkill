## 0. 一句话

发布页 JS 里的 `subdomains × urls` 是**笛卡尔积线路池**（19×3=57 条，抽检全活）；
换源逻辑必须**内联进 `searchUrl` 的 `{{}}` 或 `exploreUrl` 的 `<js>`**——
`java.evalJS` 在 eval_js/规则上下文**不存在**，jsLib 函数只能被登录 UI 的 action 通道调用。

## 1. 发布页域名池：笛卡尔积展开（本篇核心发现）

发布页 `publish.js` 的结构：

```javascript
var subdomains = ['thu','pku','fdu','sjtu','zju','nju','xmu','sysu','whu',
                  'jlu','scu','ruc','bnu','nku','tju','sdu','hust','xjtu','hit'];  // 19个
var urls = ['arj2ftl0.cc/', '40ygo615.cc/', 'h2na6qa39.cc/'];                     // 3个根域
var newestUrls = [];
for(var i=0;i<urls.length*3;i++){
  newestUrls.push('https://' + getRandomSubdomain() +'.' + urls[randomNum(0,urls.length-1)]);
}
```

**要点**：
1. **`urls` 是根域池，`subdomains` 是子域池，真实线路 = 两者笛卡尔积**。
   发布页只随机展示 9 条（`urls.length*3`），但**全集有 19×3=57 条**。
2. **`urls` 数组会变**（v1 时第一项是 `40ygo615.cc`，v2 变成 `arj2ftl0.cc`）。
   所以必须**动态抓发布页 + 内置兜底全集**双轨，不能只硬编码。
3. **内置兜底全集要按当前 `urls` 顺序排列**，把发布页首位根域对应的线路放最前，
   保证"硬编码默认线"就是最优线的概率最大。

### 线路池解析代码（可直接复用）

```javascript
function hgLines(){
  var out=[], seen={};
  function add(u){u=hgST(u); if(!u||u.indexOf('http')!=0||seen[u])return; seen[u]=1; out.push(u)}
  // ① 发布页动态 urls
  try{
    var h=String(java.ajax(HG_PUB));
    if(h.length>500){
      var m=h.match(/var\s+urls\s*=\s*\[([\s\S]*?)\]/);
      if(m){
        var re=/['"]([a-z0-9.\-]+\.[a-z]{2,}\/?)['"]/gi, mm;
        while((mm=re.exec(m[1]))!=null){
          var r=mm[1].replace(/\/+$/,'');
          for(var i=0;i<HG_SUBS.length;i++) add('https://'+HG_SUBS[i]+'.'+r);
        }
      }
    }
  }catch(e){}
  // ② 内置兜底全集
  for(var j=0;j<HG_ROOTS.length;j++)
    for(var k=0;k<HG_SUBS.length;k++) add('https://'+HG_SUBS[k]+'.'+HG_ROOTS[j]);
  // ③ 硬编码默认线置首
  add(HG_DEF);
  return out;
}
```

> `var\s+urls\s*=\s*\[([\s\S]*?)\]` 只匹配**第一个** `urls` 数组声明。
> 注意 `newestUrls` / `foreverUrls` / `otherUrls` 也是 `xxxUrls = [` 形态，
> 用 `var\s+urls\s*=` 锚定（前面是 `var ` + 空格）可避开 `newestUrls`——
> 因为 `newestUrls` 的声明是 `var newestUrls = [`，正则里 `urls` 前的 `\s+` 不会跨过 `newest`。
> **实测验证**：`/var\s+urls\s*=\s*\[([\s\S]*?)\]/` 只抓到 3 个根域，没误抓 `newestUrls`。

### 测速判活阈值要按站点调

本站首页 143~145KB，用 **>20000 字节** 判活（发布页只有 5KB，若沿用 >5000 会误判发布页为线路）。
死线/拦截页通常 <5KB，20KB 阈值对本站安全。

## 2. ★`java.evalJS` 不存在 —— jsLib 函数在规则上下文调不动

**现象**：`exploreUrl` 的 `<js>` 里写

```javascript
try { L = String(java.evalJS('hgPick(false)')); } catch(e) { }
```

报：

```
InternalError: 找不到方法 "io.legado.app.data.entities.BookSource.evalJS(string)"
```

**根因**：`java.evalJS` 这个绑定**只在登录 UI 的 action 通道**存在
（App 内部 `source.evalJS(loginUrl + "\n" + action)`），
在 `eval_js` MCP 工具、`exploreUrl`、`searchUrl`、规则 `@js` 里都**没有**。

**解法（三选一）**：

| 方案 | 适用 |
| --- | --- |
| ① **换源逻辑内联进 `searchUrl` 的 `{{}}`** | 搜索入口（本站采用） |
| ② **换源逻辑内联进 `exploreUrl` 的 `<js>`** | 发现入口（本站采用，做了简化） |
| ③ **逻辑全放 `loginUrl`，只让登录 UI action 调** | 需要"手动点按钮才换源"的场景 |

本站采用 ①+② 组合：`searchUrl` 用 `{{source.get('hg_line') ? ... : 默认}}` 读缓存线路
（**不触发测速**，测速交给登录 UI 的 `hgDoLine()`），`exploreUrl` 用 `<js>` 探测默认线是否活着。

> 这与 `方法-legadoE登录面板V1动态与发现页点选化.md` 第 3 节第 4 条互为印证：
> **发现页 action 只能看到 jsLib（shareScope），loginUrl 函数不可见**。
> 反过来也成立——**规则/发现页求值上下文看不到 loginUrl 里的函数**。

## 3. ★`httpUserAgent` 字段不存在 —— UA 必须走 `header`

**现象**：JSON 里写 `"httpUserAgent": "Mozilla/5.0 ..."`，
保存后 App 回读的字段列表里**根本没有这个键**：

```
APP KEYS: ['bookSourceComment','bookSourceGroup','bookSourceName','bookSourceType',
'bookSourceUrl','bookUrlPattern','concurrentRate','customButton','customOrder',
'enabled','enabledCookieJar','enabledExplore','eventListener','exploreUrl','header',
'lastUpdateTime','loginUi','loginUrl','respondTime','ruleBookInfo','ruleContent',
'ruleExplore','ruleSearch','ruleToc','searchUrl','weight']
```

GSON 直接丢弃未知字段（不报错），所以**保存成功但 UA 静默丢失**。

**解法**：UA 写进 `header`（JSON 对象字符串）：

```json
"header": "{\"User-Agent\":\"Mozilla/5.0 (Linux; Android 14; Pixel 8 Build/UQ1A.240105.002; wv) AppleWebKit/537.36 (KHTML, like Gecko) Version/4.0 Chrome/131.0.6778.81 Mobile Safari/537.36\",\"Accept\":\"text/html,...\",\"Referer\":\"https://l205.arj2ftl0.cc/\"}"
```

**验证方法（必做）**：保存后立刻 `get_source` / LAN `getBookSource` 回读，
逐字段 md5 比对。字段不在 `APP KEYS` 里就是被丢了。

> 这解释了为什么本站**不设 UA 也能跑**——CF 的 `error code: 1010` 是对**裸 Python/默认 UA** 的拦截，
> Legado 的 OkHttp 默认 UA 已足够。但显式设 UA 更稳（尤其发布页与测速请求）。

## 4. ★`bookUrlPattern` 尾斜杠陷阱（12 样本单测必做）

**错误写法**：

```json
"bookUrlPattern": "https?://[^/]+/video/\\d+(?:/ep-\\d+/?)?$"
```

| 输入 | 结果 | 期望 |
| --- | --- | --- |
| `/video/5498/` | ❌ **不匹配** | ✅ |
| `/video/1813/ep-2/` | ✅ | ✅ |

**根因**：`(?:/ep-\d+/?)?$` 把斜杠关在可选组里。当 ep 段缺席时，
尾斜杠 `/` 没有任何规则覆盖，`$` 前的 `/` 落空 → 不匹配。

**正确写法**：

```json
"bookUrlPattern": "https?://[^/]+/video/\\d+(?:/ep-\\d+)?/?$"
```

斜杠移出可选组，独立成 `/?` → 四种形态全覆盖：

| URL | 匹配 |
| --- | --- |
| `/video/5498` | ✅ |
| `/video/5498/` | ✅ |
| `/video/1813/ep-2` | ✅ |
| `/video/1813/ep-2/` | ✅ |

**通用教训**：`bookUrlPattern` 必须写**正负样本单测**（至少 12 条），
且必须覆盖「带尾斜杠 / 不带尾斜杠」两种形态——站点两种都会产出。

## 5. 登录 UI V1 三件套：text 测速 + button 检查 + button 当前

### 5.0 ★登录态判据：第一版判定错误的实锤（v3 修正）

```
len=17440 authOpen=true loginReg=false profileAcct=true wo=true => LOGGED   ← 错
```

两个根因：

1. **`String.fromCharCode(30331,24405,27880,20876)` = 「登录注册」，漏了中间的 `/`**。
   真实页面文案是 `登录/注册`（`/` = 码点 **47**）。正确序列：
   `30331,24405,47,27880,20876`。
   **教训**：中文文案用码点写法时，**标点也必须逐字符核对**——
   从真实页面 `charCodeAt` 逐个打点，不能凭印象写。
2. **`edge-profile-account` 是 SSR 骨架 class，游客态也有**（4 处）；
   **`我` 字太常见**（"我的"到处都是）。这两个判据完全不可靠，已废弃。

**修正后判据（实测正确）**：

```
len=17440 guestBtn=true dashId=true busy=true logout=false => GUEST   ← 正确
```

| 判据 | 实现 | 可靠性 |
| --- | --- | --- |
| 游客按钮 | `data-auth-open="login">登录/注册` | ★★★ 最稳（属性+文案双特征） |
| ID 占位 | `ID：—`（`65306`=「：」，`8212`=「—」） | ★★★ 仅未加载/未登录时出现 |
| 加载中 | `aria-busy="true"` | ★★ 骨架特征，辅助 |
| 已登录 | `退出`/`登出`/`signOut`/`logout` | ★★★ 仅登录态出现 |

```javascript
function hgQ(c){return String.fromCharCode(34)+c+String.fromCharCode(34)}   // 拼双引号，避开转义
function hgCheckLogin(){
  var L=hgPick(false), h='';
  try{ h=String(java.ajax(L+'/profile/')) }catch(e){}
  if(h.length<2000) return '无法连接线路：'+L+'\n请检查网络或切换线路';
  var guestBtn=h.indexOf('data-auth-open='+hgQ('login')+'>'+String.fromCharCode(30331,24405,47,27880,20876))>=0;
  var dashId=h.indexOf('ID'+String.fromCharCode(65306)+String.fromCharCode(8212))>=0;
  var busy=h.indexOf('aria-busy='+hgQ('true'))>=0;
  var logout=h.indexOf(String.fromCharCode(36864,20986))>=0||h.indexOf('signOut')>=0||h.indexOf('logout')>=0;
  if(guestBtn&&dashId)
    return '游客状态（未登录）\n搜索/详情/目录/播放均可正常使用\n登录后可看收藏与观看历史\n当前线路：'+L;
  if(logout) return '已登录\n当前线路：'+L;
  return '状态未知（页面结构可能已变化）\n当前线路：'+L;
}
```

> **通用纪律**：登录态判据优先选 **SSR 特征属性**（`data-auth-open`）而非 class/文案；
> class 常是骨架（游客登录态都有），文案容易被"我的""推荐"这类通用词污染。
> 无法获得已登录态样本时，**已登录判据必须标注「未实测」**，不能当成已验证。

### 5.1 验证方法论：登录 UI action 跑不通时，用 `ruleContent` 当探针

```json
"loginUi": "[{\"name\":\"line\",\"type\":\"text\",\"viewName\":\"'线路(点按测速)'\",\"action\":\"hgDoLine()\"},{\"name\":\"chk\",\"type\":\"button\",\"viewName\":\"'检查登录状态'\",\"action\":\"hgCheckLogin()\"},{\"name\":\"cur\",\"type\":\"button\",\"viewName\":\"'当前线路'\",\"action\":\"hgCurLine()\"}]"
```

**设计取舍**：

| 类型 | 用途 | 为什么不用别的 |
| --- | --- | --- |
| `text`（带 action） | 「线路」点按触发全量测速 | E 版文本行带 action → TextWatcher 600ms 防抖自动执行，比 button 多一种触发方式 |
| `button` | 「检查登录状态」「当前线路」 | 一次性动作，无状态 |
| ~~`select`~~ | — | 57 条线路做下拉太长；且 E 版 V1 渲染 Spinner 体验差 |
| ~~`toggle`~~ | — | 适合"短值循环"（模式切换），线路是长 URL 不适合 |

**`viewName` 必须 3..19 字符且首尾单引号**（字面量直渲，避开异步 evalUiJs）：

```javascript
function vn(s){ s=String(s); return s.length>=3 && s.length<=19 && s.charAt(0)==="'" && s.charAt(s.length-1)==="'"; }
vn("'线路(点按测速)'")  // 15 → true
vn("'检查登录状态'")    // 8  → true
```

**登录态判据（游客/已登录/未知/不可达 四态）**：

```javascript
function hgCheckLogin(){
  var L=hgPick(false), h='';
  try{ h=String(java.ajax(L+'/profile/')) }catch(e){}
  if(h.length<2000) return '无法连接线路：'+L+'\n请检查网络或切换线路';
  if(h.indexOf('data-auth-open')>=0 && h.indexOf(String.fromCharCode(30331,24405,27880,20876))>=0)
    return '游客状态（未登录）\n搜索/详情/目录/播放均可正常使用\n登录后可看收藏与观看历史\n当前线路：'+L;
  if(h.indexOf('edge-profile-account')>=0 && h.indexOf(String.fromCharCode(27491))>=0)
    return '已登录\n当前线路：'+L;

```

> `String.fromCharCode(30331,24405,27880,20876)` = 「登录/注册」码点写法，
> 避开 JSON 传输层中文转义风险。判据选 **SSR 特征属性**（`data-auth-open`）而非文案更稳。

## 6. 搜索频控：`concurrentRate` 单位是毫秒

```json
"concurrentRate": "1/1500"
```

= 每 **1500 毫秒**最多 1 次请求（**不是** 1.5 次/秒，也不是 1500 次）。

**纪律**：
- 用户明确要求"不要主动探测搜索访问频率"时，**只做 3 次连续同关键词对照**就停
  （看响应是否一致、有无验证码），不做递增压测
- 3 次对照足够判断"有没有即时风控"；要判断"累积频控"必须长时间观察，那属于运维不是制源
- 保守取值 `1/1000`~`1/2000`；站点无验证码无变化时可放宽到 `1/500`
