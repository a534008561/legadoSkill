## 二、RSS 订阅源机制（源码级，本次新踩到的）

### 1. `ruleArticles` 的结果与空标题自动过滤
`RssParserByRule.getItem` 末尾 `if (rssArticle.title.isBlank()) return null` ⇒ 广告空卡会被自动丢弃，但更稳妥的是在 `@js` 里就过滤掉「无 `a[href*=/archives/]` / 无 `h3.title` 文本」的卡片（本模式 31 个 `video-item` → 24 条有效）。

返回类型：**`new Packages.java.util.ArrayList()` 装 Jsoup `Element`**，两版通吃（E 版 `getElements` 只认 `List`，Rhino 原生数组会 CCE）。

### 2. `searchUrl` 是「URL 模板 + 复用 ruleArticles/ruleNextPage」
- `searchUrl` 支持 `{{key}}` `{{page}}` `{{...JS...}}` 以及 Legado 的 `url,{"method":"POST","body":"…","headers":{…}}` 选项语法，整串由 `AnalyzeUrl` 解析（`replaceKeyPageJs` 先替换 `{{}}`/页码，再切第一个逗号后的 UrlOption）。
- 搜索/分类**共用** `ruleArticles`、`ruleNextPage` ⇒ 两条规则必须同时兼容 HTML 与 JSON：用 `String(result).charAt(0)==='{'` 分流。
- JSON 分支的 `ruleNextPage` 直接 `return String(baseUrl)`（baseUrl=搜索地址模板），下一次 loadMore 会把 `{{page}}` 求值成新页码；`cur_page>=total_page` 时返回 `''` 终止。
- 实测：`word=教授` 返回 10 条/`total_page=8`，标题/href/封面全部正确。

### 3. ★★`sortUrl` 的 @js 结果有 ACache 缓存 —— 换线路后分类域名不跟着变
`RssSourceExtensions.sortUrls()` 对 `@js:`/`<js>` 的 sortUrl 结果做 `ACache("rssSortUrl").put(md5(sourceUrl+sortUrl))`，**key 与运行期变量无关**；只有「菜单→刷新分类」（`clearSortCache`）或重新保存书源才失效。
⇒ 做「线路切换」的源**不要**用 `@js` 返回带域名的分类串，改用**静态条目 + `{{}}` 模板**：

```
🔥 最新黑料::{{HLW_BASE(source)}}/hlcg/
🍉 今日热瓜::{{HLW_BASE(source)}}/jrrs/
```

- `parseRssSortUrls` 只按 `(?:&&|\r?\n)+` 和 `::` 切分，条目里的 `{{}}` 原样保留；
- 真正请求时 `AnalyzeUrl` 用 `source` 绑定求值 `HLW_BASE(source)`，**每次请求即时生效，无缓存**；
- 变量为空时返回 `''` ⇒ URL 变 `/hlcg/` ⇒ `getAbsoluteURL(sourceUrl, …)` 自动回落到源域名，天然有兜底；
- 代价：`parseXML` 里 `analyzeRule.setBaseUrl(sortUrl)` 拿到的是**模板串**，所以
  - `ruleLink` 会被 `getString(isUrl=true)` 用 **`redirectUrl`（真实响应 URL）** 解析，相对链接仍正确，可保持 `tag.a.0@href`；
  - `ruleNextPage` 的结果是用 `sortUrl`（模板）做 base 的 `getAbsoluteURL`，模板解析失败会原样返回相对地址 ⇒ **必须在规则里自己拼绝对 URL**（取变量域名，回落 `source.getKey()`）。

### 4. ★RSS 列表封面不走 `coverDecodeJs`
`RssArticlesAdapter*.convert` 里是 `ImageLoader.load(context, item.image)`（纯 Glide），没有 `sourceOriginOption`，所以 **AES 图床的封面必然解不开**，只能显示占位。
`coverDecodeJs` 字段留着不报错，但别指望列表封面。正文图必须走页内解密。

### 5. ★登录面板的文本框值不在 `source.get()`
`SourceLoginDialog.getLoginData(rowUis)` 把文本输入读成 `Map<String,String>`，按钮 action 执行时 `put("result", 该 Map)`（LT `handleButtonClick` / E `evalUiJs` 同）。
⇒ 面板里读输入框必须：

```js
function HLW_r(k){ // Java HashMap 在 Rhino 里 get/bracket/dot 三种取法都可
  var v=''; try{ var g=result.get(k); if(g!=null) v=String(g); }catch(e){}
  if(v===''){ try{ var q=result[k]; if(q!=null) v=String(q); }catch(e2){} }
  return v;
}
```

读到后再 `source.put('hlwPub', v)` 落库（`BaseSource.put` → `CacheManager.put` → **写 appDb.cacheDao，耐久**，重启仍在）。
另：`loginInfo`（文本框内容）只有点 ✓ 触发 `login()` 时才 `putLoginInfo` 保存 ⇒ 免登录源也要写 `function login(){…return 'ok'}`。

### 6. viewName 动态按钮（ms 写入按钮）
V1 静态 loginUi 里按钮的 `viewName` 非「单引号短字面量」时走 `evalUiJs(viewName)` = `source.evalJS(loginUrl + "\n" + viewName)`，绑定 `result`=loginData。
⇒ `"viewName": "HLW_lineBtn(1)"`，`HLW_lineBtn` 在 loginUrl 里定义，返回 `线路1. host · 123ms ▶当前`。切换/测速后调用 `java.reLoginView()` 重绘（不是 `refreshExplore()`，后者只重绘，名字易误解）。

## 三、★★两个「规则文本」级大坑

### 1. `@js` 规则里任何 `{{` 都会被当成内联 JS 规则
`AnalyzeRule.SourceRule.init` 用 `evalPattern` 扫描**整条规则文本**（不只是默认模式），把 `{{…}}` 拆成独立 `jsRuleType` 片段再逐段求值。
本次踩坑：`ruleNextPage` 的注释里写了「模板，`{{page}}` 会自增」⇒ 运行期抛

```
org.htmlunit.corejs.javascript.EcmaError: ReferenceError: “page” 未定义 (<script-4863>#1)
```

⇒ **规则（含注释、字符串）里禁止出现 `{{` / `}}`**；需要描述时写「页码占位符」。

### 2. 规则串不要用 `&&`/`||` 混淆（本版可留，但组合规则场景会切段）
`splitSourceRule` 本版只切 `@js:`/`<js>`，但 `SourceRule` 的 `putMap`/`get`/`##` 等仍有语义；历史版本会对 `&&`/`||` 切分。**最保险是 @js 里把这些运算符写在 `(function(){…})()` 内部**（本方案如此，未受影响）。

## 四、正文内嵌 H5 播放器（ruleContent 产出整页）

### 提取顺序很重要
1. `doc.select('div.dplayer')` **先**取视频（此时还没删除）；
2. 再拿 `div.client-only-placeholder.editormd-preview` 元素，用 **Jsoup 结构性删除**（优于正则，避免跨块吞正文）：
   ```js
   cel.select('script, style, ins, .opt-stage, .dplayer, .detail-hot-gossip, .ssp-placement, div[data-ssp-slot-id], .a2a_kit, .article-tags, .detail-promo-actions, .detail-blockquote, [data-reading-content-end]').remove();
   ```
3. `blockquote` 按关键字判（`hlwi12|最新入口|分享请告知|商务合作|heiliao|18hlw`）保留正文引用；
4. `cel.html()` 之后再走字符串兜底（去注释/脚本/`<a>` 去壳/`<img>` 换 `data-hlw-enc`）。

效果：原文 68KB → 24KB，`data-hlw-enc` 42~45 张，`dplayer/opt-stage/文章标签/推广按钮/重磅热瓜/官方公告` 全 0。

### 页内脚本要点
- **图片**：`fetch(u) → arrayBuffer → crypto.subtle.importKey('raw', TextEncoder.encode(KEY), {name:'AES-CBC'}) → subtle.decrypt({iv})`。**PKCS#7 填充由 WebCrypto 自动剥离**（本图床正是 PKCS#7，实测 3 张全部合法）；再用 `URL.createObjectURL` 回填，`IntersectionObserver` 懒解密。
- **视频**：`hls.js`（`https://s4.zstatic.net/ajax/libs/hls.js/1.6.13/hls.min.js`，配 jsdelivr/unpkg 兜底动态加载），`new Hls({enableSoftwareAES:true, maxBufferLength:30})`；m3u8 为 `#EXT-X-KEY:METHOD=AES-128` + 独立 `crypt.key`，软件 AES 可播。
- **直链自愈**：`auth_key` 约 30~60 分钟过期 → 页内「🔄 刷新直链」用 **preloadJs 暴露的 `ajaxAwait`** 重取文章页，`DOMParser` 再解 `config`，重建 `<select>` 并重播。
  ```js
  // preloadJs
  (function(){try{window.ajaxAwait=ajaxAwait;window.java=java;}catch(e){}})();
  ```
- 播放按钮与 `<select>` 用 `addEventListener` 绑定（页内脚本是 IIFE，不要写全局 onclick）。

## 八、播放器 v2：倍速 / 全屏 / 竖屏全屏（261128 追加）

### 1. 需求理解
- 「竖屏识别」不是按钮：**全屏时若视频是竖屏，就锁竖屏全屏；横屏视频才转横屏**，退出全屏恢复系统自动旋转。
- 内联容器按视频真实比例自适应（不再是死 16:9），竖屏视频不会缩成小条。

### 2. 实现
- **倍速**：`video.playbackRate`，按钮循环 `1 → 1.25 → 1.5 → 2 → 2.5 → 3 → 1`（最高 3x），`loadedmetadata/canplay/play` 时统一 `applyRate`，切集/换线路保持。
- **全屏**：`box.requestFullscreen()`（Legado `WebChromeClient.onShowCustomView` 接管：隐藏系统栏 + 屏幕常亮；`ReadRssActivity.kt:574`）。
  - 失败/不支持 → **伪全屏兜底**：`position:fixed;inset:0;z-index` + `html.hlw-fslock` 锁滚动。
  - 未开播时点全屏会先 `play()`
  - 按钮文案随 `fullscreenchange`/`webkitfullscreenchange` 同步「⛶ 全屏 / ✕ 退出」。
- **比例自适应**：`loadedmetadata` 后读 `videoWidth/videoHeight`，把 `padding-top = h/w*100%`（夹 40%~165%）写进容器；`data-ratio=port|land` 让播放按钮在竖屏时上移到 40%。
- **方向锁定**（源码级，本节最重要）：
  - Legado 在 WebView 注入 `WebJsExtensions.basicJs`（`ReadRssActivity.kt:635`），把 `screen.orientation.lock/unlock` polyfill 到 `JSInterface.lockOrientation`；
  - `JSInterface.lockOrientation` **只在 `ctx.isFullscreen == true` 时生效**（即 `onShowCustomView` 之后），否则静默丢弃；
  - 映射：`portrait`/`portrait-primary` → `SCREEN_ORIENTATION_PORTRAIT`（固定竖屏）；`landscape` → `SENSOR_LANDSCAPE`（横屏且受重力控制正反）；`landscape-primary` → 正向横屏；`'unlock'` 命中 else → `SCREEN_ORIENTATION_UNSPECIFIED`（恢复系统）；
  - ⇒ 进入全屏后立刻调用可能撞上 `isFullscreen` 还没置位 → **延时重试 200ms/600ms**（`lockOri` 内 setTimeout，且重试前判 `isFs`）；
  - 退出全屏 → `screen.orientation.unlock()`；
  - ⚠ 伪全屏兜底路径下 `isFullscreen=false`，`lock` 不生效（方向随系统），这是 App 限制，不是规则问题。
- 视频元素加 `controls`（原生播放/暂停/进度），自定义 chip 放**右上角**避免与原生控制条重叠。

### 3. 验证（无需真机也能跑）
用 QuickJS（`/usr/bin/qjs`）+ DOM 桩跑 `part_page.js`：
- 倍速 1→3.0x→1.0x、`playbackRate` 同步；
- 竖屏 1080×1920 → `paddingTop=165.00%`/`data-ratio=port`；横屏 1920×1080 → `56.25%`/`land`；
- 进全屏 `lock('portrait')`、退出 `unlock`、横屏视频 `lock('landscape')`；
- 无 `requestFullscreen` 时走伪全屏（class/锁滚动/按钮文案/退出清理）全部 PASS。
桩文件：`/workspace/hlw/test_stub.js` + `combined_test*.js`，可直接 `qjs combined_test3.js` 复跑。
