# 方法：书籍变量切换线路（STV 范式）+ 抓包驱动的发现页端点定位

> 261109 猫眼看书（🐈 / yutinglu.com）v4 实战。前置：v3 已用去加固 APK 逆出 MkAES 打通正文（见《方法-脱壳APK逆向白盒密钥打通加密正文》）。

## 0. 一句话结论

1. **选线路用书籍级变量**（`book.getCustomVariable()`），不要用全局 `source.put` / `infoMap` —— 全局态必然串书（rrssk v6 漂移病）。
2. **发现页端点不要从 dex Retrofit 注解猜域名**：`BookService` 只有相对路径且带 `Domain-Name` 头，真实域要靠抓包。本次 dex 猜 `d.yutinglu.com/book_city/...` 全 404，ProxyPin 实锤是 **`book.yutinglu.com`** 且路径带 `.html`、全部筛选用 `-1`。

## 1. STV 的书籍变量范式（源码级可移植）

STV 成品（`examples/STV越南聚合_sangtacviet.vip.json`）的三处同款函数，抄过来即用：

```js
function CVAR(){
 try{var v=book.getCustomVariable();if(v!=null&&String(v).length>0)return String(v)}catch(e){}
 try{var v2=book.getVariable('custom');if(v2!=null&&String(v2).length>0)return String(v2)}catch(e2){}
 return '';
}
function SEL(L){                       // L = 实时线路数组
 var best=0,bp=-1;
 for(var i=0;i<L.length;i++){var p=parseFloat(String(L[i].choose||'').replace('%',''));if(isNaN(p))p=0;if(p>bp){bp=p;best=i}}
 var cv=String(CVAR()).replace(/[^0-9]/g,'');
 if(cv.length>0){var n=parseInt(cv,10)-1;if(n>=0&&n<L.length)return n}
 return best;                          // 未填变量 → 默认按站点 choose 占比取最高
}
```

- `book.getCustomVariable()` 是**书籍级**（Legado 书籍菜单「设置书籍变量」写入），每本书独立，天然不串书；`book.getVariable('custom')` 为旧版兜底。
- `source.put('stvo_...')` 在 STV 里只用于**自动换源记忆/死源黑名单**，不是用户选线通道。想让用户自己选，就用书籍变量。
- **三处规则必须都读同一个 `SEL()`**：`ruleBookInfo.init`（渲染列表+写 tocUrl）、`ruleToc.chapterList`（真正取目录）、必要时 `ruleContent`。本次把选中 `site_path` 拼进 `tocUrl` 查询串 `?line=<encodeURIComponent(path)>`，目录规则优先用它 ⇒ **详情与目录永远同一条线，不会各选一次漂移**（rrssk 同源教训）。

### 详情简介里渲染实时线路列表（原 App 同款信息）

```
━━━━ 本书线路（共10条，实时） ━━━━
● 1．qu  选择67.04%  更新2026-11-01 20:28:54
     最新：第2203章 梦魇碎心   ← 当前
○ 2．xsjtxt  选择17.51%  更新2025-01-01 05:55:54
     最新：第2120章 世外厨神
...
换线路：书籍菜单 → 设置书籍变量，填上面的编号（如 2）→ 下拉刷新详情与目录即可。
```

`●/○` 纯文本，不要拼 `□ + String.fromCharCode(9633/9634)`（本次第一版渲染成 `□ □` / `□▢` 很难看）。`site_name / choose / last_chapter_name / updated_at` 全是 source 接口实时返回的，不写死。

## 2. ★ jsLib 环境不绑定 `java`（第三次踩，务必记牢）

v4 第一次落库后 `debug_source` 报：

```
TypeError: base64DecodeToByteArray 不是函数，它是 object。 (<script-72>#86)
```

根因：新增的 `U8(s)` 里写了裸 `java.base64DecodeToByteArray(...)`。jsLib 共享 scope 只按 jsLib 字符串创建并 `preventExtensions`，规则环境的 `java` 绑定挂不到 jsLib 函数体的作用域链上（见 /topics/legado-js-scope-binding.md、261108 91PORN 七轮实锤）。

★ **定式**：jsLib 里所有需要宿主能力的函数一律 `function X(jv, ...)`，调用处显式传 `java`：

```js
function U8(jv,s){ ... return String(new Packages.java.lang.String(jv.base64DecodeToByteArray(b64),'UTF-8')); }
function D8(jv,c){return U8(jv,D(jv,c));}      // 与旧 D(jv,c) 同模式
```

检查方法：落库前 `grep` jsLib 里的裸 `java.`，只应剩 `Packages.java.*` 类路径。

## 3. ★ 主协议解密的中文乱码：latin1 → UTF-8 二次反解

旧 `D()` 逐字节 `String.fromCharCode(255&p[q])` 拼 latin1 串，对纯 ASCII JSON 没问题；但 **source 接口的 `site_name` / `last_chapter_name` 含中文**，直接 `F()` 出来是 `ç¬¬2203ç« ` 乱码。

定式 `D8(jv,c) = U8(jv, D(jv,c))`：把 latin1 串的每个 codepoint 还原成 byte，再用 `new String(bytes,'UTF-8')` 构造。实测 source 10 条线路中文全部正常。

## 4. ★ 首块被 IV 覆盖 ⇒ 整体 JSON.parse 必失败，用「逐对象括号配平」通用兜底

主协议 `AES/CBC/NoPadding` 的**首个明文块被 IV 覆盖**（旧文档已记：要按端点补 JSON 前缀 `F()`）。但本次多个端点补前缀也救不回来：

| 场景 | 症状 | 原因 |
|---|---|---|
| source 接口（部分书） | `F(raw,'source')` 返回原始字符串 ⇒ 线路 0 条 ⇒ 目录 `TocEmptyException` | 首条 `site_id` 是字符串不是数字，`F()` 的候选前缀写死 `{"list":[{"site_id":1`；且开头被 IV 吃掉成 `eee"` |
| 书城首页/榜单/rank2tag | `F()` / `JSON.parse()` 全 null | 明文开头就是半个字段（如 `le":"书写奇迹"` 或 `d1胖的老鼠"`），尾部却完整 |

★ **通用解法 `OBJS(raw, anchor)`**：不管整体结构，按锚点字段（`"book_id"` / `"site_path"`）定位 → 向前 `lastIndexOf('{')` → 向后做**花括号配平**（跳过字符串内的 `{`/`}`，处理 `\\` 转义）→ 对切片单独 `JSON.parse`。

```js
function OBJS(raw){                    // 锚点固定 site_path
 var out=[],re=/"site_path"\s*:/g,m;
 while((m=re.exec(raw))!==null){
  var st=raw.lastIndexOf('{',m.index);if(st<0)continue;
  var dep=0,q=false,esc=false,end=-1;
  for(var i=st;i<raw.length;i++){var c=raw.charAt(i);
   if(esc){esc=false;continue} if(c==='\\'){esc=true;continue}
   if(c==='"'){q=!q;continue} if(q)continue;
   if(c==='{')dep++; else if(c==='}'){dep--;if(dep===0){end=i+1;break}}}
  if(end>st){try{out.push(JSON.parse(raw.slice(st,end)))}catch(e){}}
 }
 return out;
}
```

- `P8()`：`F(raw,kind)` 失败 → `OBJS(raw,'site_path')` 兜底成 `{list:L}`。实测救回《玄鉴仙族》5 条线路（原本 0 条）。
- `BOOKS()`：同思路按 `"book_id"` 提取，**四类发现端点通用**（书城首页 60/73 本、分类 20 本/页、榜单 199 本、rank2tag 15 本），字段与搜索一致 ⇒ `ruleExplore` 一套规则通吃。
- 去重：同一本书可能在多个模块重复出现，`book_id` seen 去重。

⚠ 不要试图「猜更多补前缀」穷举端点形态 —— 首块丢失是协议固有，逐对象提取才是稳定解。

## 10. ★★★261109 报障修复：「切线路不生效 / 简介刷新还是线路1 / 上面网址没变」

### 现象（用户原话）
「切换路线没有成功，简介刷新之后还是一，进去之后那个上面的那个网址也没有变化」

### 根因实锤（不是猜测，三重证据）

1. **源码**：`AnalyzeRule.kt:834` 的 `bindings["book"] = book` **只在规则 @js 环境**注入。`BaseSource.getShareScope(jsLib)` 用 jsLib 字符串创建并 `preventExtensions` 密封的共享 scope **没有 book**。
2. **App 内实测**：`typeof book`（jsLib 函数体内）= `"undefined"`，`CVAR()` 返回 `""` ⇒ `SEL()` 永远按 choose 占比取最高（线路1）⇒ 与现象完全一致。
3. **STV 对照**：STV 成品 **`jsLib` 长度 = 0**，`cvar()` 内联在 `ruleBookInfo` / `ruleToc` / `ruleContent` 每条规则里各一份 —— 我当时看到这个事实却没照做，把 `CVAR()` 放进了 jsLib。与同会话刚踩的「jsLib 裸 `java.`」是**同一个作用域坑的第三个实例**。

### 键名核实（避免修错方向）

`BookInfoActivity.setBookVariable()` 源码实锤：

```kotlin
private fun setBookVariable() {
    val variable = withContext(IO) { book.getCustomVariable() }
    val comment = source.getDisplayVariableComment(
        """书籍变量可在js中通过book.getVariable("custom")获取""")
    showDialogFragment(VariableDialog(getString(R.string.set_book_variable), book.bookUrl, variable, comment))
}
override fun setVariable(key: String, variable: String?) {
    when (key) {
        viewModel.bookData.value?.bookUrl -> viewModel.bookData.value?.let {
            it.putCustomVariable(variable)          // BaseBook: putVariable("custom", value)
            if (viewModel.inBookshelf) viewModel.saveBook(it)
        }
    }
}
```

`BaseBook.kt`：`getCustomVariable() = getVariable("custom")`、`putCustomVariable(v) = putVariable("custom", v)`，`Book.variable` 存 JSON `{"custom":"3"}`。⇒ **键名 `custom` 没错**，用户填数字后 `book.getCustomVariable()` 必返回该数字。唯一故障就是 jsLib 读不到 `book`。

### 修法定式（与 `java` 同款：显式传宿主绑定）

```js
// jsLib：绝不直接碰 book/java 绑定，全部走参数
function CVAR(bk,jv){
 var vals=[];
 if(bk){
  try{var v=bk.getCustomVariable(); if(v)vals.push(String(v))}catch(e){}
  try{var v2=bk.getVariable('custom'); if(v2)vals.push(String(v2))}catch(e2){}
  try{var v3=bk.variable; if(v3)vals.push(String(v3))}catch(e3){}   // JSON {"custom":"3"} 兜底
 }
 if(jv){                                             // AnalyzeRule.get(key) 会查 book.getVariable(key)
  try{var g=jv.get('custom'); if(g&&String(g)!=='null')vals.push(String(g))}catch(e4){}
 }
 for(var i=0;i<vals.length;i++){var m=String(vals[i]).match(/\d+/);if(m)return m[0]}
 return '';
}
function SEL(L,bk,jv){ /* ... */ var cv=CVAR(bk,jv); ... }

// 规则 @js（有 book 绑定）里显式传：
//   var sel=SEL(L,book,java);        ← init 与 chapterList 都这样
```

`CVAR` 返回「首个数字」，兼容用户填纯 `3`、`{"custom":"3"}` 整串、`lineNo=3` 等多种形态；越界编号（如 99）回落默认。

### ★ 第二个改動：把线路真值从 `tocUrl` 解耦

旧版 `init` 把选中 `site_path` 拼进 `x.tocUrl + '?line=...'`。用户说「上面那个网址没变化」正是指它：
- `BookInfo.kt` 每次刷新详情都会**重写 `book.tocUrl`**，而详情页顶部显示的是 `bookUrl`，本来就不会随线路变；
- 残留旧 `?line=` 还会与用户改过的变量冲突。

**终版**：`tocUrl` 永远是干净的 `.../book/source/v4/{floor}/{id}.html`，**书籍变量是线路唯一真值来源**，`chapterList` 自己 `SEL(L,book,java)`，不读 `baseUrl` 上任何查询串。改完变量 → 进目录 / 目录页下拉刷新即生效。

### 配套

- 加书源级 `variableComment`（`BookInfoActivity.setBookVariable` 会优先显示）：「填线路编号（1 起）… 填完刷新详情、再进目录」。
- `SRCLIST` 的指引改为「详情页右上角菜单 → 设置书籍变量 → 填编号 → 菜单『刷新』，再进目录或目录页下拉刷新」。

### 验证

```

  无变量→sel0(qu) / 2→sel1(xsjtxt) / 3→sel2(wsg) / 10→sel9(us23) / 99→回落默认
  变量3 + baseUrl 残留旧 line=qu 的冲突场景 → 仍选 wsg
  CVAR(null,fakeJv) 仅 java 通道也返回 '3'；CVAR(null,null) 返回 '' 不抛异常
debug_source(逆天邪神)：默认线路1、tocUrl 无 ?line=、2198章、正文全绿
check_source 1/1
```

### ★★ 通用铁律（第三次实锤，写进检查清单）

> **jsLib 里不能直接引用任何「规则环境才注入」的绑定：`java` / `book` / `source` / `result` / `baseUrl` / `chapter` / `cookie` / `cache`。**
> 一律写成 `function X(jv,bk,...)`，由规则 @js 显式传参；或 `this.source.getVariable()` 这类跨环境稳定通道。
> 落库前必须 `grep` jsLib 里的裸绑定（只应剩 `Packages.java.*` 类路径与注释文字）。
> **判据**：「面板/变量写了但规则没反应」先查绑定作用域，不要先怀疑键名或缓存。

## 14. ★261109 晚报障：「子项只看到首字 + 三个省略号」（v5.2 布局收敛）

### 现象
用户报「看不到全部字，例如历史有11个，但是除了『全部』两个字，后面全都只能看到首字，然后后面三个省略号」。

### 根因（两层，都是我 v5.1 引入的）

1. **`layout_flexGrow:1` 让 basis 形同虚设**：Flexbox 会按 grow 把剩余空间重新分配，一行能塞进远多于设定列数的项目 ⇒ 每项只约 2 字宽，4~6 字中文标题必然 `首字…`。rrssk 成品 `push()` 的默认列数是 **`numx=3`（basis 0.32）**，且 `layout_flexGrow` 只在 `g==0` 时为 0、其它为 1 是配合 `push` 的显式列数调用；我照抄时把「4/5/6 列自适应」+ grow:1 一起用，窄到 0.16（6 列）最严重。
2. **没有显式换行锚点**：只靠 `basis` 累加自然换行时，3×0.32=0.96 的余量可能被 App 再塞第 4 项。

### 修法（v5.2）

```js
var D={1:1,2:0.49,3:0.32};              // 只保留 1/2/3 列，3 列约 115dp 足够 4~6 字
function basis(n){return D[n]||0.32}
function line(items,n){
  for(var i=0;i<items.length;i++){
   var it=items[i];
   it.style={layout_flexGrow:0,                        // ★关键：0，不再抢剩余空间
     layout_flexBasisPercent:basis(n),
     layout_wrapBefore:(i%n===0)};                    // ★每组第 1 项强制换行
   K.push(it);
  }
}
```

- 排行榜 12 项 `line(rk,3)`、分类子项统一 `line(items,3)`；
- 结果：**排行榜 4 行（3+3+3+3）、历史 11 项 4 行（3+3+3+2，换行点 0/3/6/9）**，108 个 cell 全部 `grow:0 / basis:0.32`，`allGrowZero=true`；
- 「全部」与「上古先秦/秦汉三国/两宋元明/…/民间传说」全部标题完整，不再截断。

### 验证

```
MYKINDS 结构：rank.rows=4、hist.rows=4、wrapIndexes=[0,3,6,9]、hist items 11 个全名
check_source 1/1
debug_source ::1/7/8/-1/-1/1.html（历史·架空历史）20本→详情→246章→正文全绿
select action 仍为 java.refreshExplore()（v5.1 修复不回归）
get_source 回读 v5.2 完整
```

★ **通用结论**：发现页按钮文字被截断成「首字…」时，**先查 `layout_flexGrow` 是不是 1**（grow 会吃掉 basis 的限宽），再查是否给了每组第 1 项 `layout_wrapBefore:true`。纯靠 basis 自然换行在 App 的余量计算下不可靠；中文 4 字标题至少要 0.32（三列）才稳。★列数宁少勿多：宁可多几行，也别把 11 个子类压成一行。

## 16. ★★261109 晚终版：发现页宽度「不用算，用 Legado 自带自动模式」（v5.4）

### 用户两次纠正
1. 「人气榜、畅销榜就三个字，怎么占了一整格一整行？不是让你自适应吗？」
2. 「这个应该不用算的吧，我记得阅读里有一个好像是自动的呀」← **用户是对的**，我前面三轮一直在手工算字数/basis，方向错了。

### 源码实锤（FlexChildStyle.kt）
```kotlin
data class FlexChildStyle(
    val layout_flexGrow: Float = 0F,
    val layout_flexShrink: Float = 1F,
    val layout_alignSelf: String = "auto",
    val layout_flexBasisPercent: Float = -1F,      // ★ -1 = 不按百分比
    val layout_wrapBefore: Boolean = false,
    val layout_justifySelf: String = "auto"
)
fun apply(view: View) {
    val lp = view.layoutParams as FlexboxLayout.LayoutParams
    lp.flexBasisPercent = layout_flexBasisPercent   // 无条件写入
    ...
}
```
Google Flexbox 里 `flexBasisPercent = -1` 回退到 `WRAP_CONTENT` ⇒ **View 按文字内容测量宽度、Flexbox 自动折行**。这就是用户记忆里的「自动」。

### 前几版为什么反复出问题（根因链）

| 版本 | 我做的 | 结果 |
|---|---|---|
| v5.1 | `flexGrow:1` + basis 按列数 | grow 抢剩余空间使 basis 失效 ⇒ 一行塞太多 ⇒「首字…」 |
| v5.2 | `grow:0` + 固定 3 列 basis 0.32 + wrapBefore | 不再截断，但 4 字标题仍被固定列限制 |
| v5.3 | 按 `t.length`（UTF-16）算 basis | `🏆 人气榜` UTF-16=6（emoji 占 2 + 空格 + 3 中文）被判「≥5字」→ basis **0.99** ⇒ 12 个榜单每项独占整行 = 又是一长条 |
| **v5.4** | **`style` 完全不写 basis/grow** | 交给默认 -1/0 自动按内容排 ✅ |

★ 手工算字数本身就是错路：emoji/符号/空格会让 UTF-16 长度与可见宽度不成比例；而且 Legado 本来就有自动模式，不需要我算。

### 终版写法

```js
// 所有发现项：style 留空对象（或干脆不写 style），只有分组标题/折叠条/select 给 wrapBefore
function flow(items){ for(var i=0;i<items.length;i++){ items[i].style={}; K.push(items[i]); } }
function head(t){ K.push({title:t,url:'',type:'url',style:{layout_wrapBefore:true,layout_justifySelf:'flex_start'}}) }
function bar(...){ return {..., style:{layout_wrapBefore:true,layout_justifySelf:'flex_start'}} }
K.push({title:'📚 书城精选',url:...,type:'url'});   // 连 style 都不写
```

- 分组标题/折叠条靠 `layout_wrapBefore:true` 独占整行（**不靠 basis=1**）；
- 榜单、二级子项全部 `style:{}` ⇒ `flexBasisPercent=-1` 自动按「🏆 人气榜」「上古先秦」实际文字宽度排、自动折行，多少字显示多长；
- 折叠（91Hub）、select 切频道（rrssk 的 `java.refreshExplore()`）、常驻首 url + `exploreUrl` 整段 try/catch（check_source 兜底）全部保留不回归。
