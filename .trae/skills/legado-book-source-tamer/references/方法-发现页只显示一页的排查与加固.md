# 方法：发现页「只显示一页」的排查与加固

> 源自 hd.huadudm.com（飞飞CMS 影视站）视频书源 v1.5→v1.6 实战。
> 适用于**所有带翻页的发现规则**，不限视频站。

## 0. 一句话结论

> **"发现页只有一页"绝大多数不是站点不给你第 2 页，而是 App 的「翻页终止判定」被一次失败/空页永久锁死了。**
> 排查顺序应当是：**先证明站点第 2 页有数据 → 再证明 App 请求过第 2 页 → 最后才怀疑规则。**

## 1. 现象与第一直觉的陷阱

用户报障：「发现列表只显示一页」。

第一直觉通常是「分页 URL 拼错了」。但本次实测：

| 检查 | 结果 |
|---|---|
| `/vodshow/15--------1---.html` | 40 条 |
| `/vodshow/15--------2---.html` | 40 条 |
| `/vodshow/15--------3---.html` | 40 条 |
| p1 ∩ p2 / p2 ∩ p3 | **0 / 0**（零重复） |

`debug_source ::/vodshow/16--------{{page}}---.html` 也显示
`≡获取成功:/vodshow/16--------1---.html` —— **`{{page}}` 替换正常**。

⇒ 站点与规则都没问题。继续在规则里找，会浪费大量时间。

## 2. App 侧的终止判定（源码级，legadoT / LegadoTeam 共有）

`ExploreShowActivity.upData(state)`：

```kotlin
loadMoreView.stopLoad()
if (books.isEmpty() && adapter.isEmpty()) {
    loadMoreView.noMore(getString(R.string.empty))
} else if (adapter.getActualItemCount() == books.size) {
    loadMoreView.noMore()            // ★ 判定"到底了"
} else {
    adapter.setItems(books)
}
```

而 `books` 是 `linkedSetOf<SearchBook>`（去重键 `bookUrl`，见 `SearchBook.equals`）。

**推论**：只要某一页**没有新增任何书**，`adapter.itemCount == books.size` 成立 →
立刻 `noMore()` → **之后滚到底也不再请求**（`scrollToBottom` 要求 `loadMoreView.hasMore == true`）。

三种情况都会造成"永久只有一页"：

1. 该页请求失败（网络抖动 / CDN 限频）
2. 该页返回空壳页（站点限流）
3. 该页解析出 0 条

## 3. 三类根因与对策

### 3.1 页码为 null / 空 / 0 → URL 变成字面量 `null`

`{{page}}` 直接求值 `page`，若 `page` 是 `null`：

```
/vodshow/15--------null---.html   →  7157 B 空壳页，li=0
/vodshow/15--------undefined---.html → 7157 B 空壳页，li=0
```

而 `{{page||1}}` / `Number(page)` 归一化后恒为 `>=1`：

```js
{{(function(){var p=Number(page);if(!(p>0)){p=1;}p=Math.floor(p);return p;})()}}
```

> 注意：`{{page||1}}` 也能兜底，但它**不会把实际页码写进变量**，不利于自检（见 §4）。

### 3.2 单页偶发失败 → 直接 noMore

对策：URL 追加 URL 选项（`AnalyzeUrl` 原生支持）：

```
/vodshow/16--------1---.html,{"timeout":20000,"retry":2}
```

`retry` 是 OkHttp 层重试，能救回 `IOException` / RST。
`timeout` 显式化，避免慢页拖垮整轮（默认值偏大）。

### 3.3 空页被当成"真到底"

**关键**：越界页与空壳页在 HTML 上是可以区分的。

| 类型 | `span.stats-text` | `ul.stui-vodlist li` |
|---|---|---|
| 真·越界（5/4） | `共 155 条数据，当前第 5 / 4 页` | 0 |
| 空壳页（限流） | **不存在** | 0 |
| 末页（4/4） | `共 155 条数据，当前第 4 / 4 页` | 35 |

所以：

```js
var sm = String(statsText).replace(/\s+/g,'').match(/第([0-9]+)[/]([0-9]+)页/);
if (sm) { cur = Number(sm[1]); tot = Number(sm[2]); }

if (cur > 0 && tot > 0 && cur >= tot) return [];   // A 真·到底 → 让 App 正常 noMore
throw new Error('第N页返回空页面（站点可能临时限流），请点「重试」');  // B 假空页 → 弹重试
```

> 抛错路径下 App 走 `errorLiveData → loadMoreView.error(msg)`，
> **不会写 noMore**，用户点一下就能继续。这是"失败要显性化"的价值。

## 4. 翻页自检：让"App 有没有请求第 2 页"可观测

把实际页码写进书源变量，登录面板加一个按钮读出来：

```js
// URL 模板里（每次请求都会求值）
{{(function(){var p=Number(page);if(!(p>0)){p=1;}p=Math.floor(p);
   try{source.put(String.fromCharCode(104,103,112,103),String(p));}catch(e){}return p;})()}}
```

```js
// loginUrl 里
function pageDiag(){
  var K = String.fromCharCode(104,103,112,103);   // "hgpg"
  var v = String(source.get(K));
  java.longToast('最近一次请求页码：' + (v===''||v==='null' ? '（无记录）' : v));
  return v;
}
```

读法：

| 显示 | 含义 |
|---|---|
| 无记录 | App 没走到 URL 模板替换（规则/字段被覆盖？） |
| 长期 `1` | App 只请求过第 1 页 → **UI 层没触发翻页**（不是规则问题） |
| 出现 `2+` | 翻页链路正常，问题在别处 |

### 4.1 为什么键名要用 `String.fromCharCode`

这段表达式要嵌进**单引号 JS 字符串**（`'/vodshow/'+type+o+'------{{...}}---.html'`）。
表达式内部若出现任何引号（`'hgpg'`），就会**提前闭合外层字符串**导致语法错。
`String.fromCharCode(104,103,112,103)` 产出的仍是 `"hgpg"`，但源码里零引号。

这是「零引号纪律」的一个具体应用：**能被嵌进字符串的代码片段，内部不允许出现任何引号。**

## 6. 避坑清单

| # | 坑 | 后果 | 对策 |
|---|---|---|---|
| K1 | 只看 `debug_source` 就下结论 | debug 默认 page=1，**永远看不出翻页问题** | 必须手动用 `::/xxx/2/` 指定第 2 页 |
| K2 | 空页一律 `return []` | 偶发限流被当"到底"，永久停翻页 | 区分真越界与空壳页 |
| K3 | `{{page}}` 不做归一化 | `null` 进 URL → 站点返回空壳 | `Number(page)` + `>0` |
| K4 | 分页 URL 拼在 `.html` 后面 | 站点对畸形 URL 返回 200 正常页 → 永远第 1 页 | 页码必须落在正确段位 |
| K5 | 用固定文件名/固定 URL 缓存 | 多页互相覆盖 | 缓存键含页码/书籍 id |
| K6 | 只加 `retry` 不加 `timeout` | 慢页拖垮整轮 | 两者一起加 |
| K7 | 在 `{{}}` 里写带引号的 JS | 破坏外层单引号字符串 | `String.fromCharCode` 拼常量 |

## 7. 通用结论

1. **"站点不给数据"与"App 不再请求"是两件事**，必须用 HTTP 日志 + 自检变量分开证明。
2. **翻页类规则的失败必须显性化**：返回空数组 = 告诉 App「没有更多」，这是**不可逆**的。
   真到底才返回空，其余一律抛错。
3. **给规则加可观测性**（写变量 + 面板按钮）比反复猜测快一个数量级。
4. **零引号纪律要贯彻到"会被嵌套的代码片段"**，不只是顶层字段。
