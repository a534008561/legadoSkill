## 二十余个版本换来的三句话

1. **正文语种由「铸 key 那次请求的 Cookie」决定**（`transmode=chinese`），
   不是读正文时带的 Cookie；抄错一次，后面 degloss / squeeze / 分段 / 排版全在擦屁股。
2. **中文目录在响应的 `oridata` 字段**，`data` 是越南语；只读自己预期的字段会得出完全错误的结论。
3. **正文「一整段」有三个关口**：规则输出 → 净化链路（这个 App 比上游激进，会把段落合并）
   → 渲染层（TextView 不给 `<p>` 间距，只有 `<br/>` 换行）。修「怎么切」是没用的。

## 已实现的能力

- 正文稳定中文（`transmode=chinese` 铸会话；对照版有 `<i t='中文'>` 兜底还原）
- 目录中文章名（`oridata`）+ 🔑/🔒 双态解锁标记（`vip` / `unvip`，与服务端 `unvip` 计数交叉校验）
  —— v11.11 修复：标记解析从「平铺扫描」改为「结构化分隔符解析」，见下方
- 章节 ID 用真编号（`序号+雪花ID` 混合，按「紧邻章名左槽、更长者优先」解析，`#s=` 片段备用）
- 分段自适应（五种切法打分选最优，覆盖空行型/标签型/制表符型三种来源）
- 登录面板（账密 + Cookie 粘贴 + 状态检查 + 退出），线路切换带自检
- 详情页来源列表（不含网址，可换源保进度）

## v11.11 修复：分隔符型目录数据的解析陷阱（2026-10-08）

**报障**：《神豪从高考后开始》faloo 来源，部分目录的 🔑/🔒 标记缺失（**不是章节缺失**）。

**根因**：站点目录数据格式为 `-//-` 分记录、`-/-` 分字段：
```
[序号, 章节ID, 标题, 状态?] -//- [序号, 章节ID, 标题, 状态?] -//- ...
状态 = unvip(已解锁🔑) / vip(未解锁🔒) / 缺省(免费)
```
而书源的 `pseg()` 是 v9.x 遗留的**平铺扫描**——把整份数据 `split('/')` 切开再猜字段。
faloo/770959 实测 **5551 章里 4384 章标题含 `/`**（如 `h073 vòng bằng hữu quan tuyên?2/30`），
这些记录被切碎 → 状态槽错位 → 🔑 丢失、标题截断。

| 指标 | 修复前 | 修复后 | 服务端字段 |
|---|---|---|---|
| 🔑 数量 | 1081 | **5460** | `unvip=5460` ✅ |
| 标题含 `/` | 截断 4384 个 | 完整 | — |
| 中间条目 | 9939 | 5551 | — |
| `n=` 参数 | 9939（错） | 5551（对） | — |

**修复**：`pseg()` 改为结构化解析（`split('-//-')` + `split('-/-')`），
保留旧逻辑为 `psegFlat()` 回退；三处同步替换
（`ruleToc.chapterList` / `ruleContent.content` / `ruleBookInfo.init`）。

**回归**：10 来源样本矩阵 —— 9 个逐字节一致；ptwxz 反而修正 1 条
（旧版把标题含 `/` 的 1 章拆成 2 条）。

## v11.12 修复：目录回归「站点原始数据」（2026-10-08）

**报障**：《镇国战神》(69shu/10044050) 第 3 章显示成第 100 章。

**根因**：旧逻辑对越南文标题做「提取章节号 → 重写为『第 N 章』」的**二次加工**。
标题 `Thứ 3 chương 100 ức ngồi ở kia một bàn`（第3章 100亿坐在那一桌）里的
「chương 100」被 `vnNum()` 正则当成章节号 → 抓出 100。同类误判全书 **30 处**
（第36→6、第701→3000、第1198→1…），凡标题含「chương N / N ức / N 个 / N 年 / N%」全部错位。

**修复**：删掉整段「重编号」逻辑（`vnNum`/`RE_VN1~3`/`prevK`/`usedN` 全移除），改为：
- 有中文（响应顶层 `oridata`，与 `data` 一一对齐）→ **用中文**
- 没有中文 → **原样用站点越南文**
- 会员状态（第 4 字段 `unvip`/`vip`）→ **🔑 / 🔒 前缀**

目录内容与官方 App 完全一致，不再有第二次加工。
