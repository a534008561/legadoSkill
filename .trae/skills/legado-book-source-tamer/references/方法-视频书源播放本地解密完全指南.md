> 2026-10-13 从番茄短剧·漫剧书源（4 次报障、7 个版本迭代）提炼
> 蓝本：github.com/ch6vip/fqapp（番茄短剧/漫剧/听书/漫画 聚合客户端，Rust 核心逆向）
> 成品：🍅番茄短剧·漫剧(APP)（check_source 1/1，LegadoTeam + legado-E 双版本实测可播）

---

## 0. 一句话总结

视频书源做不出来，九成不是"找不到接口"，而是"最后一公里"没打通：
接口、签名、解密都能跑通，debug 也显示 file:///xxx.mp4，但播放器就是加载一下就停。

本篇把"能播放"需要的完整条件链逐条列清楚，缺任何一条都播不了。

---

## 1. 整体架构

```
发现/搜索/详情/目录  ->  官方 App JSON 接口（aid=8662）
                              |
播放  ->  短剧通道（aid=1967）拿 video_model
                              |
          main_url(base64明文URL) + spade_a(CENC密钥)
                              |
书源侧：下载 -> AES-CTR 逐样本解密 -> 修 box -> 写本地文件
                              |
          返回 file:// 绝对路径 -> ExoPlayer 播放
```

为什么必须本地解密：ExoPlayer 不带 DRM/解密能力，见到 CENC 加密文件直接拒绝。

## 2. 播放链路完整条件链（本篇核心）

以下 10 条全部满足才能播放，按踩坑频率从高到低排列。

### 条件 1：返回的 file:// 路径必须是当前 App 的真实缓存目录

这是最隐蔽的坑（本次第 4 次报障才找到）：

错误写法（硬编码 Team 版包名）：
    return 'file:///storage/emulated/0/Android/data/com.legado.app.release/cache' + path;

正确写法（动态探测，内联在规则顶部，不要放 jsLib）：
    var FVCD='';
    try{ java.readFile('/'); }catch(e0){
      var mm=String(e0).match(/([/]storage[/]emulated[/]0[/]Android[/]data[/][^/]+[/]cache)/);
      if(mm) FVCD=mm[1];
      if(!FVCD){
        var m2=String(e0).match(/([/]data[/]data[/][^/]+[/]cache)/);
        if(m2) FVCD=m2[1];
      }
    }
    if(!FVCD) FVCD='/storage/emulated/0/Android/data/com.legado.app.release/cache';  // 兜底
    return 'file://' + FVCD + path;

原理：java.readFile('/') 抛的 FileNotFoundException 消息里带完整绝对路径：
    FileNotFoundException: /storage/emulated/0/Android/data/com.legado.app.release/cache: open failed: EISDIR

为什么最隐蔽：在自己手机上完全正常（包名恰好匹配），换个版本/包名就挂。

不同版本的包名对照：

| 版本 | 包名 |
|---|---|
| LegadoTeam release | com.legado.app.release |
| LegadoTeam debug | com.legado.app.debug |
| legado-E (Luoyacheng) | io.legado.app |

必须内联在规则顶部，不能放 jsLib，原因见条件 8。

### 条件 2：CENC 的 box 要清除"一组"，不是一个

只改 encv/sinf 的话，Team 版能播但 E 版拒绝。

完整清单（6 个 box 都要处理）：

| 原 fourcc | 改为 | 作用 |
|---|---|---|
| encv | hev1 | 视频轨入口（★不是 hvc1，见条件 3） |
| enca | mp4a | 音频轨入口 |
| sinf | free | DRM 描述（含 tenc） |
| tenc | 随 sinf 一起清除 | 加密模板 |
| senc | free | 样本加密索引（★Team 宽容 / E 严格） |
| saiz | free | 辅助信息大小（★同上） |
| saio | free | 辅助信息偏移（★同上） |
| schm | 一并清除 | Scheme 标记 |

本次实测（修复前 vs 修复后）：
    修复前: hev1=true mp4a=true sinf=false tenc=false senc=true saiz=true saio=true   <- E 版拒绝
    修复后: hev1=true mp4a=true sinf=false tenc=false senc=false saiz=false saio=false <- 可播

诊断信号："Team 能播 / E 版不能播" = 直接排除了"文件损坏/解密错误"，把范围缩小到"播放器严格程度差异"。

排查手法：解密后 dump 文件，grep 所有加密相关 fourcc 逐个确认，不要只查 encv/sinf。

### 条件 3：encv 要改成 hev1，不是 hvc1

| fourcc | 语义 | 后果 |
|---|---|---|
| hvc1 | 参数集(VPS/SPS/PPS)在 hvcC box 里 | 若实际内嵌在样本里，MediaCodec 拒绝整条视频轨，只有声音没画面 |
| hev1 | 参数集内嵌在样本里 | 正确 |

判定依据：样本里是否有参数集 NAL（类型 32/33/34），有则用 hev1。

ffmpeg 宽容度极高会掩盖这个问题，必须用真实播放器验证。

### 条件 4：文件必须完整写入且能被读回

    var path = String(java.downloadFile(outHex, 'https://x/'+cacheKey+'.mp4,{"type":"mp4"}'));
    var fb = java.readFile(path);   // 相对路径能读
    if(!fb || fb.length < 100000) throw new Error('文件写入失败');

路径语义对照：

| 操作 | 用相对路径 | 用绝对路径 |
|---|---|---|
| java.readFile('/x.mp4') | 内部自动拼 cachePath | 返回 null（getFile 会再拼一次前缀） |
| 播放 file:// | - | 必须用绝对路径 |

磁盘满会静默失败：ENOSPC (No space left on device)。4MB 视频 hex 通道峰值约 4 倍文件大小（hex 字符串 2 倍 + byte[] 2 倍），要给足空间。

### 条件 5：必须有重试机制（应对 CDN 抖动）

    java.ajax(url + ',{"type":"hex","retry":2,"headers":{...}}')

视频 CDN 会间歇性 Connection reset by peer。CDN 域名不能互换（换域返回错误页，签名与主机绑定），只能同域重试。

### 条件 6：默认画质选最小可用档（内存 + 时间）

| 档位 | 体积 | 解密耗时 | 内存峰值 |
|---|---|---|---|
| 360p | 7MB | ~5s | ~28MB 推荐 |
| 480p | 11MB | ~7s | ~44MB |
| 720p | 13MB | ~9s | ~52MB |
| 1080p | 23MB | ~16s | ~92MB 易 OOM |

hex 通道内存峰值约等于文件大小 x 4。默认 360P，画质在登录界面可调。

### 条件 7：codec 必须避开 bytevc2

    // bytevc2 = ByteDance 私有编码（bv2C），Android 解码器不支持
    // 表现：只有音频没有画面，或直接黑屏
    if (String(v.codec_type).indexOf('bytevc2') >= 0) continue;

同站不同 aid 的编码策略可能完全不同（本次最大发现）：

| 通道 | 360~720p | 1080p |
|---|---|---|
| aid=8662（phoenix） | bytevc2（解不了） | bytevc1 |
| aid=1967（shortplay） | bytevc1（全档可播） | bytevc1 |

发现低档位全不可播时，先横向试 aid/host/channel，别急着下"站点不支持"的结论。

### 条件 8：jsLib 作用域不等于规则作用域

错误写法（放 jsLib 里，规则调用时 java 不是同一个对象）：
    function FV_cacheDir(){ try{ java.readFile('/'); }catch(e){...} }

正确写法（内联到规则顶部）：
    var FVCD='';
    try{ java.readFile('/'); }catch(e0){ ... }

| 环境 | java 可用性 |
|---|---|
| eval_js 顶层 | 可用 |
| 函数写入 jsLib 字段后调用 | 不可用（java 解析成 Java 包命名空间） |
| 函数体写在规则 @js: 里 | 可用 |

通用规则：jsLib 里只放纯计算函数（参数全显式传入），任何碰 java/source/cache 的逻辑都内联到规则里。

### 条件 9：字节回写必须用 System.arraycopy

错误写法（Rhino 报"无法将 255 转换为 java.lang.Byte"）：
    bytes[off+i] = dec[i] & 255;

正确写法（唯一可靠方式）：
    Packages.java.lang.System.arraycopy(dec, 0, bytes, off, size);

### 条件 10：文件名必须唯一 + 可缓存复用

    var cacheKey = 'fv_' + vid + '_' + defName.replace('p','');
    var cachedPath = String(source.get(cacheKey) || '');
    if(cachedPath && java.readFile(cachedPath).length > 100000){
      return 'file://' + FVCD + cachedPath;   // 秒播
    }

固定文件名（如 fqa.m4a）会导致多剧多章互相覆盖、缓存全失效。

## 3. 完整可用的 ruleContent 模板

    @js:
    (function(){
    // 条件1：动态探测缓存目录（内联）
    var FVCD='';
    try{ java.readFile('/'); }catch(e0){
      var mm=String(e0).match(/([/]storage[/]emulated[/]0[/]Android[/]data[/][^/]+[/]cache)/);
      if(mm) FVCD=mm[1];
      if(!FVCD){ var m2=String(e0).match(/([/]data[/]data[/][^/]+[/]cache)/); if(m2) FVCD=m2[1]; }
    }
    if(!FVCD) FVCD='/storage/emulated/0/Android/data/com.legado.app.release/cache';

    try{
      var vid = HG_VID(String(baseUrl));
      if(!vid) throw new Error('章节参数缺失');
      var d = FV_playData(java, vid);
      if(!d) throw new Error('获取播放地址失败');
      if(d.bv2c) throw new Error('该清晰度使用私有编码 bv2C，安卓不支持');

      var defName = d.def;
      var cacheKey = 'fv_' + vid + '_' + defName.replace('p','');

      // 条件10：缓存复用
      var cachedPath = '';
      try{ cachedPath = String(source.get(cacheKey) || ''); }catch(e0){}
      if(cachedPath){
        try{
          var cb = java.readFile(cachedPath);
          if(cb && cb.length > 100000){
            cb = null;
            try{ Packages.java.lang.System.gc(); }catch(e01){}
            java.toast('使用本地缓存，秒播');
            return 'file://' + FVCD + cachedPath;
          }
          cb = null;
        }catch(e02){}
      }

      java.toast('正在解密视频（' + defName + '）');
      var keyHex = RG_cencKey(java, d.spadeA);

      // 条件5：retry 重试
      var hexStr = String(java.ajax(d.url + ',{"type":"hex","retry":2,"headers":{"User-Agent":"com.phoenix.read/72932"}}'));
      if(hexStr.length < 1000) throw new Error('视频下载失败（响应过短）');

      var bytes = RG_decodeHex(hexStr);
      hexStr = null;
      try{ Packages.java.lang.System.gc(); }catch(g0){}

      var r = RG_decrypt(bytes, keyHex);
      if(r.samples < 100) throw new Error('解密异常：样本数 ' + r.samples);
      if(r.bv2c) throw new Error('该清晰度使用私有编码 bv2C');

      var outHex = RG_encodeHex(bytes);
      bytes = null;
      try{ Packages.java.lang.System.gc(); }catch(g1){}

      var path = String(java.downloadFile(outHex, 'https://x/' + cacheKey + '.mp4,{"type":"mp4"}'));
      outHex = null;
      try{ Packages.java.lang.System.gc(); }catch(g2){}

      var fb = java.readFile(path);
      if(!fb || fb.length < 100000) throw new Error('文件写入失败');

      try{
        source.put(cacheKey, path);
        var kl = String(source.get('fv_keys') || '');
        var ka = kl ? kl.split(',') : [];
        if(ka.indexOf(cacheKey) < 0) ka.push(cacheKey);
        source.put('fv_keys', ka.join(','));
      }catch(e9){}
      RG_trimCache(java, source);

      return 'file://' + FVCD + path;
    }catch(e){
      return 'DIAG_ERR: ' + String(e.message || e);
    }
    })()

## 4. 排查 Checklist（播不了时按此顺序查）

按本次 4 次报障的实际顺序：

| # | 检查项 | 方法 | 通过标准 |
|---|---|---|---|
| 1 | debug 输出的路径字符串 | debug_source --URL 看正文内容 | file:///真实缓存路径/xxx.mp4（有目录前缀） |
| 2 | 文件真的写入了 | java.readFile(path) | 长度 > 100KB |
| 3 | 文件结构完整 | dump 前 200KB，grep fourcc | hev1/mp4a 在，encv/enca/sinf/tenc/senc/saiz/saio/schm 全不在 |
| 4 | 样本数正确 | 解密返回值 | stsz#0.count + stsz#1.count === samples |
| 5 | 不是 bytevc2 | 看 video_model | codec_type === bytevc1 |
| 6 | 零第三方类 | grep -c "hutool 或 bouncycastle" | 0（E 版 R8 裁剪会崩） |
| 7 | 零硬编码路径 | grep "com.legado" | 只允许出现在兜底默认值 |
| 8 | 有 retry | 看 ruleContent | 下载那行含 "retry":2 |
| 9 | 磁盘有空间 | 看报错 | 无 ENOSPC |
| 10 | check_source | MCP 校验 | 1/1 |

第 1 条最重要：debug 输出的实际字符串往往就是答案。本次 file:///xxx.mp4 缺目录前缀，一眼就该看出来，我却先去查文件结构绕了三轮。

## 5. 构建闸门（防止再犯）

    闸门1  文本卫生    零双引号/零反斜杠/零非BMP/零HTML实体
    闸门2  依赖安全    零第三方类 + 顶层声明全为 java/javax/android
    闸门3  JS 语法     每个 JS 块单独 node --check
                        （jsLib/loginUrl/ruleContent/ruleSearch/ruleExplore/ruleBookInfo/ruleToc）
    闸门4  JSON 结构   必需字段齐全
    闸门5  零硬编码    全文搜 com.legado 或 /storage/emulated
                        -> 只允许出现在"兜底默认值"

手改长 JSON 里的 JS 代码等于高危操作。本次加 retry:2 时多插一个 + 号，导致"在参数列表的后面缺少右括号"。

任何修改后：立刻 node --check；导入后回读 App 内实际存储版本再验一次；不要相信"文件看起来对"。

## 7. 性能速查

| 操作 | 方案 | 耗时 |
|---|---|---|
| hex 转 bytes（4MB） | new BigInteger(hex,16) | 330ms |
| bytes 转 hex（4MB） | new BigInteger(1,b).toString(16) | 103ms |
| hex 转 bytes（纯 JS 兜底） | 逐字节循环 | 10439ms/512KB 不可用 |
| AES-CTR 解密（4MB） | JCE AES/CTR/NoPadding | 约 2.4s |
| SM3（纯 JS） | - | 与 BC 版逐字节一致 |

纯 JS 兜底只保底，性能敏感操作一律用 Java 标准库（BigInteger/ByteArrayOutputStream/System.arraycopy）。

## 8. 四条铁律

1. file:// 路径必须动态探测，硬编码包名等于跨版本必挂
2. CENC 要清 6 个 box 不是 1 个（encv/enca/sinf/tenc/senc/saiz/saio/schm）
3. jsLib 只放纯计算，碰 java 的逻辑一律内联到规则
4. "某版本能用"是最强反证线索，直接锁定版本差异，别反复查解密逻辑
