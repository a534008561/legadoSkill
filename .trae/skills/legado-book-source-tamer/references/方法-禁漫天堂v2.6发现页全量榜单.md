# 禁漫天堂 v2.6：发现页补全全量排行榜

> 261128 用户要求「补全排行榜」。本版把 jmtt 发现页的榜单从「人气日/周/月/年 4 条」补成站点全部 **4 榜别 × 4 周期 = 16 条/类型**。

## 一、站点契约（App 内 java.ajax 实测）

排行榜页 `/{seg}/rank` 的 HTML 带 `data-rp-real`，明牌：

```json
{"themes":["comic","novel","video","actor","drama"],
 "sorts":["popular","favorite","new","finished"],
 "periods":["day","week","month","year"]}
```

页面按钮中文标签：

- `popular` → 人气榜
- `favorite` → 收藏榜
- `new` → 新作榜
- `finished` → 完结榜
- `day/week/month/year` → 日榜/周榜/月榜/年榜

★关键实测：SSR 直接吃 query 参数 `?sort=<sort>&period=<period>`，返回对应 TOP30，不需要走 `/rank/board` JSON API：

- `/novel/rank?sort=favorite&period=week` 首条「女神攻略调教手册」，与 popular-day 的「豪乳老师刘艳」不同；
- `/novel/rank?sort=new&period=month`、`/novel/rank?sort=finished&period=year` 也都返回不同书籍；
- `/comic/rank?sort=favorite&period=week`、`/mv/rank?sort=new&period=month`、`/drama/rank?sort=finished&period=year` 同样返回有效 TOP30。

`page` 页面 UI 的 `is-active` 仍显示 popular，这是站点前端 tab 状态没跟着 query 改，**不影响 SSR 内容**，不要据 `is-active` 误判参数无效。

## 二、书源改造

`addRankEntries()` 从固定 4 条改成双层循环：

```js
var SORTS = [['人气','popular'], ['收藏','favorite'], ['新作','new'], ['完结','finished']];
var CYCLES = [['日榜','day'], ['周榜','week'], ['月榜','month'], ['年榜','year']];
for (s in SORTS) for (p in CYCLES) {
  var u = "{{page>1?(jmHost(source)+'/search/__jmrank_end__'):(jmHost(source)+'/" + seg + "/rank?sort=" + sVal + "&period=" + pVal + "')}}";
  rows.push({title:'🏆 '+T+'·'+sName+pName, url:u, ...});
}
```

- 仍保持「榜单不用下拉选择」：16 条全是 `type:'url'` 直接入口。
- 每个榜别的第一条加 `layout_wrapBefore:true`，4 个榜别自动分成 4 行。
- 第 2 页仍用原 `{{page>1?...__jmrank_end__}}` 守卫，因为榜单只有 TOP30，无分页。
- 未采用 `/rank/board` JSON API：那是给站点前端 pushState 用的，`ruleExplore` 目前按 HTML 卡片（`a.jm-rkrow` 等）解析，SSR query 已足够。
- `actor`（女优榜）虽然存在于 `data-rp-real.themes`，但不属于本源四模式书籍内容，未加入，避免幽灵书。
