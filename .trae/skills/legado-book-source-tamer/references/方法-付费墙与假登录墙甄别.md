## 一、三种"看不到内容"的本质区别

| 类型 | 服务端行为 | 登录后可见？ | 书源该做什么 |
|---|---|---|---|
| **登录墙**（真） | 未登录 302 到 login / 返回"请登录" | ✅ 可见（免费内容需登录） | 做登录功能，正常出正文 |
| **付费墙**（常伪装成登录墙） | 返回**替换后的占位文案**，200 OK | ❌ 仍锁定 | **不要做无谓的登录功能**；给换源提示 |
| **版权缺失** | 接口返回空/字段不存在 | ❌ 全平台都无 | 明确"本站无此书正文"，引导换源 |
| **死链/脏数据** | 302 回详情页 / 404 | — | 目录侧过滤掉该章 |

**最危险的是第二类伪装成第一类**：文案写"请登录后在继续阅读本部小说！"，于是你注册、登录、加书架，第 100 章**照样锁**。63sg 和 35sw 两次都是这么浪费掉半天的。

## 二、★假登录墙的甄别流程（唯一可靠做法）

```
① 匿名访问被锁章 → 记下锁定的第一个章号 N 与响应体（存证）
② 走站点注册接口注册一个号（多数站无验证码：63sg /user/public/register.html、
   35sw /user/public/register.html、book630 /qs_register_go.php、ppxsw /qs_register_go.php）
③ 登录（务必确认登录态真的生效——用"书架页含退出/永久书架"这类仅登录态才渲染的元素判据）
④ 带会话 Cookie 重新请求【同一个章 N】
   ├─ 出正文 → 真登录墙 → 把登录功能做进书源
   └─ 仍出"请登录后继续阅读" → ★付费墙 → 停止投入，改做提示
⑤ 双站对照（有镜像时）：www 与 m 都试一遍（63sg 两站同样锁定 → 排除"移动站才免费"）
```

**第 ③ 步的坑**：登录"成功"的判据不能只看接口返回。
63sg 登录接口返回"登录成功"文案，但要用**书架页**去复核会话是否真生效；zhaoshu 更狠——POST 302 跟随后的响应体被改写，必须再 **GET 复核**（看页头有没有"退出"链接）。

**判据优先级**（通用铁律）：

```
仅登录态才渲染的元素（退出链接 / /auth/logout.php）
  > 登录入口链接（未登录页也有，易误判）
  > 页面文案哨兵（副标题这类常驻文本，最易误判）
```

> zhaoshu 那次事故就是把"登录你的找书啦账号"（登录框副标题，**登录页必含**）当成未登录哨兵 → `zsToken()` 永远取不到 → 登录永远失败。**哨兵串必须验证"是不是目标页固有内容"。**

## 三、付费墙的三种粒度

### 粒度 1：书级前缀免费（最常见）

63sg：每本**仅前约 65 章免费**，其后统一"~~~~~请登录后在继续阅读本部小说！~~~~~"。
35sw：452401 前 44 章 / 7447 前 50 章。

**实现**：正文规则检测到锁文案 → 替换成对用户有意义的提示。

```javascript
// 63sg 生产写法：把误导性文案替换为明确结论
content = String(content).replace(/~*请登录后在继续阅读本部小说!*/g,
  '【本站为付费站：此书仅前约 65 章免费，后续需在本站购买。本提示已替代原站"请登录"误导文案】');
```

**为什么不直接返回空？** 因为 Legado 的 `ContentEmptyException("内容为空")` 会让用户以为源坏了、反复重试。**给一句人能读懂的话，永远优于报错。**

### 粒度 2：章级偶发缺失（转码失败 / 手打中）

- 35sw：部分章节 `#novelcontent` 为空（站点侧转码失败）→ 给"请刷新重试"提示；
- 77shuku / aaawz：**"正在手打中…"** 占位章（连载书正常现象，可能几小时后就有了）。

→ 保留占位提示 + 剔除其中的网址，**不要过滤整章**（否则用户以为缺章）。

### 粒度 3：整本无正文（版权/来源缺失）

- qmzw5 / boluomao1：某类书（疑似晋江版权书）接口返回空 → 100 章之后全无正文；
- ggd8：C 类占位书（约 60% 的书属于此类）走 `/ajaxchapter/` 也返回空。

→ 返回**"换源指引"**而不是错误：

```
【本站无此书正文（疑似版权限制）。建议：
 ①在书源列表换一个源打开本书；②或从本站目录前段试读。
 若为连载书，可能稍后补齐。】
```

Legado 的实用技巧：**换源**。提示里明确写"长按本书→换源"，用户一点就通（比我们自己想办法强）。

## 四、占位页与 SEO 假正文陷阱

**这是最阴的一类**：占位页里塞了"书名 + 完整简介 + 展开全部"来骗搜索引擎。如果正文规则只按"有没有文字"判空，就会把**简介当正文**渲染给用户。

ggd8 的三形态实测：

```
A 类：页面直含正文                        → 直接读
B 类：内联 addcontent() 追加              → 提取 $('#ctxt').append('…') 字符串（注意 '/p>' 残渣要清）
C 类：占位"章节内容获取中"（60% 的书！）   → 必须走 /ajaxchapter/?cid={ID} 接口
      ★SEO 陷阱：C 类占位页的 #ctxt 里是【书名+简介+展开全部】垃圾
      → 规则里判断到 '章节内容获取中' 就【跳过页面回退】，直接走接口
      → 接口也返回空 → 才是真的无正文
```

**四条通用防御**：

1. **判据要"内容专属"而不是"页面专属"**：用 `章节内容获取中` 这类正文区专有串，而不是"页面有没有 h1"；
2. **正文长度 + 与简介的重合度**双判：`intro.indexOf(content.substring(0,30)) >= 0` → 判定假正文；
3. **优先走接口旁路**：占位页几乎都伴随一个 ajax 接口（从页面 JS 里找 `getchapter()`/`$.post` 的 URL）；
4. **不要把"有字"当"有正文"**。

另一类：`aaawz` 的"手打中"章、`lianaiya` 的 token 过期页（"请刷新页面"）也都是**看起来像正文的假正文**——用词表 + 长度双判。

## 五、正文规则的用户提示设计（文案模板）

原则：**说清"是什么 + 为什么 + 用户能做什么"**，一行结论一行操作。

```javascript
// 模板（零双引号纪律：用 fromCharCode(10) 造换行）
var NL = String.fromCharCode(10, 10);
return NL
  + '【本章无法阅读】' + NL
  + '原因：本站为付费站，此书仅前约 ' + FREE_N + ' 章免费。' + NL
  + '你可以：' + NL
  + '  ① 长按本书 → 换源（推荐）' + NL
  + '  ② 在本站购买后，本书前段仍可试读' + NL
  + '  ③ 稍后重试（手打更新类站点可能补齐）' + NL;
```

四个细节：

- **开头留两个换行**：Legado 正文排版需要，避免提示与上一章末尾粘连；
- **不要用 `!!!!` 或全角感叹号开头**：会被 Legado 的 `ContentEmptyException` 判定链误伤（有的版本按"内容像错误"处理）；
- **不要把网址写进提示**（用户复制不了、且会被广告清理正则误伤）；要写就写纯文本 + 说明"长按复制"；
- **提示只出现在正文规则**。`intro`/列表字段保持纯文本（`ruleSearch.intro` 里塞标签会露出来）。

如果站点有可用交互通道，提示可以升级成按钮（见[详情页交互按钮选型树](方法-详情页交互按钮选型树.md)）——例如"▶ 在浏览器打开本书"、"🔄 重新取签名直链"。

## 六、章节级兜底：不要让整个目录崩掉

**原则：坏一章不能崩整本，坏一页不能崩全目录。**

```javascript
// chapterList 里过滤"必然打不开"的脏章（63sg：/read/{id}/{卷}/0.html，标题却写第573章）
var keep = [];
for (var i = 0; i < list.length; i++) {
  var u = String(list[i].url || '');
  if (!/\/0\.html$/.test(u)) { keep.push(list[i]); }
}
// ★过滤后为空 → 回退原列表（宁可多几章坏链，也不给空目录）
return keep.length ? keep : list;
```

配套三条：

1. **占位项/空 href 过滤**：m.lzjxx 的"本页章节列表结束！"占位项（空 href）、`href` 尾段非纯数字的混入项 → 正则 `^[0-9]+[.]html$` 白名单筛；
2. **302 回详情页的章** = 死章，宁可过滤也别留在目录里（用户点了报"内容为空"体验最差）；
3. **正文规则里给"疑似死链"的兜底文案**（`如果本章打不开，请刷新目录重试`），别让 Legado 抛原始异常。

> 目录顺序、去重、分页的完整纪律见 **[方法-目录顺序与章节去重铁律](方法-目录顺序与章节去重铁律.md)**。

## 七、能不能"顺手支持购买/登录解锁"

**结论：不要。** 三条理由：

1. **技术上无效**：付费内容不在服务端下发给未购买账号，任何规则技巧都拿不到（63sg/35sw 实测登录 + 加书架后第 100 章仍锁）；
2. **法律与道德风险**：绕过付费墙与"破解"仅一线之隔，而"读免费部分"和"绕付费"的边界应由用户决定；
3. **有更好的替代**：Legado 的**换源**机制天然解决"这本书别家有"。书源的正确职责是**如实告知 + 引导换源**。

**该做的**：把 `bookSourceComment` 写清"本站前 N 章免费，其后需购买，无需注册"，并把登录 UI 保留给"确有登录墙"的站（ppxsw 搜索需登录、book630 搜索需登录 —— 那两类是真登录墙，值得做登录）。

## 九、避坑清单

| # | 坑 | 对策 |
|---|---|---|
| 1 | 看到"请登录"就去做登录功能 | 先走第二节甄别流程（注册→登录→复测同章） |
| 2 | 用页面文案当登录态哨兵 | 用"仅登录态渲染的元素"（退出链接优先） |
| 3 | 只看 POST 响应判登录成败 | 302 会改写响应体 → 再 GET 复核 |
| 4 | 把 SEO 假正文当正文输出 | 正文区专有占位串 + 与 intro 重合度双判 |
| 5 | 无正文时直接返回空 | 抛 `内容为空` 会让用户反复重试 → 返回可读提示 |
| 6 | 一章坏 → 整个目录不显示 | 章级过滤 + "过滤后为空则回退"保护 |
| 7 | 过滤过头把正常章滤掉 | 白名单式（只删确定坏的），别黑名单猜 |
| 8 | 提示里塞标签/网址 | 正文可写多行纯文本；列表字段必须纯文本；别放可被误伤的网址 |
| 9 | 试图绕过付费墙 | 技术上无效 + 风险；引导换源才是正解 |
| 10 | 把"缺参数导致的占位"当付费墙 | 先对照接口参数（`?format=g2` 这类），别急着下结论 |
| 11 | 单站复测就下"必须购买"结论 | 有镜像/子站时 www 与 m 都测（63sg 两站同锁） |
| 12 | 忽略"手打中"这类可自愈占位 | 保留提示、说明"可能稍后补齐" |

## 附：一页判定速查

```
"看不到内容"
 ├─ 响应 302 / 返回登录页 HTML ────────► 真登录墙 → 做登录
 ├─ 200 + 文案含"请登录/请购买/VIP"
 │    └─ 注册+登录+复测同章
 │         ├─ 解锁 → 真登录墙
 │         └─ 仍锁 → ★付费墙 → 提示 + 引导换源（不要做登录）
 ├─ 200 + 内容是"书名+简介+展开全部" ──► SEO 假正文 → 找 ajax 接口旁路
 ├─ 200 + "章节内容获取中/请刷新页面" ──► 缺接口/缺参数 → 先补参数再判定
 ├─ 接口 200 但字段空 ────────────────► 版权/来源缺失 → 换源提示
 ├─ "正在手打中" ─────────────────────► 连载未补齐 → 保留提示
 └─ 点击该章 302 回详情页 ─────────────► 死章 → 目录侧过滤
```
