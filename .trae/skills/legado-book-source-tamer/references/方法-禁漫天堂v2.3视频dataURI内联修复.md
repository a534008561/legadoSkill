# 补充-禁漫天堂 v2.3：视频内置播放器修复（data URI 内联 HLS）

> 261128 用户报「视频无法播放」。根因与修复见下；成品 `examples/禁漫天堂_jmtt_v2.3_视频dataURI内联修复.json`。

## 根因（源码级）

- Legado Exo2MediaPlayer 的 `DefaultMediaSourceFactory` 创建 MediaSource 时**只看 URI path 后缀**判 HLS（`.m3u8` → HlsMediaSource，否则 ProgressiveMediaSource），不看 query、不看 Content-Type。
- 本站视频详情 `_detail_.url` 是 `/media/m3u8?url=...&exp=&token=`，**path 末段是 `m3u8`（无点、无 `.m3u8` 后缀）** ⇒ 播放器把 m3u8 文本当 Progressive 文件，加载一下就停。
- 直连 CDN m3u8（从 `url=` 参数 decode 出来）实测 **403**，必须走站点代理；`/media/m3u8.m3u8`、`/media/m3u8/x.m3u8`、`/media/m3u8;ext=.m3u8` 全 404。
- 本地 file 方案也走不通：规则里 `java.getFile(rel)` 恒返回 null（`java.downloadFile` 能落盘并给相对路径、`java.readTxtFile(rel)` 能读回，但 File 对象被 Rhino unwrap 成 null）。

## 正解（Sigma 法，LT/E 双端已实证）

在 `ruleContent.content` 视频分支：

1. 从详情 `_detail_.url` 取代理 m3u8 绝对地址；
2. `java.ajax(p + jmOpt(20000))` 取回 m3u8 文本（`startsWith('#EXTM3U')`）；
3. 逐行校验：所有非注释行必须以 `http(s)://` 开头；`#EXT-X-KEY` 等行里的 `URI="..."` 也必须绝对（data URI 是 opaque origin，相对地址必然失败）；
4. `java.base64Encode(m3)` 后返回 **`data:/stream.m3u8?;base64,<payload>`** —— path `/stream.m3u8` 带 `.m3u8` 后缀，播放器即选 HlsMediaSource；**不要**写成 `data:application/vnd.apple.mpegurl;base64,...`（path 无后缀，仍当 Progressive）。

实测：LT eval 同规则得到 `m3len=15743, b64len=20992, uri=data:/stream.m3u8?;base64,I0VYVE0zVQojRVhULVg`；E `/getBookContent` 返回 21018 字节 data URI，解码后 179 行、86 个绝对 ts、KEY URI 绝对、0 条非绝对行。LT `check_source` 1/1，双端 `saveBookSource` 200。

## 注意

- 正文缓存按 bookUrl+chapter：旧书已缓存的 proxy URL 不会自动变，需要清缓存或换一条线路重新搜书（bookUrl 变）再测；E 已另加 `ability.tekovaki.cc/mv/detail/52217` 验证书。
- 分片 auth_key 有时效，data URI 随正文缓存；缓存很久后重播失效就刷新正文重取。
