# 方法：搜索限频伪装成「接口报错」的甄别与降级

> 来源：桔纸书屋 m.juzhishuwu.net 书源（2026-10-23，App 内 MCP 实测 + Python 对照实验）
> 关联：[[方法-搜索签名失败伪装成空结果]]（同族病：都用「看起来像别的故障」来伪装）

## 0. 一句话结论

杰奇CMS 的搜索限频**不返回 429，而是返回 HTTP 200 + 一个「出现错误！」页面**，
错误文案是「对不起，两次搜索的间隔时间不得少于 30 秒」。

这导致三个误判方向，全都要靠对照实验排除：

1. 误判为「搜索规则写错了」（因为 `tr#nr` 数量为 0）
2. 误判为「关键词没这本书」（因为没结果）
3. 误判为「cookie 卡了」（因为清 cookie 有时"好像"能好）

**真相：这是 IP 级滑动窗口限频，与 cookie / UA 完全无关。**

## 1. 现象与判据

### 1.1 错误页特征（974 字节，极短）

```html
<title>出现错误！</title>
...
出现错误！ 出现错误！
错误原因：对不起，两次搜索的间隔时间不得少于 30 秒
请 返 回 并修正 [关闭本窗口]
版权所有© 桔纸书屋
```

### 1.2 三条判据（缺一不可）

```python
is_err   = '出现错误' in html                       # 标题
is_short = len(html) < 2000                        # 正常搜索页 ≥ 5000
no_rows  = html.count('id="nr"') == 0              # 无结果行
```

只有 `is_err` 一条不够 —— 正常「0 结果」页也 `no_rows==0`，但长度 ≥ 4700 且标题正常。

### 1.3 正常「0 结果」页长什么样（别混淆）

```html
<title>汉武帝传记-搜索-桔纸书屋</title>
...
搜索结果 文章名称 最新章节 作者 字数 更新 状态 1/1 1 << 1 >> 1
```

- 长度 ~4700（含导航/页脚）
- 标题是 `<关键词>-搜索-桔纸书屋`
- 有分页条 `1/1`

## 2. 对照实验（必须做，否则一定误判）

### 2.1 实验设计

| 组 | 变量 | 预期（若是 cookie 限频） | 预期（若是 IP 限频） |
|---|---|---|---|
| A | 同一 session 连发 3 次 | 第 2 次起报错 | 第 2 次起报错 |
| B | 每次新建 session（无 cookie） | 全部成功 | 第 2 次起报错 |
| C | 每次伪造 `jieqiVisitTime=jieqiArticlesearchTime%3D1` | 全部成功 | 第 2 次起报错 |
| D | 换 UA | 全部成功 | 第 2 次起报错 |
| E | 静默 30~45 秒后单发 1 次 | 成功 | 成功（滑动窗口过期） |
| F | 静默后连发 5 次 | 全成功 | 前 1~2 次成功，之后报错 |

### 2.2 实测结果（本站）

| 组 | 结果 | 结论 |
|---|---|---|
| A 同 session 连发 | 第 2 次起 100% 报错 | — |
| B 每次新 session | **第 2 次起仍报错** | 排除 cookie |
| C 伪造旧时间戳 | **第 2 次起仍报错** | 排除 cookie 时间戳 |
| D 换 UA（Windows Chrome） | **仍报错** | 排除 UA |
| E 静默 45s 后单发 | 成功 | 支持滑动窗口 |
| F 静默 45s 后连发 5 次 | **全部成功**（遮天/完美世界/斗罗大陆/大奉打更人/诡秘之主） | 窗口确实是 30s 级 |

★ 关键发现：**静默足够久之后，连发多次是能过的** —— 说明不是"每次搜索都要间隔 30 秒"，
而是"上一个窗口内搜索次数超限"才拦。窗口内的配额实测约 1~2 次。

### 2.3 一个反直觉现象

同一关键词**有时成功有时失败**，与关键词本身无关：

```
完美世界   → 失败
完美世界   → 成功（几秒后）
完美       → 成功
斗破苍穹   → 失败
斗破苍穹   → 成功（几十秒后）
```

所以**不能靠"这个关键词搜不到"来判断规则错**。必须用「已知存在且刚搜成功过的词」做基准。

## 3. 书源层的处置

### 3.1 能做：bodyJs 自动重试（有限）

```json
"searchUrl": "https://m.juzhishuwu.net/modules/article/search.php?searchkey={{key}}&searchtype=articlename&page={{page}},{\"charset\":\"gbk\",\"bodyJs\":\"...\"}"
```

```js
// bodyJs：result 是响应 body 字符串
(function(){
  var n=0, body=String(result);
  while(body.indexOf('出现错误')>=0 && n<2){
    n++;
    try{ Packages.java.lang.Thread.sleep(3000); }catch(e){}
    body = String(java.ajax(baseUrl));   // baseUrl 是当前请求 URL
  }
  return body;
})()
```

⚠ 实测结论：**这个方案基本无效**。
- `bodyJs` 里能拿到 `java.ajax` / `baseUrl` / `Packages.java.lang.Thread.sleep`（已实测）
- 但窗口是 30 秒级，重试 2 次 × 3 秒完全不够
- 重试 3 次 × 3 秒也全部失败（实测「阿尔法狗/量子纠缠/汉武帝」三词，各重试 2 次均仍报错）

⇒ **不要在 bodyJs 里做长时间 sleep**（会卡住搜索线程，Legado 搜索有 30 秒 withTimeout）。
   正确做法是**写进 comment 告知用户**，靠用户手动控制搜索节奏。

### 3.2 不能做：绕过限频

已实测失败的手段：

| 手段 | 结果 |
|---|---|
| 清 cookie（`CookieStore.removeCookie`） | 无效 |
| 伪造 `jieqiVisitTime=jieqiArticlesearchTime%3D1` | 无效 |
| 伪造 `jieqiVisitTime=`（空） | 无效 |
| 换 UA（Android / Windows Chrome） | 无效 |
| 加 `&_r=<随机数>` 绕缓存 | 无效（本来就无缓存） |
| 换 `searchtype=all` | 同样受限频 |

⇒ 这是 IP 级 + 滑动窗口，书源层无解。

### 3.3 降级策略

1. `bookSourceComment` 明确写：搜索有 30 秒级限频，连续搜会失败，等 30~45 秒再试。
2. 发现页不受限频影响 → 引导用户用发现页。
3. 不要把搜索失败当成"书源坏了"，`check_source` 会通过（它只测一条链路）。

## 4. 搜索分页的假象（同站另一个坑）

### 4.1 现象

搜索页有分页条 `1/31 1 2 3 …`，点第 2 页：

```
GET ...&page=1  → 200, 30 条, 首条=斗罗大陆之史莱克七怪的成神之路
GET ...&page=2  → 200, 30 条, 首条=斗罗大陆之史莱克七怪的成神之路   ← 完全相同
GET ...&page=3  → 200, 30 条, 首条=斗罗大陆之史莱克七怪的成神之路   ← 完全相同
```

页内 `<strong>1</strong>`（当前页码）在 page=2 时仍然是 `1`。

### 4.2 判据

```python
strong = re.findall(r'<strong>(\d+)</strong>', html)   # 当前页码
names  = re.findall(r'<td class="odd"><a href="[^"]*">([^<]+)</a></td>', html)
```

`strong` 恒为 `['1']` + `names` 集合相同 → 服务端没读 `page` 参数（假分页）。

### 4.3 处置：bookList 短路

Legado 的搜索会在结果非空时持续翻页（`hasMore`）。假分页会导致**无限翻页**。

```js
// ruleSearch.bookList
@js:(function(){
  var m=String(baseUrl).match(/[?&]page=(\d+)/);
  if(m && parseInt(m[1])>1) return [];       // ★ page>1 直接返回空数组
  var J=Packages.org.jsoup.Jsoup;
  var doc=(typeof result==='string')?J.parse(result):result;
  return doc.select('tr#nr');
})()
```

要点：

- 返回 `[]` 而不是 `null` —— `null` 会让 `getElements` 走 `return ArrayList()`，效果一样但语义模糊。
- `typeof result==='string'` 兜住两种输入（`@js` 在 bookList 位置可能拿到 HTML 字符串）。
- `searchUrl` 里仍保留 `&page={{page}}`，让 `baseUrl` 带页码，短路判据才能生效。

## 5. 排查 Checklist

1. `java.ajax(searchUrl)` → 看 `len`（< 2000 → 大概率错误页）
2. `select('tr#nr').size()` 为 0 时，**先看 `title` 是否含「出现错误」**
3. 用「已知存在的书名」做基准测试，**不要用生僻词**
4. 失败后静默 45 秒，再测同一词 → 成功 = 限频，失败 = 规则错
5. `page=2` 比对首条 bookUrl → 相同 = 假分页，加 bookList 短路
6. 写进 comment，`check_source` 复测
