# 番茄漫画书源（fqapp 逆向）+ 混合类型自动判型

> 2026-10-12 实战 / 蓝本 `ch6vip/fqapp`（番茄内容聚合客户端） `/workspace/fqmanga/`
> 成品：`fqmanga.json`（40093B）书源名「🍅番茄漫画(APP)」`bookSourceUrl=https://fanqienovel.com##漫画版`
> 校验：check_source 通过 1/1（与小说版并存 2/2）

---

## 0. 一句话总结

番茄漫画走 **CM DH 通道**拿章节材料表（`materials` + `skeleton`），图片 URL **根本没用加密**——
之前以为要 AES-256-GCM 解密是错的，真相是 `java.ajax` 默认 UTF-8 解码把二进制搞坏了；
用 `{"type":"hex"}` 一看魔数是 `ffd8ffdb`（标准 JPEG）。**先验魔数，再写解密。**

## 2. 接口链路（全部实测）

### 2.1 目录/详情（同一个接口）

```
GET https://api5-normal-sinfonlineb.fqnovel.com/reading/bookapi/directory/all_items/v
    ?book_type=2&item_data_list_md5=&catalog_data_md5=&book_id={id}&book_info_md5=&need_version=true
    &iid={iid}&device_id={did}&<device params>
```
- `data.item_data_list[]` = 章节列表（`item_id` / `title` / `volume_name`）
- `data.catalog_data` **恒为空数组**，忽略它（别用它判空）
- `data.book_info` = 书籍元信息
- 实测有 `device_id`/`iid` 即可，无需额外签名头（但保持签名更稳）
- **无分页截断**：322 章、1275 章均一次返回

### 2.2 正文（CM 通道，与小说共用）

```
POST https://novelfm-hl.snssdk.com/novelfm/playerapi/full/mget/v1/?aid=3040...
body: {"book_id":X, "item_ids":[Y], "key":<DH握手>}
```
返回 `data.item_infos[itemId].content` = 解密后的 HTML，漫画的 HTML 内嵌材料表 JSON：

```html
<header></header><article><html><head></head><body>
{&#34;materials&#34;:{&#34;img_0&#34;:{&#34;data&#34;:{&#34;web_uri&#34;:&#34;novel-pic/xxx&#34;,...},&#34;type&#34;:&#34;img&#34;},...},
&#34;skeleton&#34;:{&#34;data&#34;:[{&#34;elementInfo&#34;:&#34;img_0&#34;},...]}}
</body></html></article><footer></footer>
```

- **`&` 被转义成 `&#34;` 等实体**，必须先 `Parser.unescapeEntities(s,true)`
- 取 `{` … `}` 配对 → `JSON.parse` → `materials` + `skeleton`
- **顺序必须按 `skeleton.data` 的 elementInfo**，不能按 `Object.keys(materials)`（实测键序为 img_0,1,10,11,12,2…，直接排序会乱页）

### 2.3 图片

```
https://p3-novel.byteimg.com/origin/{web_uri}
```
- `p3` / `p6` 同库可互换；`p9` 不同库会返回 HTML
- 桌面 UA（`Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36`）

### 2.4 发现页

`/reading/bookapi/bookmall/tab/v?tab_type=9&offset={(page-1)*16}&client_template=0`
→ `data.tab_item[].cell_data[].book_data[].book_data[]`，实测 20 本/页
多入口用 `?pg=N` 在 bookList 里解析实现翻页。

### 2.5 已废弃的接口（别再试）

| 接口 | 结果 |
|---|---|
| `reading.snssdk.com/reading/reader/full/v/?...` | 返回 `content:"Invalid"` |
| `api5-normal.../reading/reader/full/v/` | 同上 |
| `api5-normal.../reading/reader/batch_full/v/` | 同上 |
| `api5-normal.../reading/bookapi/search/tab/v`（书城搜索） | 全线空响应（tab_type 1/2/3/4/9 全试过） |
| `api.fanqiesdk.com/.../search/search/v1/` | ✅ 可用，但**返回全站混合结果，无法按类型过滤** |

## 3. ★★★ 核心教训：图片「加密」是个假象

### 3.1 我是怎么绕远的

按 fqapp 源码 `manga.rs` 的 `encrypt_key + picInfos + AES-256-GCM` 逻辑，判断漫画图片必须解密，
于是在 Rhino 里写：

```js
var c2=CC.getInstance('AES/GCM/NoPadding');
c2.init(CC.DECRYPT_MODE, new SecretKeySpec(aesKey,'AES'),
        new GCMParameterSpec(128, ivB));
var pt = c2.doFinal(ctB);
```
→ `AEADBadTagException: BAD_DECRYPT`（密钥、nonce 位置怎么调都不对）

### 3.2 真相

```js
// 用 type:hex 取二进制，避开 UTF-8 解码
var h = java.ajax(url + ',{"type":"hex", "headers":{...}}');
h.substring(0,8)   // → "ffd8ffdb"  ← 标准 JPEG 文件头
```

**图片没有加密**。`java.ajax` 默认按 UTF-8 解码响应体，把二进制字节当字符解码成乱码，
看起来就像密文。`AEADBadTagException` 只是更上游的错误假设派生出来的。

### 3.3 通用纪律

> 遇到「二进制 / 图片 / 音视频返回乱码」，**第一件事是用 `{"type":"hex"}` 验证魔数**，
> 而不是假设加密去写解密代码。
>
> 已知魔数：JPEG `ffd8ff`、PNG `89504e47`、GIF `47494638`、WEBP `52494646`、MP4 `000000`。
> hex 长度 = 字节数 × 2，可用来交叉校验完整性。

（`{"type":"hex"}` 是 LegadoTeam 版 `AnalyzeUrl.kt` 原生 URL 选项，
源码：`if (type != null) return StrResponse(url, HexUtil.encodeHexStr(getByteArrayAwait()))`）

## 4. ★★★ 混合类型自动判型（本次最大增量）

### 4.1 问题

fanqiesdk 搜索返回全站混合结果（小说 + 漫画），搜"非人哉"第一本是小说《师兄非人哉》。
漫画源的正文规则会直接报错 → `check_source` 失败。

### 4.2 判型字段（实测出）

| 字段 | 漫画 | 小说 |
|---|---|---|
| `book_info.comic_book_type` | `"1"` / `"2"` | **`undefined`** |
| `book_info.genre` | `"1"` | `"0"` / `"6"` |
| `book_info.type` | `"0"` | `"0"`（**不能用**） |

```js
function FQ_mgIsComic(b){
  return !!b && b.comic_book_type!==undefined && b.comic_book_type!==null && String(b.comic_book_type)!=='';
}
```
`comic_book_type` 是漫画专有字段，**这是最可靠的判型依据**。

### 4.3 双通路正文

```js
(function(){
  var m=String(baseUrl).match(/^https?:\/\/[^/]+\/page\/([0-9]{15,})/); var bid=m?m[1]:'';
  var m2=String(baseUrl).match(/#([0-9]+)$/); var item=m2?m2[1]:'';
  if(!bid||!item) throw new Error('参数错误');
  var h=FQ_mgHtmlQuiet(java,source,bid,item);   // 漫画：安静试图片，无图返回空串
  if(h) return h;
  var t=FQ_mgText(java,source,bid,item);       // 小说：直接返回 content 文本
  if(t) return t;
  throw new Error(FQ_MSG_NOMG);
})()
```

**关键：`FQ_mgHtmlQuiet` 必须是「安静版」**（内部 `try/catch` 全部吞掉返回 `''`），
否则 `FQ_mgImgUrls` 会在无图时 `throw`，永远走不到小说分支
——这是我第一次失败的直接原因。

### 4.4 `bookSourceType` 设为 64 但读小说

`bookSourceType=64`（图片型）下读小说文本，Legado 会按图片型渲染但文本仍能显示
（实测正常）。若要让小说也完美排版，可另建一个 type=0 的源，或后续用 `book.setType()` 动态切换。

## 5. ★★★ Rhino 中文文本：`String.fromCharCode` 不可靠

jsLib 里写 `String.fromCharCode(27809,26684,20026,...)` 构造中文，
经 `throw new Error(FQ_MSG_NOMG)` 抛出后，debug 显示成：

```
没格为章埋获，请重刷队本话      // 应为「该章节暂无图片，请刷新重试」
```
每个字都不对但结构像中文 → **Rhino 的 Java String 编码链把高位字符打乱**。

**正解：直接用 UTF-8 字面量**（源文件本身是 UTF-8，`save_source`/深链都能正确传输）：

```js
var FQ_MSG_NOMG="该章节暂无图片，请刷新重试";
```
（验证：debug 输出「该章节暂无图片，请刷新重试」正确。）

## 6. ★★★ 交付纪律（本次连犯两次事故）

### 6.1 `save_source` 是整体替换语义

| 事故 | 经过 | 教训 |
|---|---|---|
| **占位符毁 jsLib** | 37KB 超 MCP 内联上限（~19KB）→ 把 `jsLib` 改写成字符串 `"JSLIB"` → 落库后 `source.getJsLib()` 返回 `"JSLIB"`，eval_js 直接 `ReferenceError: JSLIB 未定义` | 大源**绝不能**手抄/占位符；必须走 uguu/dpaste + 深链 |
| **`"__KEEP__" 洗库** | 想只改 exploreUrl 保留 jsLib → 传 `"jsLib":"__KEEP__"` → jsLib 被洗成字面量 `__KEEP__` | **绝不可以用占位符保留字段**；要改就把完整内容一起传 |
| **同 URL 覆盖** | 直接用 `https://fanqienovel.com` 保存漫画源 → 用户手动恢复的小说源被覆盖 | 同类不同型源**必须用不同 bookSourceUrl** |

### 6.2 同站点多源共存的正确写法

```json
"bookSourceUrl": "https://fanqienovel.com##漫画版"
```
- 书源身份唯一，不会覆盖小说源
- **但 `##` 后缀的 URL 不能当详情页入口请求**（我造的 `manga.fanqienovel.com` 直接 `UnknownHostException`）
- 所以：**绝对不要用 `debug_source` 访问带 `##` 的 URL**；书源内部所有 URL（章节/接口）继续硬编码真实域名，完全不受影响

### 6.3 大源交付标准流程（40KB 级）

```
1. 本地生成 JSON → node --check 全部 JS 块 → 闸门（顶层const/let=0）
2. uguu.se multipart 上传（files[] 字段） → 回读字节 md5 比对（必须 MATCH）
3. 手机侧 java.ajax(raw, {"type":"hex"}) 探活（hexLen == 文件字节×2）
4. java.openUrl('legado://import/bookSource?src='+encodeURIComponent(raw))
5. get_http_logs 确认 GET raw -> 200（硬证据）
6. eval_js 绑 source.getJsLib() 回读长度+特征锚点 → 确认落库
   ⚠️ 第5步只证明"下载成功"，第6步才证明"落库"，缺一不可（导入需用户点确认弹窗）
```

### 6.4 eval_js 编译失败时的兜底

jsLib 损坏时，绑 `url` 参数的 eval_js 会直接失败（`ReferenceError`）。
此时**不传 url 参数**（空白书源上下文）即可调用 `java.openUrl` 发深链自救。

## 7. 登录 / 检查状态

番茄全站免登录（设备注册即用），所以：

- 无账号密码框，只做**连通性/设备池自检**
- `loginUrl` 顶层具名函数（LT/E 双兼容，jsLib 函数要靠 `java` 显式传参）
- `loginUi` 经典 V1 数组：说明行 + 「检查登录/连通状态」+ 「重置设备池」

```js
function FQ_mgCheck(){
  try{
    var r=FQ_mgInfo(java,source,'7113804239352105991');
    java.toast('站点连通正常：'+r.name+'（'+r.chapters+' 话）');
  }catch(e){ java.toast('检查失败：'+e); }
}
function FQ_mgResetDev(){
  try{
    source.put('fqPool','');
    var pool=FQ_ensure(source,2);
    java.toast('设备池已重置，当前 '+pool.length+' 个设备');
  }catch(e){ java.toast('重置失败：'+e); }
}
```

实测：重置设备池后立即读漫画仍出 26 张图 → **设备注册+密钥派生完全自愈**。

## 8. 避坑清单

1. ❌ 假设图片加密 → 先用 `type:hex` 验魔数
2. ❌ `catalog_data` 为空就判"目录为空" → 用 `item_data_list`
3. ❌ 按 `Object.keys(materials)` 取图序 → 必须按 `skeleton.data` 的 elementInfo
4. ❌ 忘 `unescapeEntities` → HTML 里的 `&#34;` 导致 JSON.parse 失败
5. ❌ 用 `fromCharCode` 拼中文错误提示 → 直接用 UTF-8 字面量
6. ❌ 漫画通路 `throw` 导致读不了小说 → 用安静版函数兜底
7. ❌ 用 `book_info.type` 判漫画 → 小说也是 `"0"`，用 `comic_book_type`
8. ❌ `debug_source` 访问带 `##` 的书源 URL → UnknownHost
9. ❌ 大源用 save_source 手抄/占位符 → uguu + 深链 + 回读校验
10. ❌ 同 URL 保存不同类型源 → bookSourceUrl 加 `##` 后缀
11. ⚠️ `book_type=2` 与 `book_type=0` 对同一本漫画返回相同结果（服务端按 book_id 自动识别），无需先判型再请求
12. ⚠️ 单章漫画真实存在（`serial_count=1`），别当接口失败
