## 二、三条硬规则（照抄即错）

### 1. `bookUrl` 必须自拼绝对 URL

源码 `BookList.getSearchItem` 里 `getString(ruleBookUrl, isUrl=true)` 会用 **`baseUrl`（当前列表页）** 解析相对路径。

`/ranks/hot/` 页的 `/video/323/` 会被拼成 `/ranks/hot/video/323/` → **404**。

```js
var root = String(source.get('hg_line')||'');
if(!root||root.indexOf('http')!==0){ root = String(source.getBookSourceUrl()); }
root = root.split(String.fromCharCode(35,35))[0];   // ★ 见下条
root = root.replace(/\/$/,'');
var mv = h.match(/href="(\/video\/\d+\/)"/);
if(mv) return root + mv[1];
```

### 2. 传输层会吃掉 `##`

书源 JSON 里写 `split('##')` → 传到 App 后变成 `split('#')` → 报「字符串文字没有限制」。

⇒ 必须用 `String.fromCharCode(35,35)` 构造双井号。

### 3. 多选 `bookList` 后字段级选择器不按索引对应

```css
bookList = .a, .b, .c
name = .a__title, .b__title      /* ← 返回空字符串 / 书籍总数 0 */
```

实测多选后 `name` 返回空。**根因**：多选择器的元素集合与字段选择器不按索引对应。

⇒ **所有字段必须统一 `@js:` 自解析**，按结构用各自锚点：

```js
// video: data-track-title / data-track-id / data-track-type-name / data-src
// rank:  .hg-rank-item__title / __tags / __desc
// topic: .hg-topic-card__title / __meta span，bookUrl → /topics/xxx/
```

## 四、封面修复（★★★ 三个叠加坑）

### 坑 1：`coverDecodeJs` 返回值必须是 Java `byte[]`

源码 `RhinoScriptEngine.kt:235` `unwrapReturnValue` **只 unwrap `Wrapper`**：

| JS 写法 | Rhino 类型 | `as ByteArray` | 结果 |
| --- | --- | --- | --- |
| `Packages.java.util.Arrays.copyOf(bytes, n)` | `NativeJavaArray`（**是 Wrapper**） | ✅ | 成功 |
| JS 数组字面量 `[b0,b1,...]` | `NativeArray`（**非 Wrapper**） | ❌ 强转失败 | `runCatching` **静默吞掉** → `onStreamReady(null)` |

⇒ 静默失败 → Glide `failUrl` 拉黑该 URL → 「封面二次解密失败」。

```js
// ✓ 正确
var out = Packages.java.util.Arrays.copyOf(bytes, bytes.length);
// ✗ 错误：JS 数组字面量
```

### 坑 2：Glide 丢弃 `dnsIp`

封面走 Glide `OkHttpStreamFetcher` → `AnalyzeUrl.getGlideUrl()`，**只保留 `url` + `headerMap`，丢弃 `dnsIp`**；
正文走 `getByteArrayAwait()`，`dnsIp` 完整生效。

⇒ 「正文能显示但封面全灰」的通用根因。

**解法**：`http://<CF-IP><path>` + `{"headers":{"Host":"域名"}}`
（Host 头在 OkHttp `BridgeInterceptor` 只在缺失时补 ⇒ 保留）。

**通用结论：只要图片可能走 Glide（封面/漫画浏览/预览），URL 就必须自带 IP+Host 头，不能依赖 `dnsIp` 选项。**

⚠️ **禁止在 `<img src>` 外层再套 `dnsIp`**（双层选项 ⇒ UrlOption 解析失败 ⇒ 回退裸 URL ⇒ 又超时）。

### 坑 3：三层缓存

1. **Glide 密文缓存**（磁盘）→ 改 URL 加 `&hgimgv=2` 换 cache key
2. **Glide `failUrl` 黑名单**（**进程级**）→ 改完必须**重启 App**
3. **正文缓存** → 正文图 URL 含选项串 ⇒ `MD5(src)` 变化 ⇒ **旧书须删书重加或清正文缓存**

### 判据：沙盒直连 ≠ 真机 Glide

用 LAN `/cover` 端点或 `eval_js + java.ajax` 实测。
`/cover` 返回 **PNG**（不能用 JPEG 魔数判）。
正确做法 = 先取必然失败 URL 作「占位图基准」比 md5。

## 八、E 版（legado-E）兼容改造（v9.4）

用户报「E 版目录加载失败」⇒ 源码级定位到**头号杀手**：

```kotlin
// LT 版 AnalyzeRule.getElements 末尾 —— 有显式分支
is NativeArray -> { val values = ArrayList<Any>(...); return values }

// E 版 AnalyzeRule.getElements 末尾 —— 直接强转
result?.let { return it as List<Any> }
```

Rhino `NativeArray` 不是 `java.util.List` ⇒ E 版 ClassCastException。
**症状指纹**：搜索/详情/发现全正常，**唯独目录失败**（只有目录走 `getElements`）。

### 修法

```js
// ❌ JS 数组 → E 版 CCE
var list=[]; list.push(x); return list;

// ✅ java.util.List → 两版都通
var list=new Packages.java.util.ArrayList();
list.add(x);   // ★ Java List 用 add 不是 push
return list;
```

## 九、v12：2026-11-27 站点大改版适配

> 站点约每 5~7 天迁移一代根域，2026-11-27 这次连**正文取址方式**一起换了。v11 那套 `<source src>` 规则在一夜之间全部静默失效（标签还在、`src` 变空）。

### 9.1 改版四件事（对照表）

| 项目 | v11（旧） | v12（现） |
| --- | --- | --- |
| 根域 | `xxbgwypx.cc`（全灭，DNS 返回假 IPv6） | 发布页 `huang-guo.pages.dev/publish.js` 现给 `qxeylvrkf.cc` + `hvgbwwrxd.cc`，各 19 个大学子域，**76/76 全活** 242~5061ms |
| 正文 m3u8 | 页面 `<source src="...">` | **空标签**；改由 `POST /api/videos/{id}[/episodes/{n}]/playback` → `data.streams.main` |
| 分类 | ai-duanju/ai-manju/ai-huanlian/ai-mogai | `/ai-huanlian/` `/ai-mogai/` **HTTP 410** 下线；新增 `/original/`(8页) `/newest/`(65页) `/recommend/`(3页) |
| 图床 | `pic.drleao.cn` | `pic.qnlycc.cn`（AES 密钥不变，封面改 PNG 需补 IEND 截尾） |

发布页本体也换了：`huangguoai.pages.dev` DNS 不通，现用 `huang-guo.pages.dev`（备 `huangguoai.pages.dev` 仍留在候选里）。

### 9.2 正文改接口的关键实测

```
方法开关  GET  /m3m/off/{floor(now/300000)}.json      → {"data":{"method":"POST"}}
第 1 集   POST /api/videos/{id}/playback               body {}  → data.streams.main
第 n 集   POST /api/videos/{id}/episodes/{n}/playback   body {}  → data.streams.main
```

- **游客免 token**（前端写 `useToken:true`，实际无鉴权也 200）
- **m3u8 免 `x-cdn-auth` 头**：`cdn.m3u8Enabled=true` 只给浏览器 hls.js 用，服务端认 `auth_key` 签名（裸 `java.ajax` 拿 3607B 标准 m3u8）
- `auth_key` 有效期 **10800s** ⇒ 正文侧做 25 分钟 `source.put` 缓存（实测二次 18ms）
- 兜底：主 host 失败时依次换 `thu/pku.hvgbwwrxd.cc`、`thu.arj2ftl0.cc`、`thu.jxqgmx5ga.cc`

### 9.3 发现页 8 入口 + per-kind @js（本次最重要的通用机制）

`exploreUrl` 整串写 `@js:` 返回 JSON 会被 `exploreKinds()` 双层缓存（内存 map + ACache，key=`MD5(bookSourceUrl+exploreUrl)`）⇒ **切线路后发现页仍打旧域名**。
正解：`exploreUrl` 保持静态 `title::url&&` 字符串，**每个 url 写 `@js:FIX + "/path/{{page}}/"`** —— 缓存的只是含 @js 的字符串，求值发生在每次 `AnalyzeUrl.initUrl()`（`analyzeJs() → replaceKeyPageJs() → analyzeUrl()`），实时跟随 `hg_line`，且 `{{page}}` 照常替换。

实测 HTTP 日志：`hg_line=pku` 时 → `GET https://pku.hvgbwwrxd.cc/ai-duanju/1/`。

8 个入口：AI成人短剧 / AI成人漫剧 / 原创短剧 / 最新更新 / 编辑推荐 / 热播排行榜 / 精品专题 `/topics/hot-aiduanju/` / 全部专题 `/topics/`。

### 9.4 双端兼容补充

- `java.post` 的 headers：**LT 版签名 `Any?`（收 JSON 字符串），E 版只收 `Map<String,String>`** ⇒ 规则里一律 `new Packages.java.util.HashMap()` + `put()` 双端通吃
- 返回值是 jsoup `Connection.Response`，取 body 用 `.body()`（`code()` 不存在，状态码是 `statusCode()`）
- E 版正文会被 `ContentProcessor` 加全角空格缩进（`getBookContent` 返回 `　　https://…`），靠播放器 trim
- 专题页目录带分页（`/topics/hot-aiduanju/{page}/` pages=3），`nextTocUrl` 返回分页（注意 `data-jump-tpl` 尾部已有 `/`，别再拼一个，否则 `//2/`）
