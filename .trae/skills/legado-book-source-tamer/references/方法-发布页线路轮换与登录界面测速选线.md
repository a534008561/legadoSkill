# 方法：发布页线路轮换与登录界面测速选线（域名轮换站通用方案）

> **沉淀来源**：三个生产书源实测提炼——
> ①**搜书吧**（`bookSourceUrl="搜书吧搜书吧❗❗❗"`，Discuz论坛，2025.5 by辞晨）：模式开创者——接口列表存 `source.getVariable()` 逗号串+AES加密当前域名存 `variableComment`+登录UI全套按钮+两级跳转发布页+分档测速反馈
> ②**黑料网**（hlwf6.com v2/v3，260910生产版）：工程化改良——发布页 `a.line-long` 解析+`{"timeout":8000}` 测速+**TTL 3分钟缓存**+**参数注入法**绕 jsLib 作用域限制+bookUrl 相对化自愈
> ③**麻豆传媒**（mdcmai.xyz，260909）：极简版——登录UI域名按钮+`source.put('domain')`+逐域名测速 longToast 列表
>
> **适用**：域名频繁轮换/被墙的站点——有固定"发布页"（网址发布页/宣传页，域名基本不变），页面列当前可用的主站域名（每天甚至每小时换）。

## 一、什么时候用这套方案

### 1.1 特征判定

| 站点特征 | 判定 |
|---|---|
| 有固定的"发布页"/"网址发布"页面，域名多年稳定 | ✅ 必用 |
| 主站域名像随机串（`a0xhc.iqxqviwd.cc`、`26imh.xftytaxh.cc`） | ✅ 必用 |
| 站点域名 20 分钟能轮换 3 次 | ✅ 必用 |
| 书源硬编码域名，用户反馈"前几天还能用" | ✅ 典型症状 |
| 域名被墙后过段时间换新域名复活 | ✅ 必用 |
| 域名稳定但有多个 CDN 镜像（站方维护） | ⭕ 可用测速部分 |
| 域名只有一个且多年不变 | ❌ 不必用 |

### 1.2 三档方案选型（按复杂度递增）

| 档位 | 方案 | 适用 | 代表 |
|---|---|---|---|
| L1 | **登录UI手动切换域名按钮**：`source.put('domain',d)`，几个域名按钮+测速检查按钮 | 域名少(≤6个)且轮换周期以月计 | 麻豆传媒（mdcmai5个域名按钮+⏱检查域名耗时+📚当前域名+↩️恢复默认） |
| L2 | **发布页+测速+TTL自动选线**：规则入口调 `pickLine(java,source)`，自动抓发布页→测速→选最快→缓存 | 域名轮换频繁（天/小时级），要无人值守 | 黑料网（TTL 3分钟，20分钟实测轮换3次全自动跟随） |
| L3 | **发布页+接口列表变量+登录UI全套**：线路清单存 `source.getVariable()`，登录UI可看/切/测/发布页管理 | 论坛型多线路（Discuz 等）+用户有手动运维需求 | 搜书吧（当前接口+切换A(x)+测速反馈+获取新网址jkjh+清除delet+当前接口H） |

**选型建议**：新制书源默认从 L2 起步（L1 是它的退化子集，L3 是它加登录UI运维层的超集）。L2 的 `pickLine` 做好后，L3 只是往 loginUi 多加几个按钮。

## 二、核心架构：五层流水线

```
┌──────────────────────────────────────────────────────────────┐
│  第1层 发布页抓取    第2层 线路解析过滤    第3层 测速选优         │
│  fetchPage()  ───▶  lineList(html)  ───▶  speedTest(cands)    │
│  (发布页URL也可变     (选择器/正则+黑名单)   (timeout选项+计时     │
│   ——二级跳转)                              +判活+内容校验)      │
└──────────────────────────────────────────────────────────────┘
                                                          │ best
┌──────────────────────────────────────────────────────────────┐
│  第4层 持久化+TTL                        第5层 入口注入         │
│  source.put('line',best)               searchUrl {{...}}     │
│  source.put('line_ts',now)              exploreUrl <js>      │
│  (180s内复用，过期重测)                   规则@js: pickLine()   │

```

**数据流一次完整走查（黑料网真实数据）**：
用户搜索 → `searchUrl` 的 `{{}}` 执行 `pickLine(java,source)` → 读变量 `line`/`line_ts`：未过期(3分钟内)直接返回缓存线路 → 过期则 `java.ajax('https://hlwf6.com/,{"timeout":8000}')` 抓发布页 → jsoup select `a.line-long` 过滤(必须含"线路"、排除APP/导航) → 得线路数组 `[https://x6v3k.tozpubth.cc, ...]` → 逐线路 `java.ajax(line+TMO())` 计时+响应>5000字节判活 → 取最快 → `source.put('line',best)`+`line_ts` → 返回线路拼搜索URL POST → 响应里 bookUrl 是相对路径 `/archives/123/`，Legado isUrl 自动拼到实际线路域 → **域名再怎么轮换，旧书架的相对 URL 永远落在活着的域上**。

## 三、第1层：发布页抓取

### 3.1 发布页URL的存储设计：硬编码默认值 + 变量覆盖

发布页自己也可能被墙，所以要做成可配置：

```js
// jsLib：发布页URL读变量，默认硬编码
function gv(S,k,d){var v='';try{v=String(S.get(k)||'')}catch(e){}
  if(!v||v=='null'||v=='undefined')v=d;return v?ST(v):''}
function pub(S){return gv(S,'pub','https://hlwf6.com')}
```

配套登录UI：`发布页` 文本框 + `应用发布页` 按钮，`setPub()` 写 `source.put('pub',v)`。发布页换址时用户自助迁移，不用改书源。

### 3.2 两级跳转发布页（搜书吧形态）

有些站的"发布页"是两级接力：**发布页① → `url=`参数跳转 → 发布页② → `<a href` 线路列表**。搜书吧 `jkjh()`（获取新网址按钮）：

```js
function jkjh(){
  let url = `http://www.soushu2030.com/`;                    // 发布页①
  let ids = java.ajax(url).match(/url=(.*?)\"/)[1];          // 跳转目标
  let opp = java.ajax(ids).match(/url=(.*?)\"/)[1];          // 再跳一次
  let uro = java.ajax(opp);                                  // 发布页②
  let uri = uro.match(/\<a\shref\=\"(.*?)\"\s/g);            // 抓所有链接
  let urls = uri.map(m => m.replace(/<a\s+href=\"(.*?)\"\s/, "$1"));
  java.toast('最新网址：\n' + urls.join('\n'));
  cache.put('ssbs', urls.join('\n'));                        // 缓存给用户参考
}
```

要点：
- `url=(.*?)\"` 这类**重定向参数提取**比跟随302稳（发布页可能用 meta refresh / JS 跳转，java.ajax 不一定跟）
- 抓回来的线路清单用 `cache.put` 临时存（用户看，不用于自动选线）；配套 `delet()` 按钮 `cache.delete('ssbs')` 清除
- 搜书吧还有 `M()` 按钮直接 `java.startBrowser('ged520.yesui.me/','发布页')` 打开发布页——**用户手动查最新网址的兜底入口**

### 3.3 多发布页兜底

发布页被墙时依次尝试（黑料网实践）：

```js
var html='';
try{html=String(Jv.ajax(pub(Sv)+TMO()))}catch(e){}
if(html.length<1000){try{html=String(Jv.ajax('https://hlwf6.com/'+TMO()))}catch(e){}}
```

长度阈值（<1000字节=发布页没抓到有效内容）代替 try/catch 判断——ajax 异常时可能返回异常字符串而非 throw。

## 四、第2层：线路列表解析与过滤

### 4.1 解析器两写法：结构化选择器 vs 通用正则

**黑料网（结构化发布页，jsoup 选择器）**：

```js
function lineList(h){var d=J(h);var as=d.select('a.line-long');
  var c=[];for(var i=0;i<as.size();i++){
    var t=as.get(i).text(); var h2=as.get(i).attr('href');
    if(!h2||h2.indexOf('http')!==0)continue;   // 必须绝对http
    if(t.indexOf('APP')>-1)continue;           // 排除APP下载
    if(t.indexOf(String.fromCharCode(23548,33322))>-1)continue; // 排除"导航"
    if(t.indexOf(String.fromCharCode(32478,36335))<0)continue;   // 必须含"线路"文案
    c.push(ST(h2))}
  return c}
```

**搜书吧（任意HTML，正则）**：

```js
let uri = uro.match(/\<a\shref\=\"(.*?)\"\s/g);
let urls = uri.map(m => m.replace(/<a\s+href=\"(.*?)\"\s/, "$1"));
```

**选型**：先抓发布页 HTML 看结构——有专用 class（`line-long`/`link`/`url-item`）就用选择器+文案过滤（**白名单**"线路"二字是最强过滤）；页面杂乱就用 `<a href` 全抓再过滤，或直接展示给用户手选。

### 4.2 过滤黑名单/白名单清单

| 过滤项 | 依据 | 黑料网实测 |
|---|---|---|
| ❌ APP下载链接 | 文案含"APP" | 发布页混着安卓/苹果下载按钮 |
| ❌ 导航/说明链接 | 文案含"导航" | 非线路 |
| ❌ 社交群链接 | href 是 t.me/qq.com 等 | 可按域名黑名单 |
| ❌ 海外死线 | 实测 ECONNREFUSED/超时 | heiliao.com 本网络不可达 |
| ✅ 必须含"线路" | 白名单文案 | 最强特征 |
| ✅ 必须 http 开头 | `attr('href')` 绝对地址 | 相对地址无法直连测速 |
| ✅ 去尾斜杠 `ST()` | 拼URL防双斜杠 | `https://x.cc/` → `https://x.cc` |

> **注意**：`String.fromCharCode(32478,36335)` 是"线路"二字的码点写法——书源JSON里的中文文案过滤用码点写法可避开传输层转义问题；若不在乎可以直接写中文。

### 4.3 兜底：解析到 0 条线路时

```js
if(cs.length===0) return cur || 'https://硬编码兜底线';
```

返回**旧缓存线路或硬编码默认线**，绝不返回空——空线路=规则立刻崩，用户看到的是搜索失败而不是线路失效提示。

## 五、第3层：测速选优（核心）

### 5.1 测速三要素：超时选项 + 计时 + 判活

黑料网生产版（jsLib `pickLine` 内核，此函数可整体复用）：

```js
function TMO(){return String.fromCharCode(44,123,34,116,105,109,101,111,117,116,34,58,56,48,48,48,125)}
// 即 ,{"timeout":8000} —— 8秒超时选项，fromCharCode 码点拼装防JSON转义踩坑

// 测速循环（黑料网 pickLine 片段）
var best='';var bm=99999999;
for(var i=0;i<cs.length;i++){
  var t0=Date.now();var ok=false;
  try{var b=String(Jv.ajax(cs[i]+'/'+TMO()));
      if(b.length>5000)ok=true}catch(e){}
  if(ok&&Date.now()-t0<bm){bm=Date.now()-t0;best=cs[i]}
}
if(!best)best=cur||'https://硬编码兜底线';
```

**三个判活细节**：
1. **`{"timeout":8000}` URL选项**：给每条线路 8 秒上限，防死线把整个测速拖到几分钟。这是 URL 选项（AnalyzeUrl 原生支持），逗号+JSON 拼在 URL 后
2. **响应长度阈值 `>5000`**：只"连上"不算活——必须返回真实页面。死线/拦截页通常 <5000 字节
3. **`Date.now()` 差值计时**：`bm` 保存最快耗时，`best` 保存最快线路

### 5.2 搜书吧的分档测速反馈（手动切换场景）

搜书吧 `A(x)`（切换接口按钮）切换后立即测速并给四档评语，用户体验设计值得抄：

```js
let date1 = new Date().getTime();
let html = java.get(getUrl(),header).body();
let date2 = new Date().getTime();
let t = date2 - date1;
let c = String(html).indexOf('html');          // 内容判活：响应里要有'html'
if (c == -1 || t > 5000)      java.longToast('【访问失败提示】...♣️源站已失效(可能被墙)♣️请更新网址/切换源站...');
else if (t < 1000)             java.longToast('【网络环境优良】...❤️延迟低，推荐使用此站❤️');
else if (t >= 1000 && t < 2000) java.longToast('【网络环境一般】...♦️延迟一般，勉强可使用♦️');
else if (t >= 2000 && t < 5000) java.longToast('【网络环境堪忧】...♠延迟过高，不建议使用♠...');
```

分档标准：**<1s 优良 / 1~2s 一般 / 2~5s 堪忧 / >5s或无响应 失效（可能被墙）**。带边框的 `┏┅━┅┓` ASCII 表格 + longToast 展示，信息量大时比 toast 好得多。

### 5.3 测速过程提示（防用户以为卡死）

测速全程 10~40 秒，必须先发提示（黑料网二轮修复加的）：

```js
function getLines(){ T('⏳ 正在抓取发布页并逐条测速，约10~40秒，请稍候...'); ... }
function autoLine(){ T('⏳ 正在抓取发布页并测速选优，约10~40秒，请稍候...'); ... }
```

结果用**测速表**展示（每线路耗时+最快标记）：

```js
function speedTest(cs){var msg='';var best='';var bm=99999999;
  for(var i=0;i<cs.length;i++){
    var t0=Date.now();var st='超时';var ok=false;
    try{var b=String(java.ajax(cs[i]+'/'+TMO()));
        if(b.length>5000){ok=true;st=(Date.now()-t0)+'ms'}}catch(e){st='失败'}
    if(ok&&Date.now()-t0<bm){bm=Date.now()-t0;best=cs[i]}
    msg+=NL()+cs[i].split('//')[1]+'  '+st}      // 只显示域名部分
  msg+=NL()+'—— 最快: '+(best?best+' ('+bm+'ms)':'无可用');

```

> `T()` 是三级降级 toast：`longToast → toast → copyText`（本App java.show 不存在，且部分分支版本 longToast 可能缺失）。

## 六、第4层：变量持久化与TTL缓存

### 6.1 变量API版本差异（必读）

| API | LegadoTeam新版 | legado-E/Lyc等 | 结论 |
|---|---|---|---|
| `source.get(k)` / `source.put(k,v)` | ✅ 持久化到书源variable | ✅ | **主线用这对** |
| `source.getVariable()` / `setVariable(v)` | ⚠️ eval_js上下文抛"找不到方法" | ✅（搜书吧原版用） | 双兼容写法 |
| `cache.put/get/delete` | ✅ 内存缓存 | ✅ | 存线路清单展示用（非持久） |

双兼容写法（跨版本分发必带）：

```js
var v='';try{v=String(source.get(k)||'')}catch(e){try{v=String(source.getVariable()||'')}catch(e2){}}
```

**搜书吧特殊设计**：它把**接口列表**存在 `source.setVariable()` 逗号串里（`v[0],v[1],v[2]...`），`v[1]` 是当前选中索引，切换接口就是改这个索引：

```js
v = String(source.getVariable()).split(",");
v[1] = x;                          // 切到第 x 个
source.setVariable(v.join(","));
```

而**当前域名本体**则 AES 加密存 `variableComment`（`getUrl()` 用 `aesBase64DecodeToString(variableComment, getSecretKey(),'AES/ECB/PKCS7Padding','')` + eval 解出）——这是防抄源手段，一般站点不必仿效，明文 `source.put('line',url)` 足够。

### 6.2 ★JsNull truthy 大坑（mdcmai血泪）

**Rhino 的 Java null 是 JsNull 包装对象，是 truthy！** `source.get('未设置键')` 返回 null → `if(v)` 为 **true** → `v||'default'` 兜底**不走** → 字符串拼接得到 `'null'`。必须三态归一化：

```js
function gv(S,k,d){var v='';try{v=String(S.get(k)||'')}catch(e){}
  if(!v||v=='null'||v=='undefined')v=d;   // String()包一层 + 'null'/'undefined'显式判
  return v?ST(v):''}
```

所有读变量处都要 `String()` 包一层再判空——这套 `gv()` 是标配。

### 6.3 TTL设计：3分钟的由来

```js
function pickLine(Jv,Sv,fc){        // fc=force，强制重测（绕过缓存）
  var now=Date.now();var ts=0;var cur='';
  try{ts=Number(String(Sv.get('line_ts')||'0'))||0}catch(e){}
  try{cur=String(Sv.get('line')||'')}catch(e){}
  cur=cur?ST(cur):'';
  if(!fc&&cur&&now-ts<180000)return cur;    // ★TTL 180秒：有缓存且未过期→直接复用
  ...重测...
  try{Sv.put('line',best);Sv.put('line_ts',String(now))}catch(e){}
  return best}
```

| TTL | 后果 |
|---|---|
| 无TTL（每次都测） | 每次搜索多 10~40 秒，不可接受 |
| 太短（<1分钟） | 频繁测速照样慢 |
| **3分钟** | 站点实测20分钟轮换3次域名→轮换周期约7分钟，TTL=3min保证最多落后一个轮换周期 |
| 太长（>10分钟） | 轮换后半小时还打旧域（好在301跟随能救回） |

TTL 应设为**实测轮换周期的 1/2~1/3**。做书源时观察一天取值。

另外两个使用点：
- **正文救援**：正文提取失败（线路刚好轮换）时 `pickLine(java,source,true)` 强制重测重抓一次（fc=true 绕缓存）
- **登录救援**：doLogin 线路不可达时 `pickLine2(java,Sv,true)` 重测后重试

### 7.2 ★bookUrl相对化自愈（最关键技巧）

**列表规则返回相对路径**（`/archives/123/`），让 Legado 的 isUrl 机制自动拼到**实际响应线路的域**上：

```
ruleSearch.bookUrl = "@js:'/archives/'+result.id+'/'"    // 相对路径，不带域名！
```

效果：
- 测速选中 `x6v3k.tozpubth.cc` → 搜索响应 bookUrl = `x6v3k.tozpubth.cc/archives/123/`
- 20分钟后域名轮换成 `a0xhc.ducsiyoh.cc` → 下次搜索 bookUrl 自动落在新域

## 八、作用域铁律（本App最大坑，决定函数怎么放）

### 8.1 jsLib 作用域里 java/source 缺失 → 参数注入法

**LegadoTeam版**：jsLib（getShareScope）求值环境中 `java.ajax` 不可用（JavaPackage非函数）、`source` 未定义。直接在 jsLib 写 `java.ajax(...)` 会**静默失败**——黑料网第一版的 `line()` 永远返回写死默认线，try/catch 吞掉报错极难察觉。

**解法：参数注入法**——jsLib 定义函数收参数，由**规则上下文**（那里 java/source 都可用）传进去：

```js
// jsLib 里：
function pickLine(Jv,Sv,fc){ ... Jv.ajax(...) ... Sv.put('line',best) ... }
//          ↑java实参  ↑source实参  ↑强制重测

// 规则/searchUrl 里调用（java、source 都在作用域内）：
var L = pickLine(java, source);
```

`Jv`/`Sv` 参数名故意区别于全局名，防作用域混淆。函数内所有对 java/source 的引用都必须走参数。

### 8.2 loginUrl 必须自包含（作用域独立编译）

`loginUrl` 顶层函数集与 jsLib **不共享作用域**（各自编译）。jsLib 的 `pickLine`/`ST`/`gv` 在 loginUrl 里**不可见**。黑料网做法：loginUrl 里**复制一份**工具函数（ST/gv/TMO/lineList + fetchLines/speedTest），并自建 `pickLine2` 副本：

```js
// loginUrl 顶部：复制 jsLib 的工具函数副本
function ST(u){...} function gv(S,k,d){...} function TMO(){...}
function lineList(h){...} function fetchLines(){...} function speedTest(cs){...}
function pickLine2(Jv,Sv,fc){...}   // jsLib pickLine 的本地副本
// 然后是登录/测速按钮函数
function doLogin(){...} function getLines(){...} function autoLine(){...}
function setLine(){...} function setPub(){...} function showLine(){...}
function login(){return doLogin()}   // ★右上角√按钮必需
```

> 三作用域独立铁律（米游社经验同）：**script / loginUrl / jsLib 各自编译互不通**。凡是要在三处用的函数，每处放一份副本，别指望引用。

### 8.3 MCP save_source 的零反斜杠铁律

jsLib/loginUrl/规则里的 JS 若含大量 `\"` `\\`，经 MCP 传输层双重转义极易损坏（报"源名称和URL不能为空"=JSON截断）。生产写法：
- 双引号用 `String.fromCharCode(34)`、逗号`44`、`{`123、`}`125 拼装（见 TMO/PO 函数）
- 中文过滤词用码点 `String.fromCharCode(32478,36335)`（"线路"）
- 换行用 `String.fromCharCode(10)` 存进 `NL()` 变量复用
- 体积控制：loginUrl 单文件 ≤6KB 为宜

## 十、踩坑清单（两源踩过的全记录）

1. **jsLib 作用域 java/source 缺失是静默失败**——函数永远返回默认值，try/catch 吞错。任何"线路怎么一直是默认的"先查这个（参数注入法根治）
2. **Rhino JsNull truthy**：`source.get(键)` 未设置时返回 Java null 被 String() 后是 `'null'` 字符串且判真——必须 `'null'/'undefined'/''` 三态显式判（6.2 节）
3. **`java.ajax` 失败有时 throw 有时返回异常文本**（几千字节堆栈字符串）——测速循环里 catch + 长度阈值双保险
4. **`cookie.setCookie(url,str)` 是整体替换语义**——动 Cookie 前先 getCookie 全文再改（限频Cookie场景，本方案的姐妹坑）
5. **timeout 选项必须拼成单JSON**：`url,{"timeout":8000}` ✅；`url,{...},{...}` 双JSON→GSON炸NPE
6. **测速无过程提示=用户以为书源卡死**——开头必有"⏳正在...约10~40秒"提示
7. **信息量大的结果用 longToast**（测速表）；长文本展示三级降级 `longToast→toast→copyText`
8. **登录Ui的`<js>JSON.stringify([...])</js>` 漏右括号→UI整页空白无报错**（AppLog吞掉语法错）——node --check 验证（去掉`<js>`标签后）；`source.getLoginInfoMap()` 正常返回字段即渲染成功
9. **正文/登录遇线路轮换当场失败**——关键动作（正文提取、登录POST）失败时 `pickLine(...,true)` 强制重测重试一次
10. **searchUrl 整条URL必须一个 `{{}}` 产出**——分两段后段被吞；且不要用 `@js:` 前缀（返回代码串会被当相对路径静默解析）
11. **`bookUrl` 绝对路径写死域名=书架定时炸弹**——永远用相对路径让 isUrl 自动拼当前线路域
12. **发布页线路含海外死线**——不排除会把最快测成"全部超时"（每条8秒×N条），黑名单按实测加
13. **站点 301 轮换是自动跟随的**（OkHttp 跟随重定向），相对URL+301双保险后，TTL过期几分钟内旧线路仍能打到新域——所以 301 链路好的站 TTL 可以放更宽
14. **MCP 串行铁律**：save_source/get_source/debug_source 并行调用会 Session not found，必须串行
15. **测速判活别只看状态码**——被墙线路常见返回运营商插页/CF挑战页（有响应但是垃圾内容），**内容长度阈值+关键字**双校验才可靠

## 十二、验证方法论

1. **先单测测速核心**：eval_js 绑定书源URL → `typeof pickLine==='function'` → 手动调 `pickLine(java,source,true)` 看返回（eval_js 上下文 java/source 均可用，且 jsLib 自动求值）
2. **验证 loginUi 可渲染**：`source.getLoginInfoMap()` 返回字段Map即成功（渲染失败会报具体语法错）
3. **debug_source 全链路**：搜索（看日志里实际请求URL落在哪条线路）→ 详情 → 目录 → 正文；间隔做两轮看 TTL 复用（第二轮不应重新测速）
4. **模拟线路轮换**：`source.put('line','https://死域名')` 后再搜索——应自动重测切到活线路（TTL过期或判死触发）
5. **node --check 全部JS块**（loginUi 去 `<js>` 标签后单查；它是宽容解析器，node报错不代表真坏，报"缺少)"时人工核对括号配平）
6. **check_source**：轮换站可能报"检测到重定向"日志——是正常现象不算失败
7. **多时点复测**：发布页/线路的可用性随时间漂移，交付前隔几小时再跑一轮 debug
