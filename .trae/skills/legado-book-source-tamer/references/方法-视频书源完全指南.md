## 1.1 类型体系：一个字段决定 App 走哪条路

| 层 | 字段/常量 | 值 | 事实 |
|---|---|---|---|
| 书源 | `bookSourceType` | 0 文本 / 1 音频 / **2 图片** / 3 文件 / **4 视频** | `constant/BookSourceType.kt` |
| 书籍 | `Book.type`（位掩码） | **video=0b100=4**、text=8、updateError=16、**audio=32**、**image=64**、webFile=128、local=256 | `constant/BookType.kt` |
| 映射 | `BookSource.getBookType()` | `video → BookType.video` … | `help/source/BookSourceExtensions.kt:130` |
| 分流 | `BookInfoActivity` | `book.isVideo -> readBookResult.launch(...)` → **VideoPlayerActivity** | `BookInfoActivity.kt:1500` |

```kotlin
// BookSourceExtensions.kt:130
fun BookSource.getBookType(): Int = when (bookSourceType) {
    BookSourceType.file  -> BookType.text or BookType.webFile
    BookSourceType.image -> BookType.image
    BookSourceType.audio -> BookType.audio
    BookSourceType.video -> BookType.video      // ← 视频源只认这一条
    else -> BookType.text
}
```

**要点与坑**

1. `bookSourceType` 必须是 **4**。写成 0 时正文会被当文本处理（阅读器里显示一串 URL），写成 2 会变漫画页。**视频站的唯一正确值就是 4。**
2. 搜索结果转书籍时 `book.type = bookSource.getBookType()`（`BookList.kt:173/212`），所以视频源搜出来的条目在"最近搜索/在线书籍"里天生就是视频类型，无需规则干预。
3. **刷目录会冲掉 type**（`WebBook.getChapterListAwait` 里 `removeAllBookType()` + `addType(getBookType())`）——纯视频源无影响；但"视频+漫画/图集混合源"必须在目录规则里再 `book.setType(...)` 兜住（110.42 novelServices 四平台聚合源就是靠双 `setType` 解决，听书 `setType(32)`、漫画 `setType(64)`、视频 `setType(4)`）。
4. 混合类型站（一本书可能是 MV / 连续剧 / 图集）：`type` 只能在"详情页规则"和"目录规则"两处设，**且必须在目录规则里也设一次**，否则刷完目录类型退化。

## 1.3 ★★由这张图推出的三条铁律（多数视频源卡在这里）

### 铁律 A：正文输出可以携带 URL 选项 ⇒ 逐条视频的防盗链头

`WebBook` 把正文当成一个 URL 再过一遍 `AnalyzeUrl`，所以正文规则可以返回：

```
https://cdn.example.com/ep/12.m3u8,{"headers":{"Referer":"https://www.example.com/","Cookie":"session=abc"},"timeout":30000,"retry":2}
```

- `headerMap`（含 URL 选项里的 `headers`）→ `player.mapHeadData` → 播放器发请求时带上 ⇒ **Referer/Cookie/UA 防盗链可以精确到"这一集"**，比写在书源全局 `header` 更可控（例如签名域与页面域不同）。
- ⚠️**但 `retry` / `timeout` / `dnsIp` 对"播放"无效**：视频路径只取 `analyzeUrl.url` 与 `analyzeUrl.headerMap` 两样东西，**从不发起这个 AnalyzeUrl 请求**（`VideoPlay.kt:273-287`），所以它们被解析出来就被丢掉；`timeout/retry/dnsIp` 只对"Legado 自己抓页面"的 URL 有意义。**确定能透传到播放器的只有 `headers`**（外加书源 `header` 与登录头，见铁律 B 表）。
- 引号纪律：这段字符串里的双引号是**真实需要**的，所以正文规则要输出它就必须用 `String.fromCharCode(34)` 生成，绝不能在书源 JSON 里裸写（多层转义必坏）。hanime1 的 `H1BUE()` 就是这么造 `chapterUrl` 的选项，`H1OPT()` 造普通请求选项。

★**再加一条（源码级，容易踩空）：播放器不带 Legado 的 Cookie。** `AnalyzeUrl.setCookie()`（把 `CookieStore` 合并进 `headerMap` 的那步）只在 `getResponseAwait / executeStrRequest / getGlideUrl / getMediaItem` 里被调用；**`VideoPlay` 走的是"读 `.url` + `.headerMap`"的旁路，从没调 `setCookie()`** ⇒ 播放请求默认**不含**书源会话 Cookie（对比：音频 `AudioPlayService` 用 `analyzeUrl.getMediaItem()` 才会带）。
⇒ 依赖 Cookie 防盗链的视频站，必须在正文规则里显式拼进 `headers`：

```js
var ck=''; try{ ck = java.getCookie('https://'+H1DOM(source)+'/'); }catch(e){};
var Q=String.fromCharCode(34);
best + ','+C(123)+Q+'headers'+Q+':'+C(123)+Q+'Referer'+Q+':'+Q+pageUrl+Q+','+Q+'Cookie'+Q+':'+Q+ck+Q+C(125)+C(125);
```

（`java.getCookie(url)` 规则上下文可用，见 `help/JsExtensions.kt:499`；换域名/换线路后要按**当前域**现取，别缓存整串——Cookie 是按二级域分仓的，见 8.3。）

### 铁律 B：`dnsIp` 只能救"抓页面"，救不了"播放器拉流"

| 请求 | 用哪个 OkHttpClient | 受什么影响 |
|---|---|---|
| 书源抓网页（搜索/详情/目录/正文页） | `AnalyzeUrl` 自建 client | URL 选项 `dnsIp`（`buildScopedDns`，**只劫持本域**，多 IP 逗号 = OkHttp 顺序 failover，去 Cronet，与 proxy 互斥） |
| **播放器拉视频流** | `ExoPlayerHelper.okhttpDataFactory = io.legado.app.help.http.okHttpClient`（全局共享） | **不认 dnsIp**；只认 ①域名本身可达 ②App 设置→「自定义 Hosts」(`PreferKey.customHosts` → `AppConfig.addressCache` 给全局 client 装了自定义 `dns{}`) ③系统/网络层代理 |

⇒ 结论：**视频域名被 SNI 封锁 / DNS 污染时，书源侧唯一可靠的自救是"换主机名"**（见 4.3 的 CDN 原生主机名替换法），或引导用户配 App 级自定义 Hosts。hanime1 的 `vdownload.hembed.com` 被 SNI 封锁，最终解法就是换成 CDN77 客户原生主机 `1497203185.rsc.cdn77.org`，**而不是**给它加 `dnsIp`。

> 反向陷阱：正文/目录页里如果给"视频直链"拼了 `{"dnsIp":...}`，播放器不会报错，只是白忙一场（选项被 AnalyzeUrl 剥掉，播放仍用被墙域名）。要改播放域名必须在字符串层面真的换 host。

### 铁律 C：m3u8 只能给地址，MPD 可以给文本

`content.startsWith("<")` 是唯一被识别为"内联清单"的分支（`VideoPlay.kt:205/264`，注释写着"当作mpd文本"）。

- HLS（`#EXTM3U` 开头）**不是** `<` 开头 ⇒ 会被当 URL 直接喂播放器 → 必然失败。**要内联改 HLS 只能把 master 清单落地成文件**（Legado 不给这个能力）→ 正解：**永远给 m3u8 的 URL**，若 m3u8 需要头，就靠铁律 A 注入 headers。
- DASH（`<?xml ... <MPD`）⇒ 可以把清单文本直接由正文规则输出，Legado 会写 `cache/video_temp/{md5}.mpd` 再用 `file://` 播放。可用场景：**清单内容由 JS 拼装**（如把相对地址改成绝对地址、合并多线路、把 token 塞进 SegmentTemplate）。注意：MPD 内部的分片/Representation URL 会被按 manifest 位置解析，`file://` 没有 http 头 ⇒ 里面的地址必须是自身可达的绝对 URL。
- 想给"多 P 连播"：不能靠正文拼接（正文只是"一集一个地址"）。多集 = 多章节；见 1.5。

## 1.4 播放器（GSY + ExoPlayer）能力与缓存语义

| 事实 | 依据 | 对书源的意义 |
|---|---|---|
| 播放 URL 由 ExoPlayer 的 `DefaultMediaSourceFactory` 处理，支持渐进式(mp4/webm)、HLS、DASH | `ExoPlayerHelper.createHttpExoPlayer` | 三种流形态都原生可用；无需书源处理分片 |
| 播放缓存 `SimpleCache(externalCache/exoplayer)`，LRU **100MB**，`CacheControl maxAge=1天` | `ExoPlayerHelper.cache / okhttpDataFactory` | ①同 URL 重看秒开；②**签名换值的 m3u8 只要 URL 变就自然绕缓存**；③坏流会被缓存住 → 换 URL（加 `?v=N`）是唯一的自愈手段 |
| `setLiveTargetOffsetMs(5000)` | 同上 | 直播流也勉强可用（延迟敏感） |
| 弹幕：`ruleContent.subContent` → `book.isVideo` 时 `bookChapter.putDanmaku(subContent)` | `BookContent.kt:158-161` | ★**视频源可以自带弹幕**，见 1.4.1 |
| 语速：`ExoPlayerManager.setSpeed` 只能在播放前生效（源码注释"很遗憾"） | `ExoPlayerManager.kt:82` | 书源无法弥补，别在这上面花精力 |

### 1.4.1 ★ 弹幕接入（几乎没人在书源里用过的官方能力）

```kotlin
// BookContent.kt:133-163（subContent 分支）
```

**结论 / 写法**

- `ruleContent.subContent` 输出**B 站 XML 弹幕**的地址（推荐，正文只存一个链接，体积小）或直接输出 XML 文本。
- ★XML 中 `p` 属性字段序（**以 `BiliDanmukuParser.kt:81-100` 源码为准**，与网上流传的"B站新版含 duration"写法不同，这里**没有 duration**）：

  ```
  <i><d p="23.826,1,25,16777215,1422201084,0,057075e9,757076900">文字内容</d></i>
          0        1 2   3         4          5  6          7

    2 字号          3 颜色(十进制，16777215=白)     4 时间戳(解析器未用)
    5 弹幕池 id(忽略) 6 用户 hash                    7 弹幕 id
  ```
  持续时长由 `DanmakuFactory` 自己算（滚动/固定分别处理），**不用也不能填 duration**。
- 只认 B 站 XML（`DanmakuLoaderFactory.TAG_BILI` + `BiliDanmukuParser`），**不认 ass / json / 其它弹幕变体**。
- 显示端参数已在 App 侧定死：滚动弹幕最多 5 行、禁止重叠、描边 3px、速度 = `VideoPlay.danmakuSpeed`(1.2f)、字号 × `(displayerDensity-0.6f)`、`SpannedCacheStuffer`（Spanned 渲染，但**弹幕文本按纯文本最稳**，别塞 HTML）。
- 弹幕取不到数据时**弹幕开关按钮直接隐藏**（`initDanmaku` 里 `mToggleDanmaku.visibility = GONE`）→ 写了 subContent 但取错位置=静默无弹幕，不报错。
- 若站点有弹幕接口（很多国内影视/A站系有此）→ 一行 `"subContent": "jsonpath到弹幕xml地址"` 即可白送弹幕功能；没有接口就**别写 subContent**（写了且取不到值 → 存空串，弹幕开关按钮直接隐藏，无害）。
- 注意 `subContent` 若以 `http` 开头会被 Legado **先请求一次**再存结果（`BookContent.kt:139`），所以给 URL 时要确保该 URL 不需要额外头，否则改成"在规则里直接返回 XML 文本"。

## 1.5 目录的"卷 / 集"官方模型（多线路的正确表达法）

```kotlin
// VideoPlay.kt:420-471
toc.forEach { if (it.isVolume) volumes.add(it) }      // 目录里"卷"= 线路
fun upEpisodes() {
    if (volumes.isEmpty()) { durVolume = null; episodes = toc; return }   // 扁平写法
    durVolume = volumes.getOrNull(durVolumeIndex)
    episodes = toc.subList(durVolume.index + 1, nextVolume.index)          // 卷下章节 = 剧集
}
```

| 目录写法 | 播放器表现 | 适合 |
|---|---|---|
| **扁平**（全是章节，无卷） | `episodes = toc`；横向"选集"条 = 全部剧集；★源码注释警告：*"如果全是章节没有卷的写法，播放完后会继续下一个线路重复播放"* | 单线路、每章一个视频（**hanime1 用这种**：每个 P 一行） |
| **卷 = 线路，卷下 = 剧集** | 播放页出现**两条横向列表**：线路(volumes) + 选集(episodes)；切线路由 `durVolumeIndex` 记录 | 多 CDN / 多清晰度 / 多语种线路的影视站（**推荐**：Legado 自带线路切换 UI，书源不用自己做） |
| 单层卷、无子集（电影类） | `durVolume.url` 会被当播放地址（要求卷的 URL **不以标题开头**，`VideoPlay.kt:243`） | 一部电影多线路且不想列剧集 |

⇒ **做"多线路影视站"时优先用「卷=线路」而不是把线路拼成章节名**，用户能直接用 App 的线路切换条；并且"播放完自动下一集"只会在当前线路内循环。

> 让章节成为"卷"的官方字段是 `BookChapter.isVolume`（`variable`/`isVolume`）。规则侧可在 `chapterList` 的对象里给出（LT 版支持 `isVolume` 键）；实测保守做法：把线路放在**卷的父节点**由 Legado 自动生成，或干脆用扁平 + 清晰度参数（hanime1 路线）。

## 1.6 "当前是哪一集"：四个索引与两个陷阱

| 字段 | 语义 | 陷阱 |
|---|---|---|
| `book.durChapterIndex` | 全书章节索引（0-based，指向 toc） | ★**新书默认 0 且 `durChapterTitle=null`**，不能当"用户选中的那一集"用 |
| `book.durChapterTitle` | 上次播放的章节标题 | 用它是否非空判定"真读过"（hanime1 `H1READ`） |
| `book.durVolumeIndex` / `chapterInVolumeIndex` | 线路索引 / 线路内集数 | 只有有卷时才有意义 |
| `book.durChapterPos` | 秒级进度 | 20 天内续播（`VIDEO_POS_SAVE_TIME`） |

- **陷阱 1（新书陷阱）**：用 `vids[durChapterIndex]` 反查当前集会把所有新书强制跳到第 1 集。正解 = `H1READ(book)` 守卫：未读过 → 用页面自身的 P；读过 → 才用索引。
- **陷阱 2（站点排序陷阱）**：站点 playlist 若是**新→旧**排列（hanime1 就是），Legado 永远从目录第 1 行开始播 ⇒ "点第 2 集进去却播了第 1 集"。正解 = **把入口那一集排到目录第 1 位**（`H1ORD(vids, ep)`，`ep` 从 `book.bookUrl` 解析），并在"当前P计算 / 按钮目标 / 目录顺序"三处用同一套逻辑。
- **探针实证**（可复用）：`book.bookUrl` 里**保留着点进来时那条带 URL 选项的完整字符串**（`...watch?v=407606,{"dnsIp":"..."}`），且它等于"入口那一集的地址"；`book.durChapterIndex` 在 Rhino 里**可直接赋值**。

## 1.7 ★ 播放页简介是一次性快照（Legado 无刷新通道）

源码证据链（全部实读 LegadoTeam `a6839374`，2026-09-11）：

1. `VideoPlayerActivity.showBookIntro(book)` 只在 `showBook()`（`initView`）里被调一次；
2. `VideoPlayerActivity.observeLiveBus()` 只监听 `VIDEO_SUB_TITLE`（sticky）和 `UP_VIDEO_INFO` —— **不监听 `REFRESH_BOOK_INFO`**；
3. `REFRESH_BOOK_INFO` 的唯一监听者是 `BookInfoActivity`；
4. 且 `observeEvent` 带 `lifecycle.isAtLeast(STARTED)` 判断 → 播放页在前台时详情页收不到事件。

⇒ `java.refreshBookInfo()` 在播放页是**空操作**；书源 JS 无法让播放页重绘简介。
⇒ 想让播放页信息"跟着切集变"，唯一可行组合是：**`<useweb>` 活视图（WebView 里可以自己 setInterval 改 DOM）+ `ruleContent.callBackJs`（官方事件通道）当信号**，详见第七章。

其它框架限制（同章实测记录）：

- `refresh` 时 `canReName = false` ⇒ **`book.name` 永远不更新**（书架稳定性设计）。多集书想显示"当前集标题"只能写在 intro 里（`🎬 当前P标题: xxx`）。
- 切章节不会自动刷新详情页（无钩子），用户回详情页需手动刷新或靠面板轮询。
- `VideoPlayerActivity` 的简介容器与 `BookInfoActivity` 一样支持 `<usehtml>` / `<useweb>`，按钮环境也是 `SourceLoginJsExtensions`（含 `copyText`）。

# 四、网络可达性工程（视频源的第一道生死关）

## 4.1 三种封锁的鉴别表

| 现象 | 类型 | 判据 | 处置 |
|---|---|---|---|
| `ERR_NAME_NOT_RESOLVED` / 解析出完全无关 IP（如 Facebook/百度 IP）/ TCP 全超时 | **DNS 污染** | 沙盒与真机分别 `InetAddress.getAllByName` 对比；或 DoH 查询对照 | URL 选项 `{"dnsIp":"ip1,ip2"}` |
| TCP 通、TLS `handshake aborted` / `SSL handshake failure`，且**换 IP 无效、直连真实 IP 也失败** | **SNI 封锁** | 用 IP 直连（URL 里没有该域名 ⇒ 无 SNI）能过、带域名就死 = SNI 封；`dnsIp` 生效后仍 TLS 失败 | ①换 **CDN 原生主机名**（4.3）②http 明文（若 CDN 支持）③代理 |
| 200 但响应含 `just a moment` / `cf-browser-verification` / `Attention Required` / `error code: 1034` | **CF 挑战/风控** | 只看响应前 4~6KB；1034 = 该 IP 与站点解析记录不匹配（用了别人的 CF IP 打非它托管的域） | 降频（`concurrentRate`）、换正确 IP、`java.startBrowser` 人工过盾、等 3~5 分钟 |
| 间歇 TLS RST（同一 URL 时好时坏） | **CF 节点抖动** | 多时点复测；换 IP 即好 | 全链路 `retry:3` + 异常文本校验 + 梯度等待 |

**必须内化的两条取证纪律**

- **手机侧才是真相**：沙盒（海外出口）与用户网络结论可以完全相反（本项目：`img5` 图床沙盒 200 / 手机 RST；`hanime1.me` 沙盒全 RST / 手机一条可通）。判"站点/CDN 挂了"必须用 `MCP eval_js` 在真机跑 `java.ajax`。
- **`java.ajax` 对被墙域有时不抛异常，而是把 `javax.net.ssl.SSLHandshakeException` 全文当响应体返回**（实测 2788B）。所以连通性判断必须 `indexOf('Exception')` + 内容标记双重校验，**不能只看长度**（本项目踩了 ≥3 次）。

## 4.2 `dnsIp` 的正确用法（LegadoTeam 原生）

依据 `AnalyzeUrlNetworkOptions.kt`：

```kotlin
internal fun parseDnsIpAddresses(value: String) = value.split(',').map{...}   // 逗号 = 多 IP
internal fun buildScopedDns(targetHost, addresses, fallback) = Dns { h ->
    if (h.equals(targetHost, true)) addresses else fallback.lookup(h)         // ★只劫持 URL 本域
}
internal fun validateDnsIpProxyCompatibility(proxy, dnsIp) = require(proxy.isNullOrBlank() || dnsIp.isNullOrBlank())  // ★与代理互斥
```

- 别名 `resolveIp` 也可用；值是 IP 字面量（**不接受域名**）；多 IP 逗号分隔 = OkHttp 按序 failover（**这就是"备用线路"的实现方式**）。
- 带 `dnsIp`（或自定义 `timeout` / `followRedirects`）的请求会**把 Cronet 拦截器摘掉、改走纯 OkHttp**（源码：`AnalyzeUrl.getClient()` 把 `Cronet.interceptor` 作为 `interceptorToRemove` 传给 `buildRequestClient`）⇒ 保留 SNI 与证书校验，但与 App 默认网络栈行为有差异（少数靠 Cronet 才通的站要留意）。
- 与 `proxy` 互斥 ⇒ 书源里"代理开关"生效时必须让 `H1IPX()` 返回空串（hanime1 正是这么写的：`H1IPX(src){ if(H1PX(src)) return ''; return H1IP(src) }`）。
- `dnsIp` 是 **URL 选项，不是 header**！写进 `header` 完全无效（本项目实测）。
- 只对"Legado 抓页面"生效，**对播放器拉流无效**（铁律 B）。
- 用户侧唯一的"给播放器换 IP"通道 = **App 设置 → 「自定义 Hosts」**（`PreferKey.customHosts` 存 `{"域名":"IP"}` 或 `{"域名":["ip1","ip2"]}` → `AppConfig.addressCache` → 装进**全局 `okHttpClient` 的 `dns{}`**，而播放器的 `ExoPlayerHelper.okhttpDataFactory` 正是基于这个全局 client）。
  ⇒ 书源能在 `bookSourceComment` / 控制台提示里**教用户怎么配**，但**不能替他配**。

## 4.3 ★ CDN 原生主机名替换法（SNI 封锁的通用解法）

**方法论（可移植到任何视频站）**

```
1) 确认是 SNI 封锁：拿媒体域名的真实 IP（dnsIp）建 TCP/TLS —— TCP 通、TLS 挂 = SNI 封
2) dig +short <媒体域名> CNAME  → 找到 CDN 厂商（本例 *.cdn77.net / rsc.cdn77.org）
3) 在 CDN 侧找"客户原生主机名"：{accountId}.rsc.cdn77.org（CDN77）、
   {zone}.msecnd.net / *.vo.msecnd.net（Edgecast）、{id}.cloudfront.net（CF）等
4) 验证两件事：
   a) 同一签名/带 token 的路径换主机名后仍可取流  ← 关键：**签名是否绑 Host**
      （矩阵对照法：同一 token 打 img1~img5 / 两个 CDN 主机，全 200 ⇒ 签名只绑路径+过期时间）
   b) 该主机名在用户网络可达（真机实测，不是沙盒）
5) 书源侧做开关：H1CDN(src) 返回替换后的主机，h1cdn=off 可退回原域名
```

hanime1 落地代码（5 行，通用）：

```js
function H1CDN(src){var v=H1G(src,'h1cdn'); if(v=='off')return 'vdownload.hembed.com';
                   return v||'1497203185.rsc.cdn77.org'}
function H1FIX(src,u){u=String(u); if(u.indexOf('vdownload.hembed.com')<0)return u;
                      return u.split('vdownload.hembed.com').join(H1CDN(src))}   // split/join 全替换，无正则无反斜杠
```

- 适用范围：**CDN77 这类"签名只绑路径"**的站；**不适用 Cloudflare**（Host 绑 zone，换主机名 403/1034）。
- 顺手收益：**换主机 = 换 URL = 换播放器缓存 key**，坏缓存自动绕开（三层缓存机制见交付篇）。
- ★分片级封锁无解：如果 CDN 对 `.ts` 分片要求浏览器环境（黄果剧场：`X-HG-Nonce`/`preview-token`/`window.__hgN`），书源换主机也没用 → **降级为 `java.startBrowser(详情页)` 用内置浏览器播**。

## 4.4 hosts 池测速选线（含视频站特化）

完整方法在 `方法-发布页线路轮换与登录界面测速选线.md`，这里只记**视频源新增的三点**：

1. **测速要选"轻且不缓存"的探测目标**：`https://{host}/robots.txt`（hanime1 实测 24B / 400ms 级）比首页(425KB)轻 5 个数量级，**才能对全 IP 池做全量测速而不触发 CF**。
2. **必须识别"CF 错误页也算有响应"**：`error code: 1034` / `Bad gateway` / `Origin DNS error` / `Access denied` 都有 body，**光看"长度>0"会把死 IP 判成活的**。判语料：
   ```js
   if(/Exception|Cronet|error code:|Bad gateway|Access denied|Origin DNS error/i.test(s)) → 不通
   if(/just a moment|cf-browser-verification|attention required/i.test(s))               → CF盾(可用但不计延迟)
   ```
3. **备用 IP 必须"逐个实测通过"才并入多 IP failover 组**。hanime1 曾因"把测速池前 3 个未实测 IP 拼进 h1ip"导致组里混入两个已死 IP（v3.4 修复）。多 IP 组 = 最快 3 + 命中的那 1（最多 4，按延迟序 failover）。

**延迟表持久化格式**（可照抄）：`h1lat = "IP:ms;IP:ms;…"`，失败写 `IP:x`，最多 24 条；下拉项显示 `IP · 123ms` / `IP · 不通` / `IP · 未测`；取用时 `split(' ')[0]` 保证后缀不影响解析。

## 4.5 代理通道

- 书源侧唯一入口 = **`header` 里的 `proxy` 键**（`AnalyzeUrl` init 会把 `headerMap` 中的 `proxy` 摘出来当请求代理，见 `AnalyzeUrl.kt:139-147`）：
  ```json
  "header": "<js>…若有 h1px 变量则输出 {\"User-Agent\":\"…\",\"proxy\":\"http://127.0.0.1:7890\"}…</js>"
  ```
- 代理与 `dnsIp` **互斥**（4.2）⇒ 有代理时必须让所有 URL 选项里的 dnsIp 变空串。
- 播放器是否走代理：`ExoPlayerHelper` 用全局 `okHttpClient`，**不吃书源的 proxy 选项** ⇒ 靠代理救播放必须用户在系统层开代理。这就是 hanime1 控制台里"🛜代理"提示措辞的由来：**代理能救抓取，未必能救播放**。

# 五、目录（剧集）设计：视频源专属的五个决策

## 5.1 决策 1：一 P 一行还是多 P 一行？

| 方案 | 做法 | 结论 |
|---|---|---|
| **一 P 一行（推荐）** | 目录每行 = 一个可播地址；播放器"选集条"= 全部 P | 进度/续播/事件全都自然；hanime1 采用 |
| 一行多清晰度 + `sourceRegex` | 正文里再解析选流 | 多一层解析，且 ExoPlayer 自己会自适应，收益低 |
| 卷=线路、章=剧集 | `isVolume` 行做线路 | **多线路影视站的正解**（App 自带线路切换 UI），见 1.5 |

## 5.2 决策 2：清晰度参数塞在哪？

`chapterUrl` 里除了 URL 选项还可以**塞自定义键**：`UrlOption` 是 `@Keep data class`，GSON 解析时**未知键被静默忽略**，但原始字符串仍完整留在 `chapter.url` / `baseUrl` 里 ⇒ 正文规则能把它读回来。

```js

```

- 好处：**下拉换清晰度 = 换目录行 URL = 换播放器缓存 key**，秒切不串缓存。
- 另一条等价路线：`chapterUrl = 页面URL#Q720`（fragment 不进 HTTP，天然唯一）。**两条都能用**，hanime1 两条都做了兼容读取。
- ⚠️ 用 `#fragment` 时记住铁律：**同 URL 章节会被 Legado 按 URL 去重合并**（`BookChapter.equals` 只比 url）⇒ 必须保证每行 URL 唯一（fragment 正是保证唯一性的常用手法）。
- ⚠️ URL fragment 会污染 `baseUrl`（黑料网实测：debug 时详情页 baseUrl 带 `#browser` 导致目录章节 URL 被污染）⇒ **规则里对 URL 统一 `split('#')[0]` 清洗**。

## 5.3 决策 3：`chapterList` 返回什么类型？

- 本 App（LegadoTeam）：`@js:` 返回 **JS 对象数组** + 字段规则写纯键名（`n` / `u`）完全可用（源码 `Mode.Js → NativeArray → getString 键访问`）。
- **要跨 legado-E / Lyc 版分发时必须改成「JSON 字符串数组」**（E 版 `getString/getStringList` 没有 `Mode.Js` 分支 → 对象条目的键规则取到 undefined → 目录整条被丢）。写法：
  ```js
  out.push(String(JSON.stringify({n:名, u:址})))   // 每个元素是 JSON 字符串
  // 字段规则："chapterName":"$.n", "chapterUrl":"$.u"
  ```
  ⇒ 若不确定用户用哪个 App，**默认用 JSON 字符串数组**（LT 版同样正常）。这是本项目对"下一份视频源"最省事的建议。
- 目录侧顺带塞数据（★省请求的关键技巧）：`H1PL(d,src)` 解析播放列表时**同时返回每集标题+封面映射**，让**详情页简介一次性内嵌全部集数数据** ⇒ 面板切集显示封面/标题时**零网络请求**（第七章 7.2）。

## 5.4 决策 4：目录顺序 = 播放顺序，站点倒序必须重排

```js
function H1ORD(vids,ep){ if(!ep) return vids; /* 把入口 ep 移到数组第 1 位，其余保持原序 */ }
function H1EP(Bk,fb){ return H1VID(Bk.bookUrl) || fb; }   // 从 bookUrl 取"点进来的那一集"
var vids = H1PVA(d, ep);   // = H1ORD(H1PV(d), ep)
```

- 三处必须同步：目录顺序、"当前P计算"（`H1CURV`）、按钮/简介里的"▶ 播放目标"（`H1CT`）——**任何一处漏改就会出现"文字对、播的是另一集"**。
- 章节名用站点真实标题（`h4.video-title a`），拿不到才退化成 `第N P`。
- 索引换算陷阱：`H1CT(Bk,vstr,qstr,...)` 里的"每行元素数 k"必须与实际目录结构一致（改成每 P 一行后 k 必须 = 1，`qstr` 传空串）。**改目录结构时必须全文搜这个参数**（v2.6→v2.8 就是这里算错过索引）。

## 5.5 决策 5：目录要不要分页？

- 视频站的播放列表绝大多数**内联在 watch 页**（一屏几十~几百条），**不要 `nextTocUrl`**。
- 若站点是分页接口取剧集：`nextTocUrl` 逐页返回**一个**下一页 URL（链式保序）；引 `方法-目录顺序与章节去重铁律.md`。
- 长目录（>1000 行）注意去重与顺序校验：本项目用"数字前缀升序 0 违规"作为验收法。

## 6.2 视频正文的七条纪律

1. **只输出一个绝对地址**（或一段 MPD 文本）。多行/带说明文字会被当 URL → `player.setUp` 拿到脏字符串 → "获取资源链接出错"。**Legado 对视频不做净化**（1.2），所以别指望 `formatKeepImg` 帮你清理。
   ★**书源路径不做相对地址补全**：`VideoPlay.kt:211` 的 `NetworkUtils.getAbsoluteURL(...)` 只在**订阅源(RSS)**分支里调用，书籍分支（`:262-270`）是 `content` 原样使用 ⇒ 正文返回 `/a.mp4` 或 `//cdn/a.mp4` 一定播放失败，**必须自己在规则里补成绝对 URL**（6.1 的第④步）。
2. **异常必须 `throw new Error('中文人话+下一步动作')`**。空返回的报错是 `ContentEmptyException("正文为空")`，用户完全看不懂；抛错信息会原样出现在播放器 toast / debug 日志里。
3. **时效直链不要在目录阶段固化**。目录行的 URL 应该是**页面地址**（让正文每次去取最新签名），而不是把 10 分钟就过期的 `?secure=` 直链写进 `chapterUrl`。
4. **清晰度回退要有"最近值"算法**（站点常没有 1080）；返回前**打印/提示实际给的是哪一路**更友好（可拼在 intro/面板里而不是正文）。
5. **懒渲染 / 异步注入的站点**：`source` 子节点数为 0 时必须重取页面（多轮 + 变体 URL 选项）；实在拿不到就 `java.startBrowser(详情页)` 让用户在内置浏览器里看（mdcmai/黄果剧场路线）。
6. **重取用 `Packages.java.lang.Thread.sleep(ms)`**（本 App **没有 `java.sleep`**）。
7. **别在正文里 `source.put` 大量数据后又不 try**：正文规则失败会让整集打不开，**任何"顺带写缓存/写变量"的副作用都要包 try/catch**（hanime1 的 `try{H1TA(...)}catch(e9){}`）。

## 6.3 视频源用 `nextContentUrl` / `replaceRegex` 吗？

- `nextContentUrl`：**几乎永远不要用**——正文是 URL，跟"下一页"语义冲突；多集 = 多章节。
  而且多页结果会被 `contentList.joinToString("\n")` 拼接（`BookContent.kt:169`）⇒ 两行 URL 拼成一个脏字符串喂播放器，必炸。
- `replaceRegex`：**别写**。★源码更正：`replaceRegex`（`BookContent.kt:171-177`）对视频**照样执行**，
  且执行时会 `split(LF).joinToString{"\n"){ it.trim() }}` 逐行 trim —— 一旦替换规则误伤 URL（比如想删广告字符却命中了 `?a=` 里的 `a`），
  直链会被静默改坏，表现为"播放器报错/黑屏"。不写=零风险。
- `title`（正文里取章节名）：视频源基本不需要；但**可以用它把章节名改成"当前集真实标题"**（`bookChapter.title` 会被覆盖，`BookContent.kt:193`）——多集站目录名不准时可考虑。
- `imageStyle` / `imageDecode` / `sourceRegex`：对视频无效（图片/漫画才用）。
- `title`（正文里取标题）：视频源不需要。
- `payAction`：付费站可用（`video` 类型也走同一分支），但更稳的做法是抛人话提示换源。
- `webJs` / `{"webView":true}`：★**视频站的隐藏武器**——直链由 JS 现算（如 `window.__hgN`+`api/preview-token`）时，可用 URL 选项 `{"webJs":"…","webView":true}` 让 Legado 后台 WebView 执行 JS 后再取 body。黄果剧场的 `.ts` 分片就是"只有浏览器环境才有 token"，理论上可尝试 `webView` 取 manifest；本项目当时选了 `startBrowser` 降级，**下次遇到同类站先试 `{"webView":true,"webJs":…}`**（记录为待验证项，见 14 章 K30）。

# 七、详情页 / 播放页交互：三档成型方案

## 7.1 三档（按投入排序，都能上线）

| 档 | 形态 | 能力 | 适用 |
|---|---|---|---|
| **T1 纯文本快照** | `intro` 输出 `<usehtml>` + `<button>@onclick:JS` | 按钮点击跑**完整 JsExtensions 环境**（能 `startBrowser`/`openVideoPlayer`/`ajax`），但**内容进页面就冻结** | 只要"能点"，不要求跟随 |
| **T2 快照 + 手动刷新** | T1 + `🔄刷新详情`(`java.refreshBookInfo()`) | 在**书籍详情页**有效；播放页无效（1.7） | 过渡形态 |
| **T3 活视图面板** | `intro` 输出 `<useweb>`（真 WebView，`setInterval` 自轮询）+ `ruleContent.callBackJs` 信号 | **播放切集时简介/封面/收藏态自动跟随**（App 没给的通道，自己造出来） | 多集视频站的最终形态（hanime1 v3.2~v3.9） |

选型细则与 HTML 转义纪律见 `方法-详情页交互按钮选型树.md`；视频源特有的部分是 **T3 的"跟随"机制**，下面完整拆解。

## 7.2 ★切集实时跟随：三通道拼装（本项目最高价值成果）

```
【信号通道】ruleContent.callBackJs + 书源 eventListener=true
   Legado 在 起播/存进度/退出 时都会调 SourceCallBack.callBackBook(event,...)
     startRead（进播放页）、saveRead（切集/定时保存）、endRead（finish 退出）
   绑定：event / result / book / chapter / java / source
   → 把 "入口集vid|正在播vid|时间戳" 写进 source 变量 h1now

【视图通道】intro 输出 <useweb> 面板（BookInfoActivity 与 VideoPlayerActivity 都渲染它）
   页面 setInterval(1.5s) 读 h1now；gate = (h1now[0] == 本书入口vid)  ← 多书互不串
   发现第 2 段变了 → 重绘那一集

【数据通道】绝不在面板里同步拉 425KB 页面（★会冻结 WebView 的 JS 线程 0.66~6.8s）
   ① 详情页生成时就把"每集标题+封面"内嵌进面板（来自目录侧栏，见 5.3 的 H1PL）→ 首屏与预览零请求
   ② 正文规则（在后台线程跑）顺手把"正在播这一集"的全量信息写 h1info → 面板只读内存键改 DOM
   ③ 只有都拿不到时才惰性拉页（同集 8s / 全局 2.5s 冷却 + 仅在仍显示该集时才重绘）
```

实现要点（真实代码纪律，逐条踩过）：

```js
// ① callBackJs：不要 return 真值、不要依赖 result；用 g2() 双兼容 Kotlin 属性/方法
(function(){try{
  if(event!='saveRead'&&event!='startRead'&&event!='endRead')return;
  function g2(o,k){var f=o[k]; return typeof f=='function'?String(f.call(o)||''):String(f==null?'':f)}
  var m=String(g2(chapter,'url')||g2(chapter,'chapterUrl')).match(/[?&]v=([0-9]+)/);
  var e=String(g2(book,'bookUrl')).match(/[?&]v=([0-9]+)/); if(!m||!e)return;
  var pv=String(source.get('h1now')||'').split('|');
  if(pv.length>1&&pv[0]==e[1]&&pv[1]==m[1])return;                 // 同集不重复写（防抖）
  source.put('h1now', e[1]+'|'+m[1]+'|'+String(Date.now()));

```

- **为什么不能只靠正文规则里写变量**：内容命中缓存时正文规则**根本不跑**（所以 hanime1 在 `H1TA` 和 `callBackJs` 两处都写，双保险）。
- ★`h1info` 有**体积上限**才写（`if(s.length<400000)`）——上限写太小会导致"内置封面(≈100KB)被静默丢弃 → 切 P 不跟随"（v3.9 就从 9000 提到 400000）。**给变量加护栏时，护栏值要按最坏情况算**。
- **诊断三键**（出问题时按顺序读，不要再靠猜）：`h1now`（播放器事件是否送到）/ `h1ev`（callBackJs 是否活着，带事件首字母+vid+时间）/ `h1diag`（面板心跳：`ms|P或V|ticks|BUSY|距上次拉页秒|h1now|事件`）。
- **按钮一律 `sp(fn,tip)` 包装**：先渲染 `⏳`，再 `setTimeout(60ms)` 才发桥调用 ⇒ 桥再慢也不会"点了没反应"。桥超时从 25s 降到 12s。
- **预览别打回**：`reload()/boot()` 回调只在"数据属于当前显示集"时重绘，否则用户手翻的预览会被心跳打回。
- **能力探测**：面板里每个按钮渲染前先 `typeof java.xxx=='function'` 探测（桥在不同版本能力不同）；探测结果**不要写进会被重绘比较的字段**（本项目曾用 `INFO.op2` 当标记，导致每 6 秒多刷一次画面）。

## 7.3 `<useweb>` 面板的视频站专属注意点

1. **`substring(8, intro.lastIndexOf('<'))` 截断陷阱**：面板里所有用户文本必须转义（`<`→`&lt;`），且**结尾不能再有别的 `<`**（`</useweb>` 必须最后）。
2. **`blockNetworkImage` 真相**：池化 WebView 可能被上一个使用者（`BackstageWebView` 硬写 `blockNetworkImage=true`）留在屏蔽网络图片状态 ⇒ **简介里的网络图片可能不显示，而 `data:` URL 不受影响** ⇒ 稳的做法是**规则侧下载封面 + Base64 内置**（`H1DIMG`，五护栏见 `方法-图片不显示排查总表` 第 3 节）+ 保留网络地址兜底 + `img.onerror` 逐候选重试 + 状态行回显 `🖼 封面:内置 100KB`。
3. **面板里 `<img>` 的 src 若走 Legado 图片正则提取的场景（阅读器正文）必须双引号**；简介 WebView 里则无所谓（浏览器解析）。
4. **`source.get/put` 在 useweb 与规则侧同键空间**（`CacheManager` 键 `v_{sourceKey}_{k}`，**进程内存级，App 重启失效**）⇒ 面板能读规则写的变量，反之亦然；但**重启后面板要能自愈**（本项目"首章自动重探"）。
5. **`java.request('run')` 在 useweb 里永不会 resolve**（两页都传 `activity=null`）⇒ 只能同步桥；异步一律 `setTimeout` 伪装。
6. **QuickJS/核心 JS 不支持反引号模板字符串**（面板脚本统一单引号 + `JSON.stringify`）。

## 7.4 "在 App 里播" 与 "在浏览器里看" 的降级链

```
有可播直链   → 目录行 URL 交给 Legado 播放器（最佳）
只有页面能播 → java.startBrowser(详情页, 标题)   ← 内置 WebView（规则上下文可用）
用户要外部   → java.openUrl(url)                ← 走 OpenUrlConfirmActivity（外部件确认页）
```

- 规则上下文（含 `@onclick`）里 `startBrowser` / `openVideoPlayer` 都可用；**桥（useweb 页面）里 `openVideoPlayer` 可用（有注解 + `appCtx.startActivity`），`startBrowser` 不可用**（无注解）⇒ 面板按钮要 `typeof` 探测后再渲染。
- 混合形态书（视频 + 图集，如黄果剧场）：视频给不了可靠流就 `startBrowser`；图集在正文拼 `<img>` HTML 让阅读器渲染（**src 必须双引号**，阅读器 `AppPattern.imgPattern` 硬要求）。

# 八、登录、Cookie 与"线路 × 登录态"矩阵

## 8.1 表单登录（Laravel/Django 类视频站最常见）标准流程

```
① GET 播放页/登录页 → 取 CSRF：input[name=_token]（+ 隐藏字段如 like-user-id 一并取）
② POST 目标接口，头必须齐：
     Content-Type: application/x-www-form-urlencoded
     X-CSRF-TOKEN: {token}
     Referer:      https://{域名}/watch?v={id}      ← 少这个常被拒
     X-Requested-With: XMLHttpRequest              ← 决定返回 JSON 还是整页 HTML
③ 判成败：★不要只看 POST 响应（302 会吞掉 flash 文案）→ 再 GET 一次首页复核登录哨兵
④ 成功后：java.putLoginHeader(...) 或 source.put 存账号；cookie 由 enabledCookieJar 自动持久
```

- 用 `java.ajax(url+','+JSON.stringify({method:'POST',body:...,headers:...}))` 的**URL 选项式** POST 才能复用 CookieJar（`header` 字段式 POST 不共享会话）。
- **响应常是 HTML 片段而不是 JSON**（Laravel 局部刷新）⇒ 解析要双通道：先试 `JSON.parse`，失败再按 HTML 找哨兵词（成功词/失败词各一份），并在找不到时把服务器原话（`div.text-danger` 之类）**原文回显**给用户。
- **URL 选项 JSON 必须是"单个对象"**：`url,{"a":1},{"b":2}` → GSON 解析失败 → NPE。合并成一个：`{"method":…,"body":…,"headers":{…}}`。

## 8.2 ★登录态判据：绝对不要用 `_token`

| 判据 | 可靠性 | 说明 |
|---|---|---|
| `input[name=_token]` | ❌ **匿名也下发**（CSRF 对访客也发） | hanime1 曾因它把"未登录"误报成"无收藏夹" |
| 页面含"退出登录"/某会员中心链接 | ✅ 最稳 | 仅登录态渲染 |
| `input[name=like-user-id]` 有值 | ✅ | 本站采用（还能顺手拿 uid） |
| `div[class~=playlist-checkbox-wrapper]`（收藏夹勾选框） | ✅ | 登录后才渲染，实测登录页 8 个 |
| `div.user-modal-dp-wrapper`（头像） | ✅ | 三选一兜底 |

⇒ 通用写法：`lg = uid ? 1 : (收藏夹数>0 || 头像节点) ? 1 : 0`，并把"未登录 / 已登录但无数据 / 正常"**三种文案分开**（用户能自助排查）。

## 8.3 Cookie 按域名隔离 ×多镜像域名 = 换线路掉登录

```
GET hanime1.me → 3108B 匿名页（无 user-modal）      ← 当前线路
GET hanime1.com → 224KB，user-modal-dp-wrapper ✅   ← 登录时用的域
```

- Legado `CookieStore` **按二级域分仓**（`CookieStore.getCookie(domain)`）。多镜像同后端时，切域名 = 换 cookie 仓 = 变匿名。
- 解法：**"🔗 同步登录态到其它域名"** —— 以带 `remember_web_*`（Laravel 长期登录）的域为源，把 `域名会话键` **合并**写入其它镜像域：
  ```js
  var all = java.getCookie(srcUrl);            // 先读全串
  // 用 getCookie(target) 读出目标域已有 cookie，保留 cf_clearance 等不动，覆盖三个登录键
  cookie.setCookie(targetUrl, merged);         // ★setCookie 是“整体替换”语义！必须先读全再回写
  ```
- 相关铁律（引 Cookie 限频篇）：`cookie.setCookie(url,str)` **整体替换**；本 App 无 `java.setCookie`；`cookie.removeCookie(url,key)` 两参签名不存在 → 只能 get + set 配对。
- **别把第三方站域名混进同步列表**（本项目 `javchu.com` 是 JAV 站，必须排除）。

## 8.4 账号自动回填与官方加密存储

- `source.getLoginInfo()` = Legado **可逆 AES(androidId)** 解密后返回原文 JSON（`BaseSource.kt:254`）；`source.putLoginInfo({账号,密码})` 返回 Boolean。
- 面板初始化取值顺序：`state内存 → source 变量 → getLoginInfo()`，且**用户显式清空过的（state 里已是字符串）不要被存储值覆盖**（否则"清空密码"永远清不掉）。
- 登录成功的**两个分支**（真登录 / 本来就已登录）都要 `putLoginInfo`，不要依赖用户手点"💾保存账号"。

## 8.5 `loginCheckJs`：把它当"响应拦截器 + 风控翻译器"

- 语义：搜索/发现/详情/目录/正文**每次请求后**都跑；`result` 是 `StrResponse`，**必须原样 `return result`**。
- ★本 App 里 Kotlin data class 的属性在 Rhino 中可能是**方法**：`result.body` 要写 `(typeof r.body=='function')?r.body():r.body` 双通道。
- ★必须 IIFE 包裹（顶层不能 `return`）。
- 视频站最有用的翻译：**CF 挑战页 / 1020 拒绝 / 限频页 → `throw new Error('中文+下一步动作')`**，只查 `<8000` 字节的响应（大页面里可能偶然含关键词）。

# 九、搜索与发现页（视频站通用打法）

## 9.1 列表：一个 JS 函数通吃所有卡片模板

视频站首页/搜索/分类/相关/播放列表是**五六种卡片**，逐个写 CSS 规则既脆弱又会被状态污染咬。hanime1 的做法：`H1CARDS(html)` 一次解析成对象数组，字段规则只取键名：

```js
function H1CARDS(html){
  var d=Jsoup.parse(html); var out=[]; var seen={};
  d.select('a[href*=watch]').forEach(function(a){
    var v=(String(a.attr('href')).match(/[?&]v=([0-9]+)/)||[])[1]; if(!v||seen[v])return;
    var card=a.closest('[class*=horizontal-card],li,div'); if(!card)return;      // ★向上找卡片根
    var t=取(card,'div.title,h4.video-title,.home-rows-videos-title,a[class*=title]')
         || img.alt || img.title;                                                  // 三级标题兜底
    seen[v]=1;
    out.push({ title:t, v:v,
      cover: 取属性(card,'img', 'src|data-src|data-original'),                   // 懒加载三连
      dur:   取(card,'div[class^=duration]'),
      stats: card.select('div[class^=stat-item]').前3个.join(' '),
      artist:取(card,'div.subtitle a,.video-meta-data a') });
  });
  return out;
}
```

可移植要点：

- **锚点用 `a[href*=watch]`（链接里带视频 ID）而不是卡片 class** ⇒ 换模板只影响 `closest()` 的候选；
- `closest('…,li,div')` 用"任意祖先 li/div"保证一定能拿到一个容器（配合标题多级兜底）；
- 属性前缀选择器 `div[class^=duration]`（CSS 前缀属性）扛得住站点把 class 名加哈希后缀；
- 封面必须 `src || data-src || data-original`（视频站封面几乎都懒加载）；
- **`attr('href')` 不要用 `absUrl('href')`**（jsoup 无 baseUri 时 absUrl 恒空 → bookUrl 退化 → "书籍总数:1"）。

字段映射（视频站语义）：

| Legado 字段 | 视频站建议含义 | 实现 |
|---|---|---|
| `name` | 标题 | `title` |
| `bookUrl` | `@js:H1BU(String(result.v))` ⇒ **只存 ID + 模板域名 + URL 选项** | 换域名/换线自愈 |
| `author` | 上传者/制作方 | `result.artist` |
| `kind` | 时长 + 观看/点赞统计（或分类） | 拼 `⏱12:34 观看 1.2萬` |
| `wordCount`（详情） | **观看次数**（借用"字数"位显示） | 正则 `观看次数：([0-9,]+) 次` |
| `lastChapter`（详情） | **共 N P**（借用"最新章节"位显示集数） | `o.pn>1?('共'+o.pn+'P'):''` |
| `intro` | 列表页必须纯文本；详情页才是面板（引按钮选型树约束③） | — |
| `checkKeyWord`（放在 **ruleSearch 内**） | 本站一定命中的词 | `"催眠"` |

> **借位显示**（观看数→字数、集数→最新章节）是视频源很实用的技巧：Legado 的书籍 UI 只有这几个槽位。

## 9.2 发现页：把"参数矩阵"变成按钮

```js
exploreUrl = "<js>…rows.push({title:'🏳 本日排行',url:U('sort=本日排行&')});
                     rows.push({title:'📂 MMD',url:U('genre=MMD&')});
                     rows.push({title:'# NTR',url:U('tags[]=NTR&')});
                     rows.push({title:'🔮 下月预告',url:'https://'+H1DOM(source)+'/previews/'+H1YM()+H1OPT(source)});
                     JSON.stringify(rows);</js>"
function U(q){return 'https://'+H1DOM(source)+'/search?'+q+'<js>page</js>'+H1OPT(source)}   // 带 {{page}}
```

- 用 `<js>` **运行时生成** ⇒ 域名跟着变量走（写死的 exploreUrl 换域名即全废）；也顺便规避"MCP 传输双引号"问题。
- 分类/标签如果站点有接口（`/app/api/genres` 之类），**动态拉全量**（nicomanga 595 标签的做法），别硬编码。

## 9.3 搜索的三件事

1. **分页**：`&page={{page}}`。若站点单页给满（如 52 条）且无翻页，就**别写 page**，免得 Legado 反复请求同一页。
2. **限频**：视频站常见"搜索间隔 N 秒"（Cookie 标记型 / IP 窗口型）→ 引 `方法-Cookie标记型限频破解.md`；hanime1 无搜索频控，只有 CF 抖动 → `concurrentRate:"1/1500"` + `loginCheckJs` 翻译报错。
3. **搜索词长度**：本站中文/英文均可；有最小长度限制的站要在 `searchUrl` 前置 JS 里校验并抛人话提示。

# 十、控制台（登录 UI）——视频源几乎必须自带

视频源的运行参数**比小说源多得多**：域名 / hosts IP（可多值）/ 代理 / CDN 修复开关 / 清晰度 / 图片内置 / 收藏夹选择 / 账号 / 状态回显。**这些都必须在 App 里可改**（不能让用户重导书源）。结论：**用 V2 面板**（V1 没有 select/toggle/countdown）。


**本轮踩出来、值得写进规范的四条**

1. ★**哨兵词冲突**：`applyForm` 用选项文案里的关键词做分支（`indexOf('自动')`、`indexOf('自定义')`）。
   - 「🔗 多IP**自动**切换」含"自动" → 误走"清空 hosts"分支；
   - 分组标题写「──── **自定义**…」，用户误点 → 把备用池第 1 条写进 hosts。
   ⇒ **规则：分支哨兵用唯一词；所有分组标题文案必须避开哨兵词**（本项目把标题改成「我填入的IP」）；并且对读到的值加格式校验（`/^[0-9.]+$/` 不通过就判"配置无变化"，不动线路）。
2. ★**多值不能当 select 的 value**：`h1ip` 是逗号串时，V2 面板显示成一整串 IP ⇒ 必须**拆成分组**（"多IP自动切换(N)·当前生效"这一项代表整组，逐 IP 另列）。永远保证 `value ∈ options`。
3. **延迟/状态做成"最近一次实测"**：`h1lat` 键存 `IP:ms;IP:x`，选项后缀 ` · 123ms/ · 不通/ · 未测`，取用时 `split(' ')[0]` ⇒ 显示与解析解耦。
4. **危险动作一律 `countdown`**：测速类（会连发十几个请求，视频站常挂 CF）给 30~90 秒倒计时，既防连点也自我提醒"不急别点"。

> V2 的完整数据链路（`evalLoginUiV2` / `loginAction(act,state,form)` / `{state,error,login,close}` 命令协议、`parseRender` 校验、Kotlin 默认参数要传全）见 `方法-登录UI-V2新版面板.md`。

# 十一、工程化：让 90KB 的大源不出错

完整规范见 `方法-书源交付质量闭环.md`，这里只写**大体积视频源特有**的四件事。

## 11.1 分层：规则薄、jsLib 厚、UI 在 loginUrl

```
规则字段（每个 1~30 行）→ 只调用 jsLib 函数          ← 规则里绝不留长 JS（难校验、难替换）
```

- ★**jsLib 作用域里 `java.ajax` / `source` 不可用**（本 App 已知坑）⇒ 所有需要网络/变量的函数一律**参数注入**：`H1CUR(Jv,src,Bk,res,burl)`，调用处写 `H1CUR(java,source,book,result,baseUrl)`。

## 11.2 构建脚本纪律（本项目真实翻车记录）

```python
base = json.load(open('hanime1_v38.json'))            # ① 一律以上一版为基线
src  = src.replace(OLD_BLOCK, NEW_BLOCK)              # ② jsLib 用"整块（按行）替换"
assert src.index('A') < src.index('B')               # ③ 顺序断言：新代码插在哪
assert '"chapterList"' in json.dumps(base)           # ④ 字段存在性断言
subprocess.run(['node','--check',tmp_js])            # ⑤ 每个 JS 块都编译校验
```

- ★**不要用跨块正则**：`re.search(r"if\(act==='cdn'\)\{.*?\);");` 的 `.*?` 会**吃到下一个动作块的 `);};`**，把新代码插进别的 `if` 内部——`node --check` 照样通过，纯逻辑错（本项目真实事故）。⇒ 动作分支改用**唯一字面锚点**插入 + 顺序断言。
- ★**零双引号、零反斜杠、零真实换行**（jsLib/loginUrl/规则文本）：引号一律 `String.fromCharCode(34)`，正则里的 `\s` 改成 `new RegExp(C(92)+'s*…')` 或字符集 `C(9,10,13,32)`。这样整段 JSON 可以安全穿过 **MCP 传输 / 剪贴板 / dpaste**。
- ★**Python 里 `%` 格式化别渗进 JS**（toast 显示 NaN）；heredoc 写 JS 时单引号会被 shell 吃掉。

## 11.3 一致性校验（保存成功 ≠ 保存对了）

```
本地 build → node --check 全块 → 打印每字段 len+md5 基线
→ save_source（★必须传完整 JSON：整体替换语义，漏字段=清库）
→ eval_js(url绑定书源) source.getJsLib()/getLoginUrl()/getRuleXxx() 逐字段回算 md5
→ 不一致 → 150 字符分段 md5 二分 → charCode 逐字定位 → 改本地重存
```

- ★**md5 比对只比 UTF-8 字节，不比长度**：Rhino `String.length` 是 UTF-16 长度，emoji 让它与 Python `len()` 差 80（本项目 45457↔45537）。
- Rhino 里 `String(s).getBytes('UTF-8')` **不存在** ⇒ `new Packages.java.lang.String(String(s)).getBytes(Charset.forName('UTF-8'))`。
- `save_source` 后 `lastUpdateTime`/`respondTime` 会被重置，属正常，基线须排除。
- **改完规则必须先 save_source 再测**（否则 `eval_js` 测的是 App 里的旧规则——本项目翻车点）。

## 11.4 大源导入通道（>50KB 就别手传 MCP）

```
沙盒：上传 dpaste  →  https://dpaste.com/api/v2/  ★必须带尾斜杠（否则返回 API 文档 HTML）
       raw 链接 = URL + ".txt"；沙盒侧回读做 md5 字节校验

   → Legado 判 isJsonObject 失败 → 当 JS 源解析 → 报「XML 语法格式错误 </body></html>」
```

## 12.1 探针源（probe source）—— 读运行时的真实绑定值

用完 `delete_sources` 清掉。

## 12.2 `debug_source` 的 key 前缀（源码 `Debug.kt`）

| 前缀 | 进入 | 用途 |
|---|---|---|
| 裸关键词 | 搜索 | `checkKeyWord` 或直接输入 |
| `绝对URL` | 详情页（+目录+正文全链路） | 检查 `intro`/`name`/… |
| `++URL` | 目录 | 检查 `chapterList` 顺序 |
| `--URL` | 正文 | 检查 `content` 输出的直链 |
| `::URL` | 发现页 | 检查 exploreUrl + 每个按钮 |

- ★**key 必须自带 URL 选项**（`...watch?v=1,{"dnsIp":"104.25.254.167","timeout":25000}`），否则走 Cronet + 被污染 DNS → 31 秒 `ERR_CONNECTION_TIMED_OUT`，你会误判"规则坏了"。
- ★**多页连打（8~10 req/min）会触发 CF 挑战** ⇒ 调试纪律：单页重试、优先离线 jsoup 分析、验证目录顺序时页间 ≥1.5s。
- **MCP 工具严禁并行调用**（`Session not found` / 调试通道占用）；`check_source` 对含动态 exploreUrl 的源会报 `no scheme /list-` 之类**固有现象**，以 `debug_source` 为准。

## 12.3 `java.webView(html, url, js)` = 真机 WebView 渲染探针

**验证 `<useweb>` 面板 DOM 是否真被填上**，无需看屏幕：

```js
java.webView(整份面板HTML, 'https://目标站/',
   '(function(){ return JSON.stringify({title:(document.getElementById("h1ti")||{}).textContent,
        img:(function(){var i=document.querySelector("img");return i?[i.complete,i.naturalWidth,i.src.length].join(","):"none"})()}) })()'
)
```

- ★`js` **必须是表达式**：顶层 `return` 报 `Illegal return statement`；`var a=x;` 语句式报 `missing )`。要多次采样就用 `window.__n` 自计数（返回 null/空会按 200/400/…/1000ms 重试约 30 次后抛"js执行超时"）。
- 返回非空即接受（`evaluateJavascript` 的 JSON 串会被去掉首尾引号）。
- 顺带用途：**在没有网络的沙盒里验证"图片在 blockNetworkImage 下能否渲染"**（`data:` URL 不受影响，本项目就是这样实锤 1024px 封面在屏蔽态仍渲染成功）。

## 12.4 真机网络取证（唯一可信）

- `eval_js` 绑定书源后 `java.ajax(url + ',' + JSON.stringify({dnsIp:...}))` 实测连通；
- ★**`java.ajax(url, 25)` 的第二参单位是"毫秒"**（`JsExtensions.ajax → AnalyzeUrl(callTimeout)`）⇒ 传 25 会 63ms 假超时，要传 25000（本项目真实误判）；
- `java.head(url,headerJson,timeout)` 判连通有陷阱：**部分 CDN 对 HEAD 恒 403 而 GET 200**（cdn77 实测）⇒ 判活用 `GET + 截断`，或 `HEAD` 拿到任意响应码（含 400）即视为 TCP+TLS 通。
- `get_http_logs` 对比"成功/失败请求的 UA 与最终 URL"，一步定位 UA 分发或模板/域名走错。

## 12.5 离线仿真（省配额、可回归）

| 层 | 做法 |
|---|---|
| 面板 JS | `page_vNN.js` + **node DOM 垫片**（getElementById/querySelector/createElement/textContent/onerror）跑首屏、切集、坏图重试链、冷却矩阵 |

| 规则 | `eval_js` 里 `new Packages.io.legado.app.model.analyzeRule.AnalyzeRule()` + `setContent(x)` + `getString('规则')` 走真实解析器（注意其中 `@js:` 前缀不走） |
| 源码 | `/workspace/legado_src`（LegadoTeam 全仓）直接 grep，**源码优先于一切推测** |

# 十四、避坑清单 51 条速查（K1~K51）

### 类型与播放链路
- **K1** `bookSourceType` 写 0 → 视频地址被当正文显示。必须 **4**。
- **K2** 正文多余文本/换行 → 播放器拿到脏 URL 报"获取资源链接出错"。**只输出一个地址**；多页会被 `joinToString("\n")` 拼死（`BookContent.kt:169`）⇒ 空正文报错文案有两处：`内容为空`(BookContent) / `正文为空`(VideoPlay)。
- **K3** 正文空 → 报错是"正文为空"，看不出原因 → **`throw new Error('中文+下一步')`**。
- **K4** m3u8 清单**内联**给 Legado 无效（只有 `<` 开头才当清单）→ **永远给 m3u8 的 URL**。
- **K5** MPD 可以内联（`<` 开头），但会写 `file://` 临时文件，内部分片地址必须自身可达绝对地址。
- **K6** ★`dnsIp` 对**播放器拉流无效**（播放器用全局 okHttpClient）→ 媒体域名必须"换主机名 / App 自定义 Hosts / 系统代理"。
- **K7** `header` 与正文 URL 选项的 `headers` 都会进 `player.mapHeadData` → 防盗链头有两条注入路径；★但**只有 `headers` 能到播放器**：`timeout`/`retry`/`dnsIp` 在视频路径被解析后即丢弃（从不发该请求），且**CookieStore 不会被自动合并**（`setCookie()` 未被调用）⇒ 要 Cookie 就得 `java.getCookie(当前域)` 手动拼进 headers。
- **K8** 视频源正文**跳过 HtmlFormatter 净化**（`BookContent.kt:243`），但 `replaceRegex` 仍会执行且逐行 trim → **别写 replaceRegex**（误伤直链=黑屏）；`imageStyle`/`imageDecode` 对视频无意义。
- **K9** `subContent` = **弹幕**通道（`putDanmaku`，B 站 XML）；以 `http` 开头会被先请求一次。
- **K10** 混合类型源（视频+漫画/听书）：刷目录会 `removeAllBookType()` 冲掉 type → 目录规则也要 `setType`。

### 目录
- **K11** 站点 playlist 新→旧排序 → "点这集播那集" → **入口集排到目录第 1 位**，且三处（目录/当前集/按钮）同步改。
- **K12** ★IIFE 末尾表达式不带 `return` → 字段静默为空（正文 ContentEmpty / 发现"规则为空" / 搜索无结果）。
- **K13** 同 URL 章节会被去重合并（`BookChapter.equals` 只比 url）→ 共用页面必须加 `#fragment`。
- **K14** `#fragment` 会污染 `baseUrl` → 规则里统一 `split('#')[0]` 清洗。
- **K15** 改目录结构后必须复查"每行元素数 k"这类换算参数（本项目 `floor(n/3)` 算错过索引）。
- **K16** 目录用 JSON 字符串数组 + `$.键` 才跨 legado-E（LT 版对象数组可以，E 版条目取不到值）。
- **K17** 多线路站优先用 `isVolume`（卷=线路）——App 自带线路切换，别把线路塞进章节名。
- **K18** 目录返回对象数组时 `chapterName`/`chapterUrl` 用纯键名（`n`/`u`），不要 `@js:` 再解一遍。

### 正文 / 直链
- **K19** 时效签名（10 分钟级）**不要固化进目录**；简介里的播放按钮 onclick 现取。
- **K20** 清晰度要先在候选表里查"精确命中"，否则取"数值最近"，最后兜底第一路。
- **K21** ★**书源正文不会帮你补相对地址**（`getAbsoluteURL` 只在 RSS 分支调用，`VideoPlay.kt:211` vs 书籍分支 `:262`）：`//host/path` 自己补 `https:`、`/path` 自己补 `https://页面域`。另：`^(https?:[^/]+)` 取 origin 恒为 null（`https:` 后紧跟 `//`），改 `url.split('/')` 取 `ps[0]+'/'+ps[1]+'/'+ps[2]`。
- **K22** 站点把直链藏内联 JS 变量时，正则兜底要**同时保留 DOM 主路**（`const source = '...'` 只在 DOM 无 source 时用）。
- **K23** `java.ajax` 对被墙域可能**返回异常文本**而非抛异常 → `indexOf('Exception')` + 长度 + 页面标记三重校验。
- **K24** 重取要梯度 `Packages.java.lang.Thread.sleep()`（**本 App 无 `java.sleep`**）。
- **K25** 换 CDN 主机前先验证**签名是否绑 Host**（同 token 打多主机矩阵）；**Cloudflare 系不适用**（Host 绑 zone）。
- **K26** HEAD 恒 403 但 GET 200 的 CDN 很多（cdn77 实测）→ 判活用 GET 或"任意响应码即视为通"。
- **K27** 分片(.ts) 比 master 更严（要 nonce/token）→ 无解时 `startBrowser`，并在注释与提示里写明。
- **K28** 播放缓存 100MB / maxAge 1 天 → **坏流被缓存**只有换 URL（`?v=N` / 换主机）才自愈。
- **K29** `ruleContent` 里写变量（给面板用）必须 try/catch，别让副作用掀翻正文。
- **K30** JS 现算 token 的站可试 `{"webView":true,"webJs":"…"}`（**待验证**，比 startBrowser 更接近"能播"）。
- **K51** ★目录行 URL 本身就是可播地址时**正文规则可以整个留空**（`WebBook.getContentAwait:431` 会直接 `return bookChapter.url`）⇒ 少一层规则、少一处出错；但代价是正文里不能再做变量旁路（第七章 `h1info` 通道失效），且防盗链头必须写进**目录 URL 的 `headers` 选项**。

### 详情页 / 面板
- **K31** 播放页简介是**一次性快照**，`java.refreshBookInfo()` 在播放页是空操作 → 跟随只能 `<useweb>` + `callBackJs`。
- **K32** `eventListener=true` 忘开 → `callBackJs` 永不执行（表现为"面板死活不跟随"）。
- **K33** 只在正文规则里写变量 → 命中缓存时不跑；**两处都写**。
- **K34** 变量体积护栏写太小（9000）→ 内置封面(100KB) 被静默丢弃 → 不跟随；**护栏按最坏情况**。
- **K35** 同步桥 `java.ajax` 会**冻结 WebView JS 线程**（425KB 页 0.66~6.8s）→ 首屏零网络 + 按钮 `setTimeout(60ms)` 包装 + 冷却。

- **K37** 池化 WebView 可能被 `blockNetworkImage=true` 毒到 → **图片要 `data:` 内置** + 候选链 + 状态回显。
- **K38** 桥里 `startBrowser` 无注解不可调；`openVideoPlayer` 可调（有注解 + `appCtx.startActivity`）→ 按钮渲染前 `typeof` 探测。

- **K40** 能力探测结果别写进被重绘比较的字段（本项目每 6 秒多刷一次画面）。

### 网络 / 登录 / UI / 工程
- **K41** `_token` 匿名也下发 → 登录判据要用 `like-user-id`/仅登录渲染的元素；三镜像站 Cookie **按域隔离**，要"同步登录态"。

- **K47** `loginCheckJs` 顶层不能 `return`（要 IIFE）、`result.body` 可能是方法、**必须原样 return result**。
- **K48** `save_source` **整体替换**（漏字段=清库）；大源走 dpaste+深链且**手机侧只拉一次**（429→HTML→"XML 语法错误"）。

- **K50** 调试 `debug_source` 的 key 不带 `{"dnsIp":…}` → 31s 超时，误判规则坏；多页连打触发 CF；MCP 严禁并行。

# 十六、视频站对照档案（生产源 5 例，选型时先看这张表）

| 站点 | 形态 | 取流方式 | 关键难点 | 最终方案 |
|---|---|---|---|---|
| **hanime1.me/.com** | Laravel SSR，一 P 一 mp4 | `video#player>source[size][src?secure=]` | DNS 污染 + SNI 封媒体域 + CF；播放页快照 | `dnsIp` 选线 + **CDN77 原生主机替换** + `<useweb>` 面板 + `callBackJs` 跟随 + 内置封面 |
| **mdcmai.xyz**（AI 短剧） | 纯 JSON API | `/api/v1/m3u8/proxy?path=` 返回完整 m3u8 | API 无 UA 403；**域名轮换频繁** | header 必带 UA + 登录 UI **5 域名按钮 + 耗时测速选最快** + 全部 URL 从上游提取自动跟随 |
| **huangguo.video**（AI 短剧+图集） | SSR + CF | master.m3u8 需 Referer；**`.ts` 分片需浏览器环境**（`window.__hgN`+`preview-token` 600s） | 书源无法播放分片 | **视频 → `java.startBrowser(详情页)`**；图集 → 正文拼 `<img>`（src **必须双引号**，阅读器 imgPattern 硬要求） |
| **hlwf6.com**（黑料网，视频+图文） | 多线路轮换主站 | `div.dplayer[config]` JSON 里的 m3u8（**签名约 1 小时**） | 时效签名 + 图片 AES 加密 + 线路轮换 | 简介 `<usehtml>+<button>@onclick:` 点击时**实时 ajax 重取直链** + `imageDecode/coverDecodeJs` 双钩子解图 + 发布页测速选线 |
| **novelServices(110.42:2095)** | 四平台聚合 JSON API | `/videos/{id}` → `video_list` 遍历取 `main_url`（七猫 `{"0":{main_url:m3u8}}`、书旗 `{"main":{main_url:mp4}}`） | **video_list 键名各平台不同**；`Book.type` 位掩码 4/8/32/64 | 遍历所有键提 main_url（别写 `video_list[0]`）+ 详情&目录**双 setType** + JWT `loginHeader` |

**从这张表能读出的选型结论**

1. **能拿到"绝对可播地址"的站才配做目录行 URL**；拿不到（需浏览器环境/需 nonce）就老实 `startBrowser`。
2. **签名时效决定架构**：≥1 天可固化；小时级必须点击时现取；分钟级只能"目录行指向页面 + 正文现取"。
3. **API 型视频站**（mdcmai/novelServices）比 HTML 站好做，但**域名轮换**是常态 → 上线第一天就配"域名按钮 + 测速"。
4. **一个书源里混合多种媒体类型**（视频+图集+听书）时，`Book.type` 与"正文返回什么"要按类型分支（novelServices 的教训：音频正文必须**纯 URL**，因为 `durPlayUrl = content.trim()`）。

## 17.2 面板内部函数（`H1PGS()` 返回的字符串里）

`gv lite diag sp TGC lgOf jb dom qy ipx cdn fixu J2 OBJ OPT WU PU ajax pos q1 qa at E T BT SPN stat out metaLine setCov ad covFail paint jump laz goPlay need done fav fol lik nsrc dir pick fresh play web reload tick hasPlay upline boot`
—— 职责分四层：**取值层**（`jb/OPT/WU/PU/ajax`）、**渲染层**（`paint/pg/lite/setCov/metaLine/SPN/BT`）、**动作层**（`goPlay/fav/fol/lik/dir/pick/play/web`）、**调度层**（`tick/laz/reload/boot/upline/diag`）。

## 17.3 诊断键一览（排障顺序）

```
h1dom h1ip h1pool h1q h1px h1cdn h1img h1web   ← 配置（控制台写）
h1lat                                            ← 最近实测延迟 IP:ms;…
h1uid h1gld h1plc h1lst h1lastvid h1cinfo h1email ← 账号/缓存
h1now   入口vid|播放vid|ts        ← 信号是否送达（先看这个）
h1ev    事件首字母|vid|ts          ← callBackJs 是否活着
h1info  当前集全量 JSON(≤400KB)    ← 数据是否到位
h1diag  ms|P或V|ticks|BUSY|LF秒|h1now|事件  ← 面板心跳
```

排障顺序：`h1ev` 有没有变（没变=K32 eventListener 没开）→ `h1now` 对不对（错=取 vid 的字段问题）→ `h1info` 有没有该集数据（没有=K33/K34）→ `h1diag` 的 BUSY/LF（BUSY 常驻=K35 同步桥卡住）。
