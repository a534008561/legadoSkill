# 禁漫天堂 v2.6：发现页补全全量排行榜

> 261128 用户要求「补全排行榜」。本版把 jmtt 发现页的榜单从「人气日/周/月/年 4 条」补成站点全部 **4 榜别 × 4 周期 = 16 条/类型**。

## 一、站点契约（App 内 java.ajax 实测）

排行榜页 `/{seg}/rank` 的 HTML 带 `data-rp-real`，明牌：

```json
{"themes":["comic","novel","video","actor","drama"],
 "sorts":["popular","favorite","new","finished"],
 "periods":["day","week","month","year"]}
```

页面按钮中文标签：

- `popular` → 人气榜
- `favorite` → 收藏榜
- `new` → 新作榜
- `finished` → 完结榜
- `day/week/month/year` → 日榜/周榜/月榜/年榜

★关键实测：SSR 直接吃 query 参数 `?sort=<sort>&period=<period>`，返回对应 TOP30，不需要走 `/rank/board` JSON API：

- `/novel/rank?sort=favorite&period=week` 首条「女神攻略调教手册」，与 popular-day 的「豪乳老师刘艳」不同；
- `/novel/rank?sort=new&period=month`、`/novel/rank?sort=finished&period=year` 也都返回不同书籍；
- `/comic/rank?sort=favorite&period=week`、`/mv/rank?sort=new&period=month`、`/drama/rank?sort=finished&period=year` 同样返回有效 TOP30。

`page` 页面 UI 的 `is-active` 仍显示 popular，这是站点前端 tab 状态没跟着 query 改，**不影响 SSR 内容**，不要据 `is-active` 误判参数无效。

## 二、书源改造

`addRankEntries()` 从固定 4 条改成双层循环：

```js
var SORTS = [['人气','popular'], ['收藏','favorite'], ['新作','new'], ['完结','finished']];
var CYCLES = [['日榜','day'], ['周榜','week'], ['月榜','month'], ['年榜','year']];
for (s in SORTS) for (p in CYCLES) {
  var u = "{{page>1?(jmHost(source)+'/search/__jmrank_end__'):(jmHost(source)+'/" + seg + "/rank?sort=" + sVal + "&period=" + pVal + "')}}";
  rows.push({title:'🏆 '+T+'·'+sName+pName, url:u, ...});
}
```

- 仍保持「榜单不用下拉选择」：16 条全是 `type:'url'` 直接入口。
- 每个榜别的第一条加 `layout_wrapBefore:true`，4 个榜别自动分成 4 行。
- 第 2 页仍用原 `{{page>1?...__jmrank_end__}}` 守卫，因为榜单只有 TOP30，无分页。
- 未采用 `/rank/board` JSON API：那是给站点前端 pushState 用的，`ruleExplore` 目前按 HTML 卡片（`a.jm-rkrow` 等）解析，SSR query 已足够。
- `actor`（女优榜）虽然存在于 `data-rp-real.themes`，但不属于本源四模式书籍内容，未加入，避免幽灵书。

## 六、v2.9 追加：分类不再随排序收缩

用户反馈「分类怎么少了」。根因不是榜单前移，而是 `小说排序/漫画排序/视频排序` 选了非默认项时，`sortBase()` 命中站点 `/hot`、`/freshest`、`/last_published`、`/collect` 路径，这些站点路径本身不带分类；旧逻辑 `return` 后只剩一条「全部」。实测 `/novel/all/dsjq?sort=hot` 与 `/novel/all/dsjq` 首屏完全相同（sort 参数被忽略），`/novel/hot/dsjq` 则跳到另一套无分类列表，确认无法在站点侧把非默认排序与分类路径叠加。

v2.9 修法：

- 非默认排序时先输出一条 `📚 当前排序全部（最多观看）` 保留排序能力；
- **不再 return**，继续用 `DEF_SORT` 的 query 输出全量分类（小说16/漫画13/视频14/短剧2），所以分类数量不再缩水；
- 默认排序时行为完全不变。

qjs 实测：小说默认排序 26 行/16 分类；选「最多观看」后 27 行/17 分类（16 分类 + 1 条当前排序全部）。LT/E 双端 200，check_source 1/1。

该修复已并入最终成品 v2.11（见第八节），不再单独保留 v2.9 示例文件。

## 九、v2.12 追加：去掉 emoji + 分类改三列防截断

用户反馈「分类字数显示不全」并要求「把emoji符号去掉」。

根因（源码级）：`item_fillet_text.xml` 的 TextView 是 `wrap_content + ellipsize=end + maxLines=1 + paddingLeft/Right=12dp + margin=3dp`，字号 14sp。v2.11 用 `flexBasisPercent=0.23 + flexGrow=1`，4 项均分后每项约父宽 25%；360dp 屏上约 85dp，而「都市激情」4 个汉字（约56sp）+ 24dp padding + 6dp margin ≈ 86dp，刚好触发省略号。emoji（📚/📖/🏆/🏷）再占一个字宽，更易截断。

v2.12 修法：

1. 发现页标题**去掉全部 emoji**：分类 `都市激情`、榜单 `人气周榜`、标签折叠条 `小说标签（...）`、标签展开 chip `口交`。功能性 `▸/▾` 折叠箭头保留。
2. `chipStyle()` 从 0.23 改为 **0.31**，即三列等宽（3×0.31=0.93，grow 均分到约 33.3%），每格约 114dp，4 字中文 + padding 宽松容纳；小说 16 分类变 6 行，但不再截断。

qjs 实测：26 行标题中 emoji 数为 0；榜单/分类/标签 chip 的 style 全为 `layout_flexBasisPercent=0.31 + layout_flexGrow:1`。LT/E 双端 200，check_source 1/1。

最终成品 v2.12：`/workspace/jmtt2x/deliver/jmtt_禁漫天堂_v2.12_去emoji三列网格.json`（48149B，md5 `5d443526360020abed2b11f91a983adf`）。
