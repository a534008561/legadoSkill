# 爱看书吧 m.2tsw.com 书源验证记录

> 全部结论均在「阅读」App 内经 MCP 实测（`debug_source` / `eval_js` / `check_source`），非沙盒推测。

## 一、站点结构（实测）

| 项目 | 结论 |
|---|---|
| 编码 | **GBK**（`Content-Type: text/html; charset=gbk`），正文/搜索/目录全站一致 |
| 搜索接口 | `GET /modules/article/search.php?searchkey=<GBK编码>&searchtype=all` |
| 搜索关键词编码 | **必须 GBK**（UTF-8 编码会返回 0 条或乱码标题） |
| 搜索单结果 | **302 跳详情页**（不是返回列表），需 `bookUrlPattern` 兜底 |
| 搜索多结果 | `<tr id="nr">` 行，6 列：书名/最新章节/作者/字数/日期/状态 |
| 详情页 | `/book/<id>.html` |
| 目录页 | 同详情页，`a.cp_1` 为章节；每页 45 章，共 N 页（`当前第X页，共Y页，每页显示45章`） |
| 目录分页 | `/book/<id>/<page>/`（注意尾斜杠；`/book/<id>/1.html` 是 404/空页） |
| 分页条形态 | **滑动窗口**（当前页 ±10 页左右），第 11 页起窗口内不含第 1 页 → 必须靠「当前第X页，共Y页」推算 |
| `nextTocUrl` 返回值 | **只返回「下一页」1 个 URL，末页 `return null`**（源码级铁律，见下方 §3 修正说明） |
| 正文分页 | `a.btn-info` 存在即还有下一页，href 形如 `xxx_2.html` |
| 列表页分页 | `ul.txt-list-row5`（30 条/页），`div.item` 是固定推荐位（6 条，不随页变化） |

## 二、逐项验证结果（App 内实测）

### 1. 搜索
- `剑来` → 22 条，书名/作者/字数/最新章节全部正确
- `诡秘之主` → 13 条
- `大奉打更人` → 4 条
- `夜的命名术` → 2 条
- `人道大圣` / `宿命之环` → **302 跳详情**，靠 `bookUrlPattern` 正确走详情解析，书名/作者/分类/简介/封面全部命中

### 2. 详情
`.info .fix > p:nth-of-type(N)` 取 5 行（作者/分类/动作/更新时间/最新章节）：
- 验证 5 本书，`p` 的数量恒为 5，顺序稳定
- `作者`、`类别`、`最后更新`、`最新章节` 全部通过 `##前缀` 剥离

### 3. 目录
- 初始只抓到 11 页（495 章）——**根因**：`nextTocUrl` 里用分页窗口找 `/1/` 链接，第 11 页后窗口已不含第 1 页
- 改为从 `baseUrl` 提取 bookId + 「当前第X页/共Y页」生成剩余页 URL → **5569 章**（123×45+34，与站点一致）
- ⚠ **重要修正（2026-10-23）**：此处最初写成「一次性返回剩余全部页、走并发分支」（日志 `◇并发解析目录,总页数:123`）。后经源码级分析确认该写法**必然导致目录顺序错乱**（详见 [方法-目录分页 nextTocUrl 只返回单 URL 的源码级机制](../references/方法-目录分页nextTocUrl只返回单URL的源码级机制.md)）。已改为**只返回「下一页」1 个 URL、末页 `return null`**，强制走串行分支。
- 串行抓取 124 页约 26 秒（比并发慢，但换来顺序绝对正确，这个交换是必须的）
- 实测验证（App 内 `eval_js` 串行抓全部 124 页）：`total=5569 dup=0 nonMono=0`，首章「第一章 矿奴」、末章「完本，道歉」，**站点数据本身严格递增无重复**

### 4. 正文（本次最难点）
站点在分页处**直接截断句子**，且 `&nbsp;` 被切成两半分处两页：
- 第 1 页末尾：`&amp;n`
- 第 2 页开头：`bsp;`

单纯用 `nextContentUrl` + `##替换` 无法还原，会得到：
```
这……周明
瑞顿时倒吸了口凉气
```

**解决方案**：正文规则改用 `@js`，自行 `java.ajax` 按页抓取，逐页处理后再无缝拼接：
1. 去掉 `a.btn-addbs` / `a.btn-info` / `<font>` 整块
2. 按 `<br>` 切行，逐行判定广告并丢弃
3. 每页首尾的空白与 `<br>` 全部剥掉（这是能无缝拼接的关键）
4. 跨页断裂实体修复：`&(?:amp;)?n\s*bsp;` → `&nbsp;`

### 5. 广告行清单（实测到的全部变体）
| 广告原文 | 出现位置 |
|---|---|
| `< "https:">提供的《书名》 第X章 XXX(第1/2页)` | 分页首行 |
| `本章未完，请点击下一页继续阅读` | 分页末尾 |
| `这章没有结束，请点击下一页继续阅读！` | 分页末尾 |
| `喜欢《书名》请大家收藏：xxx.com网更新速度全网最快。` | 分页末尾 |
| `【请收藏，wjiwenxue.com 努力为你分享更多好看的小说】` | 分页末尾 |
| `..！无广告！` | 正文首行 |

### 6. 发现页
- 分类列表：`/list/<1-7>_<page>.html`
- 完本：`/wanben/1_<page>`
- 排行：`/paihangbang.html`（静态单页，8 个榜单块，共 171 本去重）
- `div.item` 只有 6 条且各页相同 → 已剔除，只用 `ul.txt-list-row5`
- 排行页的 `span.s1` 是名次数字而非分类 → 用 `@js` 判断：纯数字返回空

## 三、反向验证（防误伤）

广告判定函数对以下**正文**必须保留，实测全部 KEEP：
```
他在广告公司上班，每天加班到深夜。
无广告的阅读体验确实舒服很多，可惜这样的站点太少了。

他打开电脑，输入了 google.com，页面跳了出来。
```

对以下**广告**必须丢弃，实测全部 DROP：

## 四、遗留风险

1. **失效书源条目**：搜索结果里存在已被删除的书（如 `429368294` 返回「该文章不存在」），此时详情/目录为空。这是站点数据问题，非规则问题；换源或选其它条目即可。
2. **`@js` 正文规则不走 `nextContentUrl`**：已自行循环抓页（上限 30 页），若单章超过 30 页会截断。实测最长 2 页。
3. **`concurrentRate` 未设置**：实测未触发限频，如后续出现 429/空响应可加 `{"concurrentRate":"1000"}`。
4. **排行页无作者/分类**：排行本身不提供这两项，属站点限制。
