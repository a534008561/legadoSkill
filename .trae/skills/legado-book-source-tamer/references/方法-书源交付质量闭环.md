## 一、为什么要这一整套（三次事故）

**事故 1｜误传清库（zhaoshu）**
`save_source` 只想改 `comment`，传了个只含 `comment` 的 JSON → **App 内该源其余全部规则被清空**。
根因：`save_source` 是**整体替换**语义，不是"增量合并"。靠 workspace 备份当场恢复。

**事故 2｜"已保存"但内容是错的（hlwf6/xuken/ppxsw 反复）**
MCP 回显"已保存"，但真机行为不对。逐字比对发现：手抄/传输过程中**丢了一个字符**（`;`、一个域名里的 `l`）、**转义层级错**（`\\"` 变 `\"` 变 `"`）。
根因：MCP `source` 字符串参数经传输层**双重转义**，高密度 `\"` / `\\` 必坏。

**事故 3｜大源传不动 / 传歪（nicomanga、wn10、hanime1）**
12.5KB 勉强过、18.5KB 过、68KB/89KB 整传**截断风险高**；报"参数 source 不能为空"多半是**参数内容损坏/为空**，不是大小限制。

→ 这三类事故**全部可以在交付环节 100% 防住**。以下是体系。

## 二、闭环总览：六步流水线

```
① 构建脚本 build_vNN.py（唯一事实源，一律以上一版 JSON 为基线）
        ↓ 产出 /workspace/<站>/<站>_vNN.json（+ _one.json 单行版）
② 语法体检：抽全部 JS 块 → node --check；关键 JS 做语义仿真
        ↓ 0 失败才继续
③ 编码纪律：源文本零反斜杠、零内嵌双引号（fromCharCode 运行期生成）
        ↓
④ 落库：save_source（完整 JSON）或 dpaste+深链（大源）
        ↓
⑤ ★字节级验收：本地 N 个叶子字段 len+md5 基线
              → eval_js 绑定书源逐字段回算比对
              → 差异字段 150 字符分段 md5 二分 → charCode 逐字打印
        ↓ 全对齐
⑥ 功能验收：debug_source（搜索/::发现/+目录/--正文）+ check_source
        ↓
   写 README + 更新记忆 + （可选）推 GitHub
```

**核心信条**：`回显已保存 ≠ 内容正确`；`功能跑通 ≠ 字节一致`。两者都要验。

## 三、第 1 步：构建脚本是唯一事实源

**禁止手抄 JSON 给 `save_source`。** 一律：Python 脚本 → 产 JSON → 整文件传。

```python
# build_vNN.py 骨架（hanime1 定型的模式）
import json, subprocess, sys
base = json.load(io.open('/workspace/x/site_v{N-1}.json', encoding='utf-8'))  # ★以上一版为基线
jslib = open('jslib_vNN.js', encoding='utf-8').read()
# 按【行】整块替换（不是正则局部替换）
base['jsLib'] = replace_line_block(base['jslib'], ...)
base['loginUi'] = inject_at_anchor(base['loginUi'],
    anchor="if(act==='login'){var rr=h1login(",   # ★唯一字面锚点
    code=px_block, assert_order=['cdnt','pxt','webt','login'])   # ★顺序断言
assert base['ruleContent']['content'].count('@js:') == 1
open('/workspace/x/site_vNN.json','w',encoding='utf-8').write(json.dumps(base, ensure_ascii=False, indent=1))
```

四条纪律：

1. **以上一版 JSON 为基线**，不要每版重写全量（重写=重新引入手抄风险，且容易丢历史修复）；
2. **整块（按行）替换** 而非局部正则；
3. **注入用唯一字面锚点 + 顺序断言**（见第四节）；
4. **产出两个形态**：`vNN.json`（缩进版，人读/版本管理）+ `vNN_one.json`（单行版，传 MCP/粘贴不丢格式）。

## 四、构建脚本的四类自身 bug

脚本自己也会错，而且错得很隐蔽：

### bug 1｜`.*?` 跨块吞锚（★最阴）

```python
re.search(r"if\(act==='cdnt'\)\{.*?\);\};", loginUi)   # ✗
```
`.*?` 会一路吃到**下一个**动作块的 `);};` → 新代码被插进别的 `if` 块内部 → **永不可达**。
`node --check` 照样通过（纯逻辑错，不是语法错）。

**对策**：锚点用**唯一字面串**（`if(act==='login'){var rr=h1login(`），插在其**前面**，并加**顺序断言**（cdnt < pxt < pxt结束 < webt < login）。

### bug 2｜Python 拼接漏 `+Q+`

多段 JS 字面量拼接漏一个分隔 → 生成 `':'{` 之类语法错。
**对策**：构建脚本**必须内置 `node --check`**（本次 hlwf6/77shuku/hanime1 全靠它在落库前抓到）。

### bug 3｜Python `%` 格式化渗进 JS

`%d`/`%s` 混在 JS 里 → `toast` 显示 `NaN`。
**对策**：JS 段用 `str.replace('@q@', '"')` 占位还原，不要用 `%` 或 f-string 包裹大段 JS。

### bug 4｜shell/转义层吃掉引号

Python heredoc 里写 JS，`indexOf('=='')` 这种单引号被转义层吞掉 → 索引错误。
**对策**：**JS 代码生成后必须 `node --check` 再推**（米游社篇的原文教训）。

## 五、第 2 步：语法体检（node --check + 语义仿真）

### 抽取所有 JS 块逐个体检

覆盖：`jsLib`、`loginUrl`、`realName`、每个 `@js:` 规则、每个 `<js>…</js>` 段、`exploreUrl`。

```python
import re, subprocess, os
blocks = re.findall(r'@js:([\s\S]*?)(?="\s*,|\s*"\})', text)  # 粗提，宁多勿漏
blocks += re.findall(r'<js>([\s\S]*?)</js>', text)
for i, b in enumerate(blocks):
    open(f'/tmp/b{i}.js','w',encoding='utf-8').write(b)
    r = subprocess.run(['node','--check',f'/tmp/b{i}.js'], capture_output=True, text=True)
    if r.returncode: print('FAIL', i, r.stderr[:300])
```

### ⚠️ `loginUi` 不要查

`loginUi` 是**宽容解析器**（允许字符串内真实换行 + 无引号键名合法），`node --check` **必误报**。
（同一条也适用于 `bookSourceComment` 里存 JS 库的场景。）

### 语义仿真（比语法检查更有价值）

`node` 里 stub `java`/`source` 跑按钮函数：

```javascript
// ★new Function 不返回"最后表达式值"，必须 eval 包装才等价 Rhino completion value
new Function('java','source','code','return eval(code);')(stubJava, stubSource, body);
```

Rhino 侧同理：`'return eval(JSON.stringify(code))'` 包装（m.lzjxx 实测：`new Function` 夹具不返回末表达式值）。

## 六、第 3 步：零双引号 / 零反斜杠纪律

**目标**：书源 JSON 的**规则文本里不出现 `"` 和 `\`**，只在运行期生成。这样任何传输层（MCP/剪贴板/Markdown/Python 字符串）都无法破坏它。

```javascript
var Q = String.fromCharCode(34);   // "
var B = String.fromCharCode(92);   // \
var NL = String.fromCharCode(10);  // 换行（绝不在规则里写真换行）
// URL 选项：,{"retry":3}
var OPT = String.fromCharCode(44,123,34,114,101,116,114,121,34,58,51,125);
// 正则里的 \d → [0-9]，\. → [.]（bookUrlPattern 同理：https?://www[.]x[.]com）
```

替代技巧汇总：

| 需求 | 写法 |
|---|---|
| 双引号 | `String.fromCharCode(34)`；或 HTML 里 `@q@` 占位，Rhino 端 `split('@q@').join(Q)` |
| 换行 | `String.fromCharCode(10)`；`@n@` 占位 |
| 数字/点（正则） | `[0-9]`、`[.]` |
| 单引号（HTML 属性内） | `&#39;` 实体（`<useweb>` 场景） |
| 整段 `loginUi` | `<js>JSON.stringify([...])</js>` —— 运行时才产生双引号，**源文本零双引号** |
| 大段页面 HTML | 写进 `@onclick`/`<useweb>` 前用 `esc()` 把 `<>&` 转实体 |

例外：`header` 字段**必须**是 JSON 对象字符串（源码 `BaseSource.getHeaderMap` 确认），那一处 `\"` 保留即可，是全源唯一允许的双引号对。

## 七、第 4 步：save_source 的三个语义真相

1. **整体替换**：只传部分字段 = 其余字段被清空。**必须传完整 JSON，保存后 `get_source` 回读核对。**
2. **同 URL 保留启用/排序/权重**；分组为空时保留已有分组（`BookSourceDao` 主键 = `bookSourceUrl`，`@Insert(OnConflictStrategy.REPLACE)` → 同 URL 覆盖不产生重复源）。
3. **会重置 `respondTime` / `lastUpdateTime`** —— 属正常现象，md5 基线要**排除**这两个字段（77shuku 定型）。

两个副作用坑：

- `save_source` 后 `enabledExplore` 可能被重置（aaawz 踩过）→ 保存后检查并按需重设；
- MCP 工具**严禁并行调用**（`Session not found` 竞态；`save_source`/`get_source` 必须串行）。报错就重试，但要确认是否已落库（`list_sources` 核对）。

**体积**：实测单次 18.5KB 成功；68~89KB 整传**截断风险高** → 走第九节通道。报"参数 source 不能为空/解析错乱"通常是**内容损坏**而非超限。

## 八、第 5 步：字段级 md5 回读闭环

这是整套体系的**验收闸门**，两步：

### 8.1 建立本地基线

```python
# 输出每个叶子字段的 len + md5
def walk(o, path=''):
    if isinstance(o, dict):
        for k, v in o.items(): walk(v, path + '.' + k)
    elif isinstance(o, list):
        for i, v in enumerate(o): walk(v, f'{path}[{i}]')
    else:
        b = (o or '').encode('utf-8') if isinstance(o, str) else str(o).encode('utf-8')
        print(f'{path}\t{len(b)}\t{hashlib.md5(b).hexdigest()}')
```

### 8.2 App 内回读比对

`eval_js`（绑定该书源）逐字段回算：

```javascript
function P(o, k) { var f = o[k]; return typeof f === 'function' ? f.call(o) : f; }  // Kotlin 属性双兼容
var out = [];
[['ruleSearch.name', source.getSearchRule ? P(source.getSearchRule(),'name') : null],
 ['ruleContent.content', P(source.getContentRule(),'content')]
].forEach(function(p){
  var s = String(p[1] == null ? '' : p[1]);
  var b = new Packages.java.lang.String(String(s)).getBytes(
            Packages.java.nio.charset.Charset.forName('UTF-8'));   // ★见下方坑
  out.push(p[0] + '\t' + b.length + '\t' + java.md5Encode ? '' : '');
});
```

**三个必踩的度量坑**：

| 坑 | 真相 | 对策 |
|---|---|---|
| `String(s).getBytes('UTF-8')` | Rhino 里**不存在该签名** | `new Packages.java.lang.String(String(s)).getBytes(Charset.forName('UTF-8'))` |
| `len` 两侧不等 | Rhino `String.length` 是 **UTF-16 长度**，Python `len` 是**码点数**，emoji 差 74~155 | **只比 UTF-8 md5，不比长度** |
| 显示层吞字符 | `workspace_read_file` 会丢字符（`;` 丢失案） | 以 `eval_js` 实测为准 |

### 8.3 差异定位：二分 + 逐字

```
差异字段 → 150 字符分段 md5 二分 → 定位到具体 150 字符窗口
        → charCode 逐字打印（两侧对齐）→ 一眼看到丢/多的那个字符
```

### 8.4 功能等价差异的处理

若差异只是 `NL('') → NL()`、文档字段这类**功能等价**改动：
**不要硬把 App 改成和文件一致**，而是把本地文件对齐 App 存储版本，再终验一次全量 md5。基线以"实际在跑的那份"为准。

## 九、第 6 步：大源导入通道（dpaste + 深链）

68KB+ 的书源不要整传 MCP。用这条通道（2026-09-14 定型，hanime1 v3.4~v3.9 生产在用）：

```
① 沙盒上传 dpaste
   POST https://dpaste.com/api/v2/        ← ★必须带尾斜杠，否则返回 API 文档 HTML
   参数：content / syntax=json / expiration_days=365
   raw 链接 = 返回 URL + ".txt"
② 沙盒侧算 md5，与本地基线比对（确保上传无损）
③ 手机侧拉回算 md5：java.ajax(raw) → 比对
   ★只允许拉一次！同 IP 短时二次拉 → 429 HTML → 导入器当 JS 源解析 → "XML 语法错误"
④ 唤起导入：java.openUrl('legado://import/bookSource?src=' + encodeURIComponent(raw))
   → OnLineImportActivity（路径 /bookSource）→ ImportBookSourceDialog
   → 用户点一次「确定」完成
⑤ 落库后仍要执行第八节 md5 回读（同 URL REPLACE 覆盖，不产生重复源）
```

同理可用 `legado://import/addToBookshelf?src=encodeURIComponent(书籍网址)` 做"点链接即开书"（见[详情页交互按钮选型树](方法-详情页交互按钮选型树.md)）。

## 十、版本备份链与命名规范

```
/workspace/<站名>/
  build_vNN.py              构建脚本（唯一事实源）
  <站名>_vNN.json           缩进版成品 = App 内那版
  <站名>_vNN_one.json       单行版（传输用）
  jslib_vNN.js / page_vNN.js / login_vNN.js   拆出的 JS 源码（带注释，便于审阅）
  README.md                 站点档案 + 排障史
  <站名>_v{N-1}.json        上一版（回退用）
```

三条规矩：

1. **改动前必备份**，App 当前版本也存一份（`*_from_app.json`）；
2. 版本号**只在功能/规则变更时递增**，注释级修补不算新版；
3. 清理旧版时同步更新 README 里的引用（米游社 v9g 那次专门做过一次清理）。

## 十一、交付前 checklist（打勾表）

**结构**
- [ ] `bookSourceUrl` 与站点主域一致，且与旧源不冲突（有旧源则先 `delete_sources` 再存，保排序/权重）
- [ ] `bookUrlPattern` **不匹配**搜索/发现/列表 URL（否则 `BookList.kt:62/64` 会把结果按详情页解析）
- [ ] `tocUrl` 放在 `ruleBookInfo` 内（放 `ruleToc` 被静默丢弃）
- [ ] `checkKeyWord` 放在 `ruleSearch` 内（顶层被 GSON 丢弃；官方版 `ExploreRule` 无此字段）
- [ ] `header` 是合法 JSON 对象字符串；`concurrentRate` 格式 `次数/毫秒`

**规则**
- [ ] 列表/目录字段走 `@js:` 或 XPath（绕污染），返回值形态跨版本兼容
- [ ] 所有 IIFE 都有 `return`
- [ ] 无真实换行、无裸 `<`/`&&`（onclick 内）
- [ ] `attr('href')` 而非 `absUrl`；`.replace` 前 `String()`
- [ ] 有分页迹象就考虑 `nextContentUrl`/`nextTocUrl`；**禁用 `prevContentUrl`、`:contains()`、`:first-child`**
- [ ] 无章内分页就**不设** `nextContentUrl`

**语法与字节**
- [ ] 全部 JS 块 `node --check` 0 失败（`loginUi` 除外）
- [ ] `save_source` 传**完整** JSON
- [ ] `get_source` 回读 + N 字段 md5 全对齐（排除 `respondTime`/`lastUpdateTime`）
- [ ] `enabledExplore` 等副作用位复查

**功能**
- [ ] `debug_source`：关键词（搜索）、`::URL`（发现）、`++URL`（目录）、`--URL`（正文）、绝对 URL（详情）
- [ ] `check_source` 通过（注意：动态 `exploreUrl` 聚合源、CF 站会误报，以 debug 为准）
- [ ] 跨版本目标用户 → 双版本实测
- [ ] 失败场景（付费墙/版权书/被墙）都有**可读提示**

**文档**
- [ ] README（站点档案 + 连通性档案 + 排障史）
- [ ] 记忆更新（可复用结论进 memory，别只留在对话）
- [ ] （可选）通用方法沉淀 + 推 GitHub

## 十二、避坑清单

| # | 坑 | 对策 |
|---|---|---|
| 1 | 以为 `save_source` 是增量合并 | 整体替换；传完整 JSON |
| 2 | 相信"已保存"回显 | 字段 md5 回读 |
| 3 | 手抄 JSON 给 MCP | 一律构建脚本产物 |
| 4 | 高密度 `\"` / `\\` 过传输层 | 零双引号零反斜杠纪律 |
| 5 | 大源硬塞 MCP | dpaste + 深链 |
| 6 | dpaste URL 漏尾斜杠 | `api/v2/` |
| 7 | 深链拉两次 | 429 HTML → "XML 语法错误"；只拉一次 |
| 8 | 构建脚本正则跨块 | 唯一字面锚点 + 顺序断言 |
| 9 | 只 `node --check` 不做语义仿真 | 逻辑错（不可达分支）它查不出 |
| 10 | 拿 node 查 `loginUi` | 宽容解析器，必误报 |
| 11 | 比长度判定一致 | UTF-16 vs 码点；只比 UTF-8 md5 |
| 12 | md5 基线含 `respondTime` | 保存会刷新，排除 |
| 13 | MCP 并行调用 | Session not found；串行 |
| 14 | 改 jsLib 后直接 eval_js 测 | 旧绑定还在（SharedJsScope），**必须先导入再测** |
| 15 | 无 sleep 用 `java.sleep` | `Packages.java.lang.Thread.sleep(ms)` |

## 附：最小可复用 md5 校验脚本

```python
# verify_local.py —— 生成本地基线（列顺序要与 eval_js 输出一致，便于肉眼比对）
import json, io, hashlib, sys
d = json.load(io.open(sys.argv[1], encoding='utf-8'))
SKIP = {'respondTime', 'lastUpdateTime', 'customOrder', 'enabled', 'enabledExplore'}
def walk(o, p=''):
    if isinstance(o, dict):
        for k, v in sorted(o.items()): walk(v, p + '.' + k)
    elif isinstance(o, list):
        for i, v in enumerate(o): walk(v, f'{p}[{i}]')
    else:
        leaf = p.rsplit('.', 1)[-1]
        if leaf in SKIP: return
        s = o if isinstance(o, str) else json.dumps(o, ensure_ascii=False)
        b = (s or '').encode('utf-8')
        print(f'{p}\t{len(b)}\t{hashlib.md5(b).hexdigest()}')
walk(d)
```

> 把它输出存成 `md5_vNN.txt`，与 App 回读结果 `diff` 一下，零差异才算交付完成。
