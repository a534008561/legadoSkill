## 一、站点画像与为什么值得单独沉淀

这是一类最常见的"模板站"，规则本身很简单，但有 **4 个此前技能库未记载的坑**，
全部在本次 MCP 实测中踩到并定位到源码级机制：

| 维度 | 实际情况 |
|---|---|
| 站点 | `m.tkshuw.com`（PC 站 `www.tkshuw.com` 同后端，结构完全不同） |
| 页面 | 纯静态 HTML，无 JS 渲染、无加密参数、无验证码 |
| 防护 | Cloudflare 前置，`cfCacheStatus: DYNAMIC`，**无 JS 挑战**（python UA 也返回 200） |
| 搜索 | `GET /search.html?nf=关键词`，**无分页**，单页最多 100 条 |
| 详情 | `/nf_{id}/` 与 `/nf_{id}.html` 均可，内容一致 |
| 目录 | `/nf_{id}/all.html`，**全量单页**（实测 4058 章仍单页，无 `pages` div） |
| 正文 | `/nf_{id}/{序号}.html`，章内分页 `{序号}_2.html`、`{序号}_3.html` |
| 登录 | **无**（`login.html`、`/user/` 均 404），全站免登录 |

> **首个经验：这类"看起来毫无难度"的模板站，恰恰容易因为 4 个小机制翻车。**
> 不要因为它"简单"就跳过 MCP 实测——下面每一条都是实测才暴露的。

## 二、假表单：声明 POST 实则 404

### 现象

站点 HTML 里声明的表单：

```html
<!-- 首页 -->
<form name="articlesearch" class="searchForm anfa" action="/search.html">
  <input type="text" name="nf" .../>
<!-- 分类页 -->
<form name="articlesearch" class="searchForm" method="post" action="/search.html">
  <input type="text" name="s" .../>
```

**同一个站点、同一个 action，三个页面的表单声明三种形态**：无 method + `nf`、`method=post` + `s`、`method=get` + `nf`。

### 实测结论

| 请求 | 结果 |
|---|---|
| `GET /search.html?nf=xxx` | ✅ 200，正常结果 |
| `POST /search.html` + `s=xxx` | ❌ **404**（站点 404 页） |
| `GET /search.html?s=xxx` | ❌ 200 但**返回的是默认"发现小说"列表**，不是搜索结果 |

### 根因

模板站的搜索页是**同一个文件** `/search.html`，服务端只认 `nf` 这一个查询参数。
`method=post` 的 `s` 是历史遗留的死代码，服务端没有对应路由 → 404。
而 `s=xxx` 作为 GET 参数时服务端直接忽略，返回默认列表——**这个最危险**，因为 HTTP 200、
有数据、`bookList` 也能匹配到 100 条，但内容跟关键词毫无关系。

### 排查纪律（重要）

1. **不要只看表单 HTML**。必须把首页/分类/详情/搜索页四个页面的 `<form>` 都抓下来对比——
   本站四个页面就有三种不同声明，只看一个必然踩坑。
2. **"能出数据"不等于"参数对"**。`s=xxx` 返回 200 + 100 条数据，但那是默认推荐列表。
   必须验证：搜一个**确定存在的书名**（如搜"老不死"，结果里应出现 `/nf_255656/`），
   以及搜一个**确定不存在的词**（应返回「没有关于(xxx)的内容」且 `s_list` 数为 0）。
3. **无结果的返回形态要先摸清**。本站无结果时：
   ```html
   <p style="text-align:center;padding:10px;">没有关于(zzqqxx不存在的)的内容</p>
   ```
   `s_list` 计数为 0 → Legado `bookList` 自然匹配不到 → 正常报"未获取到书籍"。
   **不需要** 额外写 `checkKeyWord`。

### searchUrl 定式

```
https://m.tkshuw.com/search.html?nf={{key}}
```

## 三、列表内联文本：一个 div 里书名作者分类全在一起

搜索结果列表项的真实 HTML：

```html
<!-- 搜索结果页（wrap-box 下） -->
<div class="s_list">
  <a href="/nf_109837/" data-toggle="tooltip" data-placement="right" title="最新章节：第二百三十八章 重塑金身">凡人修仙传之翻倍之能</a> / 冬柳无叶
</div>

<!-- 分类页（无 wrap-box） -->
<div class="s_list">[仙侠]<a href="/nf_685431/">娘子，你不会真的给我下药了吧</a> / 桃公旺</div>

<!-- 首页/最近更新页（无 title 属性） -->
<div class="s_list"><a href="/nf_193246/">关山风雷</a>/ 清风辰辰</div>
```

**关键点：`class="s_list"` 的 div 里没有 `<span>`/`<p>` 之类的子标签**，书名、作者、分类全是裸文本：

- 书名在 `<a>` 里
- **作者是 `<a>` 后面的裸文本**，分隔符是 `/`（有时有空格，有时没有：`/ 清风辰辰` vs `/ 清风辰辰`）
- 分类是**行首方括号** `[仙侠]`，且**只在分类页有**，搜索结果页和首页都没有

### 为什么不能按套路写 `##` 正则

技能库常规做法是 `author: "text##^\\[.*\\]/\\s*##"` 这类。但本案有三个变量：

1. 结果页**没有** `[分类]` 前缀 → 正则要么写两套，要么用可选组
2. 分隔符 `/` 前后空格**不固定**（`/ 冬柳无叶` vs `/ 清风辰辰`，取决于页面模板）
3. `title` 属性只在**搜索结果页**存在，分类页/首页没有 → `lastChapter` 在发现页必然为空

**结论：这种"裸文本 + 不定分隔符 + 可选前缀"的组合，用 JS 取 `lastIndexOf('/')` 比正则稳。**

```javascript
// 作者：取最后一个 '/' 之后的文本，trim 掉不定的空格
@js:var t=result.text();var i=t.lastIndexOf('/');i<0?null:t.substring(i+1).trim()

// 分类：只在行首有 [xxx] 时取，否则返回 null（不是空串，见第五节）
@js:var t=result.text();var m=t.match(/^\s*\[([^\]]*)\]/);m?m[1]:null
```

用 `lastIndexOf` 而不是 `indexOf`：书名里也可能带 `/`（如 `（综英美）干掉其他罗宾…` 这类），
取**最后一个** `/` 才是作者分隔符。

### bookList 的容器差异

| 页面 | bookList 选择器 |
|---|---|
| 搜索结果页 | `div.wrap-box div.s_list`（**必须带 `wrap-box`**） |
| 分类页 / 首页 / 最近更新 | `div.s_list` |

搜索结果页有 `div.wrap-box` 包裹，分类页没有。**不能共用一个 bookList**——
所以 `ruleSearch` 和 `ruleExplore` 要分别写。

### 封面：站点没有封面 URL，只能拼

列表项里**没有任何封面图片**（详情页有 `data-src`，列表页没有）。
封面规律是 `https://www.tkshuw.com/image/nf_{id}.jpg`，所以从 bookUrl 里抽 id 拼：

```
coverUrl: "a@href##/nf_(\d+)/.*##https://www.tkshuw.com/image/nf_$1.jpg"
```

实测 `/image/nf_{id}.jpg` 对空封面会返回一张占位图（`nocover` 内容），不会 404。
**这条不是通用做法**，只适用于"封面 URL 有严格数字 id 规律"的站。

## 四、@js 提取内联文本：result 到底是字符串还是元素

这是本次**最隐蔽的坑**，第一版写成下面这样，MCP 调试直接静默返回空：

```javascript
// ❌ 第一版：以为 result 是字符串
@js:var t=String(result);var m=t.match(/^\s*\[([^\]]*)\]/);m?m[1]:null
```

调试日志表现为：

```
[00:00.496] ┌获取分类
[00:00.496] └            ← 空，没有任何报错
```

### 源码级根因

`AnalyzeRule.getString(ruleList)` 里，`result` 的类型由**上一步规则的返回类型**决定：

- 上一步是 CSS/XPath（如 `div.s_list`）→ `result` 是 jsoup 的 `Element` 对象
- 上一步是 `@text` / `@html` / `@attr` → `result` 是字符串

`@js:` 紧跟 `bookList` 后面的 CSS 规则时，**`result` 是 `Element`**，
`String(element)` 得到的是 `org.jsoup.nodes.Element@1a2b3c4d` 这种对象地址串，
`match` 当然匹配不到，返回 `null`，**且不报错**（静默失败）。

### 正确写法

```javascript
// ✅ 先取元素文本再匹配
@js:var t=result.text();var i=t.lastIndexOf('/');i<0?null:t.substring(i+1).trim()
```

### 防御式写法（元素/字符串两种都可能时）

```javascript
@js:var t=(result&&result.text)?result.text():String(result);var m=t.match(/^\s*\[([^\]]*)\]/);m?m[1]:null
```

> **通用教训：`@js:` 里碰 `result`，先判断 `result.text` 是不是函数。**
> 这和 `方法-静默失败定位与探针法` 是同一类问题：Legado 的规则链不报错，只是给你空值。
> 判断方法很简单——**调试日志里该字段有 `┌获取xxx` / `└` 输出但 `└` 后面是空**，
> 就是静默失败，不是规则没匹配上。

## 五、nextContentUrl：空串会被当 URL 拼回当前页

### 第一版的写法与故障

```javascript
// ❌ 第一版：非分页形态返回空串
@js:var h=String(result||"");var m=h.match(/id="pb_next"[^>]*href="([^"]+)"/);
    var u=(m&&/^\d+_\d+\.html$/.test(m[1]))?m[1]:"";u
```

MCP 调试 `--` 正文调试时**完全正常**：

```
[00:00.000] ┌获取正文下一页链接
[00:00.138] └https://m.tkshuw.com/nf_255656/0_2.html
[00:00.504] 第2页完成
[00:00.504] ◇本章总页数:2
```

但走完整搜索→详情链路时，`nf_30050/0.html`（无章内分页）这一章：

```
[00:04.922] ┌获取正文下一页链接
[00:04.922] └https://m.tkshuw.com/nf_30050/0.html     ← 拼回了当前页！
[00:04.922] ┌获取章节名称
```

`本章总页数` 那行直接消失了（被去重后 `nextUrlList.size == 1` 走不到打印），
内容本身没错，但**多打了一次当前页请求**，且日志形态异常。

### 源码级根因（AnalyzeRule.getStringList）

```kotlin
if (result == null) return null                    // ← 返回 null：nextUrlList 不加东西，干净终止
if (result is String) { result = result.split("\n") }   // ← 空串 → [""]
if (isUrl) {
    for (url in result) {
        val absoluteURL = NetworkUtils.getAbsoluteURL(redirectUrl, url.toString())
        //                                          ↑ 空串在这里被拼成 redirectUrl（当前页）
        if (absoluteURL.isNotEmpty() && !urlList.contains(absoluteURL)) urlList.add(absoluteURL)
    }
}
```

再看 `BookContent.kt:63`：

```kotlin
val nextUrlList = arrayListOf(redirectUrl)   // ← 初始就含当前页
```

所以：

| JS 返回值 | `getStringList` 结果 | 最终行为 |
|---|---|---|
| `null` | `return null` → `nextUrlList` 不变 | **干净终止，零额外请求** |
| `""`（空串） | `[""]` → `getAbsoluteURL` 拼成**当前页 URL** | 请求当前页 → 靠 `!nextUrlList.contains` 去重挡下 |

**空串确实不会造成死循环**（因为初始 list 已含当前页，去重会挡），但它：

1. **多发一次当前页请求**（在 `while` 循环外，是 `analyzeContent` 里的首次判断，
   实测会真实打一次网络请求）
2. **日志形态异常**（`本章总页数` 那行不打印），排查时容易误判成"分页逻辑没生效"

### 正确写法

```javascript
@js:var h=String(result||"");var m=h.match(/id="pb_next"[^>]*href="([^"]+)"/);
    var u=(m&&/^\d+_\d+\.html$/.test(m[1]))?m[1]:"";u?u:null
//                                                                    ↑ 关键：空串转 null
```

### 与既有记载的差异（重要）

`方法-目录顺序与章节去重铁律` 第八节写的是"其余情况返回 `''`（空 → 终止，安全）"。
**那个结论只对了一半**：空串确实"安全"（不会死循环），但**不是零成本**——
它会多打一次当前页请求。`nextTocUrl` 那边同理（该文档 74 行 `return ''` 的做法）。

**修正后的通用规则：**

> 所有"用于终止"的规则返回值，**优先 `return null` 而不是 `return ''`**。
> `null` 走 `if (result == null) return null` 直接短路；`''` 会进 `isUrl` 分支被拼成 baseUrl。

同理适用于：

- `ruleContent.nextContentUrl`
- `ruleToc.nextTocUrl`
- 任何 `@js:` 结尾做"取不到就不拼"的 URL 类规则

### 三态验证法（本次实测通过）

用 `eval_js` 对 `nextContentUrl` 的 JS 做纯逻辑单测，不打网络：

```javascript
function pick(html){
  var m=String(html).match(/id="pb_next"[^>]*href="([^"]+)"/);
  return (m && /^\d+_\d+\.html$/.test(m[1])) ? m[1] : null;
}
// 章内第1页(应取 0_2.html)  → '0_2.html'
// 章内末页(应 null)          → null     ← href="1.html" 是下一章
// 全书末章(应 null)          → null     ← href="/nf_255656.html" 是详情页
// 已删除章(应 null)          → null     ← 同上
// 三页章第2页(应取 10_3)     → '10_3.html'
```

本站 `pb_next` 的三种形态（实测）：

| 场景 | `pb_next` 的 href | 处理 |
|---|---|---|
| 章内还有页 | `0_2.html` | ✅ 跟随 |
| 章内最后一页 | `1.html`（下一章） | ❌ 拒绝（不匹配 `\d+_\d+\.html`） |
| 全书最后一章 | `/nf_255656.html`（详情页） | ❌ 拒绝 |
| 章节已删除 | `/nf_255656.html` | ❌ 拒绝 |

> `\d+_\d+\.html$` 这个正则同时挡住了"下一章"和"详情页"两种伪装，是本例的核心。

## 六、站点自身截断与空章节

排查时发现两种**站点数据问题**，不是书源问题，但容易误判：

### 1. 同一 URL 的 `_2.html` 与主 URL 内容完全相同

```
nf_30050/0.html   → len 1243, md5 826881f3d034830cb70faf900e234926
nf_30050/0_2.html → len 1243, md5 826881f3d034830cb70faf900e234926   ← 完全一致
```

且 `0_3.html` 返回 404。同时正文结尾有 `（本章未完，请翻页）`。
**这是站点自己的正文截断 bug**（该书的 `_2` 页内容没入库）。
`nextContentUrl` 会正确抓到 `0_2.html`，抓完发现内容重复，但 Legado 不做内容去重，会拼两遍。

**处理：书源层无法修，只能接受。** 不要为此写 `replaceRegex` 去删 `（本章未完，请翻页）`——
其他书（如 `nf_438195`、`nf_9185217`）的正文是完整的，没有这句，删了也不误伤，
但**没有收益**。实测 `nf_438195`、`nf_9185217`、`nf_255656` 全部正常。

### 2. 目录里有"无效章节"

```html
<div class="s_list">... 第60章 无效章节,已被删除 ...</div>
```

点进去正文页是 `章节内容加载失败，请重新刷新页面！`，`htmlContent` 只有一个空格。
**这是站点自己的死章节**（书源层无法识别，因为目录页看起来完全正常）。
用户读到会看到空白章，属站点数据问题。

## 七、避坑清单

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 只看一个页面的 `<form>` 就定 `searchUrl` | **四个页面（首页/分类/详情/搜索页）的表单都抓下来对比**；本站三种不同声明 |
| 2 | `GET ?s=xxx` 返回 200 + 100 条数据就以为参数对 | 验证：①搜确定存在的书名，结果里要出现对应 id ②搜确定不存在的词，应 0 条 |
| 3 | 作者/分类按 `text##正则` 写 | 裸文本 + 不定空格 + 可选前缀 → 用 `@js:` + `result.text()` + `lastIndexOf('/')` |
| 4 | `@js:` 里直接 `String(result)` | **先判 `result.text` 是不是函数**；Element 被 String() 成对象地址，静默返回空 |
| 5 | `author` 用 `indexOf('/')` | 书名可能含 `/`，必须 `lastIndexOf('/')` |
| 6 | `nextContentUrl` 取不到时 `return ''` | **`return null`**；空串会被 `getAbsoluteURL` 拼成当前页，多发一次请求 |
| 7 | `ruleSearch` 和 `ruleExplore` 共用 `bookList` | 搜索页有 `div.wrap-box` 包裹，分类页没有，**必须分开写** |
| 8 | 以为"简单站不用 MCP 实测" | 本例 6 个坑里有 4 个（#3/#4/#5/#6）只有实测才暴露 |
| 9 | 站点自身截断/死章节，以为是书源问题 | 用 md5 对比 `_2.html` 与主页、直接请求中间章，先分清"站点问题"还是"规则问题" |
| 10 | `concurrentRate` 不设 | 本例设 `1/1500`（全站每 1.5s 最多 1 次），既压搜索频率也保护正文抓取 |
