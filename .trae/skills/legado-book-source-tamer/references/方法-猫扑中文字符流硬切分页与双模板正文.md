# 方法 - 猫扑中文（m.bookmaopu.com）字符流硬切分页、双模板正文与 nextContentUrl 三连坑

> 制作日期：2026-11-06。站点：猫扑中文文学阅读（杰奇 CMS 换皮，UTF-8）。
> 适用：LegadoTeam/legado 官版 + Luoyacheng/legado-E；MCP 调试 + LAN 直存闭环实测通过。

---

## 0. 一句话结论

本站正文分页**不是按段落切，而是按固定字节数硬切句子、连 HTML 标签都被切成两半**，且站内存在两套完全不同的正文模板（新书 `<p>` 段落 / 老书 `<br><br>` 分隔 + 站点维护噪声）。官版 `nextContentUrl` 机制在此站有三处致命冲突，正确解法是 `ruleContent.content` 用 `@js` 自抓分页、`parts.join('')` 无缝拼接、拼接后统一清洗。

### 隐蔽陷阱：伪装 404 大页

`/modules/article/reader.php`、`/modules/article/wapallchapter.php` 等探测端点返回 **HTTP 404 + 73116 字节完整小说页**（标题《诸天万界之大拯救》，有 `#nr1`、目录、正文样式）。**用「响应大小/是否有 HTML 结构」判断端点存在会全错**，必须用路径相关内容（如 `aid` 对应书名）验证。

### 隐蔽陷阱：刚更新章节空正文

最新章节（几分钟内更新）页面 `#nr1` 只有「阅读提示：阅读模式下可能会有内容不完整…」+ 3 个 `<br/>`，无正文；稍后站点生成完成才有内容。这是站点延迟，不是规则失效。

## 2. ★核心难点：字符流硬切分页（比 2tsw 更重）

m.2tsw.com 是 `&n/bsp;` 实体被切半；本站**连标签都被切**：

```
p1 末尾： …杨晨摇了摇头道：“放心吧，一切都在掌控之中，现在正<br />
p2 开头： 阅读提示：…<br /><br />是使用此物的最佳时期！把那具废动力甲抬过来。”</p>
p2 末尾： …“多谢大人！”维斯帕修斯心中的阴郁一扫而空，已经迫不及待地想要将新的动力甲穿上。<<br />
p3 开头： 阅读提示：…<br /><br />/p>
```

特征：
- 切点落在句中（「现在正」+「是使用…」），**任何按换行/段落拼接都会断句**；
- 页面各自重复「阅读提示」头 + 2 个 `<br/>`；
- 分页边界产生孤立 `<`（p2 末尾）与 `/p>`（p3 开头）；
- 非末页有 `<p>本小章还未完，请点击下一页继续阅读后面精彩内容！</p>`，末页有 `<p>喜欢《书名》请大家收藏：《书名》。</p>`；
- 老书模板（`<br><br>` 分隔）末页还带 `<div align="center"><a href="javascript:postError(...)"></a>, 报送后维护人员会在两分钟内校正章节内容,请耐心等待。` 噪声块，且 **该 div 也会被跨页切断**（`align="center"` 开头在前页、闭合在后页）。

## 3. ★nextContentUrl 三连坑（官版 BookContent.kt 源码级实锤）

```kotlin
val contentList = arrayListOf<String>()
val nextUrlList = arrayListOf(redirectUrl)
var contentData = analyzeContent(...)         // 首章页
contentList.add(contentData.first)
if (contentData.second.size == 1) {
    var nextUrl = contentData.second[0]
    while (nextUrl.isNotEmpty() && !nextUrlList.contains(nextUrl)) {
        ...
        val res = analyzeUrl.getStrResponseAwait(jsStr = webJs)  // 只有单 URL 分支传 webJs
        ...
    }
} else if (contentData.second.size > 1) {
    // ★多 URL 走 mapAsync 并发 + collect 按完成顺序 → 乱序
}
var contentStr = contentList.joinToString("\n")   // ★多页按换行拼接
```

本站冲突点：
1. **换行拼接必然断句**（字符流硬切）；
2. **末页 `pb_next` 指向目录页 `/书ID.html`**（仍是非空 URL）→ while 循环多抓一次目录页，目录页里没有 `#nr1` 但站点伪装 404 页可能带 `#nr1` → 串章噪声；另若章节末页 next 指向「下一章裸 URL」，会直接把下一章内容并进本章；
3. `getStringList(nextUrlRule, isUrl=true)` 若返回多个 URL → 走并发分支，页码顺序不可控；
4. `webJs` 只在单 URL 分支传递，JS 增强规则在并发分支失效。

**定案**：此类站点**不用** `nextContentUrl`，改 `ruleContent.content` 的 `@js:` 自行翻页。

## 4. 生产配方（本次实测全绿）

```javascript
@js:(function(){
var root='https://m.bookmaopu.com';
var cur=String(baseUrl);
var ids=cur.match(/:\/\/[^\/]+\/(\d+)\/(\d+)\//)||[];
var bookId=ids[1]||'', chapId=ids[2]||'';
var seen={},parts=[],guard=0,first=true;
while(cur&&guard<30){
  guard++;
  if(seen[cur])break; seen[cur]=1;
  var u=cur.indexOf('http')===0?cur:root+cur;
  // ★首页复用 Legado 已抓的 result，省一次请求
  var h=(first&&typeof result!=='undefined'&&result)?String(result):String(java.ajax(u));
  first=false;
  var m=h.match(/<div id=\x22nr1\x22>([\s\S]*?)<\/div>/);
  if(!m)break;
  var t=m[1];
  t=t.replace(/^[\s\S]*?正常阅读！\s*(?:(?:<br\s*\/?\s*>|\s)*)/,'');   // 每页阅读提示头
  t=t.replace(/<(?![a-zA-Z\/!])/g,'');                                  // 孤立 <
  t=t.replace(/<p>[^<]*(?:还未完|请点击下一页|请大家收藏)[^<]*<\/p>/g,'');// 广告行
  t=t.replace(/<div align=\x22center\x22>[\s\S]*?<\/div>/g,'');
  t=t.replace(/报送后维护人员会在两分钟内校正章节内容\s*[,，]?\s*请耐心等待。?\s*/g,'');
  t=t.replace(/^\s*\/p>\s*/,'');                                         // 跨页断半标签
  t=t.replace(/(?:<br\s*\/?\s*>\s*)+$/,'');                              // 页尾 <br/>
  parts.push(t);
  var n=h.match(/id=\x22pb_next\x22\s+href=\x22([^\x22]*)\x22/);
  var nx=n?n[1]:'';
  // ★★翻页判据：必须同书同章 + N.html 结尾（同时满足才翻）
  if(!nx||nx==='javascript:;'||nx.indexOf('/'+bookId+'/'+chapId+'/')!==0||!/\/\d+\.html$/.test(nx))break;
  cur=nx;
}
var html=parts.join('');                                                  // ★无缝拼接
html=html.replace(/<div align=\x22center\x22[^>]*>[\s\S]*$/,'');          // 跨页被切开的维护块兜底
html=html.replace(/<p[^>]*>/g,'').replace(/<\/p>/g,'\n');
html=html.replace(/<br\s*\/?\s*>/g,'\n');
html=html.replace(/&nbsp;/g,' ') /*…实体…*/;
html=html.replace(/[^\n]*(?:align=\x22center|postError|报送后维护人员|请耐心等待)[^\n]*\n?/g,'');
html=html.replace(/[ \t]+/g,' ').replace(/ ?\n ?/g,'\n');
html=html.replace(/\n\s*[,，]\s*(?=\n|$)/g,'\n');                         // 孤立逗号行
html=html.replace(/\n{3,}/g,'\n\n').replace(/^\s+/,'');
return html;
})()
```

### 五条铁律

1. **`parts.join('')` 不 join('\n')** —— 硬切站点必须字节级无缝；
2. **翻页判据必须双锚**：`/bookId/chapId/` 前缀 + `/N.html` 结尾。只查 `.html` 会在站点改版成「下一章 /2.html」时串章；只查前缀会在末页 next 指向目录页时多抓；
3. **首屏复用 `result`**：Legado 已抓第一页，省 1 个 RTT；
4. **清洗放在 join 之后**：跨页切开的标签/噪声块只有拼起来才完整，逐页清洗会漏；
5. **JS 里全部用 `\x22` 代替 `"`**：MCP `save_source` 会静默吞掉含双引号的字段值（旧坑再验证）；LAN `/saveBookSource` 无此限制，优先 LAN。

### 实测对照（App 内 eval_js 跑保存后的规则全文）

| 模板 | 章 | 页数 | 拼接结果 | 广告 | 残标签 | 断句 |
|---|---|---|---|---|---|---|
| 新书 `<p>` | 1366926/106955990 | 3 | 3350 字 | 0 | 0 | 「现在正是使用此物的最佳时期」完整 |

## 5. 其它可复用发现

### 5.1 `BookInfoRule` 没有 `state` 字段（Gson 静默丢字段）
官版 `BookInfoRule.kt` 字段全集：`init/name/author/intro/kind/lastChapter/updateTime/coverUrl/tocUrl/wordCount/canReName/downloadUrls`。
写 `ruleBookInfo.state` 保存成功、回读消失（无报错）。「连载中」要么放 `kind`（本站列表已这么做），要么改用 `updateTime`。**凡是写入后回读消失的字段，先查 data class 字段白名单，不要怀疑通道。**

### 5.2 `class.zxjz.-1` 稳定取「全部章节」区
详情页裸 `<div>` 容器里两个 `section.zxjz`：第 1 个「最新章节」12 条、第 2 个「全部章节」全量。用 `tag.section.N` 索引会因无 class 的父 div 计数漂移（cunshula 的 baseElement 绑定坑再现）；用 `class.zxjz.-1@tag.li` 倒取第 1 个，实测 310/4879/1066/704/298 章全部一次拿全。

### 5.3 搜索 POST 的 `{{key}}` 编码
`AnalyzeUrl.encodeParams` 对 POST body 按 `&`/`=` 拆键值后 `URLEncoder.encode(value, charset)`（默认 UTF-8），中文关键词安全：
```
searchUrl = https://m.bookmaopu.com/page/search.html,{"method":"POST","body":"type=articlename&searchkey={{key}}"}
```
实测「全民领主」「斗破苍穹」「长生修仙」均正常返回。用户明确要求「不主动探测搜索访问频率」→ 不写频控探测，只设 `concurrentRate: 1/500` 保守限速。

### 5.4 双通道全断的处置
手机端 MCP 桥（`192.168.10.7:1236`）与 LAN Web 服务（`:1122`）**同时 connection refused** ⇒ App 被杀/服务停，两条通道都不可用，只能请用户重开 App；不要反复盲试。两通道健康时优先 LAN（无 19KB 上限、无双引号吞噬、可字节级回读）。

### 5.5 设备级磁盘满 ≠ 工作区问题
`df` 111G 100%（手机其他 App 数据），proot 报 `No space left on device` 但 stdout 仍正常返回；**workspace_write_file 必然失败（ENOSPC）**，此时大文件改走「Python 内存组包 → LAN POST」或聊天内联交付，不要修 apt/装依赖。

## 7. ★「封面不显示」与「怎么全是同一副图」：封面双路径分流（用户两轮实测反馈）

### 7.1 站点有两套封面路径，不能一刀切

| 形态 | 样例 | 实测 |
|---|---|---|
| **新路径（真封面）** | `/uploads/images/167033s.jpg`、`/uploads/images/179s.jpg` | **200 image/jpeg**（批量 8/8 + 4/4 全通） |
| **旧路径（死链）** | `/uploads/241216/56e2067200e3dadba03c4747a2856f22.jpg` | **404 text/html** 72KB 伪装404大页（批量 **0/21** 可用，带完整浏览器头/Referer/Cookie/www 域/HTTP1.1 全对照均 404 ⇒ 不是防盗链） |
| 空 src | `<img src="" onerror="this.src='/static/images/nocover.jpg'">` | 浏览器靠 onerror 显示兜底图；Legado **不执行 onerror** |
| 兜底图 | `/static/images/nocover.jpg` | 200 image/jpeg 62179B 518×666 |

★**第一轮踩坑**：只抽样了搜索结果里的旧路径（21/21 404）就断言「全站封面已死」，把三处 coverUrl 全改成 nocover ⇒ 用户反馈「怎么全是同一副图？」+「我浏览网站发现有很大一部分都是用同一幅图，但是有的还是有封面的」。**反向验证组缺失**：应该去 PC 正文页「推荐阅读」/分类深分页里找非空且不同形态的 src，才发现了 `/uploads/images/<ID>s.jpg` 新路径。★教训：判「资源全死」必须先覆盖**所有路径形态 + 分批抽样**，一组样本全灭不等于总体全灭。

### 7.2 生产规则（三处 coverUrl 同一个 @js）

```javascript
@js:(function(){
var base='https://m.bookmaopu.com';
var NO=base+'/static/images/nocover.jpg';
var s='';
try{
  if(typeof result==='string'){                       // 详情环境：result 是整页 HTML 字符串（探针实锤）
    var m=result.match(/<div class=\x22xsfm\x22>\s*<img[^>]*src=\x22([^\x22]*)\x22/);
    s=m?m[1]:'';
  }else if(result&&result.select){                    // 列表环境：result 是 jsoup Element（探针实锤）
    var im=result.select('li.tjimg img').first();
    if(!im&&result.parent)im=result.parent().select('li.tjimg img').first();
    s=im?im.attr('src'):'';
  }else if(result&&result.parent){
    var im2=result.parent().select('li.tjimg img').first();
    s=im2?im2.attr('src'):'';
  }
}catch(e){}
s=String(s||'').trim();
if(!s||s.indexOf('nocover')>=0)return NO;
if(s.indexOf('http')===0)return s;
if(s.charAt(0)!=='/')s='/'+s;
if(/^\/uploads\/\d{6}\//.test(s))return NO;        // 旧日期目录判死
return base+s;                                        // 新路径绝对化
})()
```

★**列表规则取兄弟节点封面**：`bookList=class.tjxs`（span 容器）里没有封面 img，`li.tjimg` 是它的**兄弟 li**，同属 `ul.xbk`。探针实锤 `result.parent()` = `ul.xbk`、`parent().select('li.tjimg img').first()` 可取到 src。这比改 `bookList=ul.xbk`（要重写全部字段规则）风险小得多。

★**详情环境 result 是整页 HTML 字符串**（不是 Element）：探针 `t=string|str=<!doctype html>...` 实锤，所以必须从字符串正则取 `.xsfm img src`，不能用 `.select()`。同一条规则要双路径兼容两类环境。

- `debug_source` 搜索「全民领主」→ 旧路径 2621 自动回退 nocover ✓

### 7.4 通用判据（封面类问题）
1. debug 日志「┌获取封面链接 └」看是否为空/相对路径；
2. 对取到的 URL 直接 `curl -I` 看 `content-type`（**404 伪装大页返回 text/html 且 body 很大，只看状态码/大小会误判**）；
3. **必须覆盖所有路径形态**：同一站点可能并存新/旧两套图床，抽样一组全灭要继续找别的形态（深分页、PC 推荐位、详情页）；
4. `bookList` 元素是否包含封面节点（兄弟节点走 `result.parent().select()`）；
5. App 不执行 `onerror`；
6. 书已入书架且存过旧 coverUrl 时改源不回填，需删书重加（LAN `/getBookshelf` 可查）。
