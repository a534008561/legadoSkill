# 方法-书源自助运维面板与站点特色功能拆解（八叉书库实战）

> 本篇拆解一个**"自带运维能力"的书源**：用户不必来找作者，面板里点几下就能自己修好。
> 蓝本：`🌈八叉书库` v7.1，杰奇 CMS（jieqi）站，35 个面板按钮、19 个 jsLib 函数、25 个 loginUrl 函数。
> 配套阅读：`方法-线路自愈与登录面板运维套件（八叉书库实战）.md`（讲线路层，本篇讲业务层）。

## 0 一句话总结

**把「用户报障」变成「用户自助」** —— 每个高频故障都给一个按钮：
书架不显示 → 「♻️同步网站书架」；封面难看 → 「🗻净化封面」；书太杂 → 书名黑名单；不知道自己登录没 → 「🔍登录诊断」；有新版 → 「🆕版本更新」。
**按钮的判据必须来自真实页面，不能靠本地猜测。**

## 2 书架双向同步（最有价值的特色）

### 2.1 三个方向的语义

```
网站书架 ──同步──> Legado 书架      （♻️同步网站书架）
Legado 当前书 ──加入──> 网站书架    （📚加入网站书架）
Legado 当前书 ──移出──> 网站书架    （🗑移出网站书架）
```

**为什么三个都要有**：用户可能在网站上加书（手机浏览器），也可能在 Legado 里加书，
两边都要能互通，否则「书架」就是个单向死路。

### 2.2 加入网站书架 `addsh()`

```js
function addsh() {
  const {java, source, cache, cookie} = this;
  // ① 取书籍 id —— 双通道：内存缓存优先，其次解析 bookUrl
  let id = '', bkName = '';
  try {
    let m = cache.getFromMemory('8xid');
    if (m) { let k = Object.keys(m)[0]; id = String(k); bkName = String(m[k] || ''); }
  } catch(e) {}
  if (!id) {
    try {
      let bu = String((typeof book != 'undefined' && book) ? (book.bookUrl || '') : '');
      let mm = bu.match(/book[/](\d+)/);
      if (mm) { id = mm[1]; bkName = String(book.name || ''); }
    } catch(e2) {}
  }
  if (!id) { java.longToast('\n未获取到书籍 ID\n\n请先打开一本书的详情页'); return; }

  // ② 登录检查
  let site = webck();
  let jar = String(cookie.getCookie(site) || '');
  if (jar.indexOf('jieqiUserInfo') < 0) {
    java.longToast('\n❌ 请先登录\n\n加入网站书架需要登录账号'); return;
  }

  // ③ POST（★必须带 Referer，否则站点判为 CSRF）
  java.toast('正在加入网站书架…');
  let ua = java.getWebViewUA();
  let tm = new Date().getTime();
  let body = 'bid=' + id + '&ajax_request=' + tm;
  let opt = {
    headers: {'User-Agent': ua, 'Cookie': jar, 'Referer': site + '/book/' + id + '.html'},
    method: 'POST', body: body, timeout: 25000
  };
  let msg = '';
  try {
    let r = java.connect(site + '/modules/article/addbookcase.php,' + JSON.stringify(opt));
    msg = String(r.body() || '').replace(/<[^>]+>/g, '').replace(/\s+/g, ' ').trim();
  } catch(e3) { java.longToast('加入失败：' + String(e3).substring(0,80)); return; }

  // ④ 成功判据：多个同义词（不同站点措辞不同）
  java.log('addbookcase 返回：' + msg);
  if (msg.indexOf('恭喜') >= 0 || msg.indexOf('已经加入') >= 0 || msg.indexOf('已在') >= 0) {
    java.longToast('\n✅ ' + msg + '\n\n《' + (bkName || id) + '》');
  } else {
    java.longToast('\n⚠️ 返回：' + (msg || '空响应') + '\n\n可点「♻️同步书架」核对');
  }
}
```

**四个要点**：

1. **`cache.getFromMemory('8xid')` 优先**
   `book` 变量在面板按钮里可能 `undefined`（源码：`SourceLoginJsExtensions` 不注入 book），
   所以详情页规则要把 `{id: name}` 存进内存缓存，按钮从这里读。
2. **必须带 `Referer`**
   杰奇站校验 `Referer` 与 `Host` 同源，不带会返回「非法请求」。
3. **`ajax_request=时间戳`** 是防缓存参数，不带可能拿到缓存的旧响应。
4. **成功判据要宽容**：`恭喜` / `已经加入` / `已在` 三种措辞都算成功。
   ❌ 不要只判 `'成功'`（很多站返回「恭喜您，加入书架成功！」里没有「成功」二字的位置匹配）。

### 2.3 移出网站书架 `delsh()`

与 `addsh` 结构相同，只改端点 `delbookcase.php`。
**注意**：移出操作的响应往往是空的（HTTP 200 + 0 字节），不能判「失败」，
应该提示「已提交，可点同步核对」。

### 2.4 批量同步 `webbs(1)` —— 深链批量加入

这是**最巧妙**的一段：把网站书架的所有书，批量加进 Legado 书架。

```js
// webbs(x) 的 x==1 分支
if (x == 1) {
  // ① 登录检查
  if (jar.indexOf('jieqiUserInfo') < 0) { java.longToast('❌ 请先登录'); return; }
  java.toast('正在读取网站书架…');
  let b = '';
  try {
    b = String(java.connect(nm + '/modules/article/bookcase.php,{"headers":{"User-Agent":"' + ua + '","Cookie":"' + jar + '"},"timeout":25000}').body() || '');
  } catch(e) { java.longToast('读取书架失败：' + String(e).substring(0,60)); return; }
  if (!b || b.length < 1000) { java.longToast('书架页异常（' + (b?b.length:0) + 'B）'); return; }
  if (b.indexOf('frmlogin') >= 0) { java.longToast('❌ 未登录或登录已失效'); return; }

  // ② 解析书架（★三层兜底：卡片 → 全页扫 → 正则）
  let ids = [], names = [], seen = {};
  try {

    let cards = j.select('div.c_row.cf');
    if (cards.size() > 0) {
      for (let i = 0; i < cards.size(); i++) {
        let c = cards.get(i);
        let a = c.select('div.row_text h4 a').first();

        let mm = href.match(/[?&]aid=(\d+)/);   // ★aid 才是书籍 id，bid 不是
        if (!mm) continue;
        let id = mm[1];
        if (seen[id]) continue;
        seen[id] = 1;
        ids.push(id);
        names.push(String(a.text() || '').replace(/^\s+|\s+$/g, ''));
      }
    }
    // 兜底 1：没有 c_row 卡片时全页扫
    if (!ids.length) {
      let as = j.select('a[href*=aid=]');
      for (let i2 = 0; i2 < as.size(); i2++) { /* 同逻辑 */ }
    }
  } catch(e2) { java.log('解析书架失败：' + e2); }
  // 兜底 2：正则扫
  if (!ids.length) {
    let re = /[?&]aid=(\d+)/g, m3;
    while ((m3 = re.exec(b)) !== null) {
      if (!seen[m3[1]]) { seen[m3[1]] = 1; ids.push(m3[1]); names.push(''); }
    }
  }
  if (!ids.length) { java.longToast('书架里没有书'); return; }

  // ③ 逐本发深链（★间隔 700ms）
  let okN = 0;
  for (let k = 0; k < ids.length; k++) {
    let bkUrl = nm + '/book/' + ids[k] + '.html';
    let dl = 'legado://import/addToBookshelf?src=' + encodeURIComponent(bkUrl)
           + ',{"origin":"https://八叉书库.luoyacheng.ip-ddns.com"}';
    try { java.openUrl(dl); okN++; } catch(e3) {}
    if (k < ids.length - 1) { try { Packages.java.lang.Thread.sleep(700); } catch(e4) {} }
  }

  // ④ 结果摘要（★只预览前 3 本，避免 toast 溢出）
  let preview = [];
  for (let p = 0; p < Math.min(3, ids.length); p++) preview.push('· ' + (names[p] || ids[p]));
  if (ids.length > 3) preview.push('· …等 ' + ids.length + ' 本');
  java.longToast('\n✅ 网站书架共 ' + ids.length + ' 本\n已发起加入 ' + okN + ' 本\n────────\n'
    + preview.join('\n') + '\n────────\n若未全部加入，可重复点此按钮');
}
```

**五个技术点（全部踩过坑）**：

1. **`aid` 才是书籍 id，`bid` 不是**
   书架卡片的链接是 `readbookcase.php?bid=1161734&aid=33793&cid=...`。
   - `bid` = 书架记录 id（每本书在书架里的一条记录）
   - `aid` = 书籍 id（用于 `/book/{aid}.html`）
   用 `bid` 拼 URL 会 404。**这是最容易搞错的一处。**

2. **深链 `addToBookshelf` 带 `origin`**
   ```
   legado://import/addToBookshelf?src={encodeURIComponent(bookUrl)},{"origin":"{bookSourceUrl}"}
   ```
   `origin` 让 Legado 优先匹配本源（三级匹配的第一级），
   否则可能被别的源抢走（同域名多源时）。

3. **必须 `sleep(700)`**
   连续发深链系统会吞掉中间的（Android Intent 队列限制），
   实测 700ms 间隔最稳。**没有间隔时 7 本只能进 2~3 本。**

4. **三层解析兜底**
   卡片选择器（`div.c_row.cf`）→ 全页扫（`a[href*=aid=]`）→ 正则。
   站点改模板时，前两层失效但正则还能救。

5. **`seen` 去重**
   书架页每本书会出现多次（封面链接、书名链接、继续阅读链接都带 aid），
   不去重会重复加 N 倍。

### 2.5 自动同步开关 `shujia()`

```js
function shujia() {
  let dn = source.get('8xsj');
  if (dn != 1) { source.put('8xsj', 1); java.toast('🟢已启用同步网站书架'); }
  else { source.put('8xsj', 0); java.toast('⚫已关闭同步网站书架'); }
}
```

**开关必须回显当前状态**：`toast('已启用'/'已关闭')`，用户才知道点完是什么状态。
（更好的做法：按钮名动态显示状态，见 V2 面板的 `viewName`）

## 3 交互式黑名单（SVG 验证码当输入框）—— 最巧妙的一招

### 3.1 问题

Legado 的 `loginUi` 只有 `text/password/button/toggle/select`，
**没有「多行文本」「列表勾选」这类控件**。用户想批量管理黑名单（比如 50 本书）怎么办？

### 3.2 解法：把 SVG 当"输入框"用 `java.getVerificationCode()`

```js
function hmdre() {
  let hmd = JSON.parse(cache.get('8xhmd') || '{}');
  let ss = Object.entries(hmd);
  let [cb, cf] = colorz();

  // ① 生成 SVG（把操作说明画成图片）
  let svg = `<svg width="990" height="300" xmlns="http://www.w3.org/2000/svg">
<style>text { white-space: pre; word-wrap: break-word; }</style>
<rect width="100%" height="150%" fill="#${cb}"/>
<text fill="#${cf}" text-anchor="middle" dominant-baseline="middle"
      stroke="#000000" stroke-width="1" font-weight="bold">
<tspan x="50%" dy="30%" font-size="100">是否清空黑名单<tspan font-size="30">（${ss.length}）</tspan></tspan>
<tspan x="42%" dy="25%" font-size="60">输入"确认"进行清空</tspan>
<tspan x="50%" dy="20%" font-size="50">输入"名单"打印一份名单到日志</tspan>
<tspan x="50%" dy="20%" font-size="50">输入书籍ID单独移出黑名单<tspan font-size="30">(名单查看)</tspan></tspan>
</text></svg>`;
  svg = java.base64Encode(svg);

  // ② 用验证码弹窗拿到用户输入
  try {
    let ysr = java.getVerificationCode('data:image/svg+xml;base64,' + svg);
    Packages.java.lang.Thread.sleep(100);

    if (ysr == '确认') {
      cache.delete('8xhmd');
      java.toast('\n已清空');
    } else if (ysr == '名单') {
      java.log('\n💔8x黑名单：\n' + ss.join('\n'));
    } else if (/\d{3,}/.test(ysr)) {         // 纯数字 = 书籍 id
      if (ysr in hmd) {
        java.toast('\n已将书籍：' + hmd[ysr] + '\n移除黑名单');
        delete hmd[ysr];
        cache.put('8xhmd', JSON.stringify(hmd), 0);
      } else { java.toast('移出失败'); }
    }
  } catch(err) {
    java.toast('清理面板未打开（可重试）');
  }
}
```

### 3.3 原理

`java.getVerificationCode(imageUrl)` 的语义是：
**「显示一张图，让用户输入图中的内容」** —— 它不关心图是不是真的验证码。

所以：
- 图里画的是「操作说明 + 可选命令」
- 用户输入的是「命令」而不是「验证码字符」
- **零新增 UI，复用了现成的弹窗**

**这是一个通用的「文本输入通道」技巧**，可移植到任何需要用户输入的书源。

### 3.4 注意事项

| 项 | 说明 |
|---|---|
| **返回值类型** | 用户取消时返回 `null` 或空串，必须 `if (!ysr)` 保护 |
| **图必须够大** | 990×300，字号 50~100，太小在手机上模糊 |
| **data URI 支持** | `data:image/svg+xml;base64,` 可直接显示（App 内部用 Glide） |
| **命令要少** | 最多 3~4 个命令，多了用户记不住 |
| **必须给「取消」出口** | 用户点取消时不要报错 |

### 3.5 黑名单的落地：`hmdjib(id, name)`

```js
function hmdjib(id, name) {
  // 返回 true = 该书名命中黑名单 → 列表里过滤掉
  let hmd = JSON.parse(cache.get('8xhmd') || '{}');
  if (hmd[id]) return true;
  // 正则黑名单（用户可填多条，换行分隔）
  let reStr = String(source.getLoginInfoMap()['正则书名黑名单'] || '');
  if (reStr) {
    let lines = reStr.split('\n');
    for (let i = 0; i < lines.length; i++) {
      let r = String(lines[i]).trim();
      if (!r) continue;
      try { if (new RegExp(r).test(name)) return true; } catch(e) {}
    }
  }
  return false;
}
```

**在 `name` 规则里调用**：
```js
let i = hmdjib(id, result);
if (i) result = '';      // ★返回空串 → Legado 自动过滤该条
```

**`result = ''` 就是 Legado 的「过滤」机制**：bookList 解析时名称为空的条目会被丢弃
（`BookList.getSearchItem` 里 `if (name.isBlank()) return null`）。

## 4 SVG 生成封面 `jinghuafm()`（无图也有好看封面）

### 4.1 场景

站点封面经常 404 或画质差。用书名 + 背景色现场画一张 SVG 封面。

### 4.2 核心：把长书名切成多行

```js
function splitString(str) {
  const length = str.length;
  if (length < 15) {
    return length < 9 ? [str] : [str.slice(0,7), str.slice(7)].filter(s => s);
  } else if (length < 20) {
    return [str.slice(0,7), str.slice(7,13), str.slice(13)].filter(s => s);
  } else if (length < 24) {
    return [str.slice(0,7), str.slice(7,13), str.slice(13,18), str.slice(18)].filter(s => s);
  } else {
    return [str.slice(0,7), str.slice(7,13), str.slice(13,18), str.slice(18,22), str.slice(22)].filter(s => s);
  }
}
```

**为什么按 7 字切**：中文书名 7 字一行在封面比例下最舒服（约 1:1.4 的书籍封面）。

### 4.3 逐字排布（支持竖排/艺术字）

```js
function pingString(ss) {
  let rr = '', ii = 0;
  for (let i1 = 0; i1 < ss.length; i1++) {
    let c1 = ss[i1], l2 = c1.length;
    for (let i2 = 0; i2 < l2; i2++) {
      let c2 = c1.charAt(i2);
      rr += `<tspan x="${100 + 180*ii}" y="${180 + 170*(i2+i1)}">${c2}</tspan>`;
      ii++;
    }
  }
  return rr;
}
```

`x` 按行（`ii`）递增，`y` 按字（`i2+i1`）递增 → 形成**竖排艺术字**。

### 4.4 接入 Legado

```js
// ruleBookInfo.coverUrl
let jhf = source.get('8xjhf'), img;
if (jhf == '1') img = jinghuafm();     // 净化模式：返回 data:image/svg+xml;base64,...
else { /* 正常封面 */ }
return img;
```

**Legado 直接支持 `data:image/svg+xml;base64,` 作为封面**（Glide 可渲染 SVG）。
**优点**：零网络请求、永不 404、颜色可配。
**缺点**：占内存（SVG 字符串几 KB）、不支持模糊背景。

### 4.5 配色 `colorz()`

```js
function colorz() {
  let m = source.getLoginInfoMap() || {};
  let cb = String(m['封面背景颜色'] || '').replace('#','') || '151E27';
  let cf = String(m['封面字体颜色'] || '').replace('#','') || 'dddddd';
  // ★reset() 要保留颜色配置，否则重置后封面变默认色
  return [cb, cf];
}
```

**颜色必须让用户可配**：面板里两个 `text` 输入框（`封面背景颜色` / `封面字体颜色`），
值存 `loginInfo`，`reset()` 时保留。

## 5 版本更新检查 `gengxin()`（gitee commits 当更新源）

### 5.1 思路

书源本身也在迭代，用户怎么知道有新版本？
**用 gitee/github 的 commits API 当版本号来源**。

```js
function gengxin() {
  const {java, source} = this;
  let url0 = 'https://gitee.com/lyc486/yuedu2/commits/main/书源/八叉/8x.json?browser_history=0&page=1&per=4';
  let rr0 = java.get(url0, {
    'User-Agent': 'Mozilla/5.0 (Linux; Android 14)',
    'X-Requested-With': 'XMLHttpRequest'
  }).body();
  let gxlrr = [];
  try { gxlrr = com.jayway.jsonpath.JsonPath.read(rr0, '$.list[0:4].title') || []; } catch(e) {}

  // 当前版本号从 exploreUrl 里读（★把版本号写在规则里，改版时一起改）
  let banben = '0';
  try { banben = String(source.exploreUrl).match(/let banben="([\d\.]+)"/)[1]; } catch(e) {}

  // 解析 commit title 形如 "1.8.6-修复xxx"
  let gxlr = String(gxlrr[0] || '').split(/^([^\-]+)-/);
  gxlr[0] == '' ? '' : gxlr = ['', '0', gxlr[0]];

  let gxts;
  if (gxlr[1] > banben) { gxts = ['更新', '0,140,186']; }   // 蓝底「更新」
  else { gxts = ['导入', '76,175,80']; }                     // 绿底「导入」
  // ... 生成 HTML 页面，startBrowser 打开
}
```

### 5.2 三个设计点

1. **版本号写在 `exploreUrl` 里**（`let banben="1.8.6"`）
   好处：改版时只改一处，且 `gengxin()` 能从 `source.exploreUrl` 反查，不用重复维护。
2. **commit title 格式约定 `版本号-说明`**
   用 `split(/^([^\-]+)-/)` 拆出第一段当版本号，字符串比较（`>`）即可。
   ⚠️ 只适合 `1.8.6` 这种**同位数**版本号；跨位数（`1.10` vs `1.9`）字符串比较会错，
   需要补零或转数组比较。
3. **按钮文案随状态变**
   有新版 → 蓝色「更新」；已最新 → 绿色「导入」（可重复导入覆盖）。

### 5.3 替代方案（推荐给新源）

gitee 的 commits API 需要 `X-Requested-With` 头，且返回 HTML（需 JsonPath 提取）。
**更简单**：自己托管一个 `version.json`：
```json
{"version":"1.8.6","url":"https://.../8x.json","note":"修复书架"}
```
书源 `java.get` 直接读，无需 JsonPath。**推荐新源用这个。**

## 6 功能开关矩阵（`bfqfun2` 通用开关）

```js
function bfqfun2(x) {
  let xx = source.get('bx' + x);
  if (xx != 1) { source.put('bx' + x, 1); java.toast('🟢已开启 ' + x); }
  else { source.put('bx' + x, 0); java.toast('⚫已关闭 ' + x); }
}
```

**一个函数管所有开关**：`bfqfun2('下载')` → 存 `bx下载`。

**在规则里读**：
```js
if (source.get('bx下载') == 1) { /* 下载模式 */ }
```

**注意 `!= 1` 而不是 `== 0`**：未设置时 `source.get` 返回 `null`，
`null != 1` 为 true → 走「开启」分支（默认开启）。若想默认关闭要写 `== 1`。

## 9 避坑清单（K1~K14）

| 编号 | 坑 | 症状 | 解法 |
|---|---|---|---|
| **K1** | 书架用 `bid` 拼书籍 URL | 404 | 用 `aid`（`[?&]aid=(\d+)`） |
| **K2** | 深链连发无间隔 | 7 本只进 2~3 本 | `sleep(700)` |
| **K3** | 深链不带 `origin` | 被别的源抢走 | `,{"origin":"{bookSourceUrl}"}` |
| **K4** | 书架不去重 | 每本重复加 N 次 | `seen[id]` 去重 |
| **K5** | POST 不带 `Referer` | 返回「非法请求」 | 带同源 Referer |
| **K6** | 成功判据只认「成功」 | 明明成功却报失败 | 多同义词 + 空响应宽容 |
| **K7** | 移出操作判空响应为失败 | 实际已成功 | 提示「已提交，可核对」 |
| **K8** | `getVerificationCode` 返回值不判空 | 用户取消时报错 | `if (!ysr) return` |
| **K9** | SVG 字号太小 | 手机上看不清 | ≥50px，画布 990×300 |
| **K10** | `result=''` 不生效 | 黑名单书还在 | 必须在 **name** 规则里返回空（不是 author） |
| **K11** | 开关默认值判断反 | 首次用是关闭状态 | `!= 1` 才是「默认开」 |
| **K12** | `reset()` 清掉颜色配置 | 重置后封面变丑 | 保留颜色/账号/网址 |
| **K13** | 版本号字符串比较跨位数 | `1.10 < 1.9` 判错 | 补零或数组比较 |
| **K14** | `gengxin()` 里 `java.get` 第二参写错 | 拿不到 commits | 第二参是 **headers 对象**，不是 URL 选项字符串 |
