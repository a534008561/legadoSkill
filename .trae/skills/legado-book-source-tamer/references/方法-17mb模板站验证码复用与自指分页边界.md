# 方法：17mb 模板站验证码模板复用与自指分页边界（261127 天华书实锤）

## 何时用

目标站属于 17mb/笔趣阁系 SSR 移动模板：搜索 `/s.php` 必带 4 位图形验证码，目录按 `N-section.asp` 分节，正文按 `read-<cid>-N.asp` 分页。典型站点：m.tianhuabooks.com、www.manyanshu.com。

## 一、先确认站点搜索契约

1. 首页 HTML 里 `<script>search();</script>`，真正表单由 `/17mb/scripts/common.js` 的 `search()` 写出：`POST /s.php`，字段 `keyword`。
2. 不带正确验证码时 `/s.php` 返回 200 但只有 `layer.prompt` + `/searchcode.php?t=...`，不是真实结果。
3. 正确链路：`GET /searchcode.php?t=<ts>` 取 190x40 PNG → `POST /s.php` 带 `keyword` + `code`。
4. **不要反复探测搜索频率**；只做一次正确提交验证，书源内固定 3 秒节流即可。

## 二、★同模板验证码库可直接复用

- 天华书与蔓延书城的验证码图同为 **190x40、4 固定槽 x=[0,32]/[40,74]/[88,124]/[136,168]、y=3..39、阈值 L<200、16x24 归一化**，字符池同为 `23456789ABCEFGMNPRSTVYZabcdefghkmnprstuvwxyz`。
- 直接把已训练好的 512 模板 base64（蔓延书城源 `searchUrl` 里的 `TB`）搬到新站，离线 OCR 一次 + 同会话 POST 搜索即可拿到 25 条结果；后续 LT/E 真机 `debug_source`/WS 均识别成功。
- 判定复用的三个硬条件：图片尺寸一致、槽位/阈值切出来字形一致、POST 反证出结果。只满足“看起来像”不能直接照搬。

## 三、★静态 JS 的 zstd 压缩坑（本次新发现）

- 用 `java.ajax('/17mb/scripts/common.js')` 拿到的是**乱码**，不是编码错，而是 `curl -D` 显示 `content-encoding: zstd`；OkHttp/Legado 未按 zstd 解压，拿到的是压缩字节按文本解码。
- 书源 JS 环境没有 zstd 解码器；**不要在书源里解析该 JS**。离线用 `curl` + Python `zstandard.ZstdDecompressor().stream_reader()` 解压后读 `search()` 契约即可（注意 `decompress()` 会因帧头无 content size 报错，必须 stream_reader）。
- 书源本体不请求 common.js，因此该坑不影响成品；它只影响“通过 JS 反推搜索表单”的分析路径。

## 四、★★目录末页「下一页」自指，必须用 baseUrl 指纹截断

- 天华书第 1 页 `.listpage .right a` 指向 `2-section.asp`，但**最后一页仍有一个「下一页」指向自身**（如 `74-section.asp` → `74-section.asp`）。
- 只写 CSS `nextTocUrl` 会无限重复抓末页、目录总数虚高甚至卡死。
- 正解：

```js
"nextTocUrl": "@js:(function(){var h=String(result||'');var m=h.match(/<span class=\"right\"><a href=\"([^\"]+)\"[^>]*>下一页<\\/a><\\/span>/);if(!m)return null;var u=m[1];if(u.charAt(0)==='/')u='https://m.tianhuabooks.com'+u;if(u===String(baseUrl||''))return null;return u;})()"
```

- 这是「内容级判据」而非页码上限：站点以后加章节，新末页自身链接会变化，规则自动继续跟随。

## 五、正文分页与注入脚本

- `nextContentUrl` 只认 `chaper_na5` 文案含「下一页」；末页是「下一章」，必须 `return null`，否则串章。
- `#chapter_con` 内混有 `<div id="p-cache-provider">` + `<script data-path="/scripts/vendor.chunk.js">` + `<div><center>本章未完…</center></div>`，均在正文容器内；`content` 规则先按 `id="chapter_con"` 切到 `class="chapter_an chapter_bottom_an"`，再删 `<script>` 块、p-cache div 和 center 提示。

## 六、发现页越界页是 200 空列表

- 分类/榜单越界页返回 HTTP 200、页面无 `.sort_list_con`，但仍保留「下一页」文案。
- `ruleExplore.bookList` 解析不到条目就返回**空的 java.util.ArrayList**，Legado 自动停止翻页；不要写死 274 页之类上限。

## 七、验收顺序

1. LT：MCP `debug_source` 关键词搜索（OCR 一次）→ 裸 URL 详情 → `++URL` 目录（含末页自指验证）→ `--URL` 正文页 → `::URL` 发现 → `check_source`。
2. E：LAN 1125 `POST /saveBookSource`（单源整体替换，勿读全部源）→ WS 1126 `/bookSourceDebug` 分别发关键词/裸 URL/`++URL`/`--URL`/`::URL`。
3. 大文件（本例 46KB）走 LAN 1122/1125，MCP 单对象不适合塞超长模板库。
