# 音乐书源制作指南（以网易云音乐听书源为蓝本）

> 2026-09-17 从「网易云音乐」听书源（bookSourceType=1，check_source 通过 1/1，debug 全链路实测）提炼的**音乐类书源通用方法论**。覆盖：内容模型设计、音频类型的官方机制（源码级）、播放直链与歌词通道、接口设计套路、发现页组织、登录方案、开箱模板、避坑清单与移植改动表。
>
> **与姊妹文档的分工**：本篇讲「怎么做音乐书源」；加密接口返回空（如网易云 weapi 的 200 空体）怎么办看 [方法-网易云类weapi加密站的明文接口降级方案.md](方法-网易云类weapi加密站的明文接口降级方案.md)；列表返回值协议的跨版本差异看同文 §4；交付校验闭环看 [方法-书源交付质量闭环.md](方法-书源交付质量闭环.md)。

## 0. 一句话总结

音乐书源 = **把「歌单/专辑」当书、「歌曲」当章节、「播放直链」当正文、「歌词」当副文**；`bookSourceType=1` 让 Legado 自动按音频类型（BookType.audio=32）走 AudioPlay 播放器，`ruleContent.content` 直出 URL、`ruleContent.subContent` 塞 LRC 歌词实现播放器同步显示。核心难点不在规则而在**接口层**：播放地址接口的音质参数、直链过期、无版权兜底，以及列表数据的全量补齐（如歌单 trackIds → 批量取名）。

## 1. 适用场景识别

**适合做音乐书源的站点**：

- 有结构化歌曲/歌单数据（JSON API 最佳，HTML 列表页也行）
- 播放地址可匿名或低门槛获取（无需付费墙后的签名）
- 站点核心能力是「单曲 / 歌单（专辑） / 榜单 / 分类 / 搜索」四件套

**典型形态**：

| 形态 | 例子 | 书 = | 章节 = |
|---|---|---|---|
| 云音乐站 | 网易云 / QQ / 酷狗 / 酷我 | 歌单或单曲 | 歌曲 |
| 电台 / 播客 | 喜马拉雅（免费段）/ 蜻蜓 / PodCast | 专辑 | 单集 |
| 个人音乐库 | Navidrome / Subsonic | 歌单或专辑 | 歌曲 |
| 二次元音频 | bilibili 音频区 / Miku 站 | 合集 | 单曲 |

**不适合**：付费墙后才能听全站的（每章都要 VIP 的站点做出来体验极差）、纯 MV 视频站（那是视频源 bookSourceType=2 或 0+video，走 [方法-视频书源完全指南.md](方法-视频书源完全指南.md)）。

## 2. ★内容模型设计（音乐书源的第一步）

Legado 的 Book/Chapter 结构是**强制的两级**，音乐站点天然有两种对象，必须先决策映射：

### 2.1 映射决策表

| 站点对象 | 当「书」 | 当「章节」 | 说明 |
|---|---|---|---|
| 歌单 / 专辑 | ✅ 一本书 | 每首歌一章 | **首选**。章节多=有目录页体验，适合榜单/分类入口 |
| 单曲 | ✅ 一本书（1章） | 唯一歌曲 | 搜索结果可直接当书，点进去 1 章即播 |
| 歌手 / 音乐人 | ✅ 可做书 | 该歌手热门歌曲 | 适合「歌手页」入口；章节=热门曲目 |
| 榜单 | ✅ 一本书 | 榜内歌曲 | 发现页入口天然是榜单 |

**网易云实战的选择**：搜索/每日推荐/新歌的「单曲」→ 1 章的书；榜单/分类/推荐歌单的「歌单」→ N 章的书。详情页用 `init` 规则统一两种 JSON 结构（见 §7）。

### 2.2 字段填法（音乐站特有）

| Legado 字段 | 音乐站填什么 | 网易云实例 |
|---|---|---|
| name | 歌单名 / 歌曲名 | `$.name` |
| author | 歌手（多人用 `/` 或 `,` 连接） | `$.author`（JS 里 `ar.map(a=>a.name).join('/')`） |
| kind | 内容类型标签 | `'单曲'` / `'歌单'`（逗号分隔=多个可点标签） |
| cover | 歌单封面 / 专辑封面 / **歌手头像兜底** | `$.cover` |
| intro | 歌单描述 / **歌词前 500 字当简介** | `$.intro` |
| wordCount | 时长（秒）或曲目数 | `Math.round(dt/1000)+'秒'` / `trackCount+'首'` |
| lastChapter | 更新频率 / 最新曲目 | `$.lastChapter` |
| tocUrl | 目录 API（与详情同址则留空复用） | `""` |

> **封面兜底是音乐站高频坑**：搜索接口的歌曲对象常常**没有专辑封面字段**（网易云 `album.picUrl` 为 null）。解法：取 `artists[0].img1v1Url`（歌手头像）当封面，比空封面好得多。

## 3. ★bookSourceType=1 的官方机制（源码级，音乐书源的地基）

设 `bookSourceType: 1`（听书）后，以下行为**全部自动**，规则里不用写 setType：

| 机制 | 源码位置 | 行为 |
|---|---|---|
| 类型派生 | `BookSource.getBookType()` | 返回 `BookType.audio(32)` |
| 搜索/发现自动设类型 | `BookList.kt:173 / 212` | 列表解析时自动 `book.type = audio` |
| 刷目录重设类型 | `WebBook.kt:306` | `removeAllBookType() + addType(getBookType())`，详情页 init 设的 type 会被冲掉 → **如需动态类型必须在 chapterList 再设一次** |
| 歌词通道 | `BookContent.kt:152` | `book.isAudio → bookChapter.putLyric(subContent)` → **`ruleContent.subContent` 的返回值就是 LRC 歌词**，AudioPlay 播放时同步滚动显示 |
| 跳过净化 | `BookContent.kt:243` | `isAudio` 时**跳过 HtmlFormatter HTML 净化**（正文本来就是纯 URL） |
| ⚠️ replaceRegex 仍执行 | `BookContent.kt:171` | 且**逐行 trim** → 音频源写 replaceRegex 会把播放 URL 切断或吃掉协议头 |

### 3.1 三条铁律

1. **音频源的 `ruleContent.replaceRegex` 必须留空**。正文是 `https://...mp3`，任何正则清理都可能破坏 URL。
2. **正文 content 就是播放 URL 纯文本**，不要包 HTML/JSON，不要带引号换行。AudioPlay 直接拿 `content.trim()` 当 `durPlayUrl`。
3. **tocUrl 留空可省一次请求**：`BookInfo.kt:158-160` tocUrl 为空时 `book.tocUrl = baseUrl` 且 `tocHtml = body`；`WebBook.kt:312` 目录阶段 `bookUrl == tocUrl && tocHtml 非空` → 直接复用详情响应，不再发请求。**详情和目录是同一个 API 时必用**。

### 3.2 音乐源 vs 有声小说源（都是 bookSourceType=1）

| | 音乐源 | 有声小说源 |
|---|---|---|
| 章节数 | 歌单 N 首 = N 章 | 小说 N 章 |
| 章节名 | `歌曲名 - 歌手` | 章节标题 |
| 正文 | 播放 URL（约 30 分钟过期） | 播放 URL（通常长期有效） |
| 副文 | **LRC 歌词（subContent）** | 一般无 |
| 音质 | br 参数可切（320000/128000） | 通常固定 |
| 缓存友好度 | 低（URL 过期快） | 高 |

**直链过期是音乐源特有的设计点**：网易云播放地址 URL 路径含时间戳，约 30 分钟失效。Legado 的章节缓存按 URL 存，过期后播不动。解法：**不做特殊处理**——用户重新进入章节会重走 content 规则取新链；若需要在播放中刷新，可在 `callBackJs` 里按时间戳判断（参考视频书源的跟随机制）。

## 4. ★列表规则返回值协议（LT 版，列表大小为 0 查这里）

**`AnalyzeRule.kt:478-507` 源码实锤**：`getElements()` 对 @js 规则的返回值只接受 `List<*>` / `Array<*>` / `NativeArray`：

```kotlin
when (val value = result) {
    is List<*> -> ...
    is Array<*> -> ...
    is NativeArray -> ...
}
return ArrayList()   // ← String 落到这里，列表大小 0，静默无结果
```

- ❌ `return JSON.stringify(out)` → debug 日志「列表大小:0」「书籍总数:0」
- ✅ `return out`（JS 数组）→ item 是 NativeObject，字段规则 `$.name` / `$.author` 直取

**适用字段**：`ruleSearch.bookList` / `ruleToc.chapterList` / `ruleExplore.bookList`。

**E 版（legado-E/Lyc）相反**：`getString` 对 NativeObject 无 Mode.Js 分支，需要列表返回 **JSON 字符串数组**。只做 LegadoTeam（官方）版 → return JS 数组 + 纯键名 JSONPath 字段；要双版本兼容见 [方法-legado各版本行为差异对照.md](方法-legado各版本行为差异对照.md)。

**init 规则相反**：`BookInfo.kt:75` init 用 `getElement`（单数），返回 **String 是正确的**（setContent 替换全部内容）。别把两套协议搞混。

## 5. ★Rhino 的 java.lang.String 没有 .length 属性

所有 Java 方法返回的字符串（`BigInteger.toString()`、jsoup `.text()/.html()/.attr()`、`java.ajax()` 的返回值）在 Rhino 里是 **java.lang.String**，只有 `length()` 方法、没有 `.length` 字段：

```js
var enc = b.modPow(e, n).toString(16);   // java String
enc.length        // undefined
enc.length < 256  // NaN < 256 = false → 补零循环一次都不执行
```

**统一对策**：所有 Java 返回字符串先用 `String()` 包裹再操作。`String(s).replace(正则, 串)` 也避免了 jsoup 字符串的「选择不明确 char,CharSequence」重载报错。

`String(s).getBytes('UTF-8')` 在 Rhino 里**不存在**（java.lang.String 的 getBytes(String) 不被识别），要字节数组用：
```js
new Packages.java.lang.String(String(s)).getBytes(Packages.java.nio.charset.Charset.forName('UTF-8'))
```

## 6. 播放直链的获取与兜底

### 6.1 URL 模式与音质参数

音乐站播放接口通常是 `?ids=[N]&br=音质`：

| 站 | 接口 | 音质参数 |
|---|---|---|
| 网易云 | `/api/song/enhance/player/url?ids=[N]&br=320000` | 320000/192000/128000；VIP 歌高 br 也返回标准音质（不会因 br 失败） |

**音质降级兜底模板**（320k 取不到降 128k）：
```js
@js:(function(){
  var j = JSON.parse(String(result));
  var d = (j.data && j.data[0]) || null;
  if (!d) throw new Error('播放地址获取失败');
  if (!d.url) {
    try {
      var fb = String(java.ajax('…/player/url?ids=[' + d.id + ']&br=128000'));
      var fd = (JSON.parse(fb).data || [])[0];
      if (fd && fd.url) return fd.url;
    } catch (e) {}
    var msg = '歌曲不可播放: ';
    if (d.code == 404 || d.code == -110) msg += '无版权或VIP专享, 可尝试登录';
    else msg += 'code=' + d.code;
    throw new Error(msg);   // ← 明确提示比静默空正文好一万倍
  }
  return d.url;
})()
```

### 6.2 播放器拉流的两个事实

1. **AudioPlay/ExoPlayer 不带 Legado 的 Cookie**：`setCookie()` 只在 `getResponseAwait`/`executeStrRequest`/`getMediaItem` 路径调用，音频正文走 `durPlayUrl` 直拉。如果播放直链需要登录态/Cookie 防盗链，必须 `java.getCookie(域名)` 手动拼进 URL 选项的 headers（网易云直链不校验 Referer，无需此步）。
2. **直链 CDN 通常不校验 Referer**（网易云 m702/m801），播放器裸拉即可。

### 6.3 无版权 / VIP 的用户体验设计

不要返回空正文（用户只看到「内容为空」不知道为啥）。**`throw new Error(中文原因)`** 会在阅读界面显示出来：
- `无版权或VIP专享, 可尝试登录`
- `播放地址获取失败 code=xxx`

## 7. ★init 规则统一多形态详情

音乐站详情页 API 常常一个端点返回多种结构（单曲 JSON / 歌单 JSON）。`BookInfo.kt:75`：init 返回值 `setContent(...)` **替换掉整个内容**，后续字段从新内容解析。

```js
@js:(function(){
  var j = JSON.parse(String(result));
  if (j.playlist)  return JSON.stringify(plOut(j.playlist));    // 歌单
  if (j.songs && j.songs.length) return JSON.stringify(songOut(j.songs[0])); // 单曲
  return JSON.stringify({name:'未知', author:'', kind:'', cover:'', intro:'…'});
})()
```

输出统一扁平 JSON 后，字段规则全用 `$.name` / `$.author` / `$.intro` 纯 JSONPath（双版本兼容，E 版也能取）。

**歌词当简介**：单曲详情可在 init 里就取一次歌词接口，`txt.replace(/\[[^\]]*\]/g,'')` 去时间轴后截前 500 字当 intro——详情页立刻有内容，不用等播放。

## 8. 歌单全曲目补齐（音乐站特有的大数据坑）

**问题**：歌单详情接口的 `tracks` 常常只给前 10 首（网易云 v6 接口），但 `trackIds` 数组给全量 ID。直接出目录会丢歌。

**解法**：trackIds 全量 + 每批 ≤50 个调「批量歌曲信息」接口补名：

```js
var known = {};
(pl.tracks||[]).forEach(function(t){ known[t.id] = mkName(t); });
var ids = (pl.trackIds||[]).map(function(t){ return t.id; });
var unknown = ids.filter(function(i){ return !known[i]; });
for (var i = 0; i < unknown.length; i += 50) {
  var cs = unknown.slice(i, i+50).map(function(x){ return {id: x}; });
  var rr = String(java.ajax('…/api/v3/song/detail?c=' + java.encodeURI(JSON.stringify(cs))));
  JSON.parse(rr).songs.forEach(function(s){ known[s.id] = mkName(s); });
}
// 225 曲歌单 = 5 次批量请求 ≈ 10s，一次性补齐
```

**分页替代方案**：如果站点支持 offset 翻页且 trackIds 不给全量，用 `nextTocUrl` 链式分页（参考小说目录分页做法）。

## 9. 接口设计套路（音乐站通用清单）

一个完整音乐书源需要的接口能力，按 Legado 流程对齐：

| Legado 流程 | 需要的接口 | 网易云实例 |
|---|---|---|
| 搜索 | `search?s=词&type=1&limit=N&offset=(page-1)*N` | `/api/search/get` |
| 详情（单曲） | `song/detail?c=[{id}]` | `/api/v3/song/detail` |
| 详情（歌单） | `playlist/detail?id=N` | `/api/v6/playlist/detail` |
| 目录补名 | 批量 `song/detail?c=[{id1},{id2}…]` 每批 ≤50 | 同上 |
| 正文（播放地址） | `player/url?ids=[N]&br=音质` | `/api/song/enhance/player/url` |
| 副文（歌词） | `song/lyric?id=N` | `/api/song/lyric` |
| 发现-榜单 | `toplist` | `/api/toplist` |
| 发现-推荐 | `personalized/playlist?limit=N` | `/api/personalized/playlist` |
| 发现-分类 | `playlist/list?cat=分类&limit=N&offset=N` | `/api/playlist/list` |
| 发现-新歌 | `discovery/new/songs?areaId=0` | `/api/discovery/new/songs` |
| 登录态 | `nuser/account/get` | `/api/nuser/account/get` |

**通用规律**：
- 分页几乎全是 `offset`（偏移量）模式，不是页码 → `{{(page-1)*limit}}`
- `c` / `cat` 等含 `[{` 或中文的参数必须 `java.encodeURI()` 编码
- 搜索 type 参数常区分单曲/歌单/专辑（网易云 type=1 单曲 / 1000 歌单 / 10 专辑）→ **搜索歌单要改 type，否则搜不到歌单书**
- 批量接口上限普遍 50（网易云）/ 100，超了分批

## 10. 发现页组织（ExploreKind）

发现页用 `exploreUrl` 的 `<js>` 运行时生成 JSON 数组。音乐站的标准布局：

```js
(function(){
  var items = [];
  // 分组标题行（url 缺省 = 整行不可点）
  items.push({title: '每日精选', url: '', style: {layout_flexBasisPercent: 1, layout_wrapBefore: true}});
  items.push({title: '官方榜单', url: base + 'toplist'});
  items.push({title: '推荐歌单', url: base + 'personalized/playlist?limit=30'});
  items.push({title: '每日推荐', url: base + 'v3/discovery/recommend/songs'});
  items.push({title: '新歌速递', url: base + 'discovery/new/songs?areaId=0&limit=30'});
  items.push({title: '歌单分类', url: '', style: {layout_flexBasisPercent: 1, layout_wrapBefore: true}});
  var cats = ['华语','流行','摇滚','民谣','电子','说唱','古风','ACG',…];
  for (var i = 0; i < cats.length; i++) {
    items.push({title: cats[i], url: base + 'playlist/list?cat=' + java.encodeURI(cats[i]) + '&limit=30&offset={{(page-1)*30}}'});
  }
  return JSON.stringify(items);
})()
```

**要点**：
- `offset={{(page-1)*30}}` 留给 AnalyzeUrl 二次求值（`{{}}` 每次请求都求值，天然支持翻页）
- 中文分类名必须 `java.encodeURI`
- `ruleExplore.bookList` 用 `baseUrl.indexOf('/api/xxx')` 分支按入口选解析模板（一个 JS 自适应多接口）
- 分组标题行 = `url` 为空 + `layout_flexBasisPercent: 1`

## 11. 登录方案：Cookie 粘贴优先

音乐站登录的**唯一稳路是 Cookie 粘贴**（密码登录接口多半走加密且被站点风控）：

```js
function loginByCookie() {
  var ck = String(result.get('Cookie') || '').trim();
  if (!ck) { java.longToast('请粘贴Cookie(含MUSIC_U)'); return; }
  source.putLoginHeader(JSON.stringify({Cookie: ck}));   // 自动写 CookieStore
  checkLogin();
}
function checkLogin() {
  var j = JSON.parse(String(java.ajax('…/api/nuser/account/get')));
  if (j.code == 200 && j.profile) java.longToast('已登录: ' + j.profile.nickname);
  else java.longToast('未登录或登录已过期(不影响匿名搜索/播放)');
}
function logout() { source.removeLoginHeader(); java.longToast('已退出登录'); }
```

**机制**：`BaseSource.kt:235 putLoginHeader(json)` 内部 `CookieStore.replaceCookie`，`enabledCookieJar: true` 后所有同站请求自动携带。

**loginUi 四件套**：Cookie 粘贴框 / 手机号+密码（标注「可能被拦截，空响应时引导改 Cookie」）/ 检查登录状态 / 退出登录。

**loginCheckJs 兜底**（响应拦截器，`result` 是 StrResponse，必须原样 return）：
```js
(function(){
  var b = result.body;
  if (typeof b === 'function') b = b.call(result);   // 版本双兼容
  b = String(b || '');
  if (b.length < 1) throw new Error('接口返回空: 疑似IP受限, 请稍后重试');
  if (/频繁|限制|稍后|frequent|blocked/i.test(b)) throw new Error('触发频率限制, 请稍候再试');
  return result;
})()
```

## 12. 加密接口的降级原则（详见姊妹文档）

音乐大站普遍有加密接口（网易云 weapi / QQ 的 sign）。**如果加密 POST 返回 200 空体（content-length:0），先怀疑站点策略层秒拒，不要怀疑算法**：

1. 用**固定密钥双向验证**（真机 JS 出密文 → Python 反解）证明算法正确
2. 沙盒与真机各测一遍（都空 = 策略，不是 IP 信誉）
3. 找**同域明文 GET 镜像接口**（网易云的 `/api/` 全活，且数据往往更全，如 trackIds）
4. 整体降级到明文接口，登录改 Cookie 粘贴

完整方案与加密实现（AES 双层 + RSA modPow，已验证 100% 正确留作备用）见 [方法-网易云类weapi加密站的明文接口降级方案.md](方法-网易云类weapi加密站的明文接口降级方案.md)。

**加密能力本身可用**（做其它站时直接抄）：
- `java.createSymmetricCrypto('AES/CBC/PKCS5Padding', key, iv).encryptBase64(明文)` 与 CryptoJS AES-CBC-PKCS7 **逐字节一致**
- RSA：`new Packages.java.math.BigInteger(hex,16).modPow(e,n).toString(16)` → `String()` 包裹后补前导零到 256 位

## 14. 避坑清单

| # | 坑 | 对策 |
|---|---|---|
| K1 | @js 列表规则 `return JSON.stringify(out)` → 列表大小 0 | return JS 数组（getElements 只认 List/Array/NativeArray） |
| K2 | Java 返回字符串 `.length` 是 undefined → 补零/截断/长度判断全失效 | `String()` 包裹 |
| K3 | 音频源写 replaceRegex → 播放 URL 被逐行 trim 切断 | 音频源 replaceRegex 必须空 |
| K4 | 播放需要 Cookie 防盗链但播放器不带 Cookie | `java.getCookie(域)` 手动拼进 URL 选项 headers |
| K5 | 搜索结果歌曲对象无专辑封面（null） | `artists[0].img1v1Url` 歌手头像兜底 |
| K6 | 歌单 tracks 只有 10 首 | trackIds 全量 + 每批 ≤50 批量补名 |
| K7 | `c=[{...}]` / 中文 cat 参数未编码 | `java.encodeURI(JSON.stringify(...))` |
| K8 | 搜索只搜单曲搜不到歌单 | 搜索接口的 type 参数改歌单值（网易云 type=1000），或发现页给歌单入口 |
| K9 | 播放直链 30 分钟过期导致缓存失效 | 不特殊处理，重进章节自动取新链；别缓存 URL |
| K10 | 无版权/VIP 歌返回空正文用户不知所云 | `throw new Error('无版权或VIP专享, 可尝试登录')` |
| K11 | 密码登录走加密接口被站点 200 空体 | Cookie 粘贴（putLoginHeader 自动写 CookieStore） |
| K12 | loginCheckJs 里 `result.body` 是方法引用 | `typeof b==='function' && (b=b.call(result))` 双兼容 |
| K13 | bookUrlPattern 误匹配搜索/榜单 URL → 列表按详情页解析全垮 | 只匹配 detail 路径 |
| K14 | 详情和目录同 API 发了两次请求 | tocUrl 留空 → tocHtml 复用（WebBook.kt:312） |
| K15 | init 返回 String 以为错了（bookList 要数组） | init 用 getElement 单数，String 是正确的；两套协议别混 |
| K16 | 章节名只有歌名没歌手 | `歌曲名 - 歌手1/歌手2` 拼接，目录可读性 ×3 |
| K17 | 字节数组用 `String(s).getBytes('UTF-8')` 报找不到方法 | `new Packages.java.lang.String(s).getBytes(Charset.forName('UTF-8'))` |
| K18 | 登录 UI 填了密码但 toast 显示空（weapi 空响应） | `if (!r) toast('weapi返回空, 改用Cookie')` 显式判空 |
| K19 | 发现页分类中文未编码导致 404 | exploreUrl 的 `<js>` 里 `java.encodeURI(cats[i])` |
| K20 | 刷目录后 book.type 被冲掉（init 设的 type 失效） | chapterList 的 @js 里按需再 setType（纯音频源靠 bookSourceType 自动设，无需） |

## 15. 验证方法论

1. **接口可用性**：沙盒 urllib 与真机 `java.ajax` 各测一遍（响应时间差异本身是信息：网易云沙盒 5.5s vs 真机 0.2s）
2. **列表协议**：eval_js 里 `new AnalyzeRule().setContent(真实响应).getElements('规则')`，看 `r.length` 是否等于预期条数（0 = 查 K1）
3. **字段提取**：`ar.getString('$.name')` 逐字段验证 NativeObject 取值
4. **全链路**：debug_source 四前缀（关键词=搜索 / 绝对 URL=详情 / `++`URL=目录 / `--`URL=正文 / `::`URL=发现）
5. **音频特有验证**：正文规则返回值必须是**纯 URL 字符串**且 `String(result).indexOf('http')===0`；真机播放听一下（subContent 歌词是否同步滚动只能真机看）
6. **官方校验**：check_source 通过 1/1
7. **交付闭环**：save_source 后 eval_js 用 `source.getRuleToc()/getContentRule()` 回读规则 + 逐字段 md5 比对（save_source 是整体替换语义，回显成功 ≠ 内容正确）

## 18. 通用结论

1. **音乐书源的本质是「内容模型映射 + 接口对接」**，规则复杂度低于小说站（无字体反爬、无正文净化、无分页），难点全在播放地址接口的健壮性（过期/音质/无版权兜底）
2. **`bookSourceType=1` 的音频机制是全自动的**：类型派生、歌词通道、跳过净化都由 isAudio 驱动，规则侧只需 content 出 URL、subContent 出 LRC、replaceRegex 留空
3. **列表返回 JS 数组、字段用纯键名 JSONPath** 是 LT 版唯一稳写法（getElements 丢弃 String）
4. **所有 Java 返回字符串一律 `String()` 包裹**（Rhino 的 .length 是 undefined）
5. **无版权/VIP 用 throw 中文提示**，不要返回空正文
6. **登录 Cookie 粘贴优先**，密码登录接口被风控时立即降级，UI 明确引导
7. **直链过期不用治**，重进章节自愈；要治就在 callBackJs 里按时间戳刷
8. **明文接口优先于加密接口**：数据往往一样全（甚至更全），维护成本低一个数量级
