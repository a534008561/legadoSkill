# 方法：家族级隐患批量修复 与 落库前三重门禁

> 来源：261116 在追书大全交付后，对其同后端兄弟源（猫眼看书 / 全民小说）批量修隐患的全过程。
> 本轮新踩到的坑全部有实机数据支撑，其中 3 个是**我自己在修复过程中引入的回归**，
> 由门禁抓出。结论：改书源必须有「推送前门禁」，不能只靠 check_source 事后看。

## 一、隐患清单（同后端家族共用，逐项已实测定性）

| # | 隐患 | 实锤现象 | 根因 | 对策 |
|---|---|---|---|---|
| 1 | **同后端兄弟源共用同一 `bookSourceUrl`** | 制作追书大全时一次 `save_source` 把「📖 全民小说」**整条源静默覆盖**（Legado 以 bookSourceUrl 为主键） | 主键即身份，导入/保存=原地替换 | 每个源用**互不相同**的主键（追书改用官网 `https://xsxsapp.com/zsdq`）；推送前做主键体检（见三-1） |
| 2 | 短 `book_id` 死链 | `v4//396.html` → `code:0 书籍ID错误`，某页 42 本里 11 本死链 | `id.slice(0,-3)` 在 len(id)<=3 时得空串 | `DPRE()/DPATH()`：>=5 位去末3位 / 4 位取首位 / <=3 位补 `0`；非数字 id 丢弃 |
| 3 | **详情明文残片形态不止一种** | 《正义的使命》(3057) 书名/作者/封面全空、目录 0，`ajax(undefined,{...})` | 首块被 IV 覆盖后残片可能以 `"related_data":...` 开头（**前面没有逗号**），`F()` 的候选前缀都不带逗号 → 全部解析失败返回 null；而 init 在**字符串**上赋 `x.tocUrl` 是静默 no-op → 发出 `"undefined,{...}"` 请求 | ①`F()` 前缀候选补「以逗号结尾的填充键」（`{"_f":1,`、`{"book_id":1,`）；②init 解析不出对象时**用正则从明文抠字段**兜底；③`tocUrl` 先落**局部变量**再赋值 |
| 4 | `P2/P8` 内部 `JSON.parse` 未保护 | `check_source` 直接判源失败：`SyntaxError ... at P2 的 JSON.parse 行`；上游偶发返回 gzip 裸字节/错误页即触发 | 异常穿透规则链，比返回空更严重（整源被判失效） | `P2/P8` 全程 try/catch 返回 null，让上层走兜底；init/chapterList 各再包一层 |
| 5 | **源里手写 `Accept-Encoding`** | 给三源加 `Accept-Encoding: identity` 后，猫眼 `check_source` 立刻变「发现失效」 | CDN **无视 identity 照样 gzip**（实测猫眼 UA：带 identity 仍返回 `1f 8b` 104023B），而手写该头会**关闭 OkHttp 透明解压**；该 CDN 是否 gzip 取决于 UA（iPhone/微信 UA 与裸请求=明文，okhttp/三星 UA=gzip） | **绝不由源设置 Accept-Encoding**，交回客户端 gzip+自动解压；源侧只做「非 JSON 响应体判空」兜底 |
| 6 | 翻页终止**状态键含页码** | 真实管线 p3 仍返回 60 条（该停不停） | 状态键用 `indexOf('.html')` 截断，把 `/3` 留在 key 里 → 每页各存一份状态 → 永远比不到上一页 | 键只截到**最后一个 `/`**（丢掉 `{page}.html` 段），并按「完整页 URL」取页码（截断串过不了 `\.html$` 正则） |
| 7 | 缺 `bookUrlPattern` | 发现页空列表时 Legado 回退「按详情页解析」，收下**幽灵书**（书名=分类、链接=`v4/0/3.html`） | 空列表回退路径没有详情 URL 合法性校验 | 补 `bookUrlPattern` 后回退条目被判非法丢弃 → 干净的「书籍总数:0」 |

## 二、修隐患时我自己写坏的三处（都由门禁当场抓出）

1. **全局字符替换写坏 jsLib**：为清理"多余转义"做了 `s.replace("\\'","'")`，
   连带把括号配平里合法的 `'\\'`（反斜杠字面量）改成 `'\''` → 三个源的 jsLib 全部语法损坏。
   ⇒ **纪律：修补书源禁止对全文做字符级替换**；改成「heredoc 整段重写目标函数 + 逐处断言 + 与干净基线比对」。
2. **模板占位符笔误**：`'%s_LIST' % 'ME_LIST'` → 生成 `ME_LIST_LIST`；`@@L@@_LIST` 同理会变 `ZD_LIST_LIST`。
   ⇒ 占位符要么整个函数名替换，要么只替换前缀变量，不可与后缀字符串拼接。
3. **Python 变量名笔误**（`OLD` vs `OLD_HEAD`）导致补丁脚本中断，但**后续推送脚本照常执行**，
   于是把"没打上补丁的旧版"推给了两台设备。
   ⇒ 修补与推送必须是**同一个原子流程**（或推送前重新断言文件内容），不能分两个脚本各跑各的。

## 三、落库前三重门禁（本轮全部实际用到）

> 第一道 + 部分第三道已固化为可执行工具：**`scripts/source_lint.py`**
>
> ```bash
> # 静态检查（G1 主键互撞 / G2 Accept-Encoding / G3 占位符笔误 / G4 未定义函数 /
> #            G5 slice(0,-N) 无位数边界 / G6 状态键含页码·缺 pattern·缺节流 / G7 顶层 return）
> python3 scripts/source_lint.py 源A.json 源B.json 源C.json
> # 附带真机主键占用体检（异名占用即判失败）
> python3 scripts/source_lint.py --devices http://192.168.10.2:1122,http://192.168.10.2:1125 源A.json
> ```
>
> 该工具已按「正向零误报 + 反向全召回」双向自测：对追书大全/全民小说/猫眼看书三份成品全部通过；
> 对逐个注入 7 类真实缺陷的坏源全部报错。**门禁工具的误报会逼人绕过它，漏报比没有更危险，两者都必须测。**

### 1) 主键体检 preflight（推送前，防覆盖别人的源）

```python
# 对每个待推送文件：读目标设备该主键现有源；同名=更新(安全)，异名=冲突(禁止盲推)
GET {base}/getBookSource?url={quote(obj['bookSourceUrl'])}   # LT 1122 带 x-legado-token / E 1125 免 token
→ data 为空        : 新增，安全
→ 名称与本次一致   : 更新本源，安全
→ 名称不同         : ✗ 主键被占用，直接推送会静默删掉对方源
```

### 2) Rhino 编译门禁（真机语法，比肉眼看可靠）

对**已落库**源逐段 `@js:` / `<js>` 做「只编译不执行」：

```js
try{ new Function(jsBody) }catch(e){ /* 语法错误 */ }   // 构造即编译，不发请求、无副作用
```
覆盖 `jsLib` + 五组规则每个字段 + `exploreUrl` + `loginUrl`。本轮实测：能当场抓出 `ME_LIST_LIST`
之外的全部引号/转义类错误（追书 16 段、全民 16 段、猫眼 15 段，最终 0 失败）。
注意：`eval_js` 里 `source.evalJS(...)` 不可调用（InternalError 找不到方法），但 jsLib 函数是直接绑定的。

### 3) check_source + 真实管线功能验证

`check_source` 只能证明"结构可用"；本轮 6 类隐患里只有 #4、#5 会被它抓到，
#2/#3/#6/#7 都必须**真机链路**才暴露。因此固定四项实测：
- 短 id / 4 位 id / 长 id 各一本跑详情→目录→正文；
- 发现页跨页：先「已看过 p2」再实测 p3 应为 `书籍总数:0`（**不能只靠 mock**，见 §四-2）；
- 反向用例：内容不同的相邻页必须继续出数据；同页连调不得终止；
- 多引擎验证时**每个引擎用不同的书**（见 §四-3）。

## 四、本轮三个新的测试方法论（都是"测试本身骗了我"）

1. **别用 `java.ajax(u+',{"timeout":...}')` 的返回值形态判成功**：要断言 `charAt(0)==='{'` 与
   `JSON.parse` 可解析，否则会像 #5 那样把 gzip 裸字节当"正常响应"继续跑。
2. **跨页/跨调用状态的验证必须走真实管线**：mock 里我共用一个 store，把 #6（键含页码）完美掩盖了；
   真实管线一验就露。⇒ 凡"跨请求状态"逻辑，测试要模拟真实调用方（换 URL、换页码、重开进程）。
3. **E 版正文缓存按 bookUrl 存盘，跨 origin 复用**：多引擎矩阵若用同一批书，
   第一个引擎做真实抓取，后面的引擎读缓存 → 出现「A 引擎失败、B 引擎通过同一本书」的假象，
   极易误判成引擎/规则差异（本轮就因此多绕了两轮）。⇒ **每引擎换不同的书**。
4. 顺带：`/refreshToc` 返回整本目录（数千章），批量脚本要即时释放响应体，否则沙盒会被 OOM 杀掉（signal 9）。
