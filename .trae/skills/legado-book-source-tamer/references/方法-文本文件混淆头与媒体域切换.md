# 方法-文本文件混淆头与媒体域切换

> 来源：ACFAN v16 修复（2026-10-07）。用户反馈「小说正文只显示标题 / 有声小说不播放 / 有声调起视频播放 / 视频不播放」，
> 排查后发现三类新的跨站可复用问题：①文本文件带混淆头（网页能读、规则读到乱码）
> ②同一资源存在多个域，`playPath` 域 403 而 `mp4Domain` 域可用 ③JS 字符串拼装缺引号导致整段脚本静默失效。
> 附「H5 发现页按站点分类体系重建」的方法。

---

## 0 一句话总结

**站点给的「文件地址」和「能用的文件地址」可能不是同一个**——同一份 txt/mp3 在 `playPath` 域返回 403，
在 `mp4Domain` 域正常。且文本文件常带**混淆头**（网页 JS 会跳过，规则直读必乱码）。
排查口诀：**先对比「网页读到的内容」与「规则读到的内容」，不一致就怀疑①头②域。**

## 1 现象谱系

### 1.1 文本文件带混淆头

| 表现 | 说明 |
|---|---|
| 网页阅读正常，书源读到乱码 | 文件头有站点自加的混淆字节 |
| `info` 字段只有几百字（预览） | 完整正文在独立的 .txt 文件里 |
| 文件 GBK/UTF-8 严格解码都失败 | 因为前 N 字节不是合法文本 |

**ACFAN 实测**：每个 .txt = **101 字节混淆头 + UTF-8 正文**
- 头部前 4 字节固定 `a3c1a3c1`（GBK 解码为「ＡＡＡ」）
- 实测三个章节（15631 / 14018 / 111863 字节）**偏移都是 101**
- 头部内容疑似字数统计等元数据（非正文）

### 1.2 同一资源多域（播放地址 403）

| 字段 | 值 | 可用性 |
|---|---|---|
| `playPath` | `https://xxs830.mallnn.xyz/service/novel/xxx.mp3` | ❌ 403 / 16 字节错误 |
| `mp4Domain + fictionUrl` | `https://aevwi.jts3qsek.work/service/novel/xxx.mp3` | ✅ 2097152 字节 ID3 |

★ 两个 URL 的**路径部分完全相同**，只有域名不同。这类「响应里给了两个域」的设计，
必须**逐个实测**，不能默认 `playPath` 可用。

### 1.3 JS 字符串拼装缺引号（视频不播放的真凶）

生成内联 HTML/JS 时，用 `String.fromCharCode(34)` 造引号：

```js
// ✘ 缺右引号 → 生成的 JS 变成 var SRC="https://...;（字符串未闭合）
+'var SRC='+Q+m3u8+';'

// ✔ 引号成对
+'var SRC='+Q+m3u8+Q+';'
```

★ 症状极具迷惑性：**页面能打开、video 元素存在，但整个 `<script>` 因 SyntaxError 不执行**
（浏览器控制台报 `Uncaught SyntaxError: Unexpected identifier 'none'`），
表现为「点了播放没反应」。

## 2 定位法

### 2.1 文本文件：先找「第一个合法 UTF-8 中文字符」

```js
function AC_ftxt(sv,jv,url){
  var r = jv.get(String(url), null, 60000);
  var b = r.bodyAsBytes();
  if(!b || b.length < 10) return '';
  var start = 0;
  for(var i=0;i<b.length-3;i++){
    var b0=b[i]&255, b1=b[i+1]&255, b2=b[i+2]&255;
    // UTF-8 中文：E4-E9 + 80-BF + 80-BF
    if(b0>=0xe4 && b0<=0xe9 && b1>=0x80 && b1<=0xbf && b2>=0x80 && b2<=0xbf){ start=i; break; }
  }
  var sub = Packages.java.util.Arrays.copyOfRange(b, start, b.length);
  return String(new Packages.java.lang.String(sub, 'UTF-8'));
}
```

★ 为什么不用「固定偏移 101」：**不同站点/不同文件头长度会变**。
用「第一个合法 UTF-8 中文」自适应更稳（本站在 101，别站可能在 64/128）。
★ 若正文里本来就有二进制/emoji 混排，可再加护栏（比如要求连续 3 个中文字符）。

### 2.2 多域资源：逐个实测（Python 离线对照）

```python
import urllib.request
for name, url in [
    ('playPath', 'https://xxs830.mallnn.xyz/...'),
    ('mp4Domain','https://aevwi.jts3qsek.work/...'),
]:
    try:
        req = urllib.request.Request(url, headers={'User-Agent':'Mozilla/5.0'})
        data = urllib.request.urlopen(req, timeout=30).read()
        print(f'{name}: {len(data)} bytes, head={data[:4].hex()}')
    except Exception as e:
        print(f'{name}: FAIL {e}')
```

★ 判活要看**内容**（ID3 头 / 正文可读），不是看 HTTP 200（本站 403 前会返回 16 字节 JSON）。

### 2.3 内联 JS 页面：用 `java.webView` 渲染探针

```js
var probe = java.webView(html, baseUrl,
  '(function(){var v=document.getElementById("v");return v?"video-ok":"no-video";})()');
```

★ 探针返回 `video-ok` 只说明 DOM 存在；**要判断脚本是否执行，得看 `msg` 元素内容是否变化**：

```js
// 初始是 "Loading player..."，脚本跑通后会 display:none
'(function(){var m=document.getElementById("msg");return m?m.textContent:"no-msg";})()'
```

★ 探针返回 null 会按 intervals 重试 >30 次（约 25~30s）→ 抛「js执行超时」。
**超时不等于失败**（可能只是还没加载完），要看有没有 SyntaxError 日志。

## 8 补充：标签筛选的数组参数与站点分组（v18 新增）

> 来源：ACFAN v18（2026-10-07）。用户反馈「有声小说有更多分类」+ 需求「增加精选分区」，
> 抓包分析后发现两个通用知识点：①**过滤参数可能是数组**（单数形式无效）②**站点分组接口**的用法。

### 8.1 过滤参数是数组（★最易踩）

**坑**：`tagId=1`（单数）服务端**静默忽略**，返回未过滤的全量列表 → 看起来「参数无效」。
**真相**：抓包显示真实参数是 **`tagIds: [1, 27]`（数组）**。

```json
// 抓包真实请求体
{"tagIds":[29,33,36,37,41],"fictionType":2,"page":1,"pageSize":15}
{"tagIds":[1,27],"fictionType":1,"page":1,"pageSize":15}
```

**验证方法**：单数参数返回全量（和不过滤一样）→ 怀疑参数名/类型错 → **去抓包看真实请求体**。

**多标签语义**：实测是 **AND（交集）**——不同组合返回不同结果：
| 参数 | 结果 |
|---|---|
| `[29]` | 布偶猫 / 百合向高铁... |
| `[29,37]` | 剧情调教... / 睡前故事... |
| `[29,38]` | 乱轮妈妈... / 睡前故事... |

★ 交集语义下，单标签命中数可能为 0（因为必须同时满足所有标签），
**设计分类入口时要用「主标签 + 副标签」组合**（如 `[29,37]` 而非单独 `[37]`）。

### 8.2 双标签体系（tagType）

同一站点的标签接口常按 `tagType` 分多套：

| tagType | 用途 | 数量 |
|---|---|---|
| 1 | 文字小说标签 | 18 个（1学生妹 2处女 7人妻 10调教 11乱伦...） |
| 2 | 有声小说标签 | 15 个（29音频小说 31调教 33人妻 36古典 37乱伦...） |

★ 用法：`GET /api/fiction/other/tagList` → 按 `tagType` 分组 → 分别生成分类入口。

### 8.3 站点分组接口（stations）

**精选类分区的数据源**：`GET /api/station/stations?classifyId=4&pageSize=10&page=N`

| 特性 | 说明 |
|---|---|
| 返回 | 站点数组，每站自带 `videoList`（4~6 个视频） |
| 分页 | `pageSize=10`，p1=10站 / p2=8站（共 18 站） |
| 复用 | `videoList` 的条目结构与视频列表接口**完全一致** → 直接复用现有解析器 |
| 局限 | 只有 `classifyId=4`（精选）有数据；其他 classifyId 返回空 |

```js
// 精选站点入口（j=s:N）
var sidx=parseInt(N,10);
var spage=Math.floor((sidx-1)/10)+1;   // 每页10站
var spos=(sidx-1)%10;
var so=AC_get(sv,jv,'/api/station/stations',AC_q({classifyId:4,pageSize:10,page:spage,restricted:0}));
var st=so.data[spos];
return AC_items(sv,{data:st.videoList,domain:String(so.domain||'')});
```

★ 站点名可能带 emoji/装饰符（如 `⭐必看人气创作者`），显示前要清洗：
```js
var nm=String(names[k]).replace(/^[^\u4e00-\u9fa5A-Za-z0-9]+/,'').substring(0,14);
```

### 8.4 编码冲突（★分支顺序坑）

**踩坑**：新增 `t:` 标签分支时，**旧的 `t:` 热词搜索分支还在**（在 `c:` 和 `n:` 之间），
旧的先匹配 → 新分支永远不执行 → 表现「标签筛选返回 0 条」。

**正解**：
1. 加新分支前先 `grep` 检查该前缀是否已被占用
2. 冲突时给旧功能换前缀（热词搜索从 `t:` 改为 `q:`），**两处都要改**（jsLib 分支 + exploreUrl 编码）
3. 验证：新老功能各跑一次

```js
// 编码分配表（ACFAN v18）
// v:分类:sortType   视频
// c:classId|最新     漫画
// n:ft:st:classId   小说（分类）
// t:tids:ft         小说（标签，tagIds 数组）
// s:idx             精选站点
// q:keyword         热词搜索
```

| # | 坑 | 正解 |
|---|---|---|
| K11 | 过滤参数用单数（`tagId`） | 抓包看真实请求体；数组参数用 `tagIds:[...]` |
| K12 | 交集语义下用单标签做分类 | 用「主+副」组合（`[29,37]`） |
| K13 | 新增 URL 编码前缀不查重 | 先 grep 已有分支；冲突则给旧功能换前缀（两处同改） |

## 9 补充：发现页排布优化（v19）

> 用户反馈「一列直下太长了」→ 根因是**固定 `layout_flexBasisPercent` 列数被 divider 挤成竖排**。

### 9.1 症状与根因

| 写法 | 表现 |
|---|---|
| `style:{layout_flexBasisPercent:0.31}` | 期望 3 列 → **实际被挤成一列直下**（超长） |
| `style:{layout_flexBasisPercent:0.48}` | 期望 2 列 → 同样失效 |
| `style:{layout_flexGrow:1}` | ✅ **自动流式**，按可用宽度自适应列数 |

★ 源码原因（ExploreAdapter + item_find_book.xml）：条目的 divider/margin 会吃掉宽度，
固定 basis 的「百分比」在这种布局下不可靠；**`flexGrow:1` 让条目按内容宽度自动填充**。

### 9.2 正确写法（三段式）

```js
// ① 条目：自动流式（核心）
function row(t,c){R.push({title:t,url:B+c,style:{layout_flexGrow:1}});}
// ② 分区标题：整行 + 换行 + 左对齐
function head(t){R.push({title:t,url:null,
  style:{layout_flexBasisPercent:1,layout_wrapBefore:true,layout_justifySelf:'flex_start'}});}
// ③ 顶部下拉/开关：整行
R.push({title:'分类',type:'select',...,style:{layout_flexBasisPercent:1}});
```

### 9.3 配套：标题长度控制

`flexGrow` 自动流式下，条目宽度由**内容**决定——标题过长会撑开一行。
建议标题 **≤7 个汉字**（或等宽字符）：

```js
// 站点名清洗（去 emoji/装饰符 + 截断）
var nm=String(name).replace(/^[^\u4e00-\u9fa5A-Za-z0-9]+/,'').substring(0,14);
```

| # | 坑 | 正解 |
|---|---|---|
| K15 | 用 `layout_flexBasisPercent:0.31` 想排 3 列 | 改 `layout_flexGrow:1`（固定 basis 会被 divider 挤成竖排） |
| K16 | 分区标题也用 flexGrow | 标题必须 `basis1 + wrapBefore`（整行独占） |
