# 91Hub 模式：本源搜索框 + 可伸缩分组列表

> 全部结论来自 App 源码核对 + 在 39shuwu 上的**真实落地实测**（已跑通）。

---

## 一、核心结论（一句话）

91Hub 的"发现页搜索框 + 点击伸缩"**不是 App 功能，是纯书源数据实现**：

- 搜索框 = `ExploreKind{type:'text'}`
- 搜索按钮 / 折叠条 = `ExploreKind{type:'button', action:'...'}`
- 折叠状态 = `source.setVariable()` 持久化
- 重绘 = `java.refreshExplore()`
- **本源搜索 = `java.searchBook(key, source)`（双参重载）**

## 二、本源搜索的关键 API

### 2.1 源码（RssJsExtensions.kt:74~84）

```kotlin
fun searchBook(key: String, searchScope: String? = null) {   // 单参/两参（String）
    activityRef.get()?.let {
        SearchActivity.start(it, key, searchScope)
    }
}

fun searchBook(key: String, source: BookSource) {            // ★ 双参（BookSource）
    activityRef.get()?.let {
        SearchActivity.start(it, source, key)
    }
}
```

### 2.2 SearchScope 如何锁定单源（SearchScope.kt）

```kotlin
constructor(source: BookSource) : this(
    "${source.bookSourceName.replace(":", "")}::${source.bookSourceUrl}"
)

val isSource: Boolean
    get() = scope.contains("::")
```

`SearchActivity.start(context, source, key)`：

```kotlin
putExtra("searchScope", SearchScope(source).toString())
```

### 2.3 三种写法的范围差异

| 写法 | 搜索范围 |
|---|---|
| `java.searchBook(k)` | 全局（App 设置的范围） |
| `java.searchBook(k, '')` | 全局 |
| `java.searchBook(k, source)` | **只搜本源** ✅ |
| `java.searchBook(k, '源名::https://url/')` | 指定单源（手动构造） |

> 源码注释：
> `//不对单书源的搜索进行缓存，防止下次依旧为单书源搜索（单书源搜索需要每次都指定）`
> —— 单源搜索**不污染**全局设置，每次都要显式传。

## 三、折叠/伸缩的完整机制

### 3.1 折叠条（一个 button）

```javascript
function bar(title, key, defOpen) {
  var js = '(function(){var c={};'
         + 'try{c=JSON.parse(String(source.getVariable()||"{}"))||{};}catch(e){}'
         + 'c.__K__=c.__K__?0:1;'                          // 0/1 翻转
         + 'source.setVariable(JSON.stringify(c));'         // 持久化
         + 'java.refreshExplore();})()';                    // ★ 重绘
  return {
    title: (isOpen(key, defOpen) ? '▼ ' : '▶ ') + title,   // 箭头
    url: '',
    type: 'button',
    action: js.split('__K__').join(key),                   // 把占位符换成真实 key
    style: { layout_flexBasisPercent: 1 }                  // 独占整行
  };
}
```

**三个动作缺一不可**：
1. 读变量 → 2. 翻转写回 → 3. **`java.refreshExplore()`**

少了第 3 步，变量变了但界面不刷新，看起来"点了没反应"。

### 3.2 求值时决定是否渲染子项

```javascript
var cfg = {};
try { cfg = JSON.parse(String(source.getVariable() || '{}')) || {}; } catch(e) {}

function isOpen(key, defOpen) {
  return (cfg[key] === undefined) ? defOpen : (cfg[key] !== 0);
}

ui.push(bar('📖 分类', 'cat', true));      // 默认展开
if (isOpen('cat', true)) {
  for (var i = 0; i < cats.length; i++) ui.push(item(cats[i][0], cats[i][1]));
}

ui.push(bar('🏆 排行榜', 'top', false));   // 默认收起
if (isOpen('top', false)) { ... }
```

**`cfg[key] === undefined ? defOpen : cfg[key] !== 0`** 这个三元很关键：
- 首次访问（无变量）→ 用 `defOpen`
- 点过之后 → 用存储的 0/1

## 五、布局要点

| 元素 | flexBasisPercent | 效果 |
|---|---|---|
| 搜索框 | **0.6** | 占 60% |
| 搜索按钮 | **0.31** | 占 31%（合计 0.91，留余量） |
| 折叠条 | **1.0** | 独占整行 |
| 分类项 | **0.25** | 四列 |

**搜索框 + 按钮必须加起来接近 1 才能并排**，超过 1 会换行。

## 七、常见坑（实测踩过）

| 现象 | 原因 | 修法 |
|---|---|---|
| 点折叠条没反应 | 少了 `java.refreshExplore()` | 必须调用 |
| 折叠状态不保存 | 用了 `infoMap` | 改用 `source.setVariable`（infoMap 只在发现页存活） |
| 搜索变全局 | 用了 `java.searchBook(k)` | 改成 `java.searchBook(k, source)` |
| 输入框和按钮不同行 | flexBasisPercent 合计 > 1 | 0.6 + 0.31 ≈ 0.91 |
| `source.getVariable()` 是 null | 未初始化 | `String(... \|\| '{}')` 兜底 |
| 变量存了但读不到 | 直接给 `source._v` 赋值（测试假象） | 必须走 `setVariable` |
| `@js:` 语法错 | 结尾用了 `return` | 最后一行写表达式（如 `JSON.stringify(ui);`） |
| `source.sourceUrl` 是 undefined | **字段名不对** | 用 `source.bookSourceUrl` 或 `source.key` |

> 最后一条是实测发现：`source.sourceUrl` **不存在**，正确字段是 `bookSourceUrl` / `key`。
> 91Hub 里写 `source.sourceUrl` 实际会走兜底硬编码域名。

## 八、和"App 全局搜索框"的区别

| | App 发现页顶部框 | 书源自带搜索框 |
|---|---|---|
| 位置 | 屏幕顶部（系统 UI） | 书源展开面板内（书源数据） |
| 搜什么 | **书源名称/分组名** | **书源内容（书）** |
| 触发 | 边输边过滤 | 点按钮才搜 |
| 范围 | 全局书源列表 | **仅本源** |
| 可自定义 | 否 | 完全可控 |

**两者可共存**，91Hub 和改造后的 39shuwu 都是两者兼有。
