# 方法：服务端忽略页码参数（假分页）与 `||` 分支空格陷阱

> 源自 m.xhwx8.com（玄幻文学，手机站）书源实战。
> 两个坑都在 **APP 内实测**才暴露，Python 侧看起来完全正常 —— 前者被误判成"规则没写对"，后者表现为"列表有 20 条但书名全空"。

## 0. 一句话结论

1. **`?page=N` 返回 200 + 完整列表 ≠ 分页生效**：必须逐页比对 bookUrl 集合，相同即服务端根本没读这个参数（假分页）。
2. **`||` 或分支里绝对不能有空格**：`a@text || b@text` 会被切成 `a@text ` 与 `b@text`，前者 `@text ` 带尾随空格匹配失败 → 整个 `||` 返回空。

## 1. 假分页：200 + 20 条 ≠ 第 2 页

### 1.1 现象

| 请求 | 状态码 | 条数 | 首条 bookUrl |
|---|---|---|---|
| `/xianxia.html` | 200 | 20 | `book/566527.html` |
| `/xianxia.html?page=2` | 200 | 20 | `book/566527.html` |
| `/xianxia.html?page=3` | 200 | 20 | `book/566527.html` |
| `/xianxia.html?page=592`（站点自称"尾页"） | 200 | 20 | `book/566527.html` |

HTML 里明明印着 `<a href="/xianxia.html?page=2" class="a-btn">下一页</a>`
和 `<a href="/xianxia?page=592">尾页</a>` —— **链接是模板写死的，服务端不处理该参数**。

### 1.2 判据（必须做，否则会白写 nextPage 规则）

```python
def ids(html):
    return re.findall(r'<span class="s2">\s*<a href="([^"]+)"', html)

p1, p2 = ids(get(url)), ids(get(url + "?page=2"))
same = (p1 == p2)          # True → 假分页，服务端忽略 page
```

**不要用**「条数相同」判断 —— 每页 20 条是常态，条数相同不代表内容相同。
**不要用**「首条书名相同」判断 —— 首页置顶可能长期不变，要整集合比对。

### 1.3 排除法清单（本次全部实测失败）

| 尝试 | 结果 |
|---|---|
| `?page=2` / `?page=02` / `?PageNo=2` / `?pageNo=2` / `?p=2` | 全部返回第 1 页 |
| `?page=2&rnd=<随机数>`（绕缓存） | 仍第 1 页 |
| 加 `Referer` / `Cache-Control: no-cache` | 仍第 1 页 |
| `/xianxia_2.html`、`/xianxia/2.html`、`/xianxia/index_2.html` | 前两个 200 但内容仍是第 1 页，第三个 404 |
| PC 站 `www.xhwx8.com/xianxia.html?page=2` | 同样返回第 1 页 |
| 空关键词 POST 搜索 `kw=&page=2` | 0 条（搜索不支持空关键词） |

⇒ 结论：**该站分类列表物理上只有一页（20 本），站点自身功能缺失，书源层无法修复。**

### 1.4 处置策略

1. **不要写 nextPage 规则**（写了也只会拿到重复数据，触发 App 去重后判定"到底了"）。
2. 在 `bookSourceComment` 里写明该限制，避免以后误判为书源 bug。
3. 找**替代入口**补足书量：
   - 热门榜（本次 467 本，单页全量）
   - 排行榜（本次 84 本，7 个分类 tab 同页）
   - 各分类首页（每类 20 本 × 7 类 = 140 本去重后约 120 本）
   - 首页（66 本）
4. 若站点有 sitemap（本次 `sitemap.xml` → 1282 个分片 × 约 485 条 = 全站书目）：
   **sitemap 只有 URL、没有书名**，不能直接做列表规则；
   可作为「随机/最新入库」二次抓取的种子，但要逐条请求详情页，成本极高，一般不做。

## 2. `||` 分支空格陷阱（本次最隐蔽的坑）

### 2.1 现象

发现页 `bookList` 命中 20 条，`name` 却**全部为空**：

```
┌获取书籍列表
└列表大小:20
┌获取书名
└                       ← 空
◇书籍总数:0
```

### 2.2 定位过程（APP 内 eval_js 直接调 AnalyzeRule）

```js
var AR = Packages.io.legado.app.model.analyzeRule.AnalyzeRule;
var r = new AR(null, source, false, false);
r.setContent(item, baseUrl);
r.getString("span.s2 a@text");                    // → 人间至宝   ✓
r.getString("a@text");                            // → 人间至宝   ✓
r.getString("span.s2 a@text || a.black@text");    // → ""        ✗
r.getString("span.s2 a@text || span.s1@text");    // → [仙侠]     ✓（但取错了字段）
r.getString("a.black@text || span.s2 a@text");    // → 人间至宝   ✓（顺序反转就好了）
```

关键对比：**把有值的那支放后面就好了** → 说明是「前半段」被污染。

### 2.3 根因

`RuleAnalyzer.splitRule("||")` 切分后**不做 trim**，
`"span.s2 a@text || a.black@text"` 被切成：

```
"span.s2 a@text "   ← 尾随空格
" a.black@text"     ← 前导空格（这个没事，RuleAnalyzer.trim() 会去掉）
```

尾随空格让最后一段规则变成 `@text `（带空格），
`AnalyzeByJSoup.getResultLast` 的 `when(lastRule)` 里 `"text"` 精确匹配失败 →
走 `else -> element.attr("text ")` → 空字符串。

因为 `||` 是「首个非空即返回」，而第 1 支恒为空、第 2 支才有值，
当第 2 支也取不到时（首页/排行榜没有 `a.black`）整个结果就是空。

### 2.4 铁律

```text
✗ span.s2 a@text || a.popular-title@text || a.black@text
✓ span.s2 a@text||a.popular-title@text||a.black@text
```

**`&&`、`||`、`%%` 三种组合符两侧都不要留空格。**
（`%%` 是并排合并，`&&` 是顺序串联，同样受此影响。）

> 这条与「`:contains()` 不可用」「`:first-child` 不可用」同级，
> 属于**看起来完全合理但一定静默失败**的写法。

## 3. 附：`@js:` 两种合法写法

`@js:` 规则在 Rhino 里被包成函数体执行，**顶层 `return` 非法**：

```
✗ @js:var h=String(src);return h;          → ScriptException: 返回的值无效
✓ @js:(function(){var h=String(src);return h;})()
✓ @js:var h=String(src); h                ← 最后表达式即返回值
```

报错原文（本次实见）：

```
com.script.ScriptException: 返回的值无效
> 1: var h=String(src||"");...;return m?m[1]:null;
   ^ in <script-58> at line number 1 at column number 112
Caused by: org.htmlunit.corejs.javascript.EvaluatorException: 返回的值无效
```

## 4. 附：`nextContentUrl` 三态判定（配合站点"本章未完"标记）

站点每章末尾用 `<p><br />本章未完，点下一页继续阅读。>>></p>` 标记"还有下一页"，
章内分页 URL 是数字后缀 `{chapterId}_2.html`、`_3.html`…

```js
@js:(function(){
  var h=String(src||"");
  if(h.indexOf("本章未完")<0) return null;         // 无标记 → 干净终止
  var u=String(baseUrl||"");
  var m=u.match(/^(.*?)(?:_(\d+))?\.html$/);
  if(!m) return null;
  var n=m[2]?parseInt(m[2],10)+1:2;
  return m[1]+"_"+n+".html";
})()
```

**必须 `return null` 而不是 `""`**（详见《方法-假表单搜索接口与列表内联文本提取》§nextContentUrl）。

实测坑：站点对**超出末页**的 `_N.html` 仍返回 200 + 与末页**逐字节相同**的内容，
所以不能靠"页面是否存在"判断终止，只能靠"本章未完"标记。

## 5. 附：`#nr1@html` + JS 后处理清洗正文

本站正文容器 `#nr1`，广告分四类且**互相嵌套**，纯 CSS 正则 `##...##` 清不干净：

| 广告形态 | 位置 |
|---|---|
| `<p class="pages">您所看到的内容#中间#有#缺失…x#h#w#x#6#.c#o#m</p>` | 正文末尾 |
| `<p><br />本章未完，点下一页继续阅读。>>></p>` | 正文末尾 |
| `「如章节缺失请退#出#阅#读#模#式」` | 正文末尾 |
| `<p>第2章亲戚xhwx6\.c\om(xh/wx/6.看)！</p>` | 正文末尾（**夹在正文段落里**） |
| `榴弹怕水提醒您：…请牢记玄幻文学的域名：https://m.xhwx8.com…` | 部分书末尾整段 |
| `<iclass="lb_top2"><ahref="…">《廓晋》</a>…</i>` | **HTML 残缺**（`<i class=` 的 `x` 被吞），jsoup 解析成畸形文本 |

处理顺序（**顺序不能乱**）：

```js
@js:(function(){
  var h=String(result||"");
  // ① 先删整段大块（含"提醒您/推荐作品"的长段落）
  h=h.replace(/<p[^>]*>[\s\S]*?(榴弹怕水提醒您|向你推荐他的其他作品|最新章节网址)[\s\S]*?<\/p>/g,"");
  // ② 畸形 <iclass="lb_top2"> 推荐位
  h=h.replace(/<i\s*class="lb_top2">[\s\S]*?<\/i>/g,"");
  // ③ pages 提示块
  h=h.replace(/<p class="pages">[\s\S]*?<\/p>/g,"");
  // ④ 本章未完提示块
  h=h.replace(/<p>\s*<br\s*\/?>\s*本章未完[\s\S]*?<\/p>/g,"");
  // ⑤ 含域名/缺失提示的行内广告
  h=h.replace(/<p>[^<]*(xhwx|#中#间#有#缺#失|请退)[^<]*<\/p>/g,"");
  // ⑥ 「…」包裹的提示
  h=h.replace(/「[^」]*」/g,"");
  // ⑦ 去外壳：@html 取的是 innerHTML，不该含闭合 </div>
  h=h.replace(/^<div[^>]*>/,"");
  h=h.replace(/<\/div>[\s\S]*$/,"");     // ← 用 [\s\S]*$ 兜住尾随空行
  // ⑧ 空段落
  h=h.replace(/<p>\s*<\/p>/g,"");
  // ⑨ 站点每章末尾必加的「！」标记（⚠ 必须在删空段落之后）
  h=h.replace(/！\s*<\/p>\s*$/,"</p>");
  return h.trim();
})()
```

### 5.1 两个顺序陷阱

1. **`</div>` 删除要用 `<\\/div>[\\s\\S]*$`**，不能写 `<\/div>\s*$`
   —— innerHTML 尾部常有 `\n \n ` 与空段落，`$` 锚点会失败。
2. **末尾「！」的清理必须在删空段落之后**
   —— 原始结构是 `…心。！</p>\n <p></p>\n \n`，
   `！</p>` 后面还有空段落，`！\s*<\/p>\s*$` 直接匹配会失败。
   先 `replace(/<p>\s*<\/p>/g,"")` 把尾巴清干净，再处理「！」。

### 5.2 整章都是广告时

某些"章节"（如作者公告、填坑节番外）**通篇都是广告文案**，
清洗后长度为 0 → App 抛 `ContentEmptyException: 内容为空`。
这是**正确行为**（比把广告当正文强），不要为了"不报错"而保留广告。

## 6. 附：目录取「第 2 组 ul.chapter」

本站详情页有两个 `<ul class="chapter">`：第一个是「最新章节」6 条，第二个才是全量正文目录。

| 写法 | 结果 |
|---|---|
| `ul.chapter:nth-of-type(2) li` | **101 条** ✓ |
| `ul.chapter:eq(1) li` | 0 条（jsoup 不支持 `:eq`） |
| `ul.chapter:nth-child(2) li` | 0 条（jsoup 的 `nth-child` 按父元素算，此处父级不同） |
| `ul.chapter[1] li` | 0 条（Legado 的 `[1]` 索引必须**在规则末尾**，写中间会被当选择器） |

**结论**：jsoup 里取「第 N 个同类元素」唯一可靠写法是 `:nth-of-type(N)`。

## 7. 本站最终配置要点

```json
"searchUrl": "https://m.xhwx8.com/search,{\"method\":\"POST\",\"body\":\"kw={{key}}&page={{page}}\"}",
"ruleToc": {
  "chapterList": "ul.chapter:nth-of-type(2) li",
  "nextTocUrl": "div.listpage span.right a.onclick@href"
},
"bookUrlPattern": "https?://(?:m|www)\\.xhwx8\\.com/(?:book|[a-z]+)/\\d+\\.html$",
"concurrentRate": "2/1000"
```

- 搜索：**POST /search**，`GET /search?kw=` 返回 200 但 0 条（假成功，极易误判为"搜索无结果"）
- 分页参数 `page` 从 1 开始，`page=13` 起返回 0 条（共 12 页 × 15 条 ≈ 180 条上限）
- 目录分页：`div.listpage span.right a.onclick`，末页该 `<a>` 无 `href`（只有 `class="before"`），
  规则自然取空 → 干净终止
- `bookUrlPattern` 必须只匹配**详情页**（`/book/{id}.html` 或 `/{cat}/{id}.html`），
  不能带 `(?:_\d+)?` —— 否则目录页 `_2.html`、正文页 `/{cat}/{id}/{cid}.html` 也会被当详情页

## 8. 排查顺序 Checklist

发现页出问题时按此顺序，**每步都要实测，不要跳**：

1. `java.ajax(url)` 拿到 HTML → 确认结构存在（`doc.select(...)` 数量）
2. `r.getString(单支规则)` → 逐支验证，**先确认每支单独都能取到**
3. 再拼 `||` → 若拼完为空，**第一个怀疑空格**
4. `?page=2` 比对 bookUrl 集合 → 判真假分页
5. 假分页 → 找替代入口，写进 comment，**不要写 nextPage 规则**
6. 全部通过后 `check_source` 再跑一次
