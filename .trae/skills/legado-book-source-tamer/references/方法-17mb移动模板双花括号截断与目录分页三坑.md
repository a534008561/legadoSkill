# 方法：17mb 移动模板双花括号截断、URL 正则误吞与目录分页三坑

> 来源：2026-11-27 BL小说（blpopo）书源实战。适用 17mb/笔趣阁系移动 SSR 模板（GBK、`/s.php`、`/book/<id>.html`、`/<prefix>/<id>/` 目录）。

## 一、★★`{{}}` 表达式在 Legado 里按首个 `}}` 截断

现象：searchUrl 写成 `{{(function(){try{...}catch(e){}}if(!S){...}...})()}}/s.php`，真机 debug 报
`在函数体后面缺少 "}"`，且报错 source context 停在 `catch(e){` 处。

根因：`AnalyzeUrl.replaceKeyPageJs` 取 `{{...}}` 时是**非贪婪/首个右双花括号**截断，表达式内部任何 `}}` 都会提前结束。
常见触发源：连续 `catch(e){}if(!S){`、`if(x){...}}`、嵌套对象字面量收尾 `}}`。

正解：表达式内**绝不出现相邻 `}}`**，用空格/换行拆开：
```js
try { if(cond)S=source } catch(e) {}
if(!S) { try { S=java } catch(e) {} }
```
离线 `new Function(expr)` 编译通过不代表真机通过；必须跑一次 `debug_source` 搜索验证。

## 二、★`bookUrlPattern` 过宽会把搜索页当详情

现象：搜索请求成功（POST /s.php 拿到 8 条结果），但 debug 打 `≡链接为详情页`，
随后书名/作者全空、`未获取到书籍`。

根因：`bookUrlPattern` 写成 `https?://host/.*`，搜索页 `/s.php` 也命中，
BookList 走「单结果=详情页」兜底分支，搜索列表被完全跳过。

正解：只匹配书详情路径，例如
`https?://(?:www\.|m\.)?blpopo\.(?:com|vip)/book/\d+\.html$`。
章节/目录 URL 不需要进 bookUrlPattern。

## 三、★★17mb 移动模板目录三坑

1. **目录前缀随书 ID 变化**：`/88/88107/` 只是 ID=88107 的前两位；
   ID=119719 的目录是 `/119/119719/`。详情 `tocUrl` 不能写死 `/88/`，
   用 `.jrsj a.dise@href##/[0-9]+\.html$##/` 从「点击阅读」链接通用推导。
2. **章节列表多一条哨兵**：`ul.lb li` 末尾有
   `<a class="last tb">本页章节列表结束！</a>`（无 href），
   `chapterList: ul.lb li a` 会得 41 条且日志报「目录40未获取到url」；
   改 `ul.lb li a.xbk` 精确取 40 章。
3. **末页分页窗口全是回看链接**：第 7 页仍显示 `_1`~`_6` 链接、当前页无 href、
   「没有更多分页了！」。若取窗口第一个链接会**回跳第 1 页无限循环**。
   正解：从 `baseUrl` 解析当前页 N（无 `_N` 视为第 1 页，期望下一页=2），
   在站点自己的 `.showpage a.xbk[href]` 中只接受 `_(N+1)` 的链接；
   末页找不到 → `return null`。这是内容级判据，不写死页码上限。

## 四、域名迁移甄别（同站多模板不可混用）

- `m.blpopo.com`：HTTPS 握手被 RST，HTTP 返回中国移动反诈拦截页 ⇒ 不可用。
- `www.blpopo.vip` / `blpopo.vip`：GBK 移动模板，规则全绿（blpopo.vip 301 到 www）。
- `www.blpopo.com`：GBK **PC 模板**（biquge.css + 另一套 DOM），移动规则不兼容；
  仅可作为发布页/官网参考，不要放进线路切换按钮。

## 五、验收闭环

1. `source_lint.py` 静态门禁 + App 内 `new Function` 编全部 JS 块。
2. `debug_source`：关键词搜索 → 裸 URL 详情/目录/正文 → `++目录URL` 验证总页数与总章数 → `::URL` 发现页。
3. LT MCP 保存 + LAN 1122 `/saveBookSource`；E 走 LAN 1125，WS 1126 `/bookSourceDebug` 五链路。
4. 双端 `getBookSource?url=` 回读比对（App 会补 `customButton/eventListener/weight/respondTime`，其余字段必须 0 差异）。
5. check_source 偶发 timeout 多为站点响应慢，不等价规则错；以 debug 全链路为准。

## 六、★★E 版搜索 POST 偶发 58 秒超时：轻量入口 + bookList 自请求

同一源同一关键词，LT MCP debug 搜索 1.6s、E LAN WS 搜索 58s（首页/详情/目录均 1~3s），
E 版直连框架的慢 POST 会撞搜索 30s 超时。正解：
- `searchUrl` 改成轻量入口 `{{line}}/s.php?q={{key}},{"timeout":8000}`（只负责传关键词，响应不用）；
- `ruleSearch.bookList` 用 `@js` 自己 `java.ajax(base+'/s.php,'+JSON.stringify({method:'POST',body:'s='+k+'&type=articlename&submit=',charset:'gbk',timeout:12000}))`，
  失败再对 `https://blpopo.vip/s.php` 兜底一次；字段用 `$.name` 等 JSONPath。

### 三个配套铁律
1. **bookList `@js` 必须返回 `java.util.ArrayList`，元素是 JSON 字符串**；直接返回 `JSON.stringify(array)` 会「列表大小:0」。用诊断源实锤：ArrayList 版 1 条，JSON 字符串版 0 条。
2. **`bookList @js` 环境没有 `key` 绑定**（`typeof key==='undefined'`），把关键词通过 searchUrl 的 `q={{key}}` 传进去，规则里从 `baseUrl` 用 `/[?&]q=([^&]*)/` 取，再 `decodeURIComponent`（Rhino 的 decodeURIComponent 对标准 UTF-8 百分号编码正常）。
3. **规则内的辅助函数不要命名 `baseUrl`**：函数声明会遮蔽规则环境绑定的 `baseUrl`，导致读关键词永远失败；改名 `lineBase()` 即可。

修复后 LT 搜索 5.7s、E 搜索 4.1s，双端全链路恢复。经验源 `/workspace/blpopo/BL小说_blpopo.json`。

## 七、★★宽泛关键词的「全量无分页搜索页」会把阅读搜索拖到超时

用户搜 `系统` 报 `SocketTimeoutException`，HTTP 日志显示：
- 轻量入口 `GET /s.php?q=系统` 8s 超时；
- 规则内 `POST /s.php` 也 8s/12s/20s 均超时；
- 沙盒 curl 实测响应 `content-length: 330106`，40s 只收到 32KB（已含 171 条），全量约 1700 条；
- `&page=1`/`&p=1` 被忽略，服务端仍返回 330KB，无分页；`Range` 头被忽略；`keyword=`/旧 `type=articlesearch` 参数无效；
- HTTPS/HTTP、`blpopo.vip` 备用域、HttpURLConnection 流式读前 80KB 全部仍 >20s。

结论：**这是站点侧宽泛关键词无分页全量输出，不是书源规则错**；阅读搜索 30s 上限内无法拿全。

工程处理：searchUrl 改用静态 `favicon.ico?q={{key}}` 传关键词（避开 PHP 端点，12s 超时），
规则内自请求 12s + 备用域一次；若仍无 `class="blue"`，`java.toast('⚠️ 站点搜索响应超时/结果过多，请改搜更具体的书名或稍后再试')`
并**返回空 ArrayList**，不要在 UI 漏原始异常。窄关键词（如「作茧」）仍 8 条全绿。
