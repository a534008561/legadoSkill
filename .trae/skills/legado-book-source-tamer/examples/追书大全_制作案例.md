## 交付前最后抓到的真 bug：短 book_id 死链（详见方法文档 §12）

- 现象：书城 `index/1/0/2.html` 首条《大唐第一败家子》→ `.../v4//396.html` → `code:0 书籍ID错误！`，`TocEmptyException`。
- 根因：模板沿用 `id.slice(0,-3)`，**id ≤3 位时前缀变空串**；该页 42 本里 11 本是 3~4 位 id。
- 正确形态（实测）：4 位 → `3/3057`；≤3 位 → 前缀补 `0` ⇒ `0/396`；≥5 位不变。
- 修法：jsLib 加 `DPRE()/DPATH()` 统一三处 URL 构造（EX / ruleSearch.bookList / ruleBookInfo.init），
  非纯数字 id 直接 `continue` 丢条目。单测 13 长度样本 ⇒ ≥4 位与旧写法逐字节相同（搜索零回归）。
- 复验：4 个发现页全部短 id 共 12 本 ×(详情+线路) **12/12 双通**；`bookUrlPattern` 违规 URL **0 条**；
  真实管线 `::…/2.html` → 9 线路 → 775 章 → 正文正常。
- ⚠️ 同源模板的 全民小说 / 猫眼看书 / 顶点小说 也有相同 `slice(0,-3)` 隐患，**本次未擅自改动**（用户要求只改点名对象）。

## 「偶发被看成确定」的排查教训（方法文档 §13）

E 版一度对短 id 书稳定报 `SyntaxError: Unexpected token: <随机汉字>`，长 id 稳定通过。
我做了 5 轮二分（换 jsLib / 换 toc / 硬编码 init / 外传诊断 / 逐步 trace），最后把**真实规则原样**在新 origin 上
连跑 3 次全过，才确认是**偶发**（边缘节点异常自愈）。三个决定性信号：
① 三种互不相干的改法**全部"治好"** ⇒ 病因在改动之外；
② "同一本书每次都不行"≠"与书有关"，判确定性前须**跨时间**复测；
③ 本轮三次假信号都出自**探针自身**（顶层 `return`／jsLib 里 `source.put` 被静默吞／Python `\\d` 转义失效）。
