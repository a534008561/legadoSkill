## 一、报障指纹：先看 WS 日志的「内容页解析完成」前面那一行

用户报「加载正文失败」。`get_http_logs` 显示正文页 `view_video.php` 全部 **200 / 244~270ms**，
网络层完全正常 ⇒ 立即排除线路/UA/Cookie/风控，直接查 `ruleContent` 解析链。

★**订阅源 WS 调试（LAN 1123 `/rssSourceDebug`）的判据**：
`notPrintState=[10,20,30,40]` 不推列表/正文 HTML 原文，但**会推规则输出**。
上次 261107 交付日志里这一行其实是预警：

```
[00:03.117] ≡获取成功:https://a.26702.app/view_video.php?...
[00:03.138]                       ← ★ 空行＝ruleContent 返回空，不是"成功"
[00:03.139] ︽内容页解析完成
```

**「内容页解析完成」只代表流程走完，不代表有内容**。铁律：
调试日志里 `≡获取成功` 与 `︽内容页解析完成` 之间必须有非空输出行；
视频源应看到 `https://...mp4?...`，空行一律按失败处理，不能当绿。
修复后两轮回归（不同文章 1258507 / 1258511）：

```
[00:01.572] ︽内容页解析完成
```

## 二、根因对照实验（必须含反向验证组）

站点 261107 改版，页面里出现 `/* VLKRELOAD 11-07 */`、`/* 2026-11-04 ... */` 新脚本。
旧 `ruleContent` 内层 420B `<js>` 依赖：

```js
var html = java.getString('#player_one@script@html');
var encodedMatch = html.match(/document\.write\(strencode2\(["']([^"']+)["']\)\)/);
...
var URL = url.replace(/&f=[^&]*/,'');   // ★ 次因
```

| 实验组 | 操作 | 结果 | 结论 |
|---|---|---|---|
| A（**反向验证**） | 旧正则 `document.write\(strencode2\(` 打在真实新页面 | **null** | 旧规则必然失配 → 正文空（主因） |
| B（正向） | 新正则 `strencode2\(["']([^"']+)["']\)` | HIT，1056B | 现形态 = HTML 注释内 `var vbF0=strencode2("%3c...")` |
| C（兜底） | 明文 `<source src>`（`ccm.91p52.com`） | PROTOCOL_ERROR | 该域不可作主线路 |
| D（**签名反向验证**） | 解出直链**带 `&f=`** | **200 video/mp4，Content-Length 7088333** | 可播 |
| E（**签名反向验证**） | 同一 URL **去掉 `&f=`** | **302 → text/html 145B** | `replace(/&f=[^&]*/,'')` 会毁掉直链 |
| F（新通道） | `POST /vlk.php` + 最小指纹 | 200 / 683B `{"u":直链,"ty":"video/mp4"}` | 无需真浏览器，可作二级兜底 |

★**方法论**：站点把直链从「`document.write(strencode2(...))` 写进 DOM」改成
「HTML 注释内 `var vbF0=strencode2(...)` 伪源 + 前端 AJAX `/vlk.php` 换真链」，
这类**混淆形态漂移**不会有任何报错，只会静默返回空。排查时先做「旧正则打在新页面上」的
反向验证组，一次就能定性，不要先看网络层。

★**签名参数铁律**：老的 `strencode2` 规则里常带 `url.replace(/&f=[^&]*/,'')`（历史上为去广告或
兼容旧播放器），新站 `&f=` 已是**防盗链签名必需**。改规则前必须对「带 / 不带」各发一次请求看
`Content-Type` + `Content-Length`，不能凭旧经验删参数。

## 三、`<js>` 规则环境绑定（源码级，LT/E 双版一致）

`AnalyzeRule.evalJS`（两版源码一致）绑定：

```kotlin
bindings["java"] = this          // getString/getElements/base64Decode/post/...
bindings["source"] = source
bindings["result"] = result      // 上一层规则输出
bindings["src"] = content        // ★ 原始 content（正文 HTML 全文）
bindings["baseUrl"] = baseUrl
```

⇒ 订阅源 `ruleContent` 的 `<js>` 里 **`var html = String(result || src || '')` 可直接拿全文 HTML**，
不需要 `java.getString('#player_one@script@html')`。

★**为什么不推荐 `#player_one@script@html`**：
1. jsoup `@html` 会转义 `&` 等实体，签名直链里的 `&f=` 可能被改写成 `&amp;f=`；
2. 站点把 `strencode2` 放进 `<!-- ... -->` 注释块，`@html` 对注释/script 的处理随模板漂移；
3. 选择器本身依赖 `#player_one` id，站方一改 id 就全挂。

全文正则 + `decodeURIComponent` 是更稳的最小依赖面。
⚠ 但 `eval_js`（MCP 空白书源环境）**没有** `result/src/getString/getElements` 绑定，
只有 `java.ajax/connect/get/post/head/log/toast` ⇒ 预检新脚本时必须自己 `var result=...; var src=result;`
手工注入，或直接在 WS 规则链里跑（推荐）。

## 四、修复配方：只换内层载荷，外层与署名层字节级不动

多层 Base64 嵌套结构（本次 = 3 层）：

```
ruleContent = <js> java.base64Decode(B64_1) </js>
  B64_1 → 第2层 <js>：署名校验 a.includes(d) → java.base64Decode(B64_2)
     B64_2 → 内层 <js>：真正的直链提取
  否则 → java.base64Decode(B64_3) = 「检测到书源被恶意篡改」
```

★**最小改动原则**：只重新编码 `B64_2`（内层脚本），
`B64_1`（署名校验壳）/ `B64_3`（错误信息）/ `sourceComment` / 其余 30 个字段全部字节级原样保留。
构建脚本用 `re.subn(..., count=1)` 精确替换第 2 段 b64，并加断言：

```python
assert len(inner_b64s) == 3                       # 段数守卫
assert 'document\\.write' in old_inner and 'replace(/&f=' in old_inner  # 旧脚本指纹
assert 署名层/错误层解码后与原文完全一致          # 未误伤
for k in before:
    if k not in ('ruleContent','lastUpdateTime'):
        assert d[k] == before[k]                 # 其余字段字节级不变
```

新内层脚本（三级兜底，双版通用 API：`decodeURIComponent`/正则/`JSON.parse`/`java.post`）：

```js
<js>
var html = String(result || src || '');
var url = '';
// ① 改版主形态 var vbF0=strencode2("%3c...")（同时兼容旧 document.write 形态）
var m = html.match(/strencode2\(["']([^"']+)["']\)/);
if (m) { try {
  var dec = decodeURIComponent(m[1]);
  var s = dec.match(/src\s*=\s*["']([^"']+)["']/);
  if (s && s[1]) url = s[1];
} catch (e) {} }
// ② /vlk.php 指纹通道（页面无直链时）
if (!url && typeof java.post === 'function') { try {
  var g = (html.match(/vbG\s*=\s*["']([0-9a-zA-Z]{8,})["']/) || [])[1] || '';
  var t = (html.match(/vbGT\s*=\s*["']([0-9a-zA-Z]{8,})["']/) || [])[1] || '';
  var origin = String(baseUrl || '').replace(/^(https?:\/\/[^\/]+).*$/, '$1');
  if (origin) {
    var payload = JSON.stringify({g:g,t:t,ev:'pointerdown',op:150,mc:2,tc:1,
      sc:0,kc:0,wd:0,gl:'Adreno (TM) 640',sg:0,nc:0,pl:0,lg:2,ow:412,oh:915});
    var r = java.post(origin + '/vlk.php', payload, '{"Content-Type":"text/plain"}');
    var j = JSON.parse(String(r.body()));
    if (j && j.u) url = String(j.u);
  }
} catch (e) {} }
// ③ 明文 <source src>（早期模板 / 镜像）
if (!url) { var s2 = html.match(/<source[^>]+src=["']([^"']+\.mp4[^"']*)["']/i);
  if (s2 && s2[1]) url = s2[1]; }
if (!url || !/^https?:\/\//.test(url)) { ''; } else { url; }  // ★ 绝不删 &f=
</js>
```

★ `java.post` 返回 **jsoup Response**，取正文必须 `r.body()`（不是 `String(r)`，
也不是 `java.ajax` 的第二参——`java.ajax(url, opt)` 在本环境无该重载）。

# 附录（261108 三轮报障）：登录界面换路线，有些地方没跟着换

> 这是**机制级**新发现，比上面的站点改版更通用，凡「登录面板写变量 + `{{}}` 内联 JS / jsLib 读变量」的源都会踩。

## 一、现象与三重根因

用户实测：「登录界面换路线，有些地方没跟着换」。
把订阅源真实键 `v_https://418.sol148.com/index.php_pnLine` 写成另一域后，
LAN WS 1123 规则链里列表请求**仍是 `a.26702.app`**，文章链接也仍是旧域。

| 层次 | 根因 | 证据 |
|---|---|---|
| ① 链接钉死旧域 | `ruleLink=a@href` 抓到的是页面写入的**绝对 URL**（真机列表 46/46 条全带 `a.26702.app`）⇒ 切线路后 `rssArticle.link` 不跟随 | 列表页 `href` 域名统计 |
| ② 面板无「当前线路」可见反馈 | 只有按钮 `▶` 标记 + toast，`PN_refresh` 依赖 `java.reLoginView`（面板环境专有，`eval_js` 空白环境 undefined） | 面板 JS 逐行审查 |
| ③ ★★★ **`PN_base()` 根本读不到面板写入的值** | 写在 `jsLib`，但 `{{}}`/jsLib 的共享 scope 里 `source`/`cache`/`java`/`baseUrl` **全部不可用** | 诊断桩把状态拼进 URL query，WS「≡获取成功」直接读到 `PNDBG=L1E,SUE,BKE,CE,JGE` |

## 二、★★★ 机制定案：jsLib 共享 scope 的绑定隔离（官方源码级）

```
BaseSource.getShareScope() → SharedJsScope.getScope(jsLib)   // 只用「jsLib 字符串」建 scope
                              ↓ evaluateJsLib + preventExtensions（密封）
AnalyzeUrl.evalJS({{...}}) → bindings(java/cache/source/...) 通过 prototype/chainTo 挂上去
```

**jsLib 里定义的函数体沿自己的作用域链找变量时，看不到子 scope 的 bindings**。
所以 `PN_base(){ source.get('pnLine') }` 里的 `source` 是 undefined，恒回退默认域。
面板 action 走 `BaseSource.evalJS`（`bindings["source"]=this`），写进
`CacheManager` 的 `v_<sourceUrl>_pnLine`，但 `PN_base()` 读不到 ⇒ 切换只改了按钮文字，
列表/搜索/文章链接全不动。

诊断三组（必须含反向验证）：
- 诊断2 `PNDBG=L1E,SUE,BKE,CE,JGE` ⇒ 裸 `source`/`source.sourceUrl`/`baseUrl`/`cache`/`java` 全抛异常。
- 诊断3 纯 JS 全局 `var __PN_STATE__` 也为空 ⇒ 面板 action 与 `{{}}` 不是同一共享 scope 实例，
  **纯 JS 全局状态也不能跨环境传递**。
- 诊断4 `PNDBG=this=object,thisSource=object,GV={"page":"1"},getData={"page":"1"}` ⇒
  **`this.source.getVariable()` 可用**！这正是原书源作者 jsLib 里 `getData()` 用
  `this.source.getVariable()` 而不是裸 `source` 的原因（裸绑定失效、`this` 绑定有效）。

★ 源码佐证：
- `BaseSource.put/get` → `CacheManager` 键 `v_${getKey()}_${key}`；
  `RssSource.getKey() = sourceUrl`（RssSource.kt:124）。
- `BaseSource.setVariable/getVariable` → `CacheManager` 键 `sourceVariable_${getKey()}`，
  **两个环境同一个 key**。
- `AnalyzeUrl.get(key)`（`AnalyzeUrl.kt:390`）只查 `chapter/ruleData.getVariable`，
  **不查 CacheManager** ⇒ `java.get('pnLine')` 在 `{{}}` 环境恒空，绝不能用。
- `SharedJsScope.getSharedGlobalStateKey()` = `MD5(jsLib)+类名+MD5(getKey())`，
  但本 App 版本（legadoT/E 混合）走旧 `prototype` 路径，bindings 对 jsLib 函数不可见。

## 三、修法：双写 + 单读，全走 `getVariable/setVariable` 已验证通道

1. **面板写线路统一 `PN_writeLine(line)`**：`source.put('pnLine')`（保留旧通道）
   **＋ `source.setVariable(JSON.stringify({page, pnLine}))`**（新主通道）。
   必须**保留起始页码 `page`**（`getPage()` 读 `getData().page`），绝不写死页码上限。
   `PN_fetchPub` 取完路线、`login()` 点 √ 时各同步一次。
2. **`PN_base()` 读线路四级兜底**：
   ① `this.source.getVariable()` 解析 `pnLine`（主）→ ② `source.get` → ③ `cache.get` 精确键
   → ④ `java.get` → 默认活线路。每层 try/catch，任一环境缺绑定都不抛错。
3. **`ruleLink` 改 `@js:`**：`java.getString('a@href')` 取链接，绝对 URL 用 `PN_base()`
   同源重写 host；相对 URL 用 `baseUrl` 拼。不写死任何域名。
4. **面板加「当前线路」动态 label**（`viewName:"PN_curLineText()"` 每次渲染重跑，
   返回纯文本），`PN_switch` 后 toast 明确「列表/搜索/文章链接/正文全部跟随」。

## 四、★ 决定性反向验证（修复成败的唯一判据）

```
清空 v_<key>_pnLine（排除旧通道干扰）
只写 sourceVariable_<key> = {"page":"1","pnLine":"https://418.sol148.com"}
        ↓
WS「≡获取成功」: https://418.sol148.com/v.php?next=watch&page=1   ✅ 跟随
WS「└获取文章链接」: https://418.sol148.com/view_video.php?...      ✅ 跟随
```

（该镜像是死线路，正文页返回异常堆栈 ⇒ 正文空属站点网络层，测速按钮正是用来选活线路的；
恢复 `pnLine=a.26702.app` 后两轮不同文章回归全绿：列表 46/42 条 + 完整 `&f=` 直链。）

## 五、通用铁律（跨站）

- **凡「登录面板/按钮 action 写变量 → `sortUrl`/`searchUrl` 的 `{{}}` 内联 JS 读变量」，
  不要假设 `source/cache/java/baseUrl` 在 jsLib 里可用**；先用诊断桩把各通道状态
  拼进返回 URL，WS「≡获取成功」会原样显示（比 `java.log` 可靠，`notPrintState` 不挡 URL）。
- **`this.source.getVariable()/setVariable()` 是 jsLib ↔ 面板之间最可靠的持久化通道**
  （`sourceVariable_<sourceUrl>` 同一个 CacheManager key，两环境都可达）。
- `java.get(key)` 在 `{{}}` 环境**不是** `BaseSource.get`，不能用它读面板变量。
- `source.put` 写的值面板自己能读（按钮文字、测速 ms），但 jsLib 读不到 ⇒
  典型表现就是「按钮变了、请求没变」，与用户「有些地方没跟着换」完全吻合。
- 排查完**必须重存正式版**（诊断桩会覆盖落库），并回读 diff 0 + 两轮 WS 回归。
- 站点给绝对链接时，`ruleLink` 必须做同源重写，否则换线路后文章详情仍回旧域。

# 附录二（261108 五轮报障）：E 版「正文链接切到 app 路线，还是 418 那个路线」

> 用户给了 E 版 LAN 服务地址 `http://192.168.10.7:1125`（WS 在 **1126**，`/rssSourceDebug` 握手 101 成功；1125 根路径返回导航页，`getVariable/getHttpLogs/evalJs` 等 GET 只回显 `web/xxx` 占位串，**不是真实数据接口**）。E 版 `getRssSources` 返回 14.4MB / **3482 个订阅源**，其中 **3 个同名 91PORN**（`418.sol148.com` 是本次修复的 v5；另两个 `612.bonk199.com`、`f1011.a2507app.com` 是旧副本，ruleLink 仍 `a@href`、无 PN_var）⇒ 排查 E 版报障第一步必须按 `sourceUrl` 精确锁定是哪个副本，别被同名源误导。

## 一、现象与真因：★★★ 调试日志写死 `sourceUrl`（E/LT 两版共有）

E 版 WS 1126 日志：
