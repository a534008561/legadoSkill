# 方法：搜索引擎书源反爬验证弹窗人工过盾

> 沉淀日期：2026-11-27 ｜ 来源：幻想姬(huanxiangji.net)书源搜索修复
> 关联：方法-AEGIS-ALTCHA验证与WebView通道书源.md、方法-登录UI-V2动态渲染与useweb新特性总览.md

## 0 适用场景

书源搜索走通用搜索引擎（百度/必应/搜狗/夸克/360/Yandex）的 `site:` 跳转时，
引擎常对 App 出口 IP 返回**反爬验证页**。若验证需人工点击（Turnstile 打勾/图形码/点选），
`java.webView` 自动过盾无效，必须**弹窗让用户手动过**。

## 1 验证页识别（判定函数，三组对照必做）

```js
function FQ_isVerify(b){
  var s=String(b||'').slice(0,6000);
  return /Checking your browser|before redirecting|<title>\s*Verification|Верификация|wappass|百度安全验证|安全验证|Just a moment|cf-chl|请输入验证码|captcha|verification/i.test(s)
         && s.length<60000;
}
```

- **双条件**：关键词命中 **且** 页面偏短（<60KB）。单看 `challenge-platform` 会误杀正常结果页（CF 给每个正常页都注入统计脚本）。
- **三组对照**：真验证页=true / 小说首页=false / 详情页=false。本次实测 yandex 验证页 42278B=true、首页 37967B=false、详情页 19033B=false。
- **坑**：正则字面量里未转义的 `/` 会截断（`verify/` 要写成 `verification`）。

## 2 弹窗过盾主流程（searchUrl @js）

```js
// 1) 构造引擎 URL（默认多引擎轮换，支持 @yandex 等前缀手动指定）
var u = 'https://yandex.com/search/?text=' + encodeURIComponent(key + ' site:huanxiangji.net');

// 2) 先探测（java.ajax 跟随跳转，java.get 默认不跟随会拿 302 空 body）
try{
  var probe = String(java.ajax(u));
  java.put('FQ_seHtml', probe);            // 缓存给 ruleSearch 复用，避免二次请求
  if(FQ_isVerify(probe)){
    try{ java.startBrowser(u, '🔐手动过验证'); }catch(e){}
    try{ java.longToast('检测到反爬验证，请在弹出窗口手动通过后重新搜索'); }catch(e){}
    result = null;                          // URL 类规则终止信号，干净短路
  } else {
    result = u;                             // 正常页走标准搜索流程
  }
}catch(e){ result = u; }
```

要点：
- `java.startBrowser(url, title)` 打开**内置浏览器**（真 WebView，用户可交互点验证），`startBrowserAwait` **切勿用**——App 自动重放会被 CF/Yandex 判机器人，作废刚拿到的 clearance。
- `result=null` 是 URL 类规则的标准终止信号；返回 `""` 会被拼成当前页 URL 白发一次请求。
- Toast 必须给（用户要求各阶段有提示），且用 try/catch 包住，避免个别版本无该方法时中断。

## 3 过盾后复用（关键闭环）

1. 书源必须 `enabledCookieJar: true`。
2. Yandex 过盾后 Cookie（`yandexuid`/`bh`/`_yasc`/`i` 等）会由内置浏览器回写到书源网络栈 —— `get_cookies` 实测确认。
3. 用户"重新搜索" → 探测请求带上已过盾 Cookie → 不再命中验证页 → 正常返回搜索结果。
4. **否则会死循环**：每次都判验证→每次都弹窗。所以 CookieJar 是这套方案的必要条件，不是可选项。

## 4 自动过盾 vs 人工过盾的边界

| 验证类型 | 特征 | 方案 |
|---|---|---|
| ALTCHA PoW（自动） | `altcha-widget`、`aegis_altcha` | `java.webView` / `webViewDelayTime` 自动过，无需弹窗 |
| Yandex JS 挑战 | `Checking your browser`、`Verification` | webView 能过但可能拿到首页/超时 → **弹窗人工过更稳** |
| CF Turnstile / 图形码 / 点选 | `cf-chl`、验证码图片 | **必须弹窗人工过** |

## 5 配套：从引擎结果提取目标站链接（ruleSearch.bookList）

引擎结果里链接常是跳转链或编码形态，用 @js+jsoup 正则筛目标站 ID 再构造合成 HTML：

```js
jsoup=org.jsoup.Jsoup.parse;
var cached=java.get('FQ_seHtml');
var html=(cached&&String(cached).length>500)?String(cached):String(src);
r=jsoup(html);
links=r.select('a[href]');
sb='<div>';
for(i=0;i<links.size();i++){
  a=links.get(i);
  h=String(a.attr('href')||'');
  m=h.match(/TARGET\.net\/book\/(\d+)\/?/i) || h.match(/TARGET(?:%2E|\.)net(?:%2F|\/)book(?:%2F|\/)(\d+)/i);
  if(m) sb+='<a href=\'https://TARGET.net/book/'+m[1]+'/\'>'+String(a.text()||('书籍'+m[1]))+'</a>\n';
}
sb+='</div>';
jsoup(sb).select('a[href]');
```

## 6 通用坑清单

- `new java.lang.StringBuilder()` 在 Legado Rhino 抛「无法读取 undefined 的属性 StringBuilder」→ 必须用纯 JS 字符串 `+=`。
- `java.get(url,header)` 不跟随 302，探测要用 `java.ajax(url)` 或 `java.get(url,{}).body()` 手动处理 Location。
- 搜索页被判为"后台流程"时，某些版本 `java.startBrowser` 会被 `canOpenSourceUi()` 静默拦截（只弹 Toast 不弹窗）→ 此时改用登录面板按钮引导用户过盾（见 loginUi 过盾面板范式）。
- 每个按钮/阶段都要 Toast，用户明确要求知道当前状态。

## 8 综合搜索（多引擎全搜 + 合并提取）261127 增补

用户要求"不再专用某引擎，各引擎都搜，在结果里提取跳转本站"时，用下面这套：

```js
// searchUrl @js：六引擎全搜
var engines=[
  {n:'yandex',u:'https://yandex.com/search/?text='+q},
  {n:'baidu',u:'https://www.baidu.com/s?wd='+q},
  {n:'bing',u:'https://cn.bing.com/search?q='+q},
  {n:'sogou',u:'https://www.sogou.com/web?query='+q},
  {n:'quark',u:'https://quark.sm.cn/s?q='+q},
  {n:'so',u:'https://www.so.com/s?q='+q}
];
var merged='<div>',verifyUrl='',verifyCnt=0;
for(var i=0;i<engines.length;i++){
  var en=engines[i];
  try{
    var r=java.get(en.u,'{}');
    var loc=String(r.header('Location')||'');
    var code=+r.statusCode();
    var body=(code>=300&&code<400)?String(java.ajax(en.u)):String(r.body());
    if(FQ_isVerifyHead(loc,'',body)){verifyCnt++;if(!verifyUrl)verifyUrl=loc||en.u;}
    else merged+=body;
  }catch(err){}
}
java.put('FQ_seHtml',merged);
if(verifyCnt>0){ java.startBrowser(verifyUrl,'🔐手动过验证'); java.longToast('检测到'+verifyCnt+'个引擎需验证，请手动过后重新搜索'); }
result=engines[0].u;   // 关键：返回正常URL走标准流程，ruleSearch从缓存读合并结果
```

**四条铁律**：
1. `searchUrl` 结尾返回 `engines[0].u`（正常 URL），**不要返回 null/about:blank**——ruleSearch 从 `FQ_seHtml` 缓存读数据，src 是什么无所谓，但返回正常 URL 不会触发 App 异常流程。
2. **提取正则绝不能加 `/\/book\/(\d+)/` 兜底**——综合搜索结果里全是别站的 /book/ID，兜底会把别站书误判成本站。只认目标域名直链 + `%2E/%2F` 编码链两条。
3. `java.ajaxAll(urls,true)` 在本环境返回 Array 但元素 **是对象不是纯 String**（实测 `typeof rs[0]='object'`），串行 `java.ajax` 逐个拿 body 更可控；六引擎约 8.8 秒可接受。
4. 验证弹窗**全部搜完后统一弹一次**（弹第一个 verifyUrl），不要每个引擎弹一次——否则用户被连续弹 6 个窗口。

配套 `ruleSearch.bookList`：对缓存 html 里所有 `a[href]` 正则提 ID、`seen` 对象去重、构造合成 HTML 返回 jsoup Elements。


## 9 ★★★终章：验证弹窗死循环的根因是网络栈（TLS指纹），正解=改走 WebView 通道

现象：`java.get`/`java.ajax` 请求 Yandex 恒 302→showcaptcha；弹窗人工过完后再次搜索仍 302，死循环。
**三组对照实验定位**（缺一不可）：
1. 换 UA：MQQBV/桌面Chrome/AndroidChrome/WebViewUA 四种 UA 全部仍 302 ⇒ 不是 UA。
2. 带 Cookie：`java.get(url,'{"Cookie":"'+java.getCookie(url)+'"}')` 带全套回写 Cookie 仍 302 ⇒ 不是 Cookie（过盾 Cookie 确实回写了，get_cookies 可见 ys/yandexuid/bh）。
3. 换栈：`java.webView(null,url,'document.documentElement.outerHTML')` 走真 Chromium ⇒ **直接拿到搜索结果页**（27583B、title 正确、1.6s、无验证）⇒ 根因 = **OkHttp 的 TLS 指纹被 Yandex/JA3 判机器人**，换客户端指纹即绕过。

结论与范式：
- **搜索引擎书源遇到"弹窗过盾后仍反复验证"→ 不要再加弹窗/判据了，把搜索请求整个改走 `java.webView`**。
- 六引擎全走 WebView 实测总耗时约 10s（yandex1.6/baidu3.1/bing0.8/sogou1.4/quark1.9/so1.3），全部无验证页。
- 弹窗只保留作兜底：仅当 WebView 返回的 body 真含 `Are you not a robot|请输入验证码|Just a moment|cf-chl`（且长度<60KB）才 `startBrowser`。
- `java.webView` 的坑：`webViewGetOverrideUrl` 带 delay 在本环境会 60s 超时；直接用 `java.webView(null,url,'document.documentElement.outerHTML')` 稳定。
- 综合搜索提取规则同 §8（域名双正则、禁止 /book/ 兜底、searchUrl 末尾返回 engines[0].u）。

配套成品：`/workspace/幻想姬_www.huanxiangji.net.json`（261127 WebView通道综合搜索终版）。


## 10 ★★★再追加：site: 语法可能反而过滤掉目标站结果（261127 幻想姬实锤）

用户报"浏览器搜有本站结果，书源却0本"。关键词「实教，比企谷梦见未来老婆」对照：
- Yandex WebView 搜**原词** → 89712B，**3条** `huanxiangji.net/book/25398` 链接
- 搜 `原词 site:huanxiangji.net` → 31209B，**0条** book 链接

**根因：书源自动追加的 `site:` 把结果过滤没了**（Yandex 对该站的索引只在非 site: 查询里出现）。
⇒ 综合搜索范式必须**每个引擎搜两版**：原词 + 原词+site:，合并去重。防用户自带 site: 时重复：
`kNoSite=k.replace(/\s*site:\S*/gi,'').trim()`。

另两个配套坑：
1. **别把整页 HTML 存缓存**：12 引擎结果合并 6.5MB ⇒ 解析奇慢。正解在 searchUrl 内就用 `<a[^>]+href=["']([^"']*目标域[^"']*)["']...>` 正则只提取含目标站的 a 标签，缓存降到 ~81B。
2. **ruleSearch 里缓存长度判据要跟着改**：只存链接后缓存很短，`cached.length>500` 会误判为无效而回退读 src（验证页）⇒ 又 0 本。阈值降到 `>20`。

v4 端到端实测：搜「实教…」1本 book/25398 → 详情/365章目录/正文全绿。


## 11 搜索引擎结果没有真实书名（261127 幻想姬）

搜索引擎结果卡片标题常是 URL 文本（Yandex 的 `<h2><a>huanxiangji.net/book/25398</a></h2>`），直接拿来当 `name` 会导致搜索列表显示链接、详情页不更新。
**正解**：在 `ruleSearch.bookList` 提取到目标站 bookUrl 后，逐条 `java.ajax(bookUrl)` 抓详情页（目标站自身网络栈通常正常、约300ms/条），
用 `/<h1>([^<]+)<\/h1>/` 或 `/og:novel:book_name"\s+content="([^"]+)"/` 取真实书名，填入合成 HTML 的 a 文本；失败才回退「站点名+ID」。
实测：书名从 URL 文本变为《实教，比企谷梦见未来老婆》，详情/目录/正文全绿。


## 12 夸克滑块验证（_____tmd_____/punish）261127

夸克 `quark.sm.cn/s?q=` 在风控出口返回 **滑块验证**：
- title=`验证码拦截`，body 含「亲，请拖动下方滑块完成验证」
- 最终 URL=`https://quark.sm.cn//s/_____tmd_____/punish?x5secdata=...&x5step=1`（阿里 x5secdata 风控）

判据必须覆盖 URL 和 body 两处：
```js
if(/_____tmd_____|\/punish\?/i.test(finalUrl)) return true;
if(/验证码拦截|拖动下方滑块/i.test(body) && body.length<60000) return true;
```

拿 body+最终URL 的组合 JS（实测可用）：
```js
var raw=String(java.webView(null,url,'JSON.stringify({h:document.documentElement.outerHTML,u:location.href})'));
var o=JSON.parse(raw); var body=o.h, finalUrl=o.u;
```

**核心限制**：`java.webView` 是独立后台 WebView；前台浏览器（`startBrowser`）过完滑块后的 Cookie **不能被后台 WebView 复用**（实测过完再请求仍 punish）；`java` 无 setCookie/syncCookie API（typeof=undefined）无法手动桥接。⇒ 沙盒/风控出口下夸克无解；真机浏览器能搜到说明已过盾，真机后台 WebView 是否共享 CookieManager 需实测。处理=弹真验证URL+Toast 明确提示哪个引擎需过盾，真机过完再搜一次。


## 13 ★最终定案：site: 对 Yandex/夸克都是毒药（261127）

§10 发现 Yandex 加 site: 过滤结果；§12 夸克加 site: 触发滑块。最终结论：
**搜索引擎式书源不要追加 site:，统一用原词搜全部引擎，靠提取规则的目标站域名正则过滤别站结果。**

夸克对照实测（关键词「崩坏，世界调制模式」）：
- `?q=原词 site:huanxiangji.net` → `_____tmd_____/punish` 滑块验证页
- `?q=原词` → 正常结果页，**29 处** `huanxiangji.net/book/21172` 链接，无验证

收益：请求数从 12（6引擎×2版）降到 6，耗时从 26s 降到约 15s，且避开夸克滑块。
端到端绿：搜「崩坏，世界调制模式」→ 1 本《崩坏，世界调制模式》book/21172 → 详情作者超可爱大鸭鸭 → 1183 章目录 → 正文正常。
