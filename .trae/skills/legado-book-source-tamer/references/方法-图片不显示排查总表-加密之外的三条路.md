## 一、图片不显示的四象限归因

封面正常、章节图全挂？先定位象限：

| | 请求 200 | 请求失败 |
|---|---|---|
| **URL 提取到了** | ① 内容是密文 → 走 [AES 篇](方法-图床AES加密图片解密.md)<br>② **渲染层屏蔽网络图** → 路三 | ③ **主机被墙** → 路二<br>④ 签名/Referer 过期 → 路一 + AES 篇的缓存中毒节 |
| **URL 没提取到** | 正则失配（新格式：`?verify=` 后缀、`data-src` 懒加载、无引号属性） | 同左 |

**先判"有没有提取到 URL"**：看 HTTP 日志里有没有对图床域的请求。没有 → 是提取问题（第九节案例：`.webp?verify=` 让旧正则要求"扩展名后紧跟引号"全失配）。

## 二、路一：签名不绑主机 → 自由换 CDN 主机

wn10 的突破点：图床加了 `?verify=时间桶-签名`，且**默认主机 `img5.wnimg2.cfd` 被墙**。

关键实验（沙盒干净网络做矩阵对照）：

```
同一个 verify token  →  打到 img1 / img2 / img3 / img4 / img5  ：全部 200
```

⇒ **签名只校验"路径 + 时间桶"，不绑定 host**。于是可以任意换主机，token 照样有效。

**通用推论（值得记住）**：图床签名常见绑定维度

| 绑定维度 | 换主机可用？ | 换 UA 可用？ | 判定实验 |
|---|---|---|---|
| 只绑路径 | ✅ | ✅ | 同 token 打多主机矩阵 |
| 绑 host | ❌ | ✅ | 换 host 得 403 |
| 绑 Referer | ❌/✅ | — | 改 Referer 看码 |
| 绑 UA | ✅ | ❌ | 换 UA 看码 |
| 绑时间桶 | 桶内可重复（缓存友好） | — | 同桶重复请求看 token 是否轮换 |

时间桶（`hour-bucket`）意味着：**同桶内 URL 稳定 → 图片缓存能命中**。别在 URL 里加 `Date.now()`（会把 CDN 与 Legado 双层缓存全打穿）。

裸链（去掉 `verify`）恒 403 = 签名是**必需项**，不要试图删。

## 三、路二：SNI/DNS 封锁 → 换 CDN 原生主机名

被墙有两种，处置完全不同：

```
java.ajax('https://blocked.host/x') 报什么？
├─ ERR_NAME_NOT_RESOLVED / 解析到陌生 IP      → DNS 污染：用 {"dnsIp":"ip1,ip2"}（见 URL模板篇第五节）
└─ SSL handshake aborted / ERR_CONNECTION_RESET → SNI 封锁：换 host！
```

**SNI 封锁的解法不是换 IP，是换主机名**：

```
vdownload.hembed.com（被 SNI 墙）
   ↓ 查 CNAME 链
1497203185.rsc.cdn77.org（CDN77 的"客户原生主机名"）
   ↓ 签名只绑路径
直接可用，200
```

> **通用方法论**：`CDN 域名被 SNI 封锁 → 查 CNAME → 用 CDN 侧原生主机名（形如 {accountId}.rsc.cdn77.org / {hash}.fastly.net / 客户 ID 段前置的厂商域）`。厂商通常给同一份内容配多个可解析主机名。

同类实测（hanime1，手机侧 `java.head`）：

- `vdownload.hembed.com` = SSL handshake aborted（TLS 被掐）
- `rsc.cdn77.us` = 403（签名绑了 host 的那条路）
- `pull.cdn77.com` = 无 DNS
- `vdownload-8.hembed.com` = 404（有域名无图）
- `1497203185.rsc.cdn77.org` = **200** ✅

**逐个探候选主机，别猜。**

## 四、路三：blockNetworkImage → 规则侧下载转 data: 内置

### 源码真相（BackstageWebView，2026-09-14 实锤）

```kotlin
// BackstageWebView.createWebView()
settings.blockNetworkImage = true        // ← 硬写
// WebViewPool.release() → onPageFinished(recycleUrl) 里才复位 false
```

⇒ **池化 WebView 存在竞态**：某个 WebView 被上一个使用者置成"屏蔽网络图片"后直接被 `acquire()` 出去用 → **该页面里所有 `<img src="http…">` 都画不出来，但 `data:` URL 不受影响**（实测 `naturalWidth=1024` 正常）。

这条解释了最诡异的一类症状：**"简介/面板在别的书上图片正常，这本就是空白"**、"沙盒里我算出来的 URL 明明 200"。

### 解法：规则侧下载 + base64 内嵌

```javascript
// H1DIMG(Jv, src, u) —— 生产版（hanime1 v3.9）
function H1DIMG(Jv, src, u) {
  try {
    if (!u || !/^(https?:)/.test(u)) { return ''; }             // 护栏1：只处理 http(s)
    var resp = Jv.get(u, null, 20000);                           // 规则侧用 JsExtensions.get
    if (!resp) { return ''; }
    var ct = String(resp.contentType() || '');
    if (ct.indexOf('image/') !== 0) { return ''; }                // 护栏2：必须是图片
    var b = resp.bodyAsBytes();
    if (!b || b.length > 235520) { return ''; }                  // 护栏3：≤230KB
    var s = Packages.android.util.Base64.encodeToString(b, 2);    // NO_WRAP
    if (!s || s.length < 800) { return ''; }                      // 护栏4：过小=失败
    return 'data:image/jpeg;base64,' + s;
  } catch (e) { return ''; }                                     // 护栏5：失败退回网络地址
}
```

**面板侧组候选链**（逐个 `onerror` 降级）：

```
data:  →  网络原址(https)  →  http 版  →  cdn77 主机  →  vdownload 主机
```

并把结果回显给用户：`🖼 封面:内置 100KB` / `网络·共 N 条线路` / `❌ 封面加载失败…可切[内置]`。**用户能看到当前走的是哪条路，比默默失败强十倍。**

开关放登录 UI（`h1img=bake/net`），让用户能关（内置会拖慢首屏、增大 `h1info` 体积）。

### ⚠️ 连带坑：随数据一起传的体积上限

hanime1 那次：正文规则把封面 data 写进 `h1info` 变量，而 `h1info` 有**自带上限 9000 字节** → data 图（几十 KB）**被静默丢弃** → 切 P 不跟随。
改成 400000 才好。

> **任何"把图片/长文本塞进变量再传给面板"的设计，第一件事是核对承载它的字段/变量有没有长度闸门。**

## 五、连通性判活：根路径探测法（含 HEAD 被拒陷阱）

无需 token、无需真图即可判"这台主机通不通"：

```
HEAD https://imgN.example/
├─ 拿到任意 HTTP 响应码（哪怕 400 / 403 / 404）  → TCP + TLS 通
└─ 桥返回 null / 异常 / 空                       → 被墙
```

**但有两个反例必须知道**：

1. **HEAD 被方法拒绝**：`cdn77` 实测 **GET 任意 UA/Referer 都 200，但 HEAD 恒 403**。
   → **HEAD 403 ≠ 被墙**。判活要 GET 复核（或看响应体长度）。
2. **`java.ajax` 有时不抛异常而是返回异常文本**（约 3748 字节的堆栈串），
   → `indexOf('Exception')` / `/javax\.net\.ssl|Exception|reset by peer/i` 校验后再解析（ggd8 实锤）。

本 App 桥的对应 API：

```javascript
java.head(url, headerJson, timeout)   // 被墙时桥吞异常 → JS 侧拿到 null（不是抛错）
java.get(url)                          // 返回响应对象：.body() / .contentType() / .bodyAsBytes()
```

## 六、三层选线闭环模板（自动 / 固定 / 兜底）

```
L1 自动选线（默认）
   探测候选主机池 [站点默认主机, img1..imgN]
   逐个 HEAD/GET，4s 超时；https 全败再试 http
   命中即写 source.put('imgH', host + '|' + ts + '|' + mode)   TTL 6h
   全不通写 'fail|ts' → 30 分钟冷却（避免每章都探一遍拖慢阅读）
L2 手动固定（简介卡片/登录 UI 点一行）
   source.put('imgH', 'img2|ts|s|h')  → 正文规则下次立即跟随
   换线路 = 换 URL = 换 md5 缓存 key → 天然绕开坏缓存 ★
L3 兜底
   全不通 → 保留原址 + 在正文里提示"图床不可达，可尝试[固定线路]"
```

**为什么"换线路即绕缓存"**：Legado 图片缓存 key 含 URL 的 md5，换 host 就是换 key → 不会命中之前那张坏图。这一条同时解决了[_aes 篇_](方法-图床AES加密图片解密.md)的"缓存中毒"问题（另一路是 `?v=N`）。

**TTL 设计**：取"实测轮换周期"的 1/2 ~ 1/3（图床主机通常比域名稳定，取 6h；线路轮换站取 180s）。

## 七、★沙盒会完全误诊：必须手机侧实测

**本次最贵的通用教训**（wn10）：

```
沙盒（海外出口）：  img5.wnimg2.cfd  → 200 ✅
用户手机（国内）：  同一主机同一时刻   → TLS RST ❌
```

沙盒测出"全部可通"，据此判定"不是墙的问题，是规则问题"，方向完全错。

**纪律**：

| 问题类型 | 必须在哪一侧测 |
|---|---|
| 规则/解析逻辑 | 沙盒或 `eval_js` 都行 |
| **连通性 / 被墙 / 图床可达性** | **只能在用户手机侧**：`eval_js` 里跑 `java.head`/`java.ajax`（MCP 是在真机 App 内执行的！） |
| 站点返回内容 | 沙盒可用，但要考虑 IP 级频控差异 |
| 渲染层（图片画不画得出） | 只能真机目视，或用 `java.webView` 探针（第九节） |

> **沙盒连不上 ≠ 站点失效；沙盒连得上 ≠ 用户能看图。** 两端都测，取交集。

## 八、图片渲染的硬约束（imgPattern）

正文里想渲染图片（图集类源、说明页），必须知道官方正则：

```kotlin
// AppConfig / AppPattern.imgPattern
AppPattern.imgPattern = Pattern.compile("<img[^>]*src=\"([^\"]*|[^\"]*\"[^>]*)\"[^>]*>")
//                                 ↑★硬性要求 src 后紧跟【双引号】
```

⇒ **`<img src=xxx>`（无引号）匹配不到 → 图片不显示。**

在 JS 里拼 HTML 时按要求生成双引号，同时保持"源文本零双引号"：

```javascript
var Q = String.fromCharCode(34);
var html = '<img src=' + Q + url + Q + ' style=' + Q + 'width:100%' + Q + '>';
```

阅读器会提取 `src` 后用原生 `ImageColumn` 渲染（可长按、可缓存）。

另外两条属性写法约束：

- HTML 属性可省略引号，但**值里不能有空格**：`style=width:100%` 合法，`style=padding:9px 26px` **非法**（改 `padding:10px`）；
- 单引号在 HTML 属性里写 `&#39;` 实体（`<useweb>` 按钮 `onclick` 场景）。

## 九、java.webView：真机渲染探针

`java.webView(html, url, js)` → 走 `BackstageWebView`，**真机 WebView 渲染 + 回读 DOM**，在 `eval_js` / 规则里都能调。这是"图片到底画没画出来""面板 DOM 有没有填上"的唯一客观手段。

```javascript
// ★js 必须写成【表达式】：IIFE 包起来。顶层 return 报 Illegal return statement；
//   "var a=x;" 语句式报 missing ")"
var r = java.webView(htmlString, 'https://example.com/',
  '(function(){ return JSON.stringify({ imgs: document.images.length, '
  + 'ok: [].slice.call(document.images).filter(function(i){return i.naturalWidth>0;}).length, '
  + 'w: (document.images[0]||{naturalWidth:0}).naturalWidth }); })()');
java.log(r);
```

**行为约束**：

- 返回 `null`/空 → 内部按 `intervals[200,400,600,800,1000]` 重试 >30 次后抛 **"js执行超时"**（≈25–30s）→ 用 `window.__n` 自计数控制采样轮数；
- 返回非空即接受（`evaluateJavascript` 的 JSON 串会被去掉首尾引号）；
- **顺带验证了第四节的 blockNetworkImage**：探针页面里网络图 `naturalWidth=0`、`data:` 图正常 → 一次实验同时证明两件事。

## 十、避坑清单

| # | 坑 | 对策 |
|---|---|---|
| 1 | 图片不显示就去逆 AES | 先看 HTTP 日志有没有对图床的请求（提取 or 渲染 or 网络） |
| 2 | 旧正则要求"扩展名后紧跟引号" | `?verify=` 后缀一来就全失配 → 改按 `page_url` 数组切分/属性取 |
| 3 | 以为签名绑 host | 先做同 token 多 host 矩阵 |
| 4 | SNI 封锁去换 IP | 换 CDN 原生主机名（查 CNAME） |
| 5 | 只在沙盒测图床可达 | **手机侧 `eval_js` 才是真相** |
| 6 | HEAD 403 判定被墙 | cdn77 类"HEAD 被方法拒"，GET 复核 |
| 7 | 信 `java.ajax` 一定抛异常 | 有时返回异常文本，`indexOf('Exception')` 校验 |
| 8 | 正文 `<img src=xxx>` 无引号 | 官方 `imgPattern` 要双引号，`fromCharCode(34)` |
| 9 | HTML 属性无引号值带空格 | `padding:9px 26px` 非法 |
| 10 | useweb 面板里放网络封面就以为稳 | **blockNetworkImage 竞态** → data 内置是稳态方案 |
| 11 | 把 data 图塞进有长度闸门的变量 | 静默丢弃；核对承载字段上限（9000→400000） |
| 12 | 图 URL 加 `Date.now()` | 打穿 CDN + Legado 双层缓存；时间桶内 URL 要稳定 |
| 13 | `java.webView` 的 js 写 `return` | 必须 IIFE 表达式 |
| 14 | 探针无重试上限控制 | 30 次后抛"js执行超时"，用 `window.__n` 自计数 |
| 15 | 缓存命中后规则不再跑 | 跟随类逻辑要**双写**（content 规则 + callBackJs 事件通道） |
