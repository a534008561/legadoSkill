# 方法 · 单源多模式切换书源制作（X夜社模式）

> 沉淀日期：2026-09-16　蓝本：书源「X夜社」（bookSourceUrl=`X夜社`，bookSourceType=0）
> 定位：**一个书源同时承载 小说 / 漫画 / 写真 / 视频 / 动漫 / 有声 六种内容形态**，用户在登录界面点一个按钮就整体换模式，搜索、发现、目录、正文全部跟着切。
> 关键词：多模式书源、模式变量、laiyuan、book.type 动态位掩码、data: 播放、单源多形态

---

## 0. 一句话总结

> **把「当前模式」存进书源变量，让 `exploreUrl / searchUrl / ruleToc.chapterList / ruleContent` 四处的 JS 都先读这个变量再分支；正文分支里顺手改 `book.type` 决定阅读器按文本/图片/音频哪套 UI 渲染；视频类内容用 `data:text/html;base64,` 页面交给内置浏览器播放。**

这套写法的价值：**一个源顶六个源**。站点如果本身就是聚合站（小说 + 漫画 + 写真 + 视频 + 有声共用一个站），没必要拆成六个书源，拆开反而搜索/发现/详情逻辑重复六遍。

---

## 1. 适用场景与识别特征

### 什么时候该用「单源多模式」

| 站点特征 | 是否适合 |
|---|---|
| 同一域名下同时有小说区、漫画区、视频区、图集区 | ✅ 首选 |
| 六种内容形态的**详情页结构一致**（同一套 HTML 骨架，只有正片区不同） | ✅ 最适合 |
| 六种形态的**搜索接口形状相似**（只是 tid/分类号不同） | ✅ 最适合 |
| 各形态详情页结构差异巨大、连反爬都不同 | ⚠️ 拆成多源更省事 |
| 各形态需要不同登录态/不同 Cookie | ⚠️ 拆成多源 |
| 内容形态单一 | ❌ 不要硬套，普通单源即可 |

### 典型识别信号

- 站点 URL 里有 `/nfilter/`（小说）与 `/filter/`（其他）两套列表路径
- 搜索页同时存在 `/search/{{key}}-6------{{page}}-.html`（小说）与 `/vod/search/page/{{page}}/tid/N/wd/{{key}}.html`（影视）
- 详情页 HTML 骨架相同（`.dinfo` / `.module-items` / `.chpterlist`），只有内容区 `.module-novel-detail` / `.module-player-cartoon-list` / `.module-player-pics-list` / `.module-player-info-items` 不同

## 2. 架构总览（六形态一张表）

| 维度 | 小说 | 漫画 | 写真 | 视频 | 动漫 | 有声 |
|---|---|---|---|---|---|---|
| **模式变量值** | `小说` 或空 | `漫画` | `写真` | `视频` | `动漫` | `有声` |
| **发现列表** | `/nfilter/6/page/N.html` | `/filter/4/page/N.html` | `/filter/5/...` | `/filter/2/...` | `/filter/1/...` | `/filter/3/...` |
| **搜索 URL** | `/search/{key}-6------{page}-.html` | `/vod/search/page/{p}/tid/4/wd/{k}.html` | tid/5 | tid/2 | tid/1 | tid/3 |
| **book.type** | 8（text） | 64（image） | 64（image） | 8（text） | 8（text） | 8（text） |
| **正文载体** | `.module-novel-detail .content p` → HTML 文本 | `.module-player-cartoon-list .list img` → img 串 | `.module-player-pics-list .list img` | `player_aaaa={...}` JSON → m3u8/mp4 | 同视频 | 纯 URL |
| **播放方式** | 阅读器原生 | 阅读器原生图片列 | 同左 | `data:` 页面 + `java.startBrowser` | 同左 | `<video>` + startBrowser |

> **关键结论**：除了「小说」走 `nfilter/nsearch`，其余五种全走 `filter/vod search` 通道；也就是说**模式变量实际只分两个大类**——「小说」与「非小说」，外加正文分支里的形态差异。写规则时先分大类再细分，代码量小一半。

## 3. 核心机关：模式变量（laiyuan）

### 3.1 存储与读写

本源用的是 **书源级变量**（不是书籍级）：

```javascript
// loginUrl 里写
source.setVariable(laiyuan);          // 存：'小说' / '漫画' / ...
// 规则里读（exploreUrl / searchUrl / ruleToc / ruleContent 四处都用）
a = source.getVariable();
if (a == "小说" || a == "") { ... }
```

⚠️ **不同 App 版本 API 名字不一样**，必须做双通道兼容（否则换版本就静默失效）：

```javascript
// 兼容写法：优先 getVariable（规则上下文 JsExtensions），退回 get（BookSource/CacheManager）
function mode() {
  var a;
  try { a = source.getVariable(); } catch (e) { a = source.get("laiyuan"); }
  a = String(a);                       // ★必须 String() 归一化，见 3.3
  if (a === "null" || a === "undefined" || a === "") return "小说";
  return a;
}
```

- `source.getVariable()/setVariable()`：规则上下文（`AnalyzeRule` 的 `source = JsExtensions`）可用；某些版本里 `getVariable()` 无参、读写**书籍级** `book.variable`（存库）。本源的用法（无参 set/get）与站点自身一致，属于「书源作者约定」，能跑通就以实测为准。
- `source.get(k)/source.put(k,v)`：`BookSource` 侧通用，落 `CacheManager`（进程内存级，App 重启失效）。
- 老本行结论见 `方法-APP接口聚合书源拆解.md`：**双通道 + JsNull 归一化是标配**。

### 3.2 loginUrl + loginUi 切换面板

```javascript
// loginUrl（顶层具名函数，不带 @js: 前缀）
function set_laiyuan(laiyuan) {
  source.setVariable(laiyuan);
  java.toast(`\n当前来源已切换为:\n${laiyuan}\n切换后请刷新发现`);
}
```

```javascript
// loginUi：一个标题 + 六个按钮，每个按钮 action 直接调函数名
[
  { name: "搜索和发现来源", type: "button", style: {layout_flexBasisPercent: 1} },
  { name: "小说",  type: "button", action: "set_laiyuan('小说')",  style: {layout_flexBasisPercent: 0.4} },
  { name: "漫画",  type: "button", action: "set_laiyuan('漫画')",  style: {layout_flexBasisPercent: 0.4} },
  { name: "写真",  type: "button", action: "set_laiyuan('写真')",  style: {layout_flexBasisPercent: 0.4} },
  { name: "视频",  type: "button", action: "set_laiyuan('视频')",  style: {layout_flexBasisPercent: 0.4} },
  { name: "动漫",  type: "button", action: "set_laiyuan('动漫')",  style: {layout_flexBasisPercent: 0.4} },
  { name: "有声",  type: "button", action: "set_laiyuan('有声')",  style: {layout_flexBasisPercent: 0.4} }
]
```

要点：
- **按钮名 === 模式变量值**，让用户看到的和存进去的完全一致，避免心智负担。
- `action` 直接写**函数调用**（带参用单引号），`loginUrl` 里定义同名函数即可；这是官方 RowUi 通道的标准用法（详见 `方法-登录UI-V2新版面板.md`）。
- 切换后提示**「请刷新发现」**——因为 `exploreUrl` 是缓存的，改变量不会自动重算。想更顺滑可以在函数里补 `java.refreshExplore()`（部分版本可用，实测为准）。
- **右上角 √（确认按钮）** 仍然是登录面板的固定部件；本源没有真正的登录逻辑，√ 点下去不做事即可。

### 3.3 JsNull truthy 坑（必踩）

Rhino 里 `source.getVariable()` 未设置时返回的是 **Java null 的包装对象（JsNull）**，它 `typeof` 为 `object`，**在布尔语境里为真**：

```javascript
var a = source.getVariable();
if (a) { /* JsNull 也进这里！ */ }
a == "小说"          // false → 正确
a || "小说"          // ❌ 不走兜底，因为 a 是 truthy
"x" + a              // "xnull"
```

**统一解法**：读取后立刻 `String(a)`，再判 `"null" / "undefined" / ""` 三态。

```javascript
a = String(source.getVariable());
if (a === "null" || a === "undefined" || a === "") a = "小说";
```

本源的 `if (a == "小说" || a == "")` 恰好绕过了这个问题（用 `==` 比较字符串），但**如果你改成 `if (!a)` 或 `a ||` 形式就会静默翻车**。

## 4. 各字段按模式分发

### 4.1 exploreUrl —— 每模式一套发现列表

`exploreUrl` 用 `@js:` 返回 **ExploreKind JSON 字符串**，内部按 `a` 分支，每个分支返回一个数组字面量（反引号模板串）：

```javascript
@js:
a = source.getVariable();
if (a == "小说" || a == "") {
  `[
    {"title":"全部小说","url":"{{bhost}}/nfilter/6/page/{{page}}.html",
     "style":{"layout_flexGrow":1,"layout_flexBasisPercent":1}},
    {"title":"都市生活","url":"{{bhost}}/nfilter/25/page/{{page}}.html",
     "style":{"layout_flexGrow":1,"layout_flexBasisPercent":0.4}}
    ...
  ]`
} else if (a == "漫画") {
  `[ ... /filter/4 ... ]`
} else if (a == "写真") { ... } else if (a == "视频") { ... }
else if (a == "动漫") { ... } else if (a == "有声") { ... }
```

设计要点：
- **`{{bhost}}` 与 `{{page}}` 都留给 AnalyzeUrl 二次求值**（模板串原样输出，Legado 拿到后再替换），所以这里用反引号字符串而不是先算好 URL。
- 一级入口（全部）用 `layout_flexBasisPercent: 1` 独占整行；二级分类用 `0.4`（一行两三个）。
- 不想要的分组用 **`{"title":"","url":""}` 占位**（源码里漫画/有声分支末尾就有一个空占位），既保持网格整齐又不产生可点按钮。
- 详细 ExploreKind 语法与 style 字段见 `方法-登录UI-V2新版面板.md` 与官方 `ExploreKind` 结构。

### 4.2 searchUrl —— 每模式一套搜索接口

```javascript
@js:
a = source.getVariable();
if (a == "小说" || a == "") {
  url = `{{bhost}}/search/{{key}}-6------{{page}}-.html`;
} else if (a == "漫画") {
  url = `{{bhost}}/vod/search/page/{{page}}/tid/4/wd/{{key}}.html`;
} else if (a == "写真") { ... tid/5 ... }
else if (a == "视频") { ... tid/2 ... }
else if (a == "动漫") { ... tid/1 ... }
else if (a == "有声") { ... tid/3 ... }
```

要点：
- **searchUrl 用 `@js:` 整段产出「含 `{{}}` 的模板串」是可行的**（返回的是字符串，Legado 会再走一次 AnalyzeUrl 模板替换）。这与「searchUrl 返回 `@js:` 代码串会静默失败」那条经验**不冲突**——那条讲的是**返回里没有可求值结果、整条被当相对路径**的另一种错法；这里返回的是一段**带 `{{}}` 的完整 URL 文本**，落在合法用法内。
- 保守起见也可写成 `{{ ...三元表达式... }}`，但六个分支用三元会很长，`@js:` 更好读。
- 老坑提醒：**searchUrl 千万别返回「裸 JS 代码字符串」**，否则 Legado 会把结果当相对路径拼成 `https://api/...`。

### 4.3 ruleToc.chapterList —— 这里才是改 `book.type` 的地方

这是整个模式最**关键也最容易漏**的一步。

```javascript
// ruleToc.chapterList
<js>
r = result.match(/a="([^"]+)"/)[1];
java.base64Decode(r);
</js>
.chpterlist@.list@a.0||h1.0
@js:
a = source.getVariable();
if (a == "小说" || a == "") {
  java.longToast("已切换到小说模式");
  book.type = 8;
} else if (a == "漫画" || a == "写真") {
  java.longToast("已切换到图片模式");
  book.type = 64;
} else if (a == "视频" || a == "动漫") {
  java.longToast("已切换到视频模式");
  book.type = 8;
} else {
  java.longToast("已切换至音频模式");
  book.type = 8;
}
result;
```

**为什么必须在这里改 type？** 见 `方法-视频书源完全指南.md` 铁律：

> `WebBook.getChapterListAwait()` 每次刷目录都会先 `book.removeAllBookType()` 再 `addType(bookSource.getBookType())`，**把详情页 `init` 里设的 type 冲掉**。

所以「动态改 type」的唯一安全落点是 **`ruleToc.chapterList` 里再设一次**。书源顶层 `bookSourceType=0` 是静态值，靠不住，必须在 chapterList 里按模式覆写。

`book.type` 位掩码（LegadoTeam 版 `BookType.kt`）：

| 值 | 含义 | 阅读器 UI |
|---|---|---|
| 4 | video | 视频播放器 |
| 8 | text | 文本阅读 |
| 32 | audio | 音频播放 |
| 64 | image | 图片列表（ImageColumn） |

> 本源「有声」也给了 8（文本），配合正文返回 `<video>` HTML 由内置浏览器播放，而不是走 `audio` 原生音频模式。这是**刻意取舍**：走 audio 模式正文必须返回**纯 URL**，而本源还要显示文字说明，所以用 HTML+浏览器方案。想走原生音频就 `book.type=32` 且正文只返回 URL。

### 4.4 ruleContent —— 五分支（全源最复杂字段）


## 5. 三种「载体」写法

### 5.1 小说 → 直接把 HTML 片段交给阅读器

```javascript
java.getString(".module-novel-detail@.content@p@html", result)
```
返回段落 HTML，阅读器按文本渲染。**注意** `java.getString(rule, html)` 是「对给定 HTML 跑一次规则」的官方两参用法，比手动 `Jsoup.parse` 更省事。

### 5.2 漫画 / 写真 → `<img>` 串（**必须双引号！**）

```javascript
java.getString(".module-player-cartoon-list@.list@img@html", result)
```

关键约束（来自 `方法-图片不显示排查总表` / huangguo 案例）：

- **LegadoTeam 官方 `AppPattern.imgPattern` 形如 `<img[^>]*src="([^"]*...)"[^>]*>`，硬性要求 `src` 用双引号**。若站点是单引号/无引号，`@html` 直接产出原样就会**匹配不到 → 图片列空白**。
- 稳妥做法：不要直接吐 `@html`，而是 `@js:` 里 select 出 `img` 元素、**自己拼** `<img src="...">`（`String.fromCharCode(34)` 生成双引号），再返回。即：

```javascript
else if (a == "漫画") {
  var Q = String.fromCharCode(34);
  var imgs = Packages.org.jsoup.Jsoup.parse(String(result)).select(".module-player-cartoon-list .list img");
  var out = [];
  for (var i = 0; i < imgs.size(); i++) {
    var s = String(imgs.get(i).attr("data-original") || imgs.get(i).attr("src"));
    if (s) out.push("<img src=" + Q + s + Q + ">");
  }
  result = out.join(String.fromCharCode(10));
}
```

- 图片懒加载站点常把真链放 `data-original` / `data-src`，`src` 是占位图。**优先 `data-original`，退回 `src`**。
- 详情/搜索列表的封面同理，`ruleSearch.coverUrl` 用 `img@src` 或 `img@data-original`。

### 5.3 视频 / 动漫 → `player_aaaa` JSON → `data:` 页面 → 内置浏览器

站点把播放器配置塞在页面 JS 里：

```javascript
p = JSON.parse(result.match(/player_aaaa=({[^<]+)/)[1]);
// p.url = 播放地址（m3u8/mp4）；p.vod_data.vod_pic = 海报
```

然后**自造一个最小 HTML 播放页**，base64 后走 `data:` URL：

```javascript
html = java.base64Encode(`<!DOCTYPE html><html lang="zh-CN"><head>
<meta charset="UTF-8"><meta name="viewport" content="width=device-width,initial-scale=1">
<title>{{book.name}}</title>
<style>*{box-sizing:border-box}html,body{margin:0;width:100%;height:100%;background:#000}
body{display:flex;align-items:center;justify-content:center}
video{display:block;width:100%;max-height:100vh;background:#000}</style>
</head><body>
<video src="${p.url}" poster="${p.vod_data.vod_pic}" controls muted playsinline webkit-playsinline></video>
</body></html>`);
dataUrl = 'data:text/html;base64,' + html;
java.startBrowser(dataUrl, title);      // ★ 内置浏览器打开
java.toast('正在加载视频...');
result = ' \n\n【刷新正文】跳转播放\n不要相信且不要点击视频里的任何广告，误触后请立即返回\n🔗直链:\n' + p.url;
```

为什么这样写：
- **视频播放器必须是 App 内的 WebView/浏览器**——有些站的 m3u8 分片需要浏览器环境（Cookie/JS 校验），ExoPlayer 直拉会 403（对照 huangguo.video 三层防盗链）。
- `java.startBrowser(url, title)` 在**规则上下文**里可用（注意：在 useweb 页面桥里不可用，桥的 `activity=null`，见 `方法-简介useweb内嵌页面与浏览器调起.md`）。这里是 ruleContent 规则环境，OK。
- `data:text/html;base64,...` 让 WebView **无需联网加载页面**，只需拉视频流，最稳。
- `muted` + `playsinline` 是移动端自动播放/内联播放的通行组合。
- 正文返回值（`result = ...`）是给阅读器看的**文字说明 + 直链兜底**；用户「刷新正文」会重新触发播放。这是「正文不承载内容、只承载播放动作」的典型手法，和 `方法-视频书源完全指南.md` 里「正文规则留空 ⇒ 直接 return chapterUrl 当播放地址」是同一思路的富化版。

> ⚠️ `data:` URL 有长度上限（Chrome 约 2MB，实际 WebView 更保守）。播放页极简即可，**不要把海报 base64 塞进去**，海报用 `p.vod_data.vod_pic` 的**网络地址**（`poster` 属性）。

### 5.4 有声 → 直链 + `<video>` 兜底

```javascript
p = result;                             // 站点把音频直链直接给到正文页
html = java.base64Encode(`...<video src="${p}" controls muted playsinline ...></video>...`);
dataUrl = 'data:text/html;base64,' + html;
java.startBrowser(dataUrl, title);
result = ' \n\n【刷新正文】跳转播放\n...\n🔗直链:\n' + p;
```

用 `<video>` 标签播音频是「一个标签通吃音视频」的省事做法。**想走原生音频后台播放**就改 `book.type=32` + 正文 `return p`（纯 URL）——但代价是**拿不到任何文字界面**。

## 6. 加密/混淆：`a="..."` base64 中间层

详情页/目录/正文的入口都藏在一段被 base64 包裹的 JS 变量里：

```javascript
// ruleBookInfo.init
r = result.match(/a="([^"]+)"/)[1];
java.log(java.base64Decode(r));
```

```javascript
// ruleToc.chapterList / ruleContent 第一段：先解出真实内容页 HTML
r = result.match(/a="([^"]+)"/)[1];
java.base64Decode(r);
```

要点：
- **`ruleBookInfo.init` 负责「解一次拿到真实内容页 URL 或 HTML 里的 token」**；目录/正文再次 base64 解出正片 HTML。
- `init` 里 `java.log(...)` 是调试痕迹，正式源可以留着（无害）或删掉。
- 正则 `a="([^"]+)"` 很宽松，**站点改属性名就废**——生产源建议改宽：`/a\s*=\s*"([^"]{20,})"/` 或 `/\w+="([^"]{40,})"/`（base64 串一般较长，用长度卡一下更稳）。

## 7. 域名管理：`jsLib` 里的 `bhost`

```javascript
// jsLib
let bhost = "https://xn--9mc3qsju6x-gp7uy87mpduvnq.jzhtpgcsl.com";
```

- **所有 URL 都写成 `{{bhost}}/path`**，换域名只改一行。
- 域名是 **punycode（`xn--` 开头）**——说明是中文域名或含特殊字符的域名被编码过。**照抄即可**，不要手动还原成中文。
- 更稳的写法见 `方法-URL模板与DNS选线` / `方法-发布页线路轮换与登录界面测速选线.md`：**优先相对路径自愈**（列表返回相对 URL 让 `isUrl` 拼当前域），域名轮换时书架不死。
- 如果这类站域名轮换频繁，把 `bhost` 升级为**登录界面域名选择按钮组**（mdcmai 模式），收益极大。

## 8. `bookSourceUrl` 不是 URL 的取舍

本源顶层 `bookSourceUrl = "X夜社"`（不是网址）。影响：

| 能力 | 是否可用 | 说明 |
|---|---|---|
| 手动搜索 | ✅ | `searchUrl` 自带绝对 URL，不依赖顶层 |
| 发现 | ✅ | `exploreUrl` 同上 |
| 详情/目录/正文 | ✅ | 全部走解析出的绝对 URL |
| **书架「换源」按域名匹配** | ❌ | 没有可匹配的域名 |
| **`legado://import/addToBookshelf` 三级匹配** | ❌ | 第三级遍历 `bookUrlPattern` 会失败 |
| 书籍 URL 归属判断 | ❌ | 同上 |

**结论**：能跑，但**牺牲了跨源换源与深链导入能力**。正经做源应写真实主域，例如 `https://主域.tld`，并配 `bookUrlPattern`。本源能这么写多半是**故意规避书籍归属/防抄袭**，移植时请评估。

## 9. 制作清单（Checklist）

新建同类源按此顺序写，少走弯路：

1. **定域**：写 `jsLib` 的 `bhost`；确认主域可达（HTTP/HTTPS、UA、CF/WAF 状态）。
2. **定模式清单**：列出形态 → 变量值 → 列表路径 → 搜索参数（tid/分类号）→ 正文载体。
3. **写 `loginUi` + `loginUrl`**：按钮组 + `set_laiyuan()`。
4. **写 `exploreUrl`**：每模式一套 `{title,url,style}`；一级整行、二级 0.4；空位用空对象占。
5. **写 `searchUrl`**：每模式一个接口；确认列表容器选择器。
6. **写 `ruleSearch`**：`bookList` 先 base64/中转解出真实 HTML，再选 `条目`；字段（name/bookUrl/coverUrl/kind/intro/lastChapter）全用 `@js:` 直取 jsoup，**绕开 AnalyzeByJSoup 状态污染**（见下）。
7. **写 `ruleBookInfo`**：`init` 解 `a="..."`；`name/author/coverUrl/intro/kind/lastChapter`；`kind` 用**逗号分隔**（原生芯片可点搜索）。
8. **写 `ruleToc.chapterList`**：解 base64 → 选章节 → **`@js:` 里按模式设 `book.type`**。
9. **写 `ruleContent.content`**：五分支（HTML / img / data 播放页 / 音频 data 页）。
10. **写 `header`**：手机 UA + `Accept-Language`（这类站常有手机模板）。
11. **跑校验**：`check_source` 1/1 → `debug_source` 六模式各测一本 → 保存后 `get_source` 回读逐字段核对。
12. **提醒用户实测**：视频/音频分支必须在**真机**看内置浏览器是否弹出并播放。

## 10. 避坑清单

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| K1 | **模式变量只在 `bookSourceType` 静态设 type** | 漫画模式仍按文本渲染 / 视频不弹播放器 | 必须在 `ruleToc.chapterList` 里再设一次 `book.type`（WebBook 刷目录会重置） |
| K2 | **JsNull truthy** | `if(a)`、`a||"默认"` 全失效，模板整段被吞 | 读后立刻 `String(a)` 判三态 |
| K3 | **`getVariable/setVariable` 版本差异** | 换 App 版本后模式切换无效 | 双通道 `try{getVariable()}catch(e){get()}` |
| K4 | **`<img>` 无双引号** | 漫画/写真正文空白，图片不显示 | 拼 HTML 时用 `String.fromCharCode(34)` 造双引号；或按官方 `imgPattern` 对齐 |
| K5 | **封面用 `img@src` 但站点懒加载** | 封面全是占位图 | 优先 `data-original` / `data-src` |
| K6 | **视频走 ExoPlayer 直拉 m3u8** | 黑屏 / 403 | 用 `data:` 页 + `java.startBrowser` 交给 WebView |
| K7 | **`data:` 页里内嵌 base64 海报** | 页面过长、加载慢甚至失败 | 海报用网络 URL（`poster` 属性） |
| K8 | **`java.startBrowser` 用在 useweb 桥里** | 点了没反应（`activity=null` 静默失败） | 桥里只能用 `java.openUrl`；`startBrowser` 只在规则上下文可用 |
| K9 | **searchUrl 返回裸 JS 代码串** | 静默失败，URL 被拼成 `https://api/...` | 返回**含 `{{}}` 的完整 URL 文本** |
| K10 | **`bookSourceUrl` 写非 URL** | 换源/深链导入失败 | 评估是否真的需要；正经源写真实主域 + `bookUrlPattern` |
| K11 | **列表字段混用 CSS 多条规则** | 列表出 20 条但「书籍总数:1」 | 列表字段全改 `@js:` 直取 jsoup（AnalyzeByJSoup 状态污染） |
| K12 | **`kind` 用复杂拼接** | 分类芯片空白 | `kind` 只放纯 `.text()`；状态文案并进 `intro`（kind 走 `getStringList` 特殊路径） |
| K13 | **模式切换后不刷发现** | 用户以为没生效 | toast 明确提示「请刷新发现」；有条件补 `java.refreshExplore()` |
| K14 | **`ruleContent` 忘了返回 `result`** | 「内容为空」异常 | JS 块末尾必须有 `result;`（Rhino completion value） |
| K15 | **IIFE 里漏 `return`** | 字段静默为空 | 用 IIFE 必须显式 `return X;`，别靠表达式语句 |
| K16 | **base64 正则太窄** | 站改属性名后全线崩 | 用长度卡边界 `/a\s*=\s*"([^"]{20,})"/` |

## 11. 验证方法论

### 11.1 分层验证

1. **顶层**：`check_source` 必须 1/1。
2. **字段级**：`save_source` → `get_source` 回读，逐字段比对本地 JSON（本行当铁律，见 `方法-书源交付质量闭环.md`）。
3. **功能级**：`debug_source` 六模式各跑一本：
   - 小说：`debug_source(key="书名")` 搜索 → 详情 → 目录 → 正文
   - 视频/动漫：**必须真机看 `java.startBrowser` 是否弹出并播放**
   - 有声：同上
4. **回归级**：改任一分支后，**其余五个模式必须重测**（模式变量是全局的，一处 JS 改坏全源崩）。

### 11.2 模式变量验证（关键）

```javascript
// 在 eval_js 里（绑定本源 URL）：
var tests = ["", "小说", "漫画", "写真", "视频", "动漫", "有声"];
for (var i = 0; i < tests.length; i++) {
  source.setVariable(tests[i]);
  java.log("mode=" + tests[i] + " -> explore=" + String(source.getVariable()));
}
```

再对每个模式分别跑 `debug_source`（发现/搜索），确认：
- 返回的 URL 落在预期的 `/nfilter/` 或 `/filter/` 路径
- `book.type` 被正确设置（可在 chapterList 里 `java.log(book.type)`）

### 11.3 视频播放链路验证

`java.startBrowser` 无法在沙盒里验证，只能在**真机 eval_js** 里直接跑：

```javascript
// 伪造成 ruleContent 上下文，直接调起播放页
var p = {url: "真实m3u8", vod_data: {vod_pic: "真实海报"}};
var html = java.base64Encode("<html>...<video src='" + p.url + "' controls></video>...</html>");
java.startBrowser("data:text/html;base64," + html, "测试播放");
```

能弹出内置浏览器并播放 = 视频分支通。

### 11.4 用 `java.webView` 做渲染探针（可选）

若页面结构存疑，可用 `java.webView(html,url,js)` 在真机 WebView 里跑一段表达式，确认 DOM 是否如预期（详见 `方法-简介useweb内嵌页面与浏览器调起.md`）。

## 12. 移植模板（新站改造点）

拿到一个新「聚合站」，按此清单改本源即可：

| 改造项 | 要改什么 |
|---|---|
| `jsLib.bhost` | 换成新站主域（punycode 照抄） |
| `header.User-Agent` | 换新站手机 UA（若有 UA 模板区分则必须换） |
| `exploreUrl` | 六模式的列表路径 + 分类号（`nfilter/N`、`filter/N`） |
| `searchUrl` | 六模式的搜索路径 + `tid/N` |
| `ruleSearch.bookList` | 结果卡片选择器（`.module-items@a` 类） |
| `ruleSearch` 字段 | name/bookUrl/coverUrl/kind/lastChapter 选择器 |
| `ruleBookInfo.init` | `a="..."` 正则（可能换属性名/换混淆方式） |
| `ruleBookInfo` 字段 | `.dinfo` 等骨架选择器 |
| `ruleToc.chapterList` | 章节列表容器 + `book.type` 映射 |
| `ruleContent.content` | 五分支的内容区选择器 + 视频 JSON 变量名（`player_aaaa` 可能换名） |
| `loginUi/loginUrl` | 按钮组基本不动，仅变量名/提示语可调 |

**最少改动量**：只换 `bhost` + `exploreUrl` + `searchUrl` + 结果/章节选择器，就能让一个「同程序不同站」的聚合源跑起来。

| 站点 | 形态 | 模式数 | 特点 | 文档 |
|---|---|---|---|---|
| **X夜社**（`bookSourceUrl=X夜社`） | 小说/漫画/写真/视频/动漫/有声 | 6 | 本源范本；`data:` 播放页；punycode 域名；顶层非 URL | 本篇 |
| s.wendulou.com | 小说 | 换源（非模式） | 单书多来源切换（`book.variable("custom")` + `preUpdateJs=refreshTocUrl`） | `方法-APP接口聚合书源拆解.md` |
| rrssk 聚合 | 小说 | 26 域名 | 单源聚合多域名（`HOST_TEMPLATE_MAP`） | 记忆 6 |
| novelServices 四平台 | 小说/听书/漫画/短剧 | 4 平台 | JWT + 配额 + `video_list` 多结构 | 记忆 13 |
| mdcmai | 视频 | 5 域名 | 登录界面域名切换 + 测速 | `方法-发布页线路轮换与登录界面测速选线.md` |

**「模式切换」与「换源/换域名」的区别**：
- **模式切换**（本篇）：切换**内容形态**，影响搜索/发现/正文结构，改变 `book.type`。
- **换源**（wendulou）：同一本书换**数据来源**，书本身不变。
- **换域名**（mdcmai/hlwf6）：同一站换**接入线路**，内容不变。

三者可以叠加：`换域名 → 选模式 → 换源`，是聚合型源的终极形态。

## 14. 通用结论（写给未来的自己）

1. **单源多模式的本质** = 一个全局变量 + 四处 JS 分支 + 动态 `book.type`。
2. **`book.type` 必须在 `ruleToc.chapterList` 里设**，别信静态 `bookSourceType`。
3. **视频/音频一律用 `data:text/html;base64,` + `java.startBrowser`**，绕开 ExoPlayer 的防盗链/环境依赖。
4. **图片形态必须保证 `<img src="...">` 双引号**，否则白屏。
5. **列表字段一律 `@js:` 直取 jsoup**，绕开 AnalyzeByJSoup 状态污染。
6. **模式变量读后必 `String()`**，绕开 JsNull truthy。
7. **模式切换一定要给用户明确反馈**（toast + 「请刷新发现」），否则体验像坏了。
8. **改一个分支要重测全部模式**，全局变量是全源共享的。
