# 方法-单集视频目录污染与相关推荐池识别（黄果短剧 v9.5）

> 案例来源：黄果短剧书源 v9.5 修复「AI换脸 / AI魔改 两个发现列表，每本书点进去的详情页(目录)都是同一个」。
> 适用范围：一切「列表页正常、详情页书名正常、但目录/正文像别的内容」的视频/图文书源。

## 1. 症状与用户观感

- 发现页「AI换脸」「AI魔改」每个列表里的书名、封面各不相同；
- 但点进任何一本书，目录都是同一批 7 个章节，章节名与本书标题毫无关系；
- 播放出来的视频内容也与本书无关。

## 2. 排查链（对照实验逐步收窄）

| 步骤 | 实验 | 结论 |
|---|---|---|
| 1 | 沙盒抓列表页 SSR，正则模拟 ruleExplore.bookUrl 逐卡提取 | 每卡 href=/video/N/ 各不相同（8/8 全异）→ 列表规则无「整页首个匹配」问题 |
| 2 | 探针源：ruleExplore.bookUrl 返回 `'PROBE|'+h.substring(0,60)` | ① result=整卡 HTML；② 每卡独立（首卡 item-id=10520）；③ **bookUrl 返回相对路径会被 Legado 用列表页 URL 拼接**（/ai-huanlian/PROBE\|...）→ 主源返回绝对路径是必要的 |
| 3 | debug_source 发现页→详情→目录全链 | 详情书名/封面正确 ⇒ 详情规则没问题；**目录首章=「AI换脸明星李知恩」/video/219/，与本书(10520)无关** ⇒ 问题在目录 |
| 4 | 对比两本书的"目录"集合 | 10519 与 10520 的目录池 **7/7 完全相同**(219,228,198,197,205,7183,202) ⇒ 池化实锤 |

## 3. 根因

站点视频详情页底部有「猜你喜欢/为你推荐」区块：`<div class="hg-card-grid" id="related-grid">`，内含 7 张同分类推荐卡。
同分类下**每本书的推荐池几乎相同**（随机池+同分类过滤），这就是「每本书详情都一样」的观感来源。

chapterList 旧逻辑：

```js
var li=h.indexOf('hg-list-page');
var body=(li>=0)?h.substring(li):h;   // ← 无锚点时取整页
// 用 data-track-title 正则扫 body ⇒ 把 related-grid 的 7 张推荐卡当成章节
```

- 连续剧详情页有 `data-track-total-episode` → 走集数生成分支，不受影响；
- **单集视频（AI换脸/AI魔改 全是单集）无该属性 → 掉进兜底 → 整页正则 → 推荐池入目录**。

## 4. 修复：chapterList 三分支（语义兜底而非正则兜底）

```js
var m=h.match(/data-track-total-episode="(\d+)"/);
if(m){ /* 连续剧：按集数生成 第N集 → /video/ID/ep-N/ */ }
var li=h.indexOf('hg-list-page');
if(li<0){
  // 单集视频：目录=1章，章节URL=详情页本身(去 /ep-N/ 尾巴,第1集用根路径)
  list.add('第1集'+TAB+vr2+'/');
  return list;
}
// 专题页：有 hg-list-page 锚点后才扫 data-track-title 视频卡
```

判据选取（本项目实测）：
- 视频详情页：无 `hg-list-page`、无 `data-track-total-episode`，只有 `related-grid`；
- 专题详情页：**有** `hg-list-page`（其视频列表就在 `.hg-list-page .hg-card-grid`）；
- 故 `li<0` 是单集视频的可靠判据。

## 5. 目录污染识别三征兆（通用）

1. 章节名与书名完全无关（不同 IP/不同剧名）；
2. 换一本书，目录章节集合几乎不变（池化）；
3. 章节 URL 指向其他内容 ID（/video/219 而非本书 10520）。

任一征兆出现，先怀疑「兜底分支扫到了页面上的推荐/相关区块」，而不是怀疑列表规则。

## 6. 附带经验

- **Rhino 对 java.util.List 的 `.length`**：新版 Rhino 的 NativeJavaList 会把 `.length` 映射为 `size()`，旧判空 `if(!list.length)` 实际有效；但显式 `list.size()===0` 更清晰可靠，不依赖 Rhino 版本行为。
- **save_source 手工转录必损坏**：本次第二轮 save_source 手工重打 JSON，产出 `FQ siteName(2)`（丢下划线）、`parseInt(m[1];`（丢括号）、loginUi 尾部丢 `{`、混入其他源的选择器等多处损坏。**必须从工作区文件 `cat` 原文逐字节拷贝进参数**，禁止手打大 JSON。保存后必须 get_source 回读抽查关键函数名。
- **探针法一次实锤三件事**：bookUrl 写成 `'PROBE|'+h.substring(0,60)`，一次 debug 同时验证 result 形态、逐卡独立性、相对 URL 拼接行为。测完即删探针源。
- **对照实验要含"反向验证"**：本次 Python 模拟"逐卡 bookUrl 全异"就是反向验证组——若模拟也全同，则根因在列表规则；模拟全异+App 全同 ⇒ 根因在下游（目录），收窄方向完全不同。
