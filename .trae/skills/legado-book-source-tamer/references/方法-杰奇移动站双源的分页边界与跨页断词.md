# 泡书吧 / 溜达小说双书源经验总结（2026-11-25）

## 1. 站点共性

- 两站均为杰奇系移动小说站，UTF-8，游客可搜索/阅读，不需要登录；因此未添加登录 UI，也没有发布页线路。
- 泡书吧：`http://m.paoshu9.net`，搜索 GET `/modules/article/waps.php`，详情 `/info-<id>/`，目录正序 `/wapbook-<id>_1/`，目录反向默认页每页 20 章且共 302 页。
- 溜达小说：`http://m.txtshuku.info`，搜索 POST `/search.php`，详情 `/<id>/`，目录 `/<id>/all<N>.html`，每页 20 章。

## 2. 新发现与处理

### 2.1 Legado 内置 XPath 不支持 `normalize-space()`

真机报错：`NoSuchFunctionException: not support function: normalize-space`。因此“按下一页文字取链接”不能用 XPath 谓词实现，改为正文 HTML 上正则匹配 `<a ...>下一页</a>`。

### 2.2 越界页返回 200 + 最后一页内容

两站分类/榜单请求超过末页时返回 HTTP 200，页面自身仍显示“第50/50页”，并重复最后一页 20 本，原生 `{{page}}` 会无限翻页。

处理：`ruleExplore.bookList` 在 `@js` 中同时读取页面自身“第X/Y页”和 `baseUrl` 的请求页码；请求页码大于站点总页数时返回空 Java List。没有写死页数，站点新增书籍后会自动继续。

### 2.3 杰奇移动模板的畸形 `<p><a><h2>` 破坏 `nth-of-type`

浏览器/Jsoup 解析后 `p:nth-of-type(N)` 与源码标签序号错位，字段为空或错位。处理方法：

- 有链接的字段用 href 特征选择器，例如 `a[href^="/author/"]`、`a[href^="/list/"]`。
- 无链接的搜索字段在元素 `@js` 环境遍历 `src.select('p')`，按文本前缀 `作者：`、`分类：`、`最新章节：` 取值。
- 溜达小说详情直接使用 `og:novel:author` / `og:novel:book_name` / `og:novel:latest_chapter_name` meta，避开 DOM 位置。

### 2.4 Cloudflare JS 挑战：OkHttp 403，WebView 成功

泡书吧 App 搜索首次 OkHttp 返回 403 `Cf-Mitigated: challenge`，沙盒直连成功但真机失败。解决：

- `searchUrl` 返回 URL 选项 `,{"webView":true}`。
- 书源 header 的 UA 对齐真机 WebView UA（`java.getWebViewUA()` 实测值）。
- `ruleSearch.bookList` 在 `result` 无结果列表时再用 `java.webView` 取一次，并用 `org.jsoup.Jsoup.parse` + `java.util.ArrayList` 返回；兼容 E 版。

### 2.5 章内分页在句中硬切

两站每章 3 页左右，且可能在“一/一般人”“大病/到现在”中间断开。Legado 原生 `nextContentUrl` 会拼接换行，形成错字。

处理：`ruleContent` 用 `@js` 自行跟随站点“下一页”，逐页清理页码行、提示行、最新网址行；跨页时若上一页末尾不是句读标点，去掉末尾 `</p>`/`<br>` 和下一页开头 `<p>`/`<br>` 后无缝拼接。循环以站点“无下一页链接”和已访问 URL 集合终止，不设页数上限。

### 2.6 全局 `concurrentRate` 会拖垮长篇目录

`concurrentRate=3/1000` 是整源限速。泡书吧 302 页目录在 E 版上曾 295 秒只取到 161 页，逼近 LAN 刷新接口约 300 秒上限。用户要求“搜索不要过于频繁”，正确做法是把节流放在 `searchUrl` 的 3 秒时间戳门里，不放全局，目录/正文不受拖累。

### 2.7 官方串行目录循环的脆弱点

`BookChapterList.kt` 的串行分支中，只要某次 `res.body` 为空，当前 `nextUrl` 就被跳过并结束整条链，且不会显式报错。泡书吧长目录因此曾分别停在第 47 页、第 161 页。给 `nextTocUrl` 和 `tocUrl` 加 URL 选项 `{"retry":2,"timeout":15000}` 可缓解；站点当前网络若持续 timeout 仍无法在本轮完成完整 302 页抓取。

### 2.8 `java.ajaxAll` 返回的是 StrResponse 对象

实验性分批并发目录时发现 `String(rs[k])` 是 `Response{protocol=..., code=200...}`，必须调用 `rs[k].body()`（Rhino 中 body 是方法）。但 6 路并发在本站反而触发明显延迟，最终撤回并发方案，保留温和串行；不要把并发当默认优化。

### 2.9 双版本兼容

- E 版目录 `chapterList` 不能返回 Rhino `NativeArray`，统一返回 `new Packages.java.util.ArrayList()` 并 `add(Element)`。
- E 版不存在可靠的 `java.getElements` 用法，发现页守卫和搜索列表均用 `org.jsoup.Jsoup.parse` + Java ArrayList。
- 字段规则对 Element 使用 CSS 选择器，LT/E 都能解析。

## 3. 验证结果

- Team 版：MCP `save_source` 正式保存；`debug_source` 搜索、详情、发现、目录、正文通过；JSON 字段回读与本地一致。
- E 版：LAN 1125 `/saveBookSource` 单源保存，回读 0 字段差异；WebSocket `/bookSourceDebug` 搜索、详情、发现、目录、正文通过。
- 溜达小说《夜无疆》目录 904 章全量通过，首章正文 3 页断字修复通过。
- 泡书吧《武炼巅峰》目录首/中/尾页链接正确，正文 3 页断字修复通过；302 页全量在当前网络下受站点间歇 timeout 影响未跑完。

## 4. 实测建议

1. 先在 Team 版搜索“武炼巅峰”/“夜无疆”，确认搜索结果。
2. 打开详情并进入目录，泡书吧长篇目录如因站点超时中断，等待网络稳定后刷新目录。
3. 打开《武炼巅峰》第一章与《夜无疆》第一章，确认跨页处文字连贯。
4. E 版重复上述步骤；E 版仅按单源保存，不要读取全部书源。
