# 光遇聚合（🔅光遇聚合）书源架构拆解

> 适用对象：想做「云端代理 + 多平台聚合」型书源的开发者。
> 源信息：bookSourceUrl=`光遇聚合`，bookSourceName=`🔅光遇聚合(26.8.16)`，bookSourceType=0
> 关键尺寸：jsLib=146621 字符，exploreUrl=10532 字符，searchUrl=604 字符，ruleToc.chapterList=5897 字符，ruleContent.content=6744 字符，loginUrl=7361 字符，loginUi=6505 字符，ruleBookInfo.init=1830 字符，ruleBookInfo.intro=3606 字符，ruleToc.chapterUrl=894 字符，ruleSearch.bookList=285 字符
> 抓取方式：通过 `mcp__legado3__eval_js`（绑定书源 url）调用 `source.<字段>.substring()` 分段取出

---

## 1. 顶层定位：它和「普通单站书源」有什么不一样

**普通单站书源**：
- 规则直接描述某个目标站点的 HTML/JSON 结构
- 搜索/详情/目录/正文都走目标站点的真实 URL
- jsLib 主要承担「辅助加签/补 Cookie/二次解析」

**光遇聚合型书源**：
- 全部搜索/详情/目录/正文请求都先**打包成 `data:;base64,XXX,{"type":"..."}` 伪 URL**（"gysearch / gycatalog / gydetail / gycontent" 协议）
- 本地 jsLib 只是一个**协议转换器**：把页面级规则的结果 → 编码成 base64 → 拼成 data: URL → 丢给云端代理
- 云端代理（`BaseUrl()` 域名）才是真正干活的：它解析上游网站（番茄/七猫/QQ阅读/书旗/塔读 等），回吐统一 JSON
- 客户端用 `JSONPath`（`$.book_name`、`$.data`、`$.author` 等）解析云端 JSON，再丢回 Legado 走标准渲染

**所以一句话：光遇聚合 = 「客户端协议代理 + 云端 HTML→JSON 转译 + 客户端 JSONPath 渲染」的三段式聚合。**

这条路径的最大优点是「源切换/加新平台/修反爬」全都改云端，本地书源无需变一个字。

### 机制 A：data: URL 协议 + type 字段路由

光遇聚合的 `searchUrl` / `ruleToc.chapterUrl` / `ruleBookInfo.tocUrl` / `ruleSearch.bookUrl` 全部是 `<js>` 块，结果是一个 `data:;base64,...` URL。

**ruleToc.chapterUrl**（每章拼接协议）核心：
```js
<js>
```

- `java.hexDecodeToString(result)` 是把 data: URL 里的 hex 编码解开（`java.base64Encode` 的对偶）

- 嵌套 `js` 字段的 `book ? result : '...'` 是「当前章节已缓存则不重拉」懒加载模板

### 机制 B：request() 统一网络层 + 自动切线

`request()` 是光遇聚合最重要的 helper，定位等同于 axios：

```js
function request(url, method, body, req, index) {
    if (method == undefined) method = 'GET';
    if (body == undefined) body = {};
    if (req == undefined) req = true;
    if (index == undefined) index = 0;

    let urla = url;
    if (!url.includes('http')) {
        urla = this.BaseUrl() + url;     // 相对路径自动拼 BaseUrl
    }

    let device = '';
    try { device = java.androidId(); } catch { try { device = java.deviceID(); } catch {} }

    let qttoken = this.getToken();
    let options = {
        method: method,
        headers: {
            'cookie': `qttoken=${qttoken};deviceId=${device};`,
            'Content-Type': 'application/json'
        },
        body: JSON.stringify(body)
    };

    urla = `${urla},${JSON.stringify(options)}`;   // ← Legado ajax 的"URL+options"双段协议
    java.log(urla);

    if (!req) return urla;                  // 仅生成请求 URL 不真发

    const startTime = new Date().getTime();
    let data;
    let requestTimedOut = false;
    let requestFailed = false;

    try {
        data = java.ajax(urla);
        JSON.parse(data);                   // 顺便验证 JSON 合法性
    } catch (error) {
        requestFailed = true;
    } finally {
        const duration = new Date().getTime() - startTime;
        let timeout = parseInt(this.getVariable('超时时间') || '10') * 1000;
        if (!requestFailed && duration > timeout) requestTimedOut = true;
    }

    if (requestTimedOut) {
        let timeoutSwitch = this.getVariable('超时自动切换') || 'true';
        if (timeoutSwitch != "false") {
            this.switchToNextLine('⚠️当前线路较慢');
        }
        return data;
    }
    if (requestFailed) {
        let hostsbk = this.getVariable('云端配置')['hosts'] || hosts;
        let autoSwitch = this.getVariable('自动切换') || 'true';
        if (hostsbk.length > index && autoSwitch != "false") {
            this.switchToNextLine('❌线路报错');
            return this.request(url, method, body, req, index + 1);   // 递归重试
        } else {
            return "";
        }
    }
    return data;
}
```

**核心设计**：
- `BaseUrl()` 永远返回当前活跃线路（`getVariable('线路')`）
- 失败/超时自动 `switchToNextLine()` 切到 hosts 列表下一条
- index 递归保护：避免 hosts 用尽后无限循环
- `request(url, method, body, false)` 模式：只生成 URL 不发请求（用于"动态拼好后等下一阶段"）

**多 host 列表写法**：
```js
let hosts = [
    'https://v1.gyks.cf',
    'https://v2.gyks.cf',
    'https://v3.gyks.cf',
    'https://v4.gyks.cf',
    'https://v5.gyks.cf',
    'https://v6.gyks.cf',
    'https://v7.gyks.cf',
    'http://101.35.133.34:8888'
];
```

### 机制 C：变量系统（getVariable/setVariable）+ JSON 序列化

光遇聚合把所有用户配置都存为 `source.getVariable()` 的 JSON 字符串：

```js
// 读
function getVariable(k) {
    if (k == undefined) k = "";
    const { source } = this;
    let parsed = {};
    try { parsed = JSON.parse(source.getVariable()); } catch {}
    if (k == "") return parsed;
    let value = parsed[k];
    if (value == undefined) value = defaultConfig[k];
    return value != undefined ? value : "";
}

// 写
function setVariable(k, v, t) {
    if (t == undefined) t = true;
    const { source, java } = this;
    const vs = this.getVariable();
    vs[k] = v;
    source.setVariable(JSON.stringify(vs, null, 4));
    if (k != '云端配置' && t && k != '搜索关键词') {
        java.toast(`\n设置 ${k} 为 ${v}`);
    }
}
```

### 机制 D：检查点（loginCheckJs / 跨字段 state 传递）

**1) loginCheckJs 不存在**（光遇聚合 = null）—— 因为 token 来自 cookie，不需要登录检查。
**2) 跨字段 state 用 `java.put` / `java.get`**：

```js
// ruleToc.chapterList 的开头
let durChapterIndex = book.durChapterIndex;
java.put('book_id', book_id);          // 写
// ... 几屏后 ...
// ruleToc.chapterUrl 中
let book_id = java.get('book_id');     // 读
```

这是 Legado 提供的全局 put/get 内存 Map（key 自动转 String）。比"把 book_id 塞到 URL 里"或"重新调用 ruleBookInfo"都干净。

**注意**：
- 每次源重置（重启阅读/重载书源）put/get 表会清空
- put 的值在整个书源的字段间共享（search/explore/info/toc/content/init）
- 高频小数据首选 put，复杂数据用 `book.getVariable('custom')` 持久化

## 3. 进阶机制（4 个锦上添花）

### 3.1 checkEnv()：检测当前阅读版本

```js
function checkEnv() {
    const { java, source } = this;
    try { java.qread(); return "轻阅读"; } catch (e) {}
    try {
        if (typeof java.reLoginView == 'function') return "改版";
        new Packages.io.legato.kazusa.utils.TimeoutCancellationException('');
        return "改版";
    } catch (e) {}
    try { java.deviceID(); return "苹果"; } catch (e) {}
    if (typeof source.loginUi == 'function') return "安卓";
    return "改版";
}
```

**返回 4 个值**：
- `"轻阅读"`：开源 lyc 版（qread 探针）
- `"改版"`：legado-yes/legado-kazusa/legado 改版
- `"苹果"`：栖阅/橙柚等 iOS
- `"安卓"`：标准官方版

**典型用途**：段评气泡的 js 协议 vs click 协议切换、图片样式 TEXT vs FULL 切换、视频源不展示给 iOS 等。

```js
let islyc = checkEnv();
let jc = islyc == "改版" ? 'click' : 'js';   // 改版用 click 协议，其它用 js 协议
```

### 3.2 createFilter/createButton/createText/createSvg：发现页 UI 工厂

这 4 个 helper 把发现页按钮/选择器/输入框的 JSON 结构封成函数，避免在 exploreUrl 里手写大量样板。

```js
// select 选择器
function createFilter(title, chars, defaultVal, paramKey, size, viewName) {
    if (viewName == undefined) viewName = "'请选择类型'";
    return {
        title: title,
        type: "select",
        chars: chars,                       // 选项数组
        default: defaultVal,
        viewName: viewName,                 // 弹窗名
        action: `show(infoMap['${title}'],'${paramKey}')`,
        style: { layout_flexGrow: 1, layout_flexBasisPercent: size }
    };
}

// text 文本输入
function createText(title, action, defaultValue, size, viewName) {
    return {
        title, type: 'text',
        default: defaultValue || '',
        action,
        viewName: viewName || title,
        style: { layout_flexGrow: 1, layout_flexBasisPercent: size }
    };
}

// button 按钮
function createButton(title, action, size) {
    return {
        title, type: 'button', action,
        style: { layout_flexGrow: 1, layout_flexBasisPercent: size }
    };
}

// createSvg 段评气泡（核心！把 SVG 字符串 + 占位符 → data URL + 协议）
function createSvg(number, encodedUrl, sources) {
    var displayText = number > 99 ? "99+" : number.toString();
    let data = this.getVariable('段评设置');
    let svgstyle = data['段评样式'] || "0";
    let color = data['段评边框颜色'] || "#A7A7A7";
    let tccolor = data['段评填充颜色'] || "transparent";
    let fontcolor = data['段评字体颜色'] || "#A7A7A7";
    let zdy = svgs[0];
    try { zdy = data['自定义段评样式'][svgstyle] || svgs[0]; } catch {}
    const styleMap = { "0": svgs[0], "1": svgs[1], "2": svgs[2], "3": svgs[3], "4": svgs[4], "5": svgs[5] };
    let svg = styleMap[svgstyle] || zdy;
    svg = svg.replace('$color', color)
             .replace('$tccolor', tccolor)
             .replace('$fontcolor', fontcolor)
             .replace('$displayText', displayText);
    let islyc = this.checkEnv();
    let jc = islyc == "改版" ? 'click' : 'js';
    let style = data['气泡增大'] == "true" ? 'TEXT' : 'text';
    let encodedSvg = this.java.base64Encode(svg);
    return `data:image/svg+xml;base64,${encodedSvg},{"${jc}":"showCmt('${encodedUrl}', '${sources}' ,'段评')","style":"${style}"}`;
}
```

```js
const syncBookShelf = (book) => {
    if (!book) return;
    let book_order = book.order;
    if (book_order != 0) book_order = 1;   // 0=已读完 1=在读
    else return;
    if (moreSettings && moreSettings['同步书架'] != 'true') return;

    try {
        const ritem = item_id;
        let book_info = {
            book_name: book.name, author: book.author,
            thumb_url: book.coverUrl, book_id, tab, source: sources
        };
        book_info.read_status = book_order;
        book_info.last_chapter_item_id = item_id;
        book_info.last_chapter_title = chapter.title || "";

        // 先 check 是否已存在
        const checkResponse = request('/check_book_in_book_shelf', 'POST', {book_id, source: sources, tab});
        const check_data = parseJsonSafely(checkResponse);
        if (check_data.data.id) {
            book_info.id = check_data.data.id;
            request('/update_book_shelf', 'POST', book_info);    // update
        } else {
            request('/add_book_to_book_shelf', 'POST', book_info);  // add
        }
    } catch (error) {
        java.log(`同步阅读进度失败: ${error}`);
    }
};
```

**要点**：
- `book.order` 0/1/2 = 已读完/在读/未读
- 用 `moreSettings['同步书架']` 让用户在 UI 里关闭（默认关闭，符合隐私偏好）
- 只在 `book.durChapterIndex == chapter.index` 触发，避免每章重复推

## 4. 实战：写一个「光遇聚合型」新书源需要做哪些事

### 阶段 0：技术决策

| 决策点 | 单站型（不推荐） | 聚合型（光遇聚合风格） |
|---|---|---|
| 站点维护 | 每站改一次书源 | 改云端，客户端无感 |
| 反爬成本 | 客户端承担 | 云端统一处理 |
| 源体积 | 几 KB~几十 KB | 几十~几百 KB（含 UI） |
| 适合场景 | 单一小众站 | 主流付费站（番茄/七猫/书旗/塔读/QQ阅读等） |
| **不推荐场景** | 公开免费站 | 公开免费站（自己直接写更省事） |

### 阶段 1：搭云端

至少实现这些 endpoint（路径都是光遇聚合的，命名可换）：
- `GET /static/source_config/config.json`：返回 hosts + 平台列表
- `POST /login_api`：邮箱+密码 → {code, key, msg}
- `POST /user_api`：qttoken → 用户信息
- `GET /get_avatar`：qttoken → 头像昵称
- `GET /user_settings?set_type=legado_more|legado_para`：拉取用户设置
- `POST /user_settings`：保存设置
- `GET /discovestyle?source=&source_type=&tab=`：返回发现页分类按钮
- `POST /search?title=&tab=&source=&page=&disabled_sources=`：返回书列表
- `POST /detail?book_id=&source=&tab=&variable=`：返回书籍详情 JSON
- `POST /catalog?...`：返回章节列表 JSON
- `POST /content?...` / `POST /content?review=1`：返回章节正文
- `GET /get_review?book_id=&item_id=&ssionid=&source=`：返回段评气泡数据
- `GET /chapter_review_svg?book_id=&item_id=&source=&ssionid=&img=1`：返回 SVG
- `GET /online_video?...`：返回视频直链

## 5. 容易踩的坑

| 坑 | 表现 | 解决 |
|---|---|---|
| 1. `source.getVariable()` 返回 null | JSON.parse 崩 | 永远 `try/catch` 兜底回 `defaultConfig` |
| 2. `java.get('book_id')` 取到 undefined | ruleToc.chapterUrl 里 book_id 为空 | 确认 ruleToc.chapterList 顶部 `java.put('book_id', book_id)` |
| 3. `data:;base64,XXX` 的 `XXX` 是 hex 不是 base64 | 解码乱码 | 用 `java.hexDecodeToString(result)`，编码用 `java.base64Encode` |
| 4. `book.tocUrl` 在 ruleBookInfo 之外不生效 | 跳目录失败 | tocUrl 必须放 ruleBookInfo 内 |
| 5. 改了 hosts 但不切线 | 请求发往老 host 失败 | `switchToNextLine` 必须 + `setVariable('线路', next, false)` + `getVariable('线路')` |
| 6. loginCheckJs 顶层 return | 解析器报"期望函数" | loginCheckJs 必须 IIFE 包裹或表达式形式 |
| 7. 段评气泡图片加载失败 | `<img>` 标签崩溃 | SVG 必须 base64 + 用 `data:image/svg+xml;base64,` 前缀 |
| 8. 同步书架失败导致阅读失败 | 章节打不开 | `syncBookShelf` 用 `try {syncBookShelf(book)}catch{}` 整体吞 |
| 9. `request()` 递归无 index 上限 | hosts 用尽后死循环 | 必须 index+1 终止条件 |
| 10. `cookie.getCookie(url)` 与 `java.getCookie(url, name)` 行为不同 | 跨域读不到 | 多源 cookie 用 `for (let h of hosts) cookie.getCookie(h)` 循环读 |

## 7. 一句话总结

**光遇聚合 = "客户端协议壳 + 云端 HTML→JSON 转译 + 客户端 JSONPath 渲染"**。如果你想做一个能长期维护、能加新平台、修反爬不影响客户端的聚合源，就照这个模式抄；如果你只需要一个站点的源，写法会简单 5 倍，不必上这全套。
