# 补充-禁漫天堂 v2.1：分类与榜单改为直入口（不用下拉）

> 261128 用户要求「分类和榜单不用下拉选择」。v2.0 的 `exploreUrl` 用 `select 分类` + `select 榜单` + 一个列表入口；v2.1 改为**每个分类一个 URL 入口、每个榜单周期一个 URL 入口**，筛选仍保留 select/toggle（这是原站筛选所需控件）。成品 `examples/禁漫天堂_jmtt_v2.1_四模式.json`。

## 改动点

- 删除 `select {类型}分类` 与 `select {类型}榜单` 两行。
- `addCategoryEntries()`：按当前类型遍历站点全部分类（小说 16 个含原创、视频 14 个、漫画 13 个、短剧 1 个），每个生成一条 `type:"url"`：
  - 标题 `📚/📖 {类型}·{分类}（当前筛选）`
  - URL = `{{jmHost(source)}}` + 分类 path + `{{page>1?('/page/'+page):''}}`（`/…/all` 基准）或 `{{page>1?('/'+page):''}}`（category/原创基准） + 查询筛选串。
- `addRankEntries()`：固定生成 `🏆 {类型}·人气日榜/周榜/月榜/年榜` 4 条直入口，第 2 页守卫仍是 `/search/__jmrank_end__`。
- 筛选控件（小说状态 toggle、字数 select；视频字幕 toggle、时长 select；排序 select）不变；它们仍带 `java.refreshExplore()`，因为分类入口的 URL 在生成时把筛选值烘焙进去了，改筛选后必须重建入口。
- **站点限制**：非默认排序路径（`/hot`、`/freshest`、`/last_published`、`/collect`）会丢分类。因此当排序不等于默认时，只生成一条 `📚 {类型}·全部（…当前排序，站点此排序不带分类）` 入口，不再生成重复的分类入口。

## 验证

- qjs 模拟 infoMap：默认小说 24 行（4 控件 + 16 分类 + 4 榜单）；视频+中文字幕+最多播放 9 行（4 控件 + 1 总入口 + 4 榜单）。
- LT/E 双端 `saveBookSource` 200；LT `check_source` 1/1；分类/榜单 URL 模板与此前验证过的 `{{jmHost(source)}}`/`{{page>1?...}}` 机制一致。
